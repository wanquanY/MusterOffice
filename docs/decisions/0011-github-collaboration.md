# ADR 0011：GitHub 协作、审查与合并门禁

日期：2026-10-04。状态：Accepted。

用户在核查现有缺口后明确要求完善 GitHub 基础机制，包括提交、合并和审核。
该授权覆盖 CI、贡献文档、仓库安全与维护设置、保护规则，以及为落实这些配置创建和
合并本次 PR。不扩展到生产部署或软件包公开发行。

默认工作方式改为当前工作区的功能分支，经 PR 验证后合并 `main`；不自行创建 worktree。
这是用户本次指示对旧“直接在 main 工作”约定的更新。

采用 GitHub 原生 rulesets，将不可跳过的 PR/CI/主分支完整性规则和维护者审批规则分离。
当前仅有一个管理员，维护者本人 PR 允许使用仅限 PR 的审批例外；该例外只作用于
人工审批规则，不能跳过 CI、安全检查、讨论解决、禁止强推及删除等独立规则。
外部贡献必须由代码所有者审查；增加第二位维护者后应移除单人审批例外。

CI 复用已有验证入口与原生组件构建器，在 GitHub 托管的干净环境从公开固定输入准备依赖。
不上传个人开发机器、不引入私有产品依赖，不使用假成功、失败跳过或放宽诊断达标。
原生/WASM 文档一致性、完整渲染、Office/WPS、产品链路和发行性能继续分开验收。

验收以实际 PR 运行、合并前门禁、合并后的 main 运行，以及 GitHub 设置回读为准。
具体配置与单维护者限制见[协作治理](../governance/github-collaboration.md)。
