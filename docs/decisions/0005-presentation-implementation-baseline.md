# ADR 0005：一期演示文稿实施设计基线

- 状态：**Proposed / v0.4 实施设计基线**；用户授权继续完善整体方案，不等于本稿已经通过实现或外部兼容验收。
- 日期：2026-09-24。
- 依据：用户要求按最终效果完整设计，目标仍是完整 PPT、高质量、高性能、小体积及直接替换 Musterwork。

## 本轮收敛

1. 以 F01–F16 下的 104 项能力计划组织实现，保留每项 read/create/edit/render/play/write/preserve 及工作流状态；标准枚举注册表在相应工作包中完整生成和验证。
2. Morph、3D、墨迹、缩放导航、高级图表进入一期设计。旧二进制输入、宏保留、OLE、加密和签名分别明确处理；核心不执行宏或任意外部应用，宿主负责授权执行边界。
3. 固定整数 EMU/有理时间、稳定子对象身份、类型化原子操作、来源覆盖、增量 DAG、版本化计划与资源句柄；完整 IDL 和绑定生成器属于实施产物。
4. 绘制采用同一 Draw IR、标准 CPU 路线与 GPU 保留合成；Rust 持有领域规则，优先验证成熟字体/图形组件的窄 ABI；不为了语言纯度或体积删能力。
5. 公共导出与交付清单先落实设计 Schema 和正反例；MCP/CLI/SDK 共用语义，不能把外部应用未验证的文稿标为已认证。
6. Musterwork 采用版本化 Tool/草稿/候选/质量/Artifact 配套升级；明确媒体与容量问题，沿用 author@3 的原子导出体验和现有任务/提交 owner。
7. 质量、原生编辑、目标应用、动态行为、专业成稿、资源和产品链路分别设门禁；E0–E4 阶段不可用某一项通过代替全部。

## 仍需实际证据

组件及精确版本、目标应用构建/差异、字体/codec 授权与闭包、完整演示体积及真实设备性能、标准枚举全覆盖、Musterwork successor 实现与迁移。这些必须由实施/实验取得，文档不能宣布已达成。

本 ADR 不修改已接受的主体语言决定，不授予公开许可证，不授权公开发布，也不把架构设计的继续授权扩张为未确认的内核源码开发。
