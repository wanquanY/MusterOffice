# ADR 0007：专注办公内核与薄接入

- 状态：**Accepted：产品职责与质量约束**；具体 API、依赖拆分和代码迁移仍需实现、验证。
- 日期：2026-09-27。
- 依据：用户明确要求 MusterOffice 专注为 Agent 提供高性能、高质量 PPT 能力，不需要权限、产品页面和存储，这些由接入产品实现；同时要求 SDK/MCP 接入简单，完整能力、质量、性能和小体积目标不缩水。
- 修订范围：取代 [ADR 0004](0004-agent-integration-surfaces.md) 中由 MusterOffice 提供标准持久宿主、资源库及相关产品设施的方案。MCP/SDK/CLI/Skill/Plugin、Rust 主体、Native/WASM 和完整一期演示目标保留。

## 决定

1. MusterOffice 交付文档模型、原子编辑、格式读写、布局、渲染、播放计算、资源需求分析及质量诊断。完整动画/转场、音视频、SmartArt、公式和 Office/WPS 原生可编辑性继续作为一期门槛。
2. SDK、CLI、MCP 是同一计算能力的薄适配；Skill 描述操作方法，Plugin 封装安装与配置。它们不自建账号、租户、角色、业务权限、内容库、持久任务队列、Artifact 服务或产品页面。
3. 接入产品负责授权、输入输出、持久存储、任务恢复、幂等记录、结果提交和用户界面。MusterOffice 不要求接入方采用特定数据库、修改数据库结构或实现整套专用宿主框架。
4. 默认 SDK 以输入数据/读取句柄、操作、计算选项和输出接收器完成调用；提供内存和流等常用适配。既有产品的权限或存储对象通过薄桥接进入，不进入计算模型或必填公共业务参数。
5. 内核输入校验、资源摘要、句柄有效性、格式防护、内存/计算预算和取消仍必须保留。计算用的有界内存缓存不构成内容存储；确需文件暂存时，只使用调用方提供的临时 I/O 能力，不建立自有长期目录或后台回收服务。
6. 文稿页面、渲染输出、时间轴及播放控制属于 PPT 能力；编辑器页面、文件管理页、登录页、上传下载页和播放器 UI 属于接入产品。MusterOffice 提供无界面的绘制与播放接口。
7. 各入口共用同一语义、渲染与质量规则。按需包装只去除无关接入设施或未来办公领域，不删减一期 PPT 能力；字体、codec、暂存、通信和全部进程计入完整体积/性能账本。

## 实施影响

现有 `mo-standard-host` 已实现 SQLite、资源/任务持久化和作用域检查，`mo-host` 与 `mo-mcp` 使用了该路径。这些是旧方案的实现事实，不再是未来公共发行的必要组件；文档调整不代表依赖已经解除。已有 `CallContext`/权限/Job 等公开合同须逐项分离计算信息与宿主信息，按显式版本迁移，不能只改名称或关闭检查。

Musterwork 已有的授权、存储、草稿、Artifact 和日志改动留在产品职责内，逐项评审哪些是接入必需、哪些是产品自身的通用改造。不得继续把全产品引用追踪或通用垃圾回收当作所有 Agent 使用内核的前提，也不得通过跳过实际存在的资源安全缺口开放产品路由。

本次只修订文档。不删除现有实现、历史证据、数据库或迁移，不承诺当前 SDK/MCP 已符合新边界。后续代码收敛必须保留真实计算、验证和数据恢复能力，明确旧开发宿主的兼容与退出安排。
