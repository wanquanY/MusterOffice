# 能力目录、验证体系与实施门槛

v0.4 设计提案 · 2026-09-24。当前所有内核实现/测试状态均为 **Not started / Not verified**。本文件列出验收要求，不冒充已执行测试；设计补齐不意味着风险已经实测关闭。设计级 JSON 合同校验另见[合同目录](../../contracts/README.md)。

## 1. 能力完成状态

每个最小能力记录：ID、用户任务、语义对象/操作、read/create/edit/render/play/write/preserve 维度、组合/规模、目标档案、所需资源、测试、缺陷和证据。状态分 `not_started / implemented / verified / partial / not_applicable`；partial 必须列缺口，N/A 要说明该维度为何确实不适用。

发行状态独立记录：设计建议、设计批准、实现、单元验证、互操作验证、产品验证、可发行。不能把 `preserve=verified` 推导为 edit/play 成功；也不能把未实现能力从分母中移除后宣称“100%通过”。

## 2. 验证层级

| 层级 | 检查内容 | 不可替代的证据 |
| --- | --- | --- |
| L1 语义/安全 | 内核事务/引用/继承/事件/复杂度防护；产品授权与输入桥接 | 属性/生成式用例、错误断言、输入破坏及产品授权反例 |
| L2 格式/实际字节 | OPC/OOXML、对象/数据/字体/时间/资源闭包 | seal 后实际文件重读与预期投影对照 |
| L3 计算/渲染/资源 | 原生/WASM、增量/全量、标准帧、播放和性能 | 同资源输入、事件日志、测量数据及资源账本 |
| L4 Office/WPS | 打开、显示、播放、原生修改、回存/再导入 | 精确环境、实际步骤与输出，不仅截图 |
| L5 产品/发行 | 所有消费者、历史版本、路由、取消/恢复/提交、安装 | 真实 Agent 链路、Artifact/依赖证据及干净环境 |
| L6 成稿质量 | 同需求生成和修改任务的可读性/设计质量 | 与选定成熟产品的盲评及内容硬断言 |

每份结果绑定输入/输出 bytes、资源/font hash、引擎/规则版本、系统、设备、target build、工具版本、测试 ID 和结论。外部应用样本与私有文件迁入前检查权属、授权和去标识化；不能把客户文稿直接放进公开测试仓库。

## 5. 视觉、编辑和审美判断

先做硬断言：内容未丢、数据未改、无缺字、原生身份正确、引用完整。再对同状态截图计算差异图、文字框/基线/图表标签和遮挡；不能只用一个 SSIM 总分掩盖局部标题消失。像素容差按对象/后端/字体定义并冻结，禁止测试失败后任意放宽。

播放比对同时使用事件轨迹、状态摘要、关键帧和音画时间证据，时间容差与设备/解码器一起记录。编辑性通过指定操作验证：改文字、拉宽框、换主题、改图表数据、增 Diagram 节点、改公式、调整动画顺序和媒体片段，然后保存再读。

成稿对照固定需求/内容/素材与设计限制，候选产品及版本在测试前确定；随机匿名排序，按层级、对齐、留白、可读性、信息密度、主题一致性、修改成本评分。评分量表、通过阈值、评审者和分歧处理需 D1 批准；未定义这些不能宣称“审美无差异”。内核与 Agent/模板导致的差异分别归属和修复。

## 6. E0 高风险验证包

Rust 主体、TS 薄接入与精选 C/C++ 组件策略已由 [ADR 0003](../../decisions/0003-language-and-component-strategy.md)确认；[ADR 0006](../../decisions/0006-implementation-authorization.md)已授权一期源码及必要实验。本节定义实验问题与退出证据，实际阶段结果见[实现进度](../../implementation/progress.md)。

| 实验 | 最小完整路径 | 必须回答的问题 |
| --- | --- | --- |
| E0-1 文本/字体 | 新建/导入混合文字→原生/WASM布局→PPTX→无系统字体环境编辑→回读 | 自然重排、字体槽位和完整中文编辑是否成立 |
| E0-2 母版/图表 | 外部多层模板/图表→改主题与数据→输出→两目标应用改数据回存 | 继承、自动布局及工作簿/缓存合同是否可控 |
| E0-3 SmartArt/数学 | 节点增删/换布局与矩阵/分式改写→原生文件→外部编辑 | 原生语义与排版模型是否足够，而非缓存碰巧可看 |
| E0-4 动态/媒体 | 点击→并行/顺序效果→媒体书签→转场/seek→目标应用 | 时间模型、合成后端、媒体能力和格式映射能否同时闭环 |
| E0-5 保留/异常 | 未知扩展/共享关系/有损风险→局部改动→重读；各阶段取消 | 来源闭包、错误隔离、输出回读及资源生命周期是否正确 |
| E0-6 接入/体积 | 独立 MCP/CLI 与 Web Worker/Managed 最薄接入，冷/热资源 | 完整依赖、桥接开销、内存/播放成本；协议版本、无客户端和任务 Owner 是否守住 |

先做足以推翻架构的小样本，再做组合压力；不能先写大量简单对象再处理 SmartArt/动态语义。失败时修正文档/算法或候选组件，禁止截图化、关闭检查、永久旧引擎兜底获得通过。

## 8. 阶段准入与发行闸门

D1 冻结要求：F01–F16 子能力及目标环境明确；D01–D09 的必要决定有记录；接口和风险实验可以复现；没有一期能力被旧排除项覆盖。文档完成本轮修订尚不等于 D1 全部退出。

E0 选择技术路线后，E1 固定纵向合同，E2 逐项实现，E3 完成产品验证，E4 默认替换及退役。按风险匹配检查，不为装饰性文档变更写实现镜像测试；核心算法、格式映射和跨端/外部行为使用独立断言与反例。

发行必须同时满足：所有一期适用维度 verified；无未裁定内容丢失/损坏与 P0/P1 阻塞缺陷；目标 Office/WPS 的编辑/播放/回存通过；性能及完整体积在批准预算内；Musterwork 全消费者和历史链路通过；许可/SBOM/干净安装/升级恢复完成。通过比例不能抵消一个必需能力失败。

证据包包括源码与构建标识、依赖/许可清单、能力矩阵、测试语料及授权、外部应用结果、性能原始样本、缺陷清单、产物版本和产品替换报告。分别标注组件通过、集成通过、产品通过和可发行，不合并成模糊“验收通过”。

## 9. 开放接入完成门槛

[公共接口规格](../agent-interfaces.md)的 I01–I20 是一期发行的额外必需验收，覆盖本地/远程 MCP、协议档案、无扩展客户端、Skill/CLI/SDK、跨入口等价、产品授权与大文件桥接、Plugin 生命周期、Musterwork 与第三方独立接入。按 [ADR 0007](../../decisions/0007-kernel-only-integration-boundary.md)，还必须证明普通调用无自有账号/持久库/UI 前提、依赖不强制捆绑、同质量下的实际封装成本及计算资源释放。

这些测试证明接入形式可用，不替代 T01–T30、A01–A16、B01–B05 的文稿质量与产品能力测试。必须有第三方客户端在不依赖 Musterwork 的情况下实际完成创建/导入、编辑、检查和 PPTX 交付，才能宣称“其他 AI 产品可快速接入”。已有部分旧协议/宿主阶段证据，完整接入门禁及本次修订的 I01–I20 尚未通过；历史结果不自动证明新边界成立。
