# PPTX 读写、保留与 Office/WPS 互操作

v0.4 设计提案 · 2026-09-24。主约束为原生可编辑和用户可继续工作；格式依据采用 [ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/) 与 [Microsoft PPTX 扩展](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/efd8bb2d-d888-4e2e-af25-cad476730c9f)。引用标准不意味着已实现或已获得兼容认证。目标环境及门禁见[验收档案](../implementation/acceptance-profiles.md)。

## 1. 五种承诺分别报告

| 维度 | 通过的含义 | 不能证明什么 |
| --- | --- | --- |
| 结构 | ZIP/OPC、XML、部件、关系和类型合法 | 不证明目标应用排版/播放正确 |
| 语义 | 内容、数据、对象、继承、时间关系保持 | 不证明像素与设备行为一致 |
| 视觉 | 固定状态在目标环境达到允许差异 | 不证明原生对象可再编辑 |
| 编辑/往返 | 目标应用修改并回存后语义仍成立 | 不等于任意扩展可无损处理 |
| 播放 | 事件、效果、媒体与导航行为符合档案 | 不等于全部设备 codec 均可用 |

生成模式与导入修改模式分别验收。生成器控制了输入，不足以证明可以完整读取第三方任意 PPTX。

## 2. 包图与来源模型

导入先生成不可变 PackageGraph：部件 URI、ContentType、未压缩摘要/长度、压缩位置，包级/部件级关系、目标模式和依赖边；XML 同时建立受限语义树与保留区。校验路径规范化、关系闭包、重复部件、内容类型冲突及资源预算后才开放对象。

SourceBinding 记录对象/字段到源部件与结构节点的映射、原始 QName/命名空间、显式属性、继承来源、`AlternateContent` 分支和扩展保留区。**已知对象上的未知属性/子节点同样需要保留**，不能只保存未知整个 part。

保留边界包含：未编辑 XML 子树、未知扩展、命名空间上下文、未被消费的兼容分支、共享资源与传递关系。使用结构化语法模型和类型化覆盖，不使用正则替换 XML。

未改动部件可复用原始 bytes；修改部件允许稳定重新序列化，不能要求整个 ZIP 字节不变。语义摘要排除合法的序列化差异，但必须检测关系、内容和未知保留区的损坏。

## 3. 原生语义映射

| 对象 | Reader 持有 | Writer 保证 |
| --- | --- | --- |
| 主题/母版/版式/占位符 | 继承与显式覆写、匹配规则 | 原生层级和关联；换主题/重置布局仍有效 |
| 文字 | 逻辑段落、run、显式换行、域、属性 | 原生文字；不固化内部自动折行 |
| 表格 | 网格、合并、单元格、样式 | 原生表格；合并和内容不拆散 |
| 图表 | 系列、轴、缓存、数据工作簿、布局 | 图表和数据可编辑，缓存与工作簿一致 |
| SmartArt | 数据、连接、layout/style/colors、drawing 绑定 | 原生 Diagram 部件及一致缓存，可增加节点 |
| 公式 | 数学树、DrawingML 承载和保留结构 | 目标档案认可的 OMML，可修改数学结构 |
| 时间/转场 | 时间树、触发、目标、参数 | 原生引用、行为和页面转场 |
| 媒体 | 内嵌/外链、封面、片段/书签/播放属性 | 原资源关系及播放语义，不变海报图 |
| 备注/批注/放映 | 页面关联、身份、文本与导航 | 原生关系和内容；个人信息处理由宿主策略明确决定 |

相关格式结构包括独立 slide/master/layout/notes 和 Diagram 部件；应当按依赖处理。[PresentationML 文档结构](https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document)

数学承载及兼容分支需要目标应用验证，不能根据“XML 可解析”判定外部编辑成立。[Microsoft DrawingML 数学扩展](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/853b19c7-68a9-4f9a-a2ae-5e6cb0d02e62)

## 4. 选择性修改与受影响闭包

1. 事务产生语义 ChangeSet 和引用重写映射，标记直接修改字段。
2. 计算正反依赖闭包：共享母版/主题、图表工作簿、Diagram、时间目标和资源都参与。
3. 为每个部件选择复用、结构化覆盖、重新生成、复制或删除；给出保留风险。
4. 共享部件局部修改采用写时复制，除非操作明确修改共享定义；不能改变其他引用页。
5. 分配作用域内唯一 ID 与关系 ID，重写所有已理解引用，并核对保留区域的引用影响。
6. 检查无悬空引用、无非预期失去的内容、未知区域是否仍可解释，之后才写包。

未知扩展若引用将被删除/改名的对象，不能盲目复用。无法证明保留安全时返回具体冲突；调用方可以保持该对象不变，或显式选择有损派生副本，但有损输出不满足完整替换验收。对一期承诺能力必须实现语义处理，不能永久停留在“拒绝编辑但可保留”。

删除页后清理资源必须按可达性而非文件名猜测；共享资源仍有入边不得删除。外链不自动下载；来源图只记录链接及授权需求。

## 5. 写出与实际文件重读

Writer 消费 `CompiledPlan.semanticObjects + nativeLayout + preservationPlan`。用统一 OPC/XML 基础层输出部件、关系和 ContentTypes；不从 raster Scene 反向构造对象。压缩、部件顺序、非业务时间戳和生成 ID 的确定性规则需版本化。

输出写入宿主暂存 ResultSink，seal 后获得不可变句柄、长度和摘要。Reader 通过同一个句柄范围读取，检查真正交付的 bytes。PPTX 重读后重新建立文档并与预期语义投影比较；不得直接复用写出前的模型做“重读成功”。

对每个对象检查类型、文本/数据、字体、几何/继承及高级关系；对时间检查触发/目标/状态，对媒体检查摘要/片段/封面，对 Diagram 和公式检查语义与原生身份。解析后的实际文件可渲染标准状态帧作对照。共享代码导致的共同错误由外部应用与独立结构规则测试补充发现。

## 6. 目标应用矩阵与差异治理

建议首批为 Windows/macOS 上的 PowerPoint Microsoft 365 或 Office 2024，以及 WPS 桌面演示。**这是待批准矩阵，不是兼容声明**；具体系统版本、应用构建、更新通道、语言、字体包、codec 和打开模式必须冻结后才产生有效档案。

每条 capability × target 记录 read/display/edit/play/save/reimport 的证据；不能用一个“支持 Office/WPS”布尔值概括。其他版本可尝试打开，但不自动继承认证。Strict/Transitional 和厂商扩展的读写覆盖同样分开记录。

| 差异类型 | 处置责任 |
| --- | --- |
| writer 映射错误 | 修复格式适配与回归样本 |
| 内核排版或时间规则错误 | 修复领域规则，对原生/WASM共同生效 |
| 目标应用之间行为不同 | 记录可重现差异，制定明确兼容 profile 与同一文件折中策略；质量门槛仍需通过 |
| 应用缺少某特性或 codec | 明示目标档案不完整并阻止宣称该档案支持；不能静默栅格化后算通过 |
| 未裁定 | 保持未验收，不以任意第三方转换器作为绝对真值 |

默认交付应是一份能在已承诺目标中工作的 PPTX。如果只能给各应用分别生成变体，必须作为产品决策重新评审，不能暗中改变“直接用 Office/WPS 打开编辑”的约定。未解决的特性冲突阻止对应承诺冻结/发行。

## 7. 双向往返与外部编辑

测试闭环：Office/WPS 创建 → 内核读取 → 只改指定对象 → 原应用与另一目标应用打开/修改/保存 → 内核再导入。分别检查改动预期、未改内容、母版/主题、资源、时间图和未知内容。结构顺序及合法 ID 变化不应被误判为内容丢失。

外部编辑后的 bytes 是新输入。不能信任旧自定义对象映射天然有效；先校验映射与对象证据，匹配不确定时分配新身份并报告，而不是覆盖错对象。用户选择继续编辑与上传为模板属于不同产品流程，见[替换合同](musterwork-integration.md)。

文稿 hash 变化即使页数相同，也不能复用旧 QA/预览。模板、资源、字体或兼容规则发生变化后，同样要按对应依赖重新验证。

## 8. 输入安全与特殊格式状态

限制压缩比、总解压量、XML 深度、属性/文本长度、关系数量、几何/图表复杂度、图片尺寸和媒体索引；禁用外部实体，不执行宏、OLE 或输入脚本。外链访问由宿主授权，核心不持有网络能力。

`.pptx`、旧 `.ppt`、宏文稿、加密包、嵌入 OLE、数字签名不能混为一种文件能力。v0.4 [格式边界](../implementation/capability-matrix.md)已明确旧格式导入、宏保留而不执行、OLE 语义与宿主激活、登记加密方案读写。被修改的签名包不能继续声明原签名有效；如需移除/重签由明确的宿主策略和用户意图决定。设计包含不等于已实现。

许可、隐私与保留政策由宿主配置并记录；内核不能为清理元数据悄悄删除用户批注、备注或媒体。损坏输入失败要定位来源，不发布部分成功产物冒充完整文件。

## 9. 证据格式

报告绑定 engine/schema/profile/resource/font 版本、输入/输出 hash、目标环境、能力及测试 ID、打开是否修复、实际修改步骤、再保存/再导入结果、差异及附件。

每个用户文稿可声明“内部实际字节检查通过，适用兼容档案为 X”；若没有在 Office/WPS 实际运行该文稿，必须保持 `targetApplicationChecked=false`。发布语料的认证不能改写成用户每个文档都经过了外部应用验证。
