# 排版、字体与原生对象计算

v0.4 设计提案 · 2026-09-24。依赖[文档模型](document-model.md)，输出语义布局及可重用绘制片段；PPTX 映射由[互操作模块](ooxml-interoperability.md)负责。算法步骤与组件边界见[实施算法规格](../implementation/algorithms-and-components.md)。

## 1. 布局职责

文档采用固定页面，同时支持受控的栈、网格、对齐、分布和约束容器。导入 PPTX 的显式几何默认保留；Agent 新建对象可用约束布局，编译后形成可编辑的原生定位。不能用浏览器完整 CSS 或 DOM 测量作为核心的隐藏依赖。

布局依次处理继承、约束尺寸、文本/对象本征尺寸、容器分配、连接线、溢出及视觉边界。约束环明确诊断；迭代布局有收敛条件和次数预算，不依靠主机快慢决定何时结束。自动调整仅按作者指定策略执行，默认不丢内容。

布局结果同时保留逻辑框、内容框、实际墨迹边界、效果边界、命中几何与来源对象 ID。视觉重叠并不总是错误：背景、装饰、连接线与有意叠放要有语义角色；检测器报告证据和规则，不能把全部重叠判为失败。

## 2. 文字不是字形列表

文字管线建议为：段落/语言/方向 → 字体实例与回退链 → Unicode 分段和双向分析 → 塑形 → 换行候选 → 行布局/对齐 → 竖排/旋转 → 字形与逻辑映射。塑形库只能承担其中一部分，不能代替演示文稿的段落行为。[HarfBuzz 职责说明](https://harfbuzz.github.io/what-is-harfbuzz.html)

必须明确实现并逐目标应用对照：

- 段前/段后、百分比/固定行距、项目符号/编号、悬挂缩进和制表位。
- CJK 禁则、标点挤压、英文长词、连字符、空白、显式换行和软换行。
- RTL 与混合方向、复杂脚本、组合字符、emoji/彩色字形和垂直文字。
- 文本框内边距、垂直对齐、多栏、旋转、文本溢出与指定 autofit 策略。
- 字距、baseline、大小写效果、上/下标、超链接、域和混合样式。

Office 行为规则归属于带版本的兼容 profile；格式适配负责单位和属性映射。不能在浏览器和桌面宿主各写一套特殊换行逻辑。行高及 glyph advance 保留精度，最终量化位置明确定义。

**自动折行不得转成作者显式换行。** 写出保留原段落/软换行语义；布局建议和目标属性可控制定位，但调整框宽或替换文字后仍要自然重排。必须用“追加内容、拉宽框、改字号再保存”的编辑实验判定，而不只是看初次打开的截图。

## 3. 字体合同

FontManifest 记录资源摘要、家族/子家族、PostScript 名、语言覆盖、字重/斜体、轴实例、实际 face、嵌入权利与目标映射。资源选择为显式输入；核心不能扫描系统字体补齐。宿主可登记系统字体，但必须提供被选字节及身份，进入结果证据。

字体缺失必须在编译前报告。替代字体是明确的文档修改或调用方批准的 profile，产生新摘要和布局报告；不能静默以系统默认字体掩盖差异。需要允许用户在目标应用添加原稿未出现的字符，因此“当前字形子集可看”不足以证明可编辑交付。

建议优先使用许可清晰、允许所需嵌入和编辑的字体；完整家族按需下载/预置，文档只嵌入实际需要的合规 face。普通、粗体、斜体和粗斜体槽位的映射需检查冲突，不能把多个不同字重都当同一槽位并静默覆盖。变量字体是否实例化、实例命名与许可，以及 Office/WPS 的实际加载行为都需实验。

完整嵌入与字体体积是产品约束，不能以限制用户输入新字换取小文件。相同字体在文稿内去重、复用压缩结果，但跨文稿缓存不能作为 PPTX 离线可编辑性的前提。[Microsoft 字体嵌入说明](https://support.microsoft.com/en-us/office/fonts/benefits-of-embedding-custom-fonts)

## 4. 几何、图像与效果

几何层表达预设形状的参数、调整柄与连接点，自定义路径的线段/曲线/弧、填充规则，组的局部变换和裁剪。连接线绑定对象与连接点而非只有两端坐标；移动/旋转/组合后的连接正确性与原生编辑共同检查。

图像保留原资源、裁剪、透明度、色彩变换和显示几何；解码尺寸有上限，原始字节可直接入包时不重编码。SVG、位图、矢量来源的格式支持按目标矩阵登记；源文件中的复杂图元不能被泛称“图片支持”掩盖。

填充、渐变、透明度、线型、阴影、模糊、发光、反射、遮罩和混合顺序作为显式效果图。布局边界不含效果，视觉边界包括效果扩展。中间表面进入资源账本；不能为整个页面或每帧无限扩张缓冲。

## 5. 表格与图表

原生表格模型包含行列、合并关系、单元格 ID、内边距、边框、样式引用和文本。尺寸约束与内容容量共同求解；合并区域不能生成重复逻辑文字。表格修改应保留单元格语义，不能拆成彼此无关的文本框与线。

图表模型独立于绘制路径：系列/分类/值、空值策略、公式引用、日期系统、轴类型、刻度、数值格式、标签、图例、绘图区和样式。图表计算产生可绘制布局和原生 writer 所需设置，同一数据不能由两个互不核对的模块分别生成。

图表数据源、嵌入工作簿及 OOXML 缓存有共同规范化数据摘要。null、0、空字符串和缺失分类必须区别；日期、百分比、区域格式和系列排序有固定合同。目标应用编辑数据后应重新计算并显示预期结果，不能只检查初次打开的缓存。

轴和标签布局实现避让、旋转、换行及绘图区分配，并保留作者显式手动布局与自动布局的区别。对方应用自动布局有差异时要制定可验证映射；不能为了截图一致，把全部图表标签永久改成无关联文本框。

## 6. SmartArt 计算模型

SmartArt 是数据与连接图、布局定义、样式/颜色定义及派生 drawing 的组合。布局定义包含层级节点、选择/迭代、约束、规则和算法，不能仅把节点做一次等距排列。[Open XML LayoutNode](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.diagrams.layoutnode?view=openxml-3.0.1)

建议管线：

```text
Diagram data graph + selected layout definition + theme/style
  → validate graph and typed layout instructions
  → expand layout instances with stable data bindings
  → measure text and intrinsic geometry
  → solve constraints / algorithm-specific placement
  → derived drawing + source/data correspondence
```

模型保存数据点、连接、文本及用户覆写，与布局实例身份分离。添加节点、调换层级、切换布局应重算派生绘图并更新相关动画目标；人工调整需要明确是绑定节点的覆写还是对布局实例的临时设置，失效时报告。

布局执行器只接受已定义的有界格式指令；无任意脚本，限制递归、实例数、约束量和迭代次数。支持目录分别列出布局算法、约束类型与组合；“支持 SmartArt”不能只由一个组织结构图决定。

Writer 输出可被目标应用识别的 SmartArt 原生部件和对应绘图缓存；Reader 还原语义，目标应用更改节点后再次导入仍保留可编辑关系。保留原 XML 而不能增删节点的状态只能记 preserve，不满足一期要求。

## 7. 数学排版

MathDocument 用数学树表达文本/标识符、运算符、分式、根式、上下标、上下限、定界符、重音、矩阵、方程数组和组合。行内与独立公式有不同基线与间距策略。字符串 LaTeX 等只能作为显式受限输入适配，不能充当唯一事实源或把任意命令当可执行内容。

排版依据数学样式、紧凑样式、运算符间距、伸缩定界符、分式/根号尺寸与字体的数学度量生成盒树。OpenType MATH 提供数学常量、字形信息以及尺寸变体/组合信息；普通文本塑形不足以自动获得完整数学排版。[OpenType MATH](https://learn.microsoft.com/en-us/typography/opentype/spec/math)

Writer 按目标档案输出 OMML 及必要的 DrawingML 承载；缓存可以辅助呈现，但目标应用必须按公式编辑并回存。仅输出 SVG/路径不合格。数学内容与文本范围保持映射，以支持选中局部分式、修改矩阵行列和定位诊断。

## 8. 动态布局与合成

编译期对动画属性分类：位移/旋转/透明度等可复用静态层；改变字形、几何或遮罩的效果触发对应片段重新求值；布局相关属性的变化执行明确的局部重排或受控采样。不能假定所有动画只是 CSS transform，也不能每帧全稿重新排版。

CPU 标准绘制与实时合成共用同一已求值几何和效果顺序。采用 GPU 时需核对裁剪、色彩空间、预乘 alpha、滤镜边界与文字采样；差异按标准帧定位，不允许两后端分别改变文档规则。

## 9. 视觉质量与设计系统

内核提供主题 token、版式/布局约束、对齐分布、可读性诊断和对象级证据，Musterwork 的 Agent/模板体系负责内容组织和设计选择。不能把“支持所有图元”当成最终成稿审美已经达到成熟产品水平。

模板与设计语料至少覆盖商业汇报、研究报告、数据密集页、流程/组织图、中英混排和品牌主题；每类有明确排版约束和反例。对照任务包含生成、同义扩写、换主题、数据翻倍和外部再编辑，评估内容完整、层级、留白、对齐、可读性及修改成本。主观分数与内容硬断言分别记录。

本规格对应的未决项是具体字体家族、完整图形/图表/SmartArt 算法目录、数学字体及动态后端；它们必须进入能力目录及 E0，不能由某个基础库的宣传页代替验收。
