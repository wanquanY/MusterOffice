# 一期实施规格总表

v0.4 设计基线，2026-09-27 按 ADR 0007 修订接入职责。**已有部分实现和阶段测量，完整一期及新边界尚未验收**；实际状态见[实现进度](../../implementation/progress.md)。

本组文档把[总体设计](../presentations.md)展开为可分工、可检查的实施合同。用户已授权按最终效果继续完善整体方案；以下工程选择作为本轮设计基线，不再逐项悬置为“以后考虑”。已批准的产品目标不变，具体技术选择仍须经过 E0 证据验证；许可证、实测构建号和真实性能数据不能靠设计稿代替。

## 1. 最终交付物

| 交付物 | 必须包含 | 完成证据 |
| --- | --- | --- |
| Presentation Kernel | 可编辑文档、事务、排版、图形、图表、SmartArt、数学、时间与媒体语义、读写 | 全部适用能力维度通过，跨端与增量等价 |
| Native / Web Runtime | 相同语义核心、有界计算调度、CPU 标准绘制、实时合成、无界面播放接口 | 无产品 UI 也可执行；取消、宿主重载、内存和播放预算通过 |
| PPTX 互操作 | 外部文件导入、原生写出、回存、字体/媒体闭包和来源保留 | 精确 Office/WPS 环境中打开、修改、播放、回存、再导入 |
| Agent Distribution | 薄 MCP/CLI/SDK、Skill 与平台 Plugin；常用输入输出适配 | 无自有账号/数据库/产品页面前提；I01–I20、同源完整 PPT 能力及成本验收 |
| Musterwork Adapter | 公共接口与原任务/权限/资源/Artifact 的桥接、历史转换；产品自行接入渲染/播放 UI | 真实产品任务、历史文件、外部编辑和故障恢复全通过 |
| Release Evidence | 能力登记、兼容锁、测试语料、报告、SBOM、包与资源摘要 | 正式发行门禁通过；旧 PPT 链路已退役 |

“替换完成”是这六项共同成立。内核库能生成 PPTX、MCP 工具可调用、预览看起来正确，分别只是其中一部分。

## 3. 设计选择的状态

| 事项 | 本轮收敛结果 | 还需要什么证据 |
| --- | --- | --- |
| 语言与边界 | Rust 持有语义/事务/格式/时间；TS 为薄接入；产品自有 UI；C/C++ 通过窄 ABI 提供基础计算 | 与纯 Rust/必要 C++ 路线对照的 E0 成本与质量结果 |
| 绘制 | 保留场景、标准 CPU 绘制、GPU 合成；文本布局不得交给 DOM 或绘制库重算 | E0 复杂文字、效果、视频合成与完整包体积 |
| 编辑模型 | 整数 EMU、稳定子对象、类型化操作、不可变 revision、来源覆盖写回 | 模糊测试、外部回存及大文稿增量结果 |
| 高级能力 | Morph、3D、墨迹、缩放导航、高级图表进入一期设计和门禁 | 逐能力的 Office/WPS 支持交集与原生编辑证据 |
| Agent 集成 | 同一计算合同及薄 MCP/CLI/SDK；业务宿主归接入方 | 公共合同拆分、I01–I20、第三方客户端、Musterwork 任务映射与实际成本 |
| 产品迁移 | 版本化新 Artifact/Proof/Candidate，不伪装旧格式；保留 author@3 原子导出行为 | Musterwork 配套实现与历史回归 |
| 体积优化 | 按需模块和显式资源包；同时公布基础、完整安装及全离线成本 | 真实依赖闭包和所有支持平台测量 |

设计可以固定行为，不能预先认证第三方应用实现或未测性能。E0 失败要修改负责该问题的算法/组件，不能降低内容与编辑要求以取得通过。

## 4. 完成状态与下一步

- 已有：整体设计、设计级机器校验、部分内核/协议/产品桥接实现及阶段证据。
- 未完成：新边界下的高层 SDK/薄 MCP、完整高级内容、正式发行包、全平台/Office/WPS/完整性能与体积验收、Musterwork 替换。
- 收敛顺序：先分离计算与宿主合同，完成不依赖持久设施的公共入口，保留完整 PPT 计算与输入防护，再以公共接口接入产品；详见[边界合同](kernel-host-boundary.md)和[实施计划](delivery-plan.md)。既有证据保留原范围，不自动为新实现背书。

因此，本组可以作为实施评审和任务拆解依据；尚不能声明“实现已经无风险”“已达到 Office/WPS 效果”或“现在即可替换 Musterwork”。
