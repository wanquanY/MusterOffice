# 公共作者合同、诊断与接入一致性

2026-10-02 · 根据用户对 Musterwork / MusterOffice 全系统底层设计的要求，细化 ADR 0007 的职责及 ADR 0026 的作者合同。本文是后续实现基线，不是当前能力全部完成或正式发行声明。

## 1. 目标与边界

任何接入方都应能从公共合同完成创建、局部修改、检查、导出和再次读取；普通制作不应要求模型研究内部 Document/OperationEntry 或猜测隐藏约束。公共操作最终展开为现有唯一文档和事务，计算库仍不拥有账户、权限、文稿数据库、业务任务或产品编辑器。

MusterOffice 拥有文档语义、输入类型、字段/单位、原子计算、布局/格式/资源依赖、领域诊断及 SDK/MCP/CLI 同源公开面。宿主拥有输入授权、资源取得、持久版本 CAS、Invocation/任务恢复、输出提交、交互界面和模型预算。内核成功结果是计算候选，不能宣称宿主已保存。

## 2. 一份操作语义及生成合同

公共 Rust 类型是操作、Schema、TS 类型和有效例子的语义源。发行验证应执行所有公开例子，而不只验证 Schema 自身合法。产品可以包装自己的授权/版本字段，不能重新定义文本、裁剪、布局或单位换算。

新版本联合对象应提供明确区分字段，避免调用方和通用 Schema 验证器在 picture/shape/table 等分支间猜测。旧未标记联合类型保持原解释及正确诊断，不为兼容直接容忍未知字段。单位和允许值在相应属性旁明确声明；简写或单位便利由公共作者层确定性展开，不能由产品悄悄推断。

普通作者操作与高级原生操作是同一模型的两种入口。高级操作按类型提供可用状态、完整 Schema 依赖和例子，不让普通任务追逐几十个定义，也不把只有底层实现的能力标成作者接口已支持。

## 3. 创建与编辑的一致性

常用范围沿 ADR 0008 验收：页面、可编辑中文/富文本、段落、形状、图片、表格、现有稿与模板修改、预览和原生导出。操作扩展按真实任务覆盖，不因本次梳理要求立即实现全部高级目录。

| 操作 | 必须保持的语义 |
|---|---|
| 创建/追加 | 同一元素、文字和样式类型；稳定身份；追加不重建旧页 |
| 改位置/尺寸/形状 | 仅修改请求指定的属性，保留文字、样式、无障碍和引用 |
| 改样式/文字 | 明确区分整个文本体替换与局部格式修改，不能用全量替换冒充格式保持 |
| 插入/替换图片 | 显式选定资源；替换源图时默认保留布局及未指定裁剪；无自动外网读取 |
| 页面/元素插入删除 | 原子更新身份、层级与引用；依赖冲突可定位，不默认丢弃动画/连接线 |
| 表格修改 | 同一原生表格及稳定单元格身份；合并/拆分保留物理内容 |
| 现有 PPTX | 遵从来源保留档案；未支持的修改明确拒绝，原文件和已确认快照不变 |

作者层返回本次新增/替换资源需求。宿主交付的 Resource 元数据必须与这些需求一一对应。新增逻辑资源身份不得无意覆盖已被其他对象引用的不同内容；需要替换共享资源时必须有明确操作语义。取消与任一错误都不能发布半批修改。

## 4. 领域诊断

计算错误至少含稳定错误码、阶段、精确 JSON 路径/文稿位置、失败约束、期望类型或允许值、相关对象/页和可执行修正方向。不能只返回 `ElementContent` 不匹配，也不能把一个类型错误变成另一个对象类型缺字段。

多错误收集可以合并同一规则的重复解释，必须保留所有受影响位置与数量。可证明表达同一修正的重复规则可以去重，例如同一数值位置的 `not:number` 与 `type:string`；不同约束不得因消息长度或排序被丢弃。联合类型有歧义时报告候选约束，不制造确定性结论。

完整计算诊断属于公共结果。宿主的 UI 摘要长度不约束内核诊断；宿主按其授权内容通道保存和读取大型报告。核心只报告计算是否开始/完成、候选是否产生；产品的持久提交状态必须由产品确认。不能把失败消息中的 `retryable` 当作改变创作参数的禁止令。

## 5. 预算与数据路径

内核拥有对象数量、解压、几何/文本、图像/字体、操作与内存的计算防护；宿主拥有模型上下文、工具传输、存储、队列和业务期限。当前 `MAX_OPERATION_BYTES=32 MiB` 是计算合同防护，不能推导某模型可一次输出这么多，也不能用产品的 24 KB 创作批次限制代表公共内核能力。

示例/工作流可建议分批；计算不替宿主拆开承诺原子的操作并隐式提交。输入字节、持续渲染帧、大型输出经过宿主资源通道，Agent 控制消息只选择资源和操作。性能调整记录输入、环境、冷/热状态与实际测量，不以减少内容、质量或可编辑性换取指标。

## 6. 工作流与技能

正确调用所必需的知识随操作定义交付，包括字段、单位、版本前提和明确的失败恢复方式；不要求调用方先加载 Skill 才有可能正确构造输入。

公共 Skill 提供叙事、素材、样式选择、代表页、分批、真实预览检查、局部修订和最终交付方法。产品 Skill 负责该产品的素材身份与成果展示约定，公共操作示例应从固定内核发行物校验/生成，避免两边手工维护不同语法。Skill 不取代类型约束，也不持有账户/任务/权限权威。

## 7. 能力及发行

公开能力按创建、读取、编辑、渲染、播放、导出和保留分别说明，绑定当前版本与档案。保留原始部件、预览正确、可创建、可局部编辑不能相互冒充。

SDK、worker、WASM 和生成合同组成固定且可验证的组件组合。CLI/MCP 复用同一语义，不强带产品存储。宿主可以在已有 Capability/Provider 设施中报告缺少 worker/字体或不支持平台，内核不因此建立健康管理/部署平台。

兼容演进使用新版本；旧 wire 语义、样本和历史结果保留。不把本机 Native 测试通过推导为 WASM、Linux/Windows 或第三方应用兼容通过。

## 8. 验收

同一语料通过直接计算、公共 SDK、CLI/MCP 和接入产品，比较相同语义/资源/版本结果。至少覆盖：中文图文稿、文字/样式/背景局部修改、图片替换与裁剪、元素和页序、表格、模板与来源保留、资源身份冲突、取消、失败原子性和旧 revision。

Schema/例子、Native/WASM 语义一致、实际 PPTX 内容与编辑能力、Office/WPS 往返、宿主持久提交和真实 Agent 工作流分别给证据。没有产品就绪和真实运行证据时，只标记内核或组件通过。

本次已实现常用样式、几何、图片、元素与页面编辑，使用既有原子事务；生成合同及资源冲突、属性保留测试已通过。圆角导出改用 DrawingML 原生乘除公式表达非整数调整比例，不再拒绝合法 EMU 半径或对其取整；真实 PPTX 回读和几何求值测试通过。发行打包显式设置 native worker 的可执行权限。新固定发行仍须由宿主完成产品验收。对 Musterwork 的整合次序在接入方 `docs/architecture/agent-runtime/design/native-office-contract-and-delivery.md` 跟踪；本文件不定义其数据库、权限、工具信封或 UI 字段。
