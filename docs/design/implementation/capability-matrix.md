# 一期能力与格式边界

v0.4 设计基线。目标是完整演示文稿内核和 Musterwork 全链路替换，包含用户明确要求的所有高级内容；本页不以现有产品只有静态能力为范围上限。

## 1. 能力记录和判定

机器清单见 [capabilities.json](../../contracts/capabilities.json)。每项记录稳定 ID、所属 F01–F16、适用维度、至少一组回归、实现状态。维度为 `read/create/edit/render/play/write/preserve`；N/A 只用于语义上没有该动作的项目，附理由，不能用于隐藏未实现功能。当前所有适用维度均为 `not_started`。

`read` 是理解可查询语义；`preserve` 是保留原包内容；`edit` 是保有原生身份进行修改；`write` 是写出对应原生格式。三者互不替代。播放包含时间及交互行为，静态预览不是播放通过。

同一能力至少测试：新建、外部导入、局部编辑、组合编辑、写出重读、目标应用编辑回存、增量/全量对照。适用的子对象操作包括新增、删除、复制、重排、样式修改和引用更新。每条测试带能力 ID；存在未通过适用维度时该能力不可标为 verified。

## 3. 标准枚举不能被几个样例代表

实现仓库必须生成并审查 `feature-registry`，每条为 `(namespace, kind, nativeId, parameters, semanticVersion, capabilityId, targets, fixtureIds)`。注册表版本及摘要进入发行清单；导入遇到注册表外的内容，产生精确能力报告，不能按最近似效果猜测。

| 目录 | 完整性依据 | 必须逐项覆盖 |
| --- | --- | --- |
| 预设形状、pattern、线条端点、效果 | 固定版 ECMA-376 对应简单类型/元素与 MS 扩展 | 全部合法值、默认值、调整参数边界、组内使用 |
| 动画、转场及 Morph | OOXML timing/transition 与固定版 MS-PPTX/MS-ODRAWXML | 原生 ID/子类型、参数、方向、触发、组合与时序；“淡入可用”不代表全目录 |
| 图表与高级图表 | chart/chartEx 类型、轴、系列、数据和样式规范 | 类型×数据语义×轴关系×标签；不同图表类型不得同一算法伪装 |
| SmartArt | diagram layout 节点/算法/约束/规则及授权布局库 | 每种算法和规则；每个发行布局；改变树形、文本及数据规模 |
| OMML/数学 | 固定版数学元素/属性与 OpenType MATH | 元素类型×嵌套×字体/脚本；导入不认识的节点不得转图片冒充支持 |
| 3D、墨迹、矢量图元 | 对应标准及 MS 扩展 | 场景节点/材质/相机/动画、笔画属性、矢量记录与嵌套资源 |

正式注册表必须从锁定规范生成候选项再人工核对语义，不能复制商业 Office 内置模板、SmartArt 素材或代码。当前机器清单是能力级计划，**不是已完成的标准枚举注册表**；注册表与每项实现/样本在相应 E0/E2 门禁交付。这项工程工作有确定输入和完成条件，不是降低一期范围。

## 4. 对边界项作出的设计裁定

| 输入/行为 | 一期设计行为 | 不作何种虚假承诺 |
| --- | --- | --- |
| `.pptx/.potx/.ppsx` | 导入相应文稿、模板或放映语义；提供这些格式的原生导出档案；默认交付 PPTX | 不是把扩展名随意改写 |
| Strict / Transitional | 两者 Reader；新建默认 Transitional，显式 Strict 档案检查全部能力可表达后写出 | Strict 不可表达的扩展不能丢失后仍称无损 |
| 旧 `.ppt/.pot/.pps` | 独立 CFB/二进制解析器导入为统一模型，保留来源与转换报告；导出升级为 OOXML | 不承诺输出旧二进制格式；现有支持语料全部纳入迁移门禁 |
| `.pptm/.potm/.ppsm` | 读取、静态/动态文稿语义、保留宏部件及关系；导出宏格式须显式请求 | 内核不执行 VBA；不能将移除宏的结果标为原文档无损 |
| OLE | 原生对象身份、嵌入数据/链接、图标/预览、尺寸及关系可编辑；替换载荷是显式事务 | 编辑嵌入 Excel/其他应用的内部文档需要对应领域内核或宿主授权外部程序 |
| 加密 | 宿主提供短期密钥句柄，隔离的格式层解析/写出已登记加密方案，输出有明确加密状态 | 不把密码放进日志/模型参数；未知加密方案不“修复”成空文件 |
| 数字签名 | 检验并报告签名涵盖的原字节；修改后旧签名失效，是否重签由宿主证书服务决定 | 不替用户默签，也不沿用旧签名声称新文件已认证 |
| 在线视频/外链/动作 | 语义和链接保留；宿主明确授权后获取或激活；离线档案要求内容已可合法封装 | 不能保证第三方网站一直在线，也不能以联网缓存冒充离线资源闭包 |
| 云协作/账号/市场/AI 文案 | 接入方提供，内核提供版本/批注/事务/差异等必要基础 | 不把整个 Office 套件的云服务当作演示文稿计算核心的一部分 |

这些边界来自计算核心的职责，不削减已确认的动画、媒体、SmartArt、公式原生能力。Musterwork 没有 Office 式手工编辑器，不要求本期先复制 Ribbon UI；它必须能通过 Agent 编辑、在产品内预览/播放、下载并在传统应用继续编辑。

## 5. 跨应用能力差异

生成请求携带必需能力和目标档案。`compatibility.plan` 在导出前返回每个目标的可表达/已验证/未验证/不支持矩阵。缺失必需能力时阻止该档案成功交付，不能偷偷将 3D、SmartArt 或动画烘焙成静态图片。

共同档案只在 Office/WPS 均验证的能力上宣称共同兼容；应用专属扩展可以存在专属档案，但不能用它们替代一期共同能力的验收。若目标 WPS 构建本身不支持某个 Office 原生功能，应在 E0 给出外部应用证据并明确产品承诺；内核不能通过设计文案承诺第三方软件不存在的编辑能力。

任何范围缩减必须单独记录用户决定及影响。本轮将高级扩展纳入设计，不默认推迟；后续遇到困难不得自行从清单中删项。
