# 互操作、性能与成稿质量验收

v0.4 设计基线。以下数字是**工程目标，尚未测量**；目标应用构建、设备与资源通过锁文件实例化后才构成有效测试档案。不能把本文数字描述为当前性能。

## 1. 兼容目标与锁文件

一期目标应用族：Windows 桌面 Microsoft PowerPoint 和 WPS Presentation；macOS 桌面 PowerPoint 和 WPS Presentation。Linux 为原生计算/Managed 宿主，不据此宣称存在已验证 Linux Office。Web Viewer/Player 覆盖 Chrome/Edge、Firefox、Safari 的受支持版本档案；浏览器播放能力必须实际探测媒体、GPU、线程及内存设施。

每个发行候选锁定 `compatibility-lock`：应用名称/edition/完整 build/channel、OS/architecture、locale、字体及 hash、更新策略、GPU/driver、显示缩放、codec、测试工具及版本。至少一个当前受支持构建为每个目标应用主档案，并记录其上一受支持档案的回归结果；不能只写“Office 最新版”。清单由实际安装/测试得到，本轮不编造构建号。

支持声明是 `(capabilityId, dimensions, targetProfile, fixture set, engine/rules/resources)` 的证明，不是一句笼统“支持 WPS”。没有实际外部证据时 `targetApplicationStatus=not_proven`；内部读写正确不能升级该字段。

共同档案验证普通原生对象及已承诺高级能力。遇到目标应用自身不能表达的高级扩展，报告该精确差异和替代档案；没有用户的范围调整决定，不能以“应用专属已通过”把共同档案缺口销账。

## 2. 不可抵消的质量门禁

| 维度 | 必须通过的断言 | 初始数值目标与限制 |
| --- | --- | --- |
| 内容/语义 | 文字、数据、公式结构、原生对象身份、页序、目标引用与显式样式正确 | 必需内容遗漏、缺字、错误数据、悬挂引用、偷偷栅格化：0 |
| 文件 | OPC/OOXML关系完整，实际导出文件重读，目标应用无修复/损坏警告 | 格式错误、修复提示：0；可合法保留的未知内容完整 |
| 布局 | 字体/字号/换行、基线、bbox、裁剪、连接点、标签/图例正确 | 固定字体与环境：基线/边界偏差 P95≤0.1pt、max≤0.25pt；不允许因容差造成溢出或可读性改变 |
| 视觉 | 同状态、同尺度、同色彩/资源下进行整页及对象区域比较 | 标准后端同输入 hash 可复现；跨后端起始目标 SSIM≥0.995、边缘/文字单独检验；单一总分不可放过小面积错误 |
| 编辑 | 在 Office/WPS 里修改文字、图表数据、SmartArt、公式、动画/媒体参数后回存并再导入 | 每类至少新增和修改一次；不是只点选对象或检查 XML 标签 |
| 动态 | 对事件日志的状态/目标/属性精确一致；关键帧、交互、媒体时序正确 | 合成呈现与计划偏差≤1个目标帧；音画误差目标≤50ms；不丢语义事件 |
| 成稿 | 相同内容任务下的层次、密度、可读性、审美、模板适配和可修改性 | 见第 6 节盲评；不因内部格式正确自动判通过 |

像素比较不替代内容/布局判定；字体抗锯齿和 GPU 差异按已登记区域与规则解释，不允许人工涂掉错误区域。超出阈值可以记录已解释差异申请修订测试档案，但不能由测试代码自动提高阈值。外部应用不是唯一真值：内部语义不变量仍独立成立。

文件编辑动作必须可复现：记录输入 hash、目标 app/build、步骤、保存后 hash、预览/事件证据及语义 diff。若无法自动化某步，保存人工操作和产物记录，不能伪造自动通过。

## 3. 工作负载与运行条件

| 工作负载 | 固定输入结构 | 覆盖目的 |
| --- | --- | --- |
| W-S10 / W-S40 | 10/40 页，每页至少 6 文本域，中英混排、图片、表格/图表分布，指定字体包与像素 | 正常创作全流程、现有 Musterwork 不回退 |
| W-R80 | 80 页外部 PPTX，母版/版式/字体/共享媒体及未知扩展 | 源文件按需预览、包索引与选择性载入 |
| W-C40 | 40 页，密集表格/多轴图表/多层 SmartArt/嵌套公式 | 复杂原生对象与增量依赖 |
| W-D | 1920×1080@60fps，含文字/图形效果、1080p30 视频、音频、触发、跨页及 seek | 实时合成与媒体同步，不以静态场景证明动态性能 |
| W-X | Morph、3D 场景、墨迹重放、SVG/EMF/WMF 与高级图表 | 扩展对象、GPU/纹理和格式交集 |
| W-M | 至少 2 个同时准备/计算文稿，1 个播放，重复取消/切换 | 宿主全局准入与资源抢占 |
| W-L | 100 次 create/open/compile/export/close，另加 60 分钟播放 | 泄漏、句柄/Worker/解码器/GPU 释放 |

每组以公开可分发 corpus manifest 固定内容数量、图片压缩/解码尺寸、字体 face/bytes、媒体时长/编码/码率、输入和总资源 bytes；“40页”不能代表任意复杂度。授权未清晰的真实客户文件仅可用于私有验证，不纳入公开发行。

测量同时记录：冷安装、已安装但冷缓存、热资源/冷文档、热文档增量。不得把下载/字体准备移出图表后仍叫“首次使用”。吞吐/峰值取完整 job；线程 CPU、wall time、IO、编码/重读/QA、宿主/内核/解码器/GPU 分项另报。

基准设备分两层：最低支持层以 4 核 CPU、8GiB 系统内存的桌面级环境为初始目标；性能参考层以 8 核、16GiB 及可用硬件视频解码为初始目标。实际 CPU SKU、频率、电源、OS 和驱动在 E0 登记，**不能用这段抽象配置生成成绩**。Native/WASM、macOS/Windows/Linux 分开报表。

## 4. 时延、内存和体积预算

| 指标 | 初始门槛 | 计量边界 |
| --- | --- | --- |
| S10 完成导出 | 资源已就绪 P95≤5s | 排版、原生写出、seal 后重读、规定 QA 和预览全部包含 |
| S40 完成导出 | 同口径 P95≤8s | 不将未完成质量检查伪装后台成功 |
| 单页编辑反馈 | P95≤300ms | 受影响模型/布局/预览完成；完整 ZIP 导出另报 |
| 工作峰值 | S10≤256MiB；S40≤512MiB | 宿主+核心增量、源包、解码、缓存和输出；GPU/共享进程明确分列并给出合计 |
| 主线程 | 无大于 50ms 的办公计算任务 | 浏览器主线程不做排版/ZIP/视频解码循环 |
| 取消 | 请求到可见停止 P95≤200ms，强制终止≤2s | 协作取消检查点、Worker/进程强杀、暂存清理/提交 CAS 验证 |
| 动态播放 | 参考设备 P95 帧工作≤16.7ms、P99≤33.3ms，持续丢显示帧率<1% | 1080p W-D，全效果开启；事件不丢失；记录预热和 seek 分别成绩 |
| 长运行 | 无持续增长；稳定段结束后的存活账本回落到基线+预算内缓存 | 缓存给定上限，不能拿“这是缓存”解释单调上涨 |
| 静态核心传输 | 完整静态能力 WASM 压缩≤15MiB | 所需 JS glue/wasm/图形/塑形全部计入，字体与内容资源另列 |
| 静态原生安装 | 核心+CLI/宿主必要依赖未压缩≤30MiB/架构 | 这是安装口径，下载压缩值另列；系统库前提显式列出 |
| 完整演示发行 | E0 给出静态、动态/3D、codec、字体、完整离线包五项及总计 | 当前没有可信固定 MiB 门槛；E0 必须形成可审查预算，禁止用静态包冒充全功能大小 |

绝对最小体积与所有字体/codec 离线并不是同一个安装成本。基本安装允许按需模块，但离线模式必须一次备齐承诺闭包；第一次使用相关功能的下载、初始化、缓存和磁盘占用都计量。优化不能偷换为“依赖用户已经装好了某商业产品”。

每个时延样本至少 30 次独立测量，明确预热，报告分布与异常，不只最佳值；长运行和媒体测试采用连续窗口另报。资源大小、DPI、QA 流程、并发数改变即新档案，不沿用旧达标结论。

## 5. 容量与防失控

文档模型不硬编码 40/80 页上限；准入档案维护页数、对象数、文本量、ZIP 解压 bytes/比例、单媒体/总资源、关系深度、数学/图表/SmartArt 复杂度、CPU deadline 和内存限制。每个限制有单位及错误码，不允许整数截断。

Musterwork 旧能力至少保留 40 页创作/可编辑导入与 80 页只读预览。新媒体档案初始设计允许最高 1GiB PPTX 流式输入/输出，语义 JSON 32MiB、资源条目 10000；这些是准入目标，不是已被存储/网关证明可行的限制。MW 全链路在 E3 必须验证对象存储、上传、ContentRef、解析器及下载的相同上限；不成立时属于待解决交付缺口，不能默认回落到旧 128MiB 后宣称完整媒体支持。

大文件采用 readRange、可回读 spool 和有界解码窗口，不允许因 1GiB 文件上限分配 1GiB 线性内存。并发准入先算资源 reservation，实际超过限额可暂停可恢复任务或失败当前执行；不能挤垮宿主后再靠浏览器回收。

## 6. 专业成稿验收

至少 30 个固定 brief，覆盖商务汇报、数据分析、教育、技术、品牌、长中文、双语和外部模板改写；至少三种内容密度。与选定成熟产品使用相同输入材料、时限、编辑要求和目标文件格式，记录使用的模型/模板/资源，不把模型差异混成格式内核质量结论。

盲评至少 5 名独立评审，按可读性、层次、对齐间距、图表表达、风格一致、内容完整、修改便利分别评分；提前固定非劣目标，例如 5 分制配对均值差的 95% 置信区间下界≥-0.25。样本不足以得出结论时增加样本，不能把“不显著”说成“完全等同”。内容错误和不可编辑仍是硬失败，不被审美均分抵消。

内核、模板/约束库和 Agent 工作流分别归因；评审发现的错误须落实为对象/规则/模板/工作流修复与回归。只展示精挑的封面不构成专业成稿验收。

## 7. 发行门禁

候选发布必须同时满足：能力注册表无未说明缺项；全部必需维度/档案通过；跨端/增量/来源保留通过；真实 Office/WPS 回存；预算及完整依赖闭包；Musterwork 全消费者/历史/故障；独立第三方 Agent 接入；许可/SBOM 与可重现构建。

release manifest 绑定 engine、document/operation schema、feature registry、rules、MCP profiles、Skill digest、Plugin manifests、ABI、字体/codec 包及证据集合。升级采用版本协商、已签名发行摘要与原子安装；旧任务保持已固定版本或明确重新计算，不让中途升级产生混合证据。

CI 的结构/渲染检查可自动阻断；外部应用与专业盲评有独立证据责任人。任何未完成门禁均保持 `not_proven/blocked` 的准确状态，不靠手动改成 passed 放行。
