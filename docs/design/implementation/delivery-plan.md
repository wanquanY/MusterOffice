# 实施顺序、风险实验与完成条件

v0.4 设计基线。本页是实施合同，**不代表本轮已运行 E0 或启动内核开发**。工期不用于缩减质量目标，阶段用于尽早暴露不可行的技术路线。

## 1. D1 与 E0 的关系

D1 固定产品目标、模型/操作责任、接口、能力分解、实验输入/输出和通过条件；E0 用最小纵向实现裁定组件、规则、目标应用交集和真实预算。不能要求未经实验就“证明全部方案可行”，也不能以仍有实验为由永远不定义实现合同。

本轮已形成 v0.4 实施基线。D1 的正式签入需要检查：各文档无互相矛盾的行为；实现工作包均有能力/测试 ID；旧资料不再被当作当前合同；E0 可获得合法样本和目标应用环境。依赖/构建/性能数字由 E0 产生并填锁文件，未填项不是已通过。

## 2. E0 必须交付的实验

每项使用固定语料及资源清单，输出原生文件、重读投影、目标应用回存、运行账本、build/SBOM 和结论。实验脚本与合法样本应可复跑，截图只是证据之一。失败需定位具体组件/算法并修订设计，禁止静默换成 HTML 或商业转换服务。

| 实验 | 输入和动作 | 路线裁定及失败条件 |
| --- | --- | --- |
| E0-1 文本/字体 | 中文/英文/RTL/复杂脚本/竖排/emoji、主题继承、变宽文本框、无本机字体新增中文；Native/WASM 输出再由 Office/WPS编辑 | 塑形/布局/嵌入三层分别通过；完整字体/依赖体积记录；错误换行/缺字/禁止编辑任一发生均失败 |
| E0-2 原生对象/格式 | 多母版占位符、表格合并、多轴图表含空值/负数/日期；更改系列和主题，导出回存 | Reader/Writer/工作簿/缓存一致，编辑身份保留；检查自读自验之外的目标结果 |
| E0-3 SmartArt/数学 | 多种布局算法、节点增删/重排/换布局、长文本、嵌套分式/矩阵；目标应用继续编辑 | 原生模型与派生绘制一致；能覆盖算法类而非单张样图；不得转普通组或图片 |
| E0-4 动态/媒体/扩展 | W-D 加 Morph、3D、墨迹；点击/路径/文字分步、媒体书签、seek/跨页；Web/Native 运行 | retained 渲染与时钟可行、无逐帧 PNG；目标应用支持交集明确；全功能包与codec许可/大小计量 |
| E0-5 来源/大文件/取消 | 80页共享部件、未知扩展、二进制旧文件、加密样本、流式大媒体；每阶段取消、损坏输入 | 选择性写回、强终止、全资源释放、预算与离线闭包；任何破坏合法未改内容或半成品发布均失败 |
| E0-6 接入/提交/发行 | 本地 stdio、远程 HTTP、只支持基本 tools 的客户端、嵌入 MW 模拟提交；重复/断线/取消竞争 | 同一 OperationService/Job、无双 owner；完整依赖尺寸；第三方无需 MW 源码；并非只返回一句“连接成功” |

选型对照使用相同 workload、同精度、同字体、同输出与 QA：Rust 为主混合方案为默认；必要时对照同职责的纯 Rust 组件/更窄 C++ 边界。若必须改变已确认主体语言，提交证据和新 ADR，不由性能直觉决定。

E0 结束要产生：`dependency-lock`、`feature-registry` 的高风险项、`compatibility-lock`、字体/codec 清单、基准设备/预算、IDL 初版、ABI 初版、首个纵向 public bundle。无法得到足够证据的路线保持未通过，不能用架构图替代。

## 4. 阶段验收

- **E1：纵向骨架。** 同一文稿包含文字、图形、原生图表、SmartArt、公式、动画、音视频，通过一次修改、写出、重读、预览/播放与宿主候选提交；功能目录可以尚未全覆盖，但没有另一个静态模型。
- **E2：能力完整。** 所有一期子能力及注册枚举有实现/样本/适用维度结论；组合、极限、模糊测试与各运行平台通过。目标应用差异不能隐藏。
- **E3：替换候选。** 新公共发行包与 MW adapter 组合通过全部消费者、历史转换、40/80页回归、大媒体、外部编辑、取消/恢复及第三方接入。
- **E4：正式替换。** 新任务默认新内核，干净环境不需旧引擎，历史仍可读/可继续编辑，明确可回滚范围，全套证据绑定本次发行。

## 5. 失败处理与停止条件

若核心语义无法映射为目标原生对象，修复模型/Writer 或提交真实的产品边界冲突；不能在适配器图片化。若性能失败，按资源账本定位解析、复制、排版、绘制、编码或验证，不能从统计中删除失败阶段。若包过大，审计完整传递依赖和模块，不隐藏强制运行依赖。

核心崩溃/内存破坏/数据损失/半成品发布是发行阻断；未知目标应用能力、未澄清许可证或未完成必要迁移亦阻断相应支持声明。阻断的是发行与验收，不等于删除已有文件、终止独立设计工作或自动获得范围缩减授权。

## 6. 从需求追到实际证据

路径固定为：用户目标/ADR → Fxx.yy capability → IDL/模块/算法 → fixture IDs → T/A/B/I/MW 回归 → target/profile/build → evidence digest → release manifest。每项不适用需理由，每项失败保留诊断，每次能力变更更新全部受影响索引。

机器 Schema 检查只证明 JSON 合同形状及有限引用一致性；不是 Rust 内核测试，也不是 Office/WPS 认证。本轮设计验证报告须如实区分这三类状态。
