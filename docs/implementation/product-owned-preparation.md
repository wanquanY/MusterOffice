# Musterwork Invocation 资源接入准备器

2026-09-27：接续 [Invocation 预写额度与授权](product-invocation-content.md)，将实际创建、编辑、导出准备器与恢复元数据接入原 Runtime 的受管存储。`MW:` 表示产品仓库相对路径，产品私有源码继续保留在原仓库。该阶段不开放新 Agent 工具或切换默认 PPT 路由。

## 强制存储边界

`OfficeMutationEngine`、`OfficeExportEngine` 的构造参数已改为 `Arc<dyn InvocationContentStore>`。普通 `ContentStore` 不能作为替代，也没有空预留实现。原宿主为当前 Attempt/Invocation 注入 provider；共享计算名额仍由原 Runtime 配置，没有新增任务 owner 或队列。

创建和编辑完成内核计算及产品元数据校验后，一次预留模型与计算收据，再开始第一笔写入。导出在全部输出计划通过检查后，一次预留全部资产与 bundle、收据、最终检查报告和产品清单；两页测试文稿共 16 个输出身份。输入资源不冒充当前 Invocation 的输出；输入读取集与原提交时的重新授权仍然保留。

预留失败不会写入部分计划。完全相同的重试使用相同身份和已有额度；不同元数据形成不同不可变身份，继续计入同一 Invocation 的生命周期额度。保留输入/输出局部预算和共享存储预算，两者分别约束材料准入与持久输出，不宣称其中任何一个等同于进程内存或整机磁盘上限。

## 原提交命令的元数据准备

`MW:apps/agent-runtime/crates/runtime/artifact/src/presentation_office_prepare.rs` 提供 `prepare_office_tool_commit`。它接收原 RunContext、Attempt、Invocation、类型化原生操作，以及宿主工具选择的结果 Schema 和 JSON 数据。这里不定义新的公开工具结果协议，也不改变原提交 owner。

函数先编码恢复封套与结果，按现有演示工具的 64 KiB 限制检查结果，并执行完整提交命令校验；之后一次预留 checkpoint 与 Tool result。每个身份绑定 Invocation、用途、媒体类型和实际字节摘要。写入经过有界流式端口，再打开最终存储校验，取消或存储失败不返回可提交命令。恢复封套继续使用已有 `/2`、`/3`、`/4` 格式和各自解码规则。

准备成功只说明私有元数据可用。Tool 完成、草稿/Artifact 版本、Ledger、幂等收据仍由原事务提交；重试已提交的命令返回旧收据。已经结束的 Tool 不能重新取得写入权。

## 正式引用保留与兼容性

原生提交的 `presentation_content_refs` 现在同时保留 Tool result，补齐原有模型、资源、输出和 checkpoint 的保留集合。使用原有精确 ContentRef 校验及同一事务；失败整体回滚。不另建“已转移”布尔值来复制现有正式引用事实。

旧普通预写数据与旧恢复封套仍保持兼容。本阶段没有把所有历史原生提交一律改为必须具有 v186 资源账户，也没有把“没有账户”定义成新工具的受管写入成功证明。未来生产工具入口必须组合受管准备器和原提交器；若收紧提交来源约束，须采用明确的版本合同，并验证旧待恢复命令的迁移。

本阶段没有新增数据库迁移或依赖版本。固定 SDK 和导出 worker 保持不变；核心仓库同期的语义/渲染改动不因这些产品测试而获得验证。

最终创作回归 60 项通过、12 项显式跳过；其中 6 项导出准备与 3 项原生提交测试已使用固定 worker 另行执行，全部通过，3 项旧外部环境测试仍未执行。相关库单元 71 项、三个生产库严格 `--no-deps` Clippy、全工作区 all-targets 编译通过；工作区保留 9 条既有无关测试导入告警。没有运行完整产品测试套件。
