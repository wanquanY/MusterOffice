# 来源图表的标签继承与数据绑定

本阶段把真实图表的单点、系列和绘图区标签声明解析为可追溯的计算计划，供后续数字
格式化、文字级联与自动布局使用。计划包含数据角色及来源，不是最终显示字符串，
也不代表完整图表或整页模板已经可绘制。Musterwork 的人工验收候选保持固定。

## 计算入口与结果

Rust `compute_pptx_chart_labels` 接收来源文稿、对象、plot 物理序号和显式
`seriesIndex` / `pointIndex` 目标。来源 SHA-256 必须匹配；结果同时保留 chart 部件摘要。
JSON/WASM 入口为 `compute_pptx_chart_labels`，CLI 为：

```text
mo-cli pptx-chart-labels request.json source.pptx
```

配置标识为 `source-chart-label-bindings-v1-draft`，请求和响应具有生成的 JSON Schema
及 TS 类型。Rust 调用方持有输入、预算与取消；核心不读取任意路径、访问网络、获取
系统字体或保存业务任务。CLI 的文件读取属于薄宿主。本阶段没有新增正式 Agent 工具。

成功返回 `planned`。每个标签保留以下信息：

- 由高到低的真实声明序号，逐字段解析的开关、位置、分隔符和 numFmt。
- 原生文字属性、图形属性与布局根，供共享计算管线继续解析。
- 系列名、分类、数值、气泡大小或百分比的数据绑定；数组顺序不承诺显示顺序。
- 自定义 `c:tx` 的真实引用、删除状态和图例键是否可显示。

自定义富文本不会被拼接成普通文本框；缺省字体也不会自动变成 Arial。
声明中缺失的显示开关列在 `unresolvedFlags`，不能把 `planned` 当作完整可绘制许可。
位置、格式、主题字体、文字及布局各自仍需要后续语义解析。

## 覆盖、缺省与格式来源

单点覆盖系列、系列覆盖绘图区，独立字段分别解析。元素缺失、元素存在但没有 `val`、
显式 false 保持不同。当前草案按 ECMA CT_Boolean 解释存在但缺少 `val` 的元素为 true；
没有元素时不推测应用缺省。此规则不是对所有历史 Office 版本行为的校准声明。

numFmt 以整个元素选取：单点存在 numFmt 时，其缺少的 sourceLinked 按标准默认为
true，不能继承下层元素的 false。显式不链接的格式码优先；否则数值绑定采用来源
缓存的单点/缓存格式码，仍属于 `sourceCacheSnapshot`，没有刷新外部工作簿。
百分比不会套用数值缓存格式；缺少明确不链接的格式时，保留格式未决。

分隔符保留完整字符数据，包括空字符串。六个开关全部已解析后才应用缺省分隔符：
通常为逗号；饼图仅显示分类和百分比时为换行，不额外添加空格。删除标签不产生组件；
只有图例键开关时不凭空创建一个独立图例键。

未知属性、未知标签内容、扩展及非法布尔值返回带物理来源的诊断。被上层覆盖的非法
声明仍需通过校验。Office 限制必须在系列下出现的标签内容，不在绘图区下悄然接纳。
缺失、错误、多级缓存等尚未解析的必要数据均明确报错，不用空字符串或零代替。

依据包括 ECMA-376 Part 1 §21.2.2.49、§21.2.2.121、§21.2.2.166、§21.2.2.189，
[微软 dLbls 说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/953e5879-8008-4d14-a8bc-fbe39d848e0a)
及[图例键显示条件](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/b0d0713f-ac98-44b4-b4ee-2a490237c3ac)。
这些规则的实现测试与 Office/WPS 实机互操作是不同门禁。

## 精确比例与有界计算

饼图/圆环图的百分比直接来自原始十进制缓存。共享 `mo-charts` 的权重归一化同时服务
扇区计算和标签比例；标签不从已取整的扇区角度反推百分比，也不经过二进制浮点。
每个所需系列只计算一次整数分子与公共分母，原始数值的拼写和符号仍单独保留。
负数默认拒绝，只有调用方明确选择绝对值策略才使用其大小；总和为零没有定义百分比。
其他图表类型的百分比分母语义仍待实现，当前返回明确诊断。

准备阶段一次索引系列、缓存点、标签组及单点。组的单点身份与继承样式分离，每个
标签只查自己的声明链，不重复扫描全部兄弟标签。已有解析部件可直接复用于完整
图表编译器，避免逐标签重读 PPTX。取消和预算失败不返回部分计划。

默认最多 4,096 个请求目标、65,536 个索引缓存点、8 MiB 逻辑保留预算；后者是固定
结构成本加字符串字节，不是堆内存或 JSON 序列化大小的精确测量。来源解析预算与
比例的点数、数值字节、扩展十进制位数预算另行生效，比例成本在全部系列间累计。
预算在大整数扩展前检查，不通过缩减文本、舍弃精度或省略标签降低成本。

## 验证与未完成项

[证据摘要](../reviews/evidence/2026-09-30-source-chart-label-bindings.json)记录相关 Rust
测试、30 份完整原生/WASM 响应与独立 ZIP/XML/Fraction 核对；包含两个真实模板圆环图。
4,096 个原生单点标签的测试检查反向物理顺序、稳定 idx 和相邻标签覆盖隔离。
独立验证器主动篡改开关或分母，确认不能把错误结果当成通过；它不支持独立 MCE 投影，
也不校验最终数字显示或文字布局。旧扇区、几何、来源图表和 Draw IR 响应另做逐项对照。

两个真实模板最终绑定到三个单点的“仅数值”声明和单点文字属性根，系列“分类＋百分比”
没有误入结果。真实模板文件、文本、图片不进入公共测试目录，原文件保持不变。

继续完成：数字格式、图表样式/主题文字级联、图例文本与项目、塑形与自动布局、碰撞与

本批未解除完整 graphicFrame 准入，未改变产品运行候选，也未新增渲染、性能或安装包
