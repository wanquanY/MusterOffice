# 原生导出暂存所有权与恢复

2026-09-27：接续[嵌入式导出](embedded-export.md)和[产品受管准备器](product-owned-preparation.md)，补充宿主及 worker 异常退出后的物理暂存恢复。这是原生宿主能力，不改变文档语义、产品任务状态或 Artifact 提交权。

后续并发取得/释放锁的有界等待及 MCP 断线取消见[本地薄 MCP](thin-mcp.md)。它处理多个活跃计算正常竞争 registry 的情况；下面的显式解锁修正仍用于确保单个锁的生命周期准确，两个问题分别验证。

## 所有权协议

`mo-native-io` 的 `ExecutionSpoolRoot` 在受保护的宿主根目录下管理 `.mo-executions-v1`。根目录及祖先由宿主配置和保护，不来自 Agent JSON；参与者存活期间不能由外部程序改名或移除该目录。

`registry.lock` 排他锁串行化目录创建、清理和恢复。每个执行目录中的 `participants.lock` 由父进程与 worker 分别持有共享锁；只有能取得排他锁的执行目录才能回收。PID、文件年龄、租约到期和业务终态均不作为进程已停止的证据。父进程异常退出时，仍在工作的子进程继续保护输入和输出；worker 结束后，父进程保留的候选继续保护结果读取器。

worker 加入时先持有 registry 共享锁，再验证执行目录并取得参与者共享锁。清理器在 registry 排他锁内确认没有参与者，关闭文件句柄后删除目录，避免 Windows 上假定锁定文件可以删除。目录创建和回收包含真实目录同步；无锁文件的半成品只能在该协议命名空间内按中断创建/清理处理。registry 丢失且已有执行目录时，不重新创建可能与旧锁分裂的所有权。

文件打开拒绝符号链接，Windows 分支拒绝 reparse point。未知名称、非目录及执行目录符号链接不被自动回收；子目录内的链接不会作为外部文件树遍历。旧 `mo-execution-*` 非受管目录属于旧协议，不能通过年龄猜测后直接删除。

## 有界恢复与实际导出

单次扫描最多 1024 个命名空间条目，显式恢复每批最多删除 64 个目录，并报告存活、回收、未知项和剩余可回收项。每次新建执行还尝试回收最多 16 个孤儿目录。扫描不会因前面的存活目录用尽删除批次而跳过后续孤儿。

原 `NativeExporter::prepare` 使用受管执行目录。registry 竞争以可取消的短间隔重试，并与 worker 共用此次执行时间额度；不会在宿主线程中阻塞等待文件锁。操作系统文件 I/O 本身不宣称具有硬实时上限。显式 `recover_spools` 供宿主启动和既有维护流程调用，竞争时返回 `WouldBlock`，由宿主调度下一次尝试。

`NativeExportCandidate` 在结果读取器关闭后释放所有权。显式清理返回实际错误，析构仅尽力清理；锁竞争或中断遗留的目录由后续恢复处理。目录数量限制不替代产品输出额度、总磁盘保留或进程内存预算。

新 worker 必须接受 `--spool-dir <execution> --execution-lease-v1`，且在第一次协议读取或暂存写入前取得自己的参与者锁。旧 worker 会拒绝额外参数，新 worker 也拒绝旧参数形式和非受管目录；不能把不持锁的旧 worker 混入新清理协议。wire 文档计算格式仍为 `/1-draft`，这里改变的是私有进程启动协议。

## SDK 与依赖边界

SDK 生成器保留 Cargo 的平台条件生产依赖，排除根和目标表中的开发依赖，并继续拒绝目标构建依赖。独立消费例子的清理验证接受持久 registry，仍要求没有任何执行目录或输入暂存残留。

Unix 文件打开标志使用已锁定的 [rustix 1.1.5](../../components/rustix/component.json)，关闭默认特性、仅启用 `fs/std`；文件锁使用 Rust 标准库。已核对 crates.io 归档摘要、上游声明和四份许可/版权文本，开发采用选择 MIT。这不代表整个软件的发行许可已经确认，也不把原生宿主依赖引入纯计算/WASM 链路。

## 验证范围与产品后续

### 2026-09-27 直接计算入口回归中的锁生命周期修正

后续完整回归发现：仅依赖 `File` 析构关闭句柄，可能让重复/继承描述符延长 registry 锁的寿命。确定性测试保留同一文件描述的重复句柄，在原作用域结束后立即重新申请锁，修正前稳定得到 `WouldBlock`；并发进程测试另有可复现的偶发失败。该行为与 [Rust 1.92 文件锁的释放语义](https://doc.rust-lang.org/1.92.0/std/fs/struct.File.html#method.unlock)一致。

现使用私有 `FileLock` 将锁绑定到协议作用域：正常路径显式解锁并返回错误，异常路径析构尽力解锁。registry 与参与者锁都遵循同一规则；各参与者仍独立打开文件，因此一个参与者退出不会解除其他活跃 worker 的锁。没有延长等待、放宽测试或通过重试掩盖错误。确定性别名测试及活跃 worker 保护测试通过，包含真实进程中断的库测试连续 16 轮通过；完整后续证据归[直接计算入口](direct-computation.md)。本次运行范围仍为 macOS，不宣称其他操作系统实机验证。

以下为本阶段原始验证记录；新计算 worker 的 wire `/2-draft` 由[计算合同拆分](computation-boundary.md)另行定义，不能将旧 `/1-draft` 当作当前调用合同。

测试覆盖真实进程终止、父进程死亡时的真实导出 worker、批量恢复、并发初始化/创建、保留读取器、符号链接、registry 丢失、取消/超时及旧参数拒绝；正向结果仍由真实渲染器生成，并检查实际 PPTX、PNG 和资源文件。
