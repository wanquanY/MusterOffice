# 原生表格接入公共页面与播放

2026-09-29。本阶段把真实 `p:graphicFrame/a:tbl` 的表格背景、合并起始格填充、可确定的边框和单元格文字接入公共来源页面。它延续[单元格文字准备与保留绘制](table-text-page.md)，没有把表格改成一组伪造来源形状，也没有用图片代替可编辑表格。完整表格兼容、全部一期功能及 Musterwork 替换门槛仍未完成。

## 共享管线

页面预检区分普通图形与真实表格，最后按原 `spTree`、母版及版式顺序合成。一个原生对象可以拥有多个绘制目标；普通形状仍只有一个，表格的目标是原背景、合并起始格或原单元格的一条边。各目标保留真实对象、单元格、填充来源、声明位置与描边几何。`SourcePagePaintBinding` 的可选 `region`、`tableStroke` 只在表格目标中出现；旧形状不会新增空字段。

所有目标共用原填充、描边、坐标误差、图片入口、透明度分组和场景构建器。表格按背景、单元格填充、边框、文字顺序绘制；文字编译器对原对象只调用一次，再按合并起始格遍历其真实文字框。表格整体的透明度只合成一次，避免边框与文字重叠位置被重复衰减。

单元格渐变使用其实际区域，不能采用整张表格的尺寸或把渐变原点固定在表格左上角。线性、矩形和圆形渐变复用原画笔计算；区域精度界进入相同坐标认证。合并区域只填充一次，RTL 改变区域位置，不改变渐变在物理坐标中的方向。

播放入口仅接纳已识别的真实表格，不将其他 `graphicFrame` 当成表格。当前表格可进入移动、显隐和透明度采样；保留文字仍按同一原生对象查找全部单元格框，各框的裁剪和容量保持独立。表格的旋转／缩放等尚未接通的变换继续由现有放置预检拒绝。

## 预算与事务

公共页面在解析填充、构建网格及调用任何图片／文字组件前，先为全部可见表格累计预留物理单元格、网格步骤、单元格 ID 字节和坐标字节。文字与绘制准备使用同一个预算实现，但各自持有自己的阶段配额；这不表示各阶段已经共享同一份网格。

当前页面绘制阶段最多预留 65,536 项表格来源查询，每格预留六条边与一个填充，另计每张表格背景；`noFill` 声明同样消耗查询预算。该值是有界计算上限，不是已测容量或性能指标。实际绘制仍进入共用的整页绘制次数、渐变色标、路径及误差检查。色标配额与填充目标数量分开，不能把一个有多个色标的渐变误算成只有一个颜色槽。

失败、取消、来源冲突和未支持声明不返回部分页面。晚出现的文字错误会在第一张表格调用字体组件前被发现。不同调用不会复用可变权限、任务或存储状态。

## 边框范围

本阶段绘制可由当前共享描边引擎表达的纯色边。相邻两侧的工作颜色及完整已支持描边几何一致时，共享边只绘制一次；合并内部边不绘制，合并起始格的对角线使用合并区域。

相邻两侧声明不同（包括一侧 `noFill`、另一侧可见）目前返回带有两个真实边目标的 `TableBorderConflict`。没有套用 Word 的边框冲突规则，没有任意选左边／上边，也没有把冲突静默抹掉。原有含冲突的自有样本继续保留为失败测试；成功语料显式使用一致的边框，二者不能混为完整支持。

八组新的自有冲突校准表格已经生成并通过结构校验，WPS 实测尚未完成。`cua-driver` 守护进程缺少 macOS 辅助功能与屏幕录制权限，本次尝试已停止；没有跳过权限门槛，未把该尝试记为兼容通过。

## 验证范围

[阶段证据](../reviews/evidence/2026-09-29-table-page-verification.json)绑定最终源码、命令、实际输入和输出。自有字体只用于确定性计算测试，不代表商用字体、中文字形或排版质量验收。

- 公共文字／资源页面：合并单元格、RTL、三种渐变和多个表格；保留原生对象／单元格身份及绘制顺序。
- 实际原生时间树：表格移动、显隐、淡入，保留播放与逐帧重新编译比较；再次回到先前时间获得同一像素，保留帧无字体组件调用，整表淡入与一次整体合成的参考相符。
- 原始 XML、PPTX 页面 XSD、真实单元格边界和声明序号独立核对；线性渐变另用声明尺寸和既有 Office 插值公式计算像素参考。
- Native Worker 与 Rust WASM 通过公开入口处理原始 PPTX；比较完整响应及像素，不只重放预编译场景。
- 原普通文字／图片页面的静态与保留播放回归，继续与封存语料及历史返回比较。

最终验证通过 451 项相关来源／格式／编译测试、28 项字体集成测试；最后的输入边界修正后重新执行 13 项表格专项、严格 Clippy、工作区检查及 Native/WASM 构建。Schema／TS 与 SDK 依赖边界检查通过。

10 份自有 PPTX 通过整页 XSD 检查，276 个线性渐变像素通过独立参考；14 次静态公共请求和 18 帧保留播放的完整响应及像素在 Native/WASM 一致。旧语料的 64 次静态请求和 90 帧播放既保持跨端一致，也保持封存历史响应与像素摘要。

这些验证不等于 Office/WPS 显示一致、外部编辑往返或产品替换验收。测试耗时不作为渲染性能、RSS 或安装包体积结果。

## 仍需完成

边框冲突优先级及合并边界语义仍需目标应用校准。图片／图案单元格填充、渐变描边、完整线型及其他尚未支持的画笔保持明确诊断；没有通过忽略它们获得成功。声明行高与自动行高、网格与外框尺寸协调、合并行的内容适配和完整表格变换仍需实现／验证。

页面绘制、边框、填充和文字目前仍分别建立部分来源／网格上下文；本阶段共享的是计算引擎与预算代码，并未完成一次绑定供所有阶段使用的性能重构。后续应在来源上下文层解决重复工作，不增加另一套表格专用渲染器。

Musterwork 接入继续限定在既有 `codex/musteroffice-integration` 独立 worktree。本阶段不升级产品固定 SDK／Worker／播放材料，不切换默认 PPT 引擎；原主工作区由用户使用。完整高级内容、历史迁移、P00、E0、E1–E3 和产品端到端替换门槛保持开放。
