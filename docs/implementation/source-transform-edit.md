# 来源对象变换编辑

状态：P03 原生来源编辑的开发实现，2026-09-26。已接通现有变换声明的 Native/WASM/CLI 编辑与候选回读；完整结构编辑、Agent 服务、高级内容和 Musterwork 替换仍未完成。

## 接口与含义

`SourceTransformEdits` 包含不可变源包的 `expectedSourceSha256` 和一批修改。目标使用部件名与原生对象 ID；根形状树也使用其原生 ID。接口不接收 XML 序号、属性名称或字节偏移。对象身份在每次操作中重新从实际源包绑定，物理位置仅在格式适配器内部使用。

每项修改提供完整的 `expected` 和 `replacement` 直接声明值，包含位置、尺寸、组合对象的内部坐标及尺寸、旋转和两个翻转标志。它们不是已经经过版式继承或组变换的显示坐标。EMU 使用规范十进制字符串；旋转保留原生的有符号 int32、1/60000 度单位，允许多圈，不擅自归一化。

这些值对象描述完整状态，字段省略与 `null` 都表示没有显式声明，不表示“沿用旧值”；调用方应从已查询的直接声明构造完整预期和替换值。旋转/翻转的 `null` 表示删除显式属性，与零/false 不同。位置/尺寸的节点存在性目前必须保持；缺少 xfrm、需要新增或删除 off/ext/chOff/chExt 时，返回未实现映射，后续由结构编辑器处理。当前接口不会把继承结果直接写成子对象的显式声明。坐标和尺寸按本仓库固定的 ECMA-376 XSD 原生范围验证，不裁剪、不饱和。

实际入口为 `mo_pptx::source::edit_source_transforms`、`mo_kernel_api::edit_pptx_transforms_json`、WASM `edit_pptx_transforms` 及：

```text
mo-cli pptx-edit-transforms edits.json source.pptx new-output.pptx
```

新 JSON Schema 与 TS 类型由同一 Rust 定义生成。它仍是开发运行时接口，不等于 MCP/Skill/Plugin 已分发，CLI 文件名也不进入计算核心。

## 原子性与保留

修改前验证包摘要、目标唯一性和所有旧值；真正的修改使用[属性底座](source-attribute-overlay.md)保留原始编码和未触及的 XML 字节。语义相等的 no-op 保留原属性拼写，整包没有变更时字节相同。跨对象和跨部件修改在同一候选中计算，任何失败都不返回局部结果。

读取器记录内部来源绑定，按部件共享对象绑定表，避免为每个对象重复存储部件路径。编辑器检查原始物理 XML，而不是只相信 MCE 筛选后的属性和子节点。兼容分支中的变换，以及变换内部的未知/被忽略属性或子内容，仍需要多表示协调；当前拒绝修改但允许验证后的原样 no-op。无关对象的兼容分支和变换之外的未知内容保留。

修改版式/母版声明后，先在预期来源索引中重算受影响的继承结果，再写出并重新打开真正的候选包。文本与变换编辑共用候选验证职责：只从实际输出取得新的字节长度与摘要，语义预期来自事先计算的结果；全部已支持的投影字段必须吻合。宿主继续负责授权、持久化/CAS、取消和提交；CLI 沿用先暂存、同步、回读，再无覆盖发布的流程。

## 当前验证

- 636 项 Rust 测试、严格 Clippy、rustfmt，以及 83 份 Schema/TS 同源检查。
- 90 个新接口 Native/WASM 调用：65 次成功、25 次预期拒绝。涵盖形状、图片、连接线、组合、表格所在 graphicFrame、根形状树、跨部件、版式继承、编码/BOM、属性缺失/清除、数值边界和过期请求。表格内容保留不等于实现表格语义编辑。
- 65 份成功结果经过 Expat 的独立物理定位和 lxml/libxml2 语义核对；50 个 XML 部件发生预期变化，1,315 个未改部件及压缩条目保持原字节。420 个输出部件通过官方 XSD；故意保留未知/MCE 结构的探针不伪装成原始 XSD 通过。
- 121 次此前实际 PPTX 来源检查和文字编辑回归结果不变。CLI 新文件发布、拒绝覆盖、失败不留结果及临时文件检查通过。

## 本阶段编辑后绘制发现的问题

以下保留原阶段的失败事实。后续[共享渐变坐标精度](gradient-coordinate-precision.md)直接修复画笔计算，并用新的构建和独立像素参考验证；不回写或抹除本阶段的原始失败报告。

另选两份自有原生渐变页面，通过新接口分别平移、水平/垂直翻转和旋转 90 度。2 个原始页面及 8 个编辑后页面的实际 Native/WASM 元数据和像素一致。独立地置换原始像素后，检查共 960,000 个编辑后像素：中心焦点的 4 例完全相等；偏心焦点的平移、水平翻转、垂直翻转和直角旋转分别有 4、4、1、3 个像素不同，最大通道差为 1。

这些差异明确记录为未解决的渲染精度问题，没有通过放宽阈值计作精确通过。平移的批次只有画笔和路径原点改变，渐变场参数保持逐字相同。独立 float32 展开逆矩阵计算复现了位置敏感性，而该样本中的先减原点计算保持一致。当前绘制器使用 SkMatrix 的局部逆矩阵路径，这是后续追踪和修复的重点；独立标量诊断尚不能证明每个通道差异的完整原因，也不是已经接入的新着色器。

原有[圆形渐变误差合同](elliptic-source-pages.md)明确没有覆盖着色器逆矩阵运算及统一颜色误差；本次实际编辑链路把这一缺口变成可复现输入。后续必须在共享绘制层修复并重跑变换不变性、数值参考和性能验证，不能在 PPTX 编辑器补偿颜色或回写额外图像。

## 后续与复现

本阶段脚本为 `transform-edit-checks.py`、`transform-edit-fixtures.py`、`transform-edit-parity.mjs`、`transform-edit-reference.py`、`transform-edit-render.mjs` 和 `transform-edit-numeric.py`。最后两个工具保留未通过的独立精度结论，进程正常结束不表示精度门槛通过。产物位于 `.codex-work/transform-edit`，封存后不覆盖。

Rust 与生成类型已变更；C++ 绘制及全部依赖锁未变，继续使用 `.codex-work/elliptic-fast/component`。模块体积由阶段证据按实际产物记录，不推断完整功能成本或 Musterwork 安装包大小。本轮没有页面性能、内存、启动或安装包的新测量。

完整目标继续要求结构编辑、多表示同步、图表/SmartArt/公式等高级对象、动画媒体播放、生产宿主、Agent 分发以及真实目标应用和 Musterwork 验收。固定方向渐变的 WPS 观察仍等待先前告知的系统权限；本轮没有重试或绕过权限门槛。
