## 实现与职责

`tools/mo-mcp` 是独立锁定的 Rust workspace，复用既有 `mo-operation-service` 与 `mo-standard-host`。13 个工具涵盖能力、Schema、创建/读取/编辑/导出、上传准备/状态/封存/取消、资产描述和任务查询/取消。输入从 `HostRequest` 的真实 Schema 投影，仅移除由工具名固定的分发字段、限定动作并裁剪不可达定义；结果保持同一 `HostResponse`，同时提供 structuredContent 与 JSON 文本镜像。工具按配置权限过滤并稳定排序。

数据库、principal、scope、权限及 renderer 路径/摘要只来自可信启动配置；不接受工具参数覆盖。CLI 二进制数据通道也读取同一配置，不使用另一套默认全权限身份。能力和执行仍由同一 SQLite owner 持有。新增的原生会话资源端口转发既有权限检查；没有把路径、数据库或 MCP 依赖引入计算核心。

接入说明、配置与运行命令见[开发适配器 README](../../tools/mo-mcp/README.md)。rmcp 3.4.0 与 Tokio 等沿用已锁定的实验候选，SDK 默认 features 仍关闭。新增 base64 0.22.1 仅用于标准资源 blob 编码，版本、归档摘要及 MIT/Apache 两份原文见[组件记录](../../components/base64/component.json)。本机解析依赖图有 106 个 registry 包，包含目标条件分支；这不是实际链接包数，也不是完整传递许可审核。SDK 的混合许可历史 notice 保留，生产分发审核继续开放。

## 资源与二进制

固定资源公开适配器限额和十份同源 Schema。导出成功后才返回已公开资产的资源链接。资源 URI 绑定 originating server 内的 scope/principal 命名空间，不能代替每次读取时的宿主授权，也不映射为任意文件路径。

不超过 1 MiB 的资源以标准 base64 blob 返回，实际字节回读后核对 SHA256。更大的资源返回传输描述；操作者可用同一二进制的 `append` / `read-asset` 子命令传输，上传分块上限 256 KiB，下载结束核对退出状态、长度和摘要。工具不会自行执行命令或获得文件路径权限。这是本地原生数据通道，远程上传/下载和产品附件授权仍需接入。

## 并发、取消与退出

传输限制为 4 MiB 输入、16 MiB 序列化输出（不含换行）、八个在途/待写请求，以及独立的八个通知。计算桥接和控制桥接各有 1–8 个许可，在 `spawn_blocking` 前尝试取得；忙碌时不另建无界等待队列。许可随实际阻塞调用结束释放，异步等待者被取消不会提前释放许可。Tokio 另留两个 blocking 位置给标准输入输出；原生文档执行池保持独立预算。

输出写入/flush 前不释放请求预算，写入有十秒期限。旧协议取消后，仍在运行的 handler 保留预算；返回后保留有限的取消 ID 历史以拒绝复用，避免迟到响应错误关联。响应已交给传输后，较晚的取消不能把尚未写出的响应提前回收。现代协议普通请求与旧会话取消语义不混用。

取消 MCP 等待不调用 `jobs.cancel`；真正业务取消仍是明确工具调用。进程退出在事件循环外等待阻塞调用并关闭原生执行池，排队任务仍存于数据库。上述上限不等于严格峰值 RSS、跨进程全局并发或所有计算的强制终止预算。目前无效/歧义/超限输入采用终止连接并返回非零退出的开发策略，标准 parse/invalid-request 错误恢复仍需完成，不能声称完整协议一致性。

## 验证范围

最终 release 服务完成 167 次实际请求，分别运行 2025-11-25 initialize 和 2026-07-28 逐请求元数据档案。每代均检查 13 个工具定义与十份实际 Schema、类型化创建、原子标题编辑、历史版本、素材上传封存、真实 worker 导出、幂等重试、已提交任务取消、资源回读，以及重连查询。客户端收到 accepted 后离开，再连接能得到同一任务的成功回执。拒绝权限、另一作用域和未知工具均有负例。

两次导出各含两页和 12 份资源；MCP blob、同权限二进制下载与声明摘要一致。大于 1 MiB 的资产只返回描述，完整数据通过原生通道核对。独立 lxml/Pillow/python-pptx 检查两份实际下载 PPTX 的 20 个相关 XSD 部件、每份 15 个原生对象/八段文字，以及四页 PNG 的尺寸、颜色声明和明确像素位置。两代协议下载的 PPTX 字节和页面像素一致。样本使用自有合成字体，不能代表复杂商业文稿或 Office/WPS 编辑、播放、回存验收。

十项适配器测试覆盖输入/输出预算、重复/null ID、慢速写入、取消竞争、通知生命周期，以及真实 SQLite 写锁阻塞时取消异步等待的许可与持久任务行为。另有 61 项现有宿主回归通过；原生 renderer 由实际 MCP 导出执行，不把普通回归中忽略的集成测试计作通过。五类实际进程输入拒绝、二进制通道无权限及非法配置检查通过。严格 Clippy 与格式检查通过。

验证中保留了失败记录：首次解析测试发现 SDK 会把 `id:null` 降为通知，已在类型分发前校验原始信封；代码审查发现响应发送与取消回收存在竞争，已改为同步领取响应状态并新增测试。独立检查脚本先后误把未显式默认化的输入等同于存储模型、把取消上传当作成功状态、把现代缺失资源错误码当作旧版错误码；按实际合同和官方版本要求修正，未改变生产行为来放宽断言。[现代资源错误要求](https://modelcontextprotocol.io/specification/2026-07-28/server/resources)使用 `-32602`，旧档案保持 `-32002`。

本机 aarch64-apple-darwin、Rust 1.92.0 的锁定 release 适配器为 12,766,768 字节，包含宿主和关联文档计算代码；外置绘制 worker、字体、媒体、平台包装不在其中。不把它与仅有 Schema 的旧探针直接相减作为 MCP 开销，也不作为最终安装包估算。本轮没有测量产品级吞吐、启动时间或 RSS；每次桥接仍创建控制连接，后续应在真实负载下评估连接及 renderer 身份校验成本。
