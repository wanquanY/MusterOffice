# 原维护任务的原生模板压力计算

2026-09-28，Musterwork 独立集成 worktree 将[固定压力计划](product-template-stress-plan.md)和[实例计算](product-template-instances.md)接入原 `native_stress` 维护阶段。使用原 Agent Loop、工具日志、内容库与 SQLite Run；MusterOffice 公共 SDK 继续只负责文稿计算，没有新增业务权限、任务、存储或页面。

本阶段实现有限参数案例的实际计算与提交验证。完整视觉质量、Office/WPS 编辑往返、`native_verify`、自动上传协调和目录发布仍未完成，不能据此宣布 PPT 功能已完整替换。

后续阶段已接通显式原生策略的后端编排、页面身份及跨内容库传递，见[后端阶段实现](product-template-coordinator.md)。本文以下保留本阶段原始测试与字节记录，最终质量和完整产品链路仍未验收。

## 输入与执行

维护输入必须封存上一阶段真实接受的 `native_define` 检查点，绑定同一 compilation、generation、来源摘要、模板包、字体、设置和编译档案。模板引用必须属于当前封存的内容集合。来源重新存储时可拥有新的内容 ID，真实字节摘要、长度和媒体类型必须一致，模板包保持不变。

`stress_resource_cases` 属于接入产品封存的输入，默认空集合仅适用于无资源参数的模板。每个替换材料必须是当前输入集合中的精确引用；SDK 计算入口再检验资源定义、允许的类型及实际字节。模型不能临时增加路径、网络资源或任意绑定值。

| 原工具操作 | 压力阶段行为 |
| --- | --- |
| `prepare_input` | 从封存模板生成不可变计划，返回 `files.stress_plan` 与必需案例数 |
| `read` | 使用已有有界读取器检查计划、诊断和预览 |
| `run_case` | 只接收 `plan_ref` 与 `case_id`，由计划生成完整绑定和实际资源引用 |
| `prepare_stage` | 根据计划和真实工具结果核对全部必需案例，生成阶段文件 |
| `submit` | 独立重建阶段证明，完全一致后才完成原维护 Run |

定义与压力计算复用同一个原生请求、额度、取消、输出保存和预览管线。每次计算在读取文件前检查 1024 项、总计 256 MiB 及单文件 128 MiB 的原有容量。产品适配结果记录 SDK 实际接受参数的绑定摘要，不修改公共 SDK、worker 或文件格式。

## 完成证明

案例绑定顺序为参数基线、案例覆盖、可选参数省略。实例文档 ID 绑定计划摘要和案例编号。每个成功结果必须同时匹配：

- 同阶段真实 `run_case` 原始请求、计划引用与案例编号；完整原生请求摘要一致。
- SDK 实际接受的绑定摘要、模板摘要、来源身份和命名空间关系；绑定参数集合一致。
- 真实快照、实例回执与交付回执的文档 ID、revision 和 semanticDigest。
- 全部实际输出的摘要、长度、媒体类型，以及每个逻辑 SDK 资产对应的存储文件。

验证器一次逆序扫描工具日志，每个编号选择最近一次有效结果。重复同一案例不会增加覆盖数；漏掉案例、错误请求或失败渲染无法完成。`prepare_stage` 与 `submit` 都执行验证，不接受模型自报的通过标志。阶段身份也必须与当前封存任务一致。

接受范围明确为 `finite-parameter-instance-computation`。SDK 的结构、布局、原生编辑、播放和目标应用声明保持原样；有限计算完成不会自动提高质量等级。

## 实际证据与边界

本轮 17 项相关测试通过：2 项真实原生维护专项、12 项维护库测试、3 项原维护流程回归。维护、快照和接入库严格 Clippy 通过，执行前后源码清单一致。

测试使用原 SQLite 维护任务、脚本模型提供方和真实原生 worker。先完成定义任务，再启动同一模板的压力任务；脚本仅选择操作与案例，不提供计算结果。压力任务执行 14 次模型请求、10 次实际计算，包括 1 次计划、8 个必需案例和 1 次重复案例。提前提交和计划外编号被拒绝，12 类证据变造或缺失被拒绝。

独立 Python 检查器读取原内容库导出的文件，核对实际请求/绑定摘要，并复用 ZIP/XML 检查验证 8 份 PPTX、16 张预览和 96 个 SDK 逻辑资产。来源基线不改变部件，其他 7 个案例只改变目标文字；共 161 个非目标压缩部件保持字节一致，未修改页面预览保持一致。此样本阶段文件为 25029 字节，导出 107 项内容引用；这不是大规模容量或性能结论。

仍使用前阶段自有合成字体，字符覆盖不能证明中文、阿拉伯文或复杂语言排版质量。本次真实 worker 验证只覆盖一个必填文字参数的 8 个案例，资源、颜色、变换与组合类型的实际执行验收仍待补齐。详细命令、源码摘要和保留的失败记录见[验证证据](../reviews/evidence/2026-09-28-product-template-stress-maintenance-verification.json)。

现有 512 KiB 阶段文件、8 MiB JSON 和原任务容量仍有效。超出容量明确失败，不删除案例或把部分覆盖标为完成。当前逐例工具流程不代表已经验证 8192 个案例的调度能力；后续需要在原任务所有权内完成高效批量调度、进程恢复和大模板容量验证。

自动上传仍由原协调器选择旧流程，原生阶段的后端推进、跨内容库材料映射、`native_verify` 和原目录版本事务尚未接通。本轮没有切换 stable、新增运行依赖、发布软件包或测得发行体积；完整高级 PPT 与 P00/E0–E3 继续按目标推进。
