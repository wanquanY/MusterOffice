# 原生模板目录提交与读取

2026-09-28，Musterwork 独立 worktree 已把原生模板最终检查点接入原目录版本事务。通过验证的原生包可以形成可选择的版本，并经产品原有带签名的 Agent 接口读取。自动上传的原生环境选择、实际完整产品会话与 PPT 替换验收仍在实施。本阶段只修改产品适配；内核、SDK 和 worker 未改变。

## 字节与计算边界

目录准备从同一代、完整且不可变的 `native_define`、`native_stress`、`native_verify` 检查点取得明确的私有文件引用，逐项核对所属用户、长度、媒体类型和实际 SHA-256。读取有总量、单文件和对象数量上限，不把报告或复核 JSON 中的任意嵌套引用当作新的读取授权。

原生包、文档快照、模板定义、原始 PPTX 和资源均保持 SDK 产生的精确字节。来源交付、固定字体与设置、文档身份、页面顺序、检查对象及逐页预览必须一致。目录预览还核对真实 PNG 头中的尺寸。全部目标仍要求已测量且装得下；视觉复核不能覆盖容量失败。此处不重做排版、重写 PPTX 或新增全局质量声明。

模型请求、响应的规范证据由原 Runtime 独立提交检查持有；后端检查封存结果与实际文件的绑定。目录中保留最终检查点摘要及明确的报告、对象和复核引用。原 Runtime 审计材料的完整保留与清理链路仍需后续端到端验收，不能由目录中存在一个通过字段推定完成。

## 原事务与产品目录

HTML 和原生模板共用原有带租约和版本检查的写入事务。准备文件后、实际写版本前，再次检查任务取消、租约、代际、最终检查点、整份来源覆盖、模板所属用户、归档状态、当前版本和最近上传意图。版本记录、任务完成、当前选择与完成事件在一个事务中提交。进程在最终检查点之后重启，可以复用已完成计算；重复或并发提交不会生成第二份版本。

个人模板成功后进入自己的可选目录。运营模板先保留为私有草稿；只有原管理接口明确发布并核实素材权利，才成为公共模板。原生公共发布复用原封存检查点和有界文件校验，拒绝依靠被篡改的目录描述取得通过。测试中的发布只发生于隔离数据库，没有向真实目录发布。

带签名的 `PresentationTemplateSourceService` 已能直接消费上述事务生成的版本，返回精确包与完整资源。版本或摘要不匹配、错误用户、归档模板以及旧 `author@3` 消费原生包均被拒绝；原生消费继续使用候选 `author@7`。当前稳定版本未因此切换。

以上目录、权限、存储、任务和管理发布均属于 Musterwork。MusterOffice 继续只提供计算和薄接入，不增加相应产品系统。

## 验证

[验证证据](../reviews/evidence/2026-09-28-product-native-catalog-verification.json)记录源码摘要、完整命令、日志摘要和输入。最终 147 项不同测试通过：60 项原生与交付测试、68 项旧目录及编排回归、19 项真实 PostgreSQL 测试；11 个本阶段相关源码文件通过严格 Ruff 检查。

- 使用上一阶段真实 SDK 的定义、压力与最终产物；适配的仅为隔离测试任务的外层请求身份。Runtime 完成回执使用可信端口测试替身，不能当作整套后端与 Runtime 联机证明。
- 入库后通过真实 gRPC、生产签名校验和原目录查询读取。私有对象存储使用带摘要校验的内存提供者。
- 八类存储字节改动、八类读取后状态改变及目录证明变造不能写入版本或公开模板。新增重启测试确认已完成计算无需重复执行。
- 隔离 PostgreSQL 16.15 验证并发仅写入一个版本和完成事件、取消与租约恢复、目录竞争，以及数据库自身的版本和检查点不可变约束。测试容器已清理，未连接产品数据库。
- 首轮两处测试夹具错误已修复：缺少目录发布表，以及在进入待验证逻辑之前违反检查点状态约束。没有关闭数据库或生产验证来获得通过。保留既有 294 条后端弃用告警。

未新增性能或发行体积结论；测试耗时包含数据库和夹具开销。固定 worker 仍为 ARM64 Debug 文件，不能代表桌面发行包。

## 后续接入

上传入口的生产组合当前仍从旧引擎获取环境。下一步需要让候选原生路径从实际执行宿主发现并固定 SDK 渲染器、字体和设置，沿原上传与维护任务继续运行，随后验证真实完整会话和审计材料生命周期。历史迁移、播放与高级内容、Office/WPS 可编辑往返、Native/WASM、性能及发行体积各项门禁继续开放。
