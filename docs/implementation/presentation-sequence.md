# 原生动画分组与 Agent 作者操作

2026-09-28：新增 `PresentationSequence::compile` 和原子操作 `setPresentationSequence`。Agent 可用点击组、顺序批次和并行效果描述已实现的动画，由内核生成可播放、可导出的显式时间树。独立 Musterwork worktree 接入同一 SDK 与播放包；完整一期替换目标仍未完成。

## 结构调查与外部编辑

前一阶段的任意叶节点依赖，在三种受控 WPS 回存实验中均丢失节点引用。此次使用自有六矩形文件，在 WPS Office 12.1.22553 的动画面板中实际创建“上一动画之后”，发现其生成新时间分组、保留 `afterEffect` 编辑身份，并把组的开始偏移写在分组层级。

进一步做了三组区分性检查：

- 原生文件经过内核读取、重建与导出后，在 WPS 把首个动画从 1 秒改为 2 秒，后续组的偏移从 1000 自动变为 2000 毫秒。
- 先使 2 秒和 1 秒两个效果并行，再让第三个效果“上一动画之后”，WPS 保存的下一组偏移为 2000 毫秒。这组样本依赖并行组完成，并非列表中最后一个叶节点的结束。
- 用新的 `setPresentationSequence` 生成文件，在 WPS 把并行组中的 2 秒效果改为 3 秒，后续组自动从第 2 秒移到第 3 秒；六个效果的编辑身份保留。内核重新读取这份回存文件并通过精确时间断言。

以上是当前 WPS 版本、自有缩放样本的观察。微软的[动画开始与速度说明](https://support.microsoft.com/en-us/powerpoint/set-the-start-time-and-speed-of-an-animation-effect)说明面向用户的开始选项，不能据此推断所有底层时间图的分组规则。本次没有完成 PowerPoint 的对应操作，也没有证明所有 WPS 动画、延迟、触发器和多行为预设都按相同方式编辑。

## 作者合同

`setPresentationSequence` 位于现有 `presentations.apply` 的操作列表中，沿用输入快照、实际基础版本、原子计算、取消和变更回执。Rust SDK 从 `mo_embedded_sdk::timeline` 提供完整作者类型；JSON Schema 和 TypeScript 类型由 Rust 生成。普通调用不引入文件路径、数据库、权限或人的页面。

输入的 `groups` 是显式点击组列表。只有第一组可使用 `automatic`；`next` 组由宿主传入的下一步导航事件激活。每个组包含顺序执行的 `batches`，每个批次包含并行 `effects`。批次延迟从前一批次的整体结束计算，效果延迟从本批次开始计算。空列表用于清除该页时间线；空组、空批次和重复效果 ID 均拒绝。

编译器复用行为时钟，准确计算有限／分数重复、重复时长、速度与自动反向的有效持续时间，用并行效果的最晚结束决定下一批次的开始。所有运算使用有界有理数；无法在内部时间字段或 PPTX 毫秒字段中精确表示时返回错误，不取整。末批可无限重复，后继顺序批次不能从一个无界批次推导开始时间。

生成的树保留主序列、点击组、批次和原生效果容器；预设身份分别为点击、与上一动画同时、上一动画之后。调用者的行为 ID 保留，自动分配的容器 ID 避免碰撞。生成前核算全部节点，计算中检查取消，最后使用统一时间树验证器。

这是**整页时间线替换操作**。计算结果保存显式时间树，不额外保存另一份可能失配的作者程序。修改作者序列时应重新提交完整序列，内核重新计算偏移；不能只改已降低为时间树的某个时长字段而期待隐式重排。它不逆向猜测任意原生树，也不重写旧 `setTimeline` 的节点依赖；带不可变源绑定的文稿仍拒绝没有协同保留实现的时间线替换。

当前效果为已实现的旋转、缩放和显隐。完整动画、多行为预设、转场、媒体、SmartArt、公式及源文稿语义编辑继续开发，不因新作者接口而缩减范围。
