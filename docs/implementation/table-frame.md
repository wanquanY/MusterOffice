# 原生单元格布局与共享文字裁剪

2026-09-29，接续[原生表格文字计算](table-text.md)。本阶段实现真实单元格的声明尺寸、边距和锚定，并将水平/垂直裁剪贯通普通文字静态页面与保留式播放。单元格框计算仍是 Rust 库能力；原生表格整页绘制尚未启用。Musterwork 继续使用[独立接入工作区](product-worktree.md)，完整一期及替换验收目标不变。

## 单元格来源与计算

[CellTextBodyResolver](../../crates/mo-presentation-source/src/source/text/body/cell.rs)绑定实际表格对象和物理单元格文字体。`tcPr` 的四边距、文字方向、垂直锚定、居中锚定及水平溢出有独立来源和默认值：左右 91440 EMU、上下 45720 EMU、水平文字、顶端锚定、不居中锚定、水平裁剪。显式属性指向真实 `tcPr` 元素序号；缺失属性使用带对象和行列身份的 `CellDefault`。其他属性和 autofit 继续读取本格 `bodyPr`，复用主题与显式配置默认，不继承形状占位符文字体。

这些单元格属性与默认值来自 ECMA-376 Part 1 的 21.1.3.17 及 `CT_TableCellProperties`。当前计算配置将上述八项及其单元格默认值置于重复 `bodyPr` 属性之前；这种冲突组合、主题继承和全部目标应用行为仍需 Office/WPS 校准，配置保持 draft。类型读取和测试一致不能代替应用实测。

[TableFrameCompiler](../../crates/mo-presentation-compile/src/source_table/frame.rs)共享一次验证后的网格、真实单元格文字与普通文字框计算。几何和文字绑定共用同一所有者映射；不复制单元格成虚拟形状，不重复构建整份网格。合并原点使用完整合并区域，覆盖格的文字仍保留供查询和编辑，但单独要求绘制覆盖格会返回明确诊断。

框内尺寸使用已有精确坐标运算和原生边距；RTL 来自实际网格，锚定复用同一排版引擎。结果保留边距前后的矩形、坐标误差界、实际文字体来源和原始段落编号。`FrameCapacity` 新增可省略的单元格身份，同一对象的不同单元格可以分别报告；普通形状没有此字段。计算、诊断和容量均保留未裁剪文字及墨迹，不把被遮住的溢出当作已适配。

当前行高采用文件声明，未实现根据文字自动增高、跨行合并高度协调、全部 autofit 或垂直文字。每格预算与取消已贯通；后续完整页面必须汇总整页所有格的文字、路径、裁剪和内存预算。

## 静态页面与播放共用裁剪

[FrameClip](../../crates/mo-presentation-compile/src/source_frame/clip.rs)记录原生文字区域及需要限制的轴。[页面裁剪](../../crates/mo-presentation-compile/src/source_text_page/clip.rs)使用同一场景裁剪树包住字形、下划线和删除线。单轴裁剪的另一轴覆盖完整墨迹和装饰，并通过当前采样仿射的逆矩阵计算设备抗锯齿余量；没有任意设置一个巨大矩形。

保留式播放只存局部轮廓、绘制项和有限裁剪元数据，每帧使用当前放置重新构造并认证裁剪，不重新整形文字。裁剪附属于文稿边界，旋转、翻转和组合变换沿已有领域规则处理。精确退化的仿射使填充面积为零，零缩放关键帧合法绘制为空；不对它求不存在的逆矩阵，也不改变动画状态或溢出测量。新增元数据计入保留文字的逻辑字节预算，场景路径/裁剪仍受共享场景限额控制。

普通文字页面的 `clip` 原来明确拒绝，现在可通过已有公开静态与播放入口计算。仍未实现的 `ellipsis` 保持明确诊断。表格 GraphicFrame 页面入口未因这一项能力而提前放行。

## 验证与解释边界

本阶段的命令、失败尝试、输入、产物和源码摘要见[验证证据](../reviews/evidence/2026-09-29-table-frame-verification.json)。

424 项来源/格式/编译测试、30 项真实原生文字与绘制测试、5 项 Kernel 单元测试通过；新增 10 项测试。严格 Clippy、工作区全部目标编译及 Schema/TS 检查通过。64 次静态请求、90 帧保留式播放的 Native/WASM 完整响应和像素相同；47 份裁剪文稿通过 376 次 XSD 部件验证，公开请求/响应通过 323 次 JSON Schema 校验。此前 26 份表格导出与编辑产物字节保持，历史读写回归继续通过。

- [来源测试](../../crates/mo-pptx/tests/table_body.rs)验证显式声明、重复 bodyPr 属性、单元格默认、覆盖格独立来源、摘要绑定、取消和预算。
- [真实 HarfBuzz 框测试](../../crates/mo-harfbuzz-sys/tests/table_frame.rs)验证合并区域、共享网格、RTL、三种锚定、保留溢出和原始段落诊断；[独立 XML 校验器](../../tools/verification/native-table-frame-readback.py)对 8 份 PPTX 的 9 个计算框重新计算网格/边距，并进行 8 次 XSD 验证。
- [真实 Skia 像素测试](../../crates/mo-harfbuzz-sys/tests/text_clipping.rs)覆盖三种裁剪、旋转/翻转/非等比组合、装饰、文稿边界和从零尺寸放大；相同时间的保留式与重新计算结果逐字节比较，包含向前播放及回退采样。
- [跨端验证器](../../tools/verification/text-clipping-parity.mjs)直接调用 Native Worker 与 WASM 的静态入口及持久播放会话，比较完整响应和像素，再与上述实际 Rust 计算产物对照。单元格框自身尚无公共 Native/WASM 页面计算对照。

独立像素检查同时验证字形/装饰的路径和变换未因裁剪改变、受限区域外无墨迹、非边缘颜色保持，以及非受限轴上的内容仍存在。当前 Skia 在裁剪前处理边，并在抗锯齿和合成路径中量化覆盖率；有/无裁剪的边缘像素并非全部字节相同。检查明确使用一个设备像素的覆盖邻域及一个颜色色阶的合成舍入范围，不声称两者边缘逐字节一致。Native/WASM 和保留式/重算之间仍要求完整像素相同。以上均不是目标 Office/WPS 视觉验收或性能测量。

下一步将原生填充、边框冲突和合并边缘规则接入共享 GraphicFrame 页面绘制，完成整页预算、行高协调、实际表格 Native/WASM 渲染及 Office/WPS 编辑往返，再在独立 Musterwork worktree 同步升级固定 SDK、Worker 和播放材料并验证产品链路。本阶段没有改动产品固定材料或默认引擎，没有新的安装包体积或完整性能结论。
