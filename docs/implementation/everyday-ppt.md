2026-10-01，按 [ADR 0008](../decisions/0008-everyday-presentation-acceptance.md)推进。
用户确认 Musterwork 已接入并正常产出 PPT。本页区分内核能力、本轮改动和下一次用户验收；

## 本轮改动

补齐作者模型及 `compose` / `append` 便捷输入的段落行距、左右边距和首行缩进。
它们进入现有文档与事务、共享布局和原生 DrawingML；导出的文字继续可编辑。
没有重新建立布局引擎，没有用空格模拟缩进，也没有调整内容或字号来掩盖溢出。

`text.style` 可直接声明：

```json
{
  "lineSpacing": {"kind": "percent", "value": 150000},
  "leftMargin": "254000",
  "rightMargin": "127000",
  "indent": "-127000"
}
```

`100000` / `150000` / `200000` 分别表示单倍、1.5 倍和双倍。
固定行距使用 `{"kind":"exact","height":"317500"}`，例中为 25 磅。
长度为 EMU，12700 EMU = 1 磅；固定行距必须精确表示为 0.01 磅，非法值直接拒绝。
缩进相对于段落左边距，负值表示悬挂缩进。完整 Document 在每个 paragraph 的 `style`
设置相同字段；便捷输入则统一作用于该文本对象的所有段落。省略字段保留原继承行为及
旧文稿序列化形式。文本框的 `insets` 与段落边距仍是不同概念。

同时补齐 `append` 在冻结旧宿主中的明确拒绝分支，恢复整仓穷举匹配编译；
新计算功能继续使用现有纯计算入口，旧持久宿主不新增动作或更改合同。

产品采用时还修复了独立发布包的交付校验：原先用 Cargo 包版本构造和校验
`Versions.engine`，将 SDK 重新打包为开发版本后，会误拒同套 Worker 的文件。
现在由交付合同明确保持 `MusterOffice/0.1.0` 兼容标识，未知标识仍拒绝；
具体实现继续由 Worker SHA-256、渲染 profile、设置和全部内容摘要精确绑定。
没有放宽文件或实现身份校验，也没有要求产品绕过接收器。

## 用户测试清单

| 日常场景 | 这次应观察的结果 | 当前边界 |
| --- | --- | --- |
| 制作 3–8 页中文汇报 | 标题、正文和页面顺序正确；能预览、下载 PPTX | 构图和审美仍需实际检查 |
| 指定修改原文稿 | 仅修改指定文字、位置或样式，其他页和对象保留 | 来源导入文稿的修改范围小于原生创作文稿 |
| 多段正文 | 换行、字号、对齐、行距和缩进符合要求 | 真正的自动项目符号/编号、自动缩字及多栏尚未完整支持 |
| 图文混排 | 图片清晰、裁切正确、原始图片保留，无错误资源预算失败 | 图片采样按已有预算执行，未承诺任意容量 |
| 常用形状与基础表格 | 形状、文字、表格保持原生；表格数据和合并格正确 | 表格使用完整文档/事务，便捷输入暂不提供表格声明 |
| 保存后继续修改 | 恢复同一文稿并再次导出，已有排版属性不丢失 | 需由产品实际保存、恢复和提交链路验收 |
| 在 PowerPoint/WPS 打开并编辑 | 不弹修复提示，文字和表格可编辑，保存后内容仍在 | 需要用户在目标应用测试，不能用内核自检替代 |

原生图表完整合成、SmartArt、复杂公式和完整媒体/动画目录继续按反馈推进；
图表当前查询和局部绘制能力不代表能制作或呈现任意整张图表。
模板也按实际支持内容准入，不能将某个模板的文本修改成功推广为任意模板兼容。

## 验证入口

- 模型范围与精确表示：`crates/mo-presentation-model/tests/paragraph_layout.rs`。
- 便捷输入展开与拒绝：`crates/mo-presentation-operations/src/compose/tests.rs`。
- SDK 修改、保存及恢复：`crates/mo-embedded-sdk/tests/compose.rs`。
- 原生导出/读取声明：`crates/mo-pptx/tests/author_plan.rs`。
- 真实字体布局及像素：`crates/mo-harfbuzz-sys/tests/author_paragraph_layout.rs`。
- Native/WASM 对照：`tools/verification/author-paragraph-parity.mjs`，使用显式运行材料及
  上述 Rust 测试输出的四份文件；不覆盖历史证据。
- 独立分发后的实际导出：`tools/release/check.py`，使用真正的 registry 包而非源码
  path 依赖，执行公开 SDK 示例并验收落盘字节。具体参数见[发布检查](../../tools/release/README.md)。
