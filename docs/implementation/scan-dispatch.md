# 扫描分派与保留状态

状态：2026-09-27，分派重构及本阶段画质、取消、生命周期检查通过；局部吞吐改善有限，完整性能与替换验收仍开放。承接[任务内状态复用](scan-task-storage.md)，见[源码与产物证据](../reviews/evidence/2026-09-27-scan-dispatch-verification.json)。

## 实现边界

[`scan-continuation.patch`](../../components/skia/scan-continuation.patch)将无需保留局部资源的分派与真正可暂停的计算分开：

- `SkRasterClip` 的空裁剪直接完成，BW 区域直接返回子任务；AA 裁剪仍由独立 continuation 持有 `SkRegion` 和 `SkAAClipBlitter`，直到扫描结束或取消。
- 原有小矩形快速绘制分支在创建扫描 continuation 之前执行。原算法、适用条件、裁剪和抗锯齿不变；细矩形、非矩形以及大尺寸路径仍进入原来的 mask/RLE 扫描，局部资源继续跨让出点保留。

快速矩形原本就在单次推进中同步完成，没有扫描让出点；此次没有将可暂停的绘制改为同步。分配器、任务句柄、失败隔离、ABI、Rust/TS API、依赖与许可证均未改变；没有增加第二套绘制算法、调整精度或更新画质参考。输入资源、调度、权限、存储和 UI 仍由接入产品负责。

万个小矩形的状态链由六层减至四层，每个对象减少两次状态构造/销毁及对应转移。由于上一阶段已经复用状态块，整个任务的 step 内 malloc 只从 **10,007 降至 10,005 次**，累计请求字节从 **3,422,776 降至 3,420,224**；不能把两万个较少的状态构造称为两万个较少的 malloc。该计数仅来自 macOS 测试程序对成功 malloc 的拦截，不包含 calloc/realloc、分配器保留空间、峰值内存或 RSS。

## 验证

新增[分派边界生成器](../../tools/verification/scan-dispatch-corpus.py)生成 144 份原创输入，覆盖：裁剪后宽度 3 的两侧、宽度 32/33、mask 存储 1024 字节的两侧、细长形状、矩形/菱形、整数/小数定位、BW/AA/空裁剪。每份包含后续独立对象，确保前一个分支完成后正确恢复裁剪并继续绘制。全像素参考来自引入保留式扫描之前的固定程序，另独立检查末尾不透明标记。

- 连同既有输入，共 **773 份不同输入**；执行清单含两份重复控制输入。Native/WASM 各通过 **2,325 次**分步状态与全像素比较，WASM 另核对 775 次同步调用。
- ASan/UBSan 共 **3,128 次**结果比较，实际提前取消 **2,321 次**。包含新增边界的 580 次执行/458 次取消，以及四种扫描场景、七个中段位置的 28 次取消重绘。`detect_leaks=0`，不宣称 LeakSanitizer 或物理 RSS 验收。
- WASM 对相同四类扫描场景完成 28 次中段取消后复用，任务句柄与 TS 输入借用归零；这不证明内部堆或浏览器物理内存完全回收。
- 在原生小矩形路径上分别令四个剩余状态帧的真实 malloc 返回空，均返回分配错误 2、零输出，后续 begin 返回失效实例错误 4。范围限于这四个申请位置，不是全部分支、实际物理内存耗尽或 WASM OOM 验收。
- Node/Chrome 各核对 71 个播放帧的全部像素及元数据；Chrome `153.0.8010.53` 隔离上下文另通过 30 次步骤间取消，26 个独立 WASM Worker 的所有权与故障隔离检查通过。
- 15 步所选门禁通过，包含严格格式/Clippy、119 份 Schema、TS、原生绘制/播放/导出/CLI 集成；未声称运行全部 Rust/MCP 套件。

收尾时规范了 unified diff 的空白上下文表示，消除补丁文件的空格检查误报。最终补丁经同一 `--fuzz=0` 工具重新应用，生成的七个上游 C++ 源码/头文件与三端已构建输入逐字节相同；原补丁、等价性记录与最终补丁分别保留。Rust 摘要检查正确拒绝了旧构建记录；重新编译适配层并绑定最终补丁后，原生生产 archive、WASM 和 JS 产物字节保持一致，最终 15 步门禁通过，拒绝记录保留。重编后的 sanitizer 产物另核对 628 次边界/压力/中段取消结果；它们与原检查重叠，不计为新的独立输入。运行时计时发生在格式收尾之前，绑定相同生产字节。

## 耗时与体积

同一计时程序分别链接扫描之前、上一阶段复用、本阶段分派这三版固定组件；Apple M4 Max、36 GiB、macOS 26.2。每个版本/输入/预算组合各七个新进程，轮换并反转顺序，其他本阶段构建与测试结束后测量。结果与冻结像素逐字节一致，上一阶段与本阶段的推进次数相同。以下为累计 step 耗时的样本中位数，单位 ms：

| 输入 | 工作单元 | 扫描之前 | 任务内复用 | 本阶段分派 |
| --- | ---: | ---: | ---: | ---: |
| 高精度坐标回退渐变 | 1 | 170.938 | 168.628 | 172.476 |
| 高精度坐标回退渐变 | 4096 | 173.446 | 176.652 | 172.107 |
| 继承组渐变 | 1 | 1.248 | 1.344 | 1.275 |
| 继承组渐变 | 4096 | 1.274 | 1.303 | 1.257 |
| 一万个小矩形 | 1 | 3.923 | 4.949 | 4.906 |
| 一万个小矩形 | 4096 | 4.292 | 4.978 | 4.743 |

小对象相对上一阶段的样本中位数约改善 0.9%/4.7%，相对扫描之前仍多约 25%/11%；改善有限，不能认定吞吐回退已解决或推导通用加速比例。不同批次存在波动，不用本次数据覆盖上一阶段记录。复杂渐变在工作单元 1 下最长 step 中位数为 0.797 ms，工作单元 4096 则仍会连续计算约 172 ms；推进预算和外部响应时限必须分别验证。

上述无字体、进程内缓存为空，系统页缓存和整机负载未控制。step 计时不含 begin 验证、输入复制、取出结果、销毁、IPC 和步骤间时钟间隙；报告另保留包含启动/IPC 的进程耗时。它不是全页 P95、实际 PPT 播放吞吐、端到端取消或资源回收验收。

最终 Skia WASM **2,385,884 字节**，比上一阶段增加 **30 字节**，9 项导入/24 项导出集合不变。离线播放包两次产物完全一致：60 文件、清单外 **14,409,430 字节**、归档 **4,146,234 字节**。包内只有 `runtime/mo-skia.wasm` 改变；`releaseCleared=false`。这些数字不代表完整内核或 Musterwork 安装包。
