# Musterwork 原生已发布版本恢复

2026-09-28，在独立产品 worktree 继续实现历史 Artifact 接入。本阶段新增产品 Runtime/SQLite 的已发布版本查询与恢复事务；尚未给活动 Agent 工具增加 `open` 动作，不能据此宣称用户历史入口已完成。

## 恢复对象与版本

恢复来源是指定 Artifact 版本实际提交的原生候选，不是原草稿的当前 head，也不是重新解析导出的 PPTX。查询在同一读快照内核对租户、会话、Artifact 版本、原调用、候选持久摘要、清单引用及完整依赖列表；未发布的准备结果不能作为来源。候选查找复用生产者原有确定身份，使用主键定位，不新增候选扫描或数据库迁移。

新草稿保留原文稿 ID、内核 revision/semantic digest、页面、资源和来源 PPTX，产品草稿 ID 与修订序号重新建立，Artifact 基线绑定指定已发布版本。原草稿后来做出的未发布修改、甚至放弃原草稿，都不会修改恢复来源。随后实际 SDK 编辑和导出继续提交同一个 Artifact 的下一版本。

当前继续编辑要求指定版本仍是 Artifact 最新版本；最终事务再次核对基线。读取旧版本用于检查和实际恢复是不同操作，不能把旧版本读得到误当作能够覆盖新版本。另存副本、历史回退和 HTML 转原生仍需独立产品语义。

## 原事务与恢复记录

`OpenPublished` 是产品的类型化操作。准备结果携带紧凑的来源候选摘要与清单引用；原 SQLite writer 重新读取实际发布记录，重新推导完整目标草稿并逐字段比较，再与草稿、内容保留、Tool、Ledger 和幂等收据共同提交。模型不能把替换过的快照或资源伪装成历史恢复。资源失效或版本竞争会整体失败。

私有恢复封套新增 `presentation-authoring-checkpoint/5`，旧 /1–/4 的编码继续保留。重复提交返回首次收据，不按后来变化的 Artifact 重新计算；数据库重新打开后所有写入端必须使用新的 Runtime generation，不能复用失效的旧实例。

这些持久关系、授权和历史语义都属于 Musterwork。MusterOffice SDK/worker 没有新增数据库、任务或权限依赖，继续使用已验证的固定计算产物。

## 验证和下一步

验证命令与源码绑定记录位于忽略目录 `.codex-work/product-native-reopen/`。专项使用自有输入、真实 SDK/worker、SQLite 与 Artifact 提交，分别覆盖已发布快照恢复和再次导出、未发布/伪造/撤销输入拒绝、会话隔离与依赖闭包校验。新专项 3 项、覆盖该专项的原生创作回归 20 项、Artifact 库 46 项及三个生产库严格 Clippy 已通过；重叠专项不重复计数。首轮发现的测试接入问题保留原日志，不把旧写入器失效或不可变存储保护改成宽松实现。

实际恢复后修改的是文稿标题，两份两页 PPTX 均通过 ZIP CRC 和全部 20 个 XML 部件解析。第一版保持历史基准字节，第二版只有 `docProps/core.xml` 发生预期变化，其余部件逐字节相同。这不是完整对象编辑、视觉或 Office/WPS 互操作验收。

原 Agent 链路 12 项在相同最终源码下通过：整组先通过 10 项，两项导出证据测试因命令遗漏输出目录变量失败；补充独立目录后只重跑这两项，均通过，没有修改源码。四份 @4/@5 实际 PPTX 与上一发行阶段逐字节一致。最终共覆盖 78 个独立测试，全部命令、早期失败和摘要见[阶段证据](../reviews/evidence/2026-09-28-product-native-reopen-verification.json)。

下一步将已验证的产品端口接入不可变工具继任合同及匹配 Skill，完成原授权快照下的 Agent 调用；继续推进模板、HTML 历史迁移、完整桌面会话、播放、字体与高级内容。整体目标和所有质量/性能/体积门禁保持不变。

后续进展：上述 Agent 端口已接入 `author@6` 与 Skill v9，实际页面文字编辑与同 Artifact 第二版导出见[Agent 打开原生历史版本](product-native-open-agent.md)。本页保留内部恢复端口阶段的证据，完整替换仍未完成。
