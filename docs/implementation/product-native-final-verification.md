# 原生模板最终检查点

2026-09-28，继续在 `codex/musteroffice-integration` 独立 worktree 实施。`native_verify` 已从不可变来源和压力结果生成检查与复核对象，并接通原维护任务的独立提交验证和后端检查点。目录版本提交、自动上传入口及完整 PPT 替换仍未完成。

## 实现

最终阶段读取同代 `native_define`、`native_stress` 的封存结果。目标 0 为来源文稿，其余目标逐一对应固定压力计划；模型只能选择目标编号，不能提供自行声明的输出摘要、覆盖数或合格结论。共享来源校验器同时供压力和最终阶段使用，保持模板、来源、页面顺序、参数、字体及设置的一致性。跨内容库只按精确字节身份重新绑定外层资源引用，不重写 SDK 包和生产记录。

每个目标通过公共 SDK 的 `office_template_inspect` 检查完整产物。`prepare_review` 核对实际计算请求和已完成的工具结果，随后生成绑定检查报告、生产结果、图片和创建调用的原生复核对象。`review` 使用原有非阻塞协调器与工具日志，延续原任务查询、等待和恢复机制。在非最终阶段误调用原生复核，会返回可持久化的纠错结果，不发起计算或复核。

`prepare_stage` 仅汇集候选完成证明。提交时，独立验证器重新推导每一个目标，要求检查、复核对象和复核调用的参数与结果一致，并通过原有规范模型请求/响应验证器检查实际图片、页面覆盖、输出合同与结论。桌面端和云端组合均显式注入该验证器；缺少它不能接受最终阶段。删除生产记录、调换复核对象、遗漏目标或给结果添加自称通过的质量字段都不能形成完成证明。

文字容量是独立条件：全部目标必须明确测量为装得下，没有未测量页或溢出。视觉复核的通过不能覆盖容量失败。阶段结果只声明 `native-delivery-capacity-and-visual-review`，不提升 SDK 的 `quality_proven: false`，也不声称播放、高级内容或 Office/WPS 兼容已经通过。

后端沿原 Runtime 完成回执导出精确文件字节，校验所属用户、请求、代际、模板、固定计划和全部目标与原检查点生产结果的对应关系。最终通过后，原事务一次性更新整份来源的已验证页数；重复回执保持幂等，错误回执整体回滚。模板版本写入仍需要独立的原生目录事务，不因检查点通过而自动发生。

以上流程、模型、存储和事务都属于 Musterwork。MusterOffice 的纯计算边界、固定 SDK 和 worker 未改变，没有新增内核权限、任务平台或页面。

## 验证范围

详细命令、材料摘要、阶段差异和保留的初次失败见[验证证据](../reviews/evidence/2026-09-28-product-native-final-verification.json)。实际专项运行原维护 Agent Loop、SQLite 工具日志和真实 SDK；复核协调器端口使用规范请求/响应测试替身，不能据此认定外部视觉模型或整套后端与 Runtime 联机验收通过。原生子任务本身的独立验证见[上一阶段](product-native-review-run.md)。

本阶段共 106 项不同测试通过：65 项后端单元/传递测试、12 项真实 PostgreSQL 测试、12 项模板工具测试、10 项新旧复核测试、3 项原维护 Loop 测试、1 项模板选择测试，以及真实来源/压力任务与最终正反向任务的 3 项专项。重复执行不重复计数。

- 原有 9 份交付共 18 页、72 个文字框，仍检出一处最大宽字符溢出。即使 9 份视觉复核替身均通过，最终阶段也拒绝完成。
- 单独的自有正向样例只把第二页目标文本框宽度从 4,000,000 增为 4,500,000 EMU，保持在原组合边界内；文字、字体、22 pt 字号和 16 字符上限未改变。原失败样例完整保留。真实来源与 8 个压力案例均装得下，完整证明才能通过原提交流程。
- 正向最终结果及此前定义、压力产物通过原私有内容传输入口，独立 Python 校验保留 9 个复核对象的规范字节和摘要；105 个私有对象未被重写。
- 后端完成检查、15 类结果变造及幂等回执在原事务测试中验证；真实隔离 PostgreSQL 16.15 验证整份阶段约束、不可变检查点、取消和过期租约。该测试容器已清理，未连接产品数据库。

严格库检查覆盖维护库及桌面、云端组合；原模板工具、维护 Loop、新旧复核和模板选择另行回归。初次检查发现并修复测试编码 API 使用错误和条件表达式 lint；云端既有类型复杂度与嵌套条件也作等价整理，没有关闭 lint。后端保留已有 294 条弃用等告警。测试耗时包含编译、数据库与夹具开销，不作为渲染性能或发行包体积数据。
