# 原生图表绘制声明与颜色上下文

本项承接[源图表几何](source-circular-geometry.md)，为同一原生对象读取图表的填充、
线条和效果声明，并在图表实际颜色上下文中计算填充/线条颜色。系列、数据点、坐标轴
等节点通过不可变图表部件中的物理 XML 序号关联，声明与已计算颜色分别保存。
本阶段尚不是完整的自动图表样式、系列/点继承、描边与效果绘制或整张图表渲染。

## 共享实现

图表 `c:spPr` 里的 DrawingML 使用现有填充、线条和效果解析器，不另建简化颜色或
描边语法。原始渐变 stop 顺序、重复位置、百分比拼写、图案、图像引用、线宽和效果
图节点保留。显式空效果列表与没有效果声明保持不同，可供后续继承器正确处理。
未知几何、属性与扩展保留位置；不把“有声明”或“部分颜色可计算”当作完整绘制通过。
[Open XML 图表形状属性说明](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.chartshapeproperties?view=openxml-3.0.1)
列出了这些原生属性族。

颜色计算器先绑定所属幻灯片已解析的颜色映射与主题，再覆盖图表明确声明的
`c:clrMapOvr` 及图表关系指向的 `themeOverride` 颜色方案。未声明颜色方案的主题覆盖
不清空已有方案；颜色映射选择主题槽位，不是直接指定 RGB。
[图表颜色映射说明](https://learn.microsoft.com/es-es/dotnet/api/documentformat.openxml.drawing.charts.colormapoverride?view=openxml-3.0.1)
说明了图表独立覆盖应用颜色映射的用途。

图表主题覆盖经过内部关系、无 fragment、内容类型、字节范围和原生主题语法验证。
读取主题不触发文件路径或网络访问。调用方显式提供系统颜色；缺少对应上下文时返回
结构化未解析颜色。未知颜色映射内容不能悄悄使用旧映射继续计算。

主题色与原生变换在共享计算器的工作精度中连续计算。`rgba8` 和 `rgba16` 是最终样本，
不能重新送回下一层变换。测试中的 1/255 红色经过两次 50% 变换，工作值仍为
0.25/255，尽管八位样本已经是零。结果同时记录主题、系统或占位色依赖来源。

## 接口和资源边界

入口为 Rust `mo_kernel_api::compute_pptx_chart_paints`、
`compute_pptx_chart_paints_json`、同名 WASM 导出，以及：

```sh
mo-cli pptx-chart-paints request.json source.pptx
```

请求固定文稿 SHA、原生对象、颜色 profile 和显式颜色上下文。响应包含来源查询结果、
实际颜色映射与方案绑定、图表主题覆盖 SHA，以及按来源顺序排列的绘制声明。
`computed` 表示查询及颜色计算批次完成；每个颜色仍可能是 `unresolved`，样式继承、
黑白模式和效果绘制也没有因此自动完成。JSON Schema/TS 类型由 Rust 生成。

来源查询、后续图表重读和主题读取共用总输入字节限额；各填充与线条声明共享原生
解析预算，全部颜色共用查询数、运算步骤和百分比字节限额。取消或资源失败不返回
前缀声明。默认最多 4096 个绘制声明、256 个待计算颜色；Rust 调用者可以明确设置
预算。这个阶段会重读一次目标图表，后续完整图表准备应复用解析结果以消除此开销。

本批没有启用新的正式 MCP 能力、产品模板或产品运行时。Musterwork 的人工测试
候选保持原版本；没有建立权限系统、持久存储、页面或业务任务。

## 验证与后续

验证包括图表主题与幻灯片主题的覆盖、独立颜色映射、原始变换精度、透明度、重复
渐变位置、图案颜色、数据点绑定、MCE 分支选择、扩展保留、显式空效果、共享预算、
取消和严格 JSON 边界。旧主题/颜色映射、填充与线条计算也进行回归。

本批 26 项图表来源/样式测试（含九项新增样式测试）、39 项既有配色回归和两项
公开 API 测试通过，严格 Clippy、生成合同及 TS 类型检查通过。16 份完整 Native/WASM
响应一致，其中 14 份计算成功、两份预期错误；全部请求/响应通过 Schema。
输入包含 12 个自有案例及四个真实模板图表，未提交私有模板原文件。

[`chart-paint-parity.mjs`](../../tools/verification/chart-paint-parity.mjs) 比较完整原生/WASM
响应，并把真实圆环图的明确数据点填充接到已验证几何和实际 Skia；该诊断没有绘制
继承描边、标签、图例和整张图表的背景。不能将这种局部像素对比写成完整模板质量。

[`chart-paint-oracle.py`](../../tools/verification/chart-paint-oracle.py) 独立读取源 ZIP/XML、
父级关系、主题和映射，核对声明位置与颜色值；遇到自身没有实现的变换会失败，
不使用默认色跳过。真实图的像素探针直接以源 XML 中的数据点颜色为参考。

独立程序核对 14 个图表、48 份形状声明、37 个声明颜色，并对两张实际圆环填充图
执行 12 处颜色/透明像素探针。两帧全部像素与元数据在原生/WASM 中相同，实际诊断图
已查看。错误色值、漏掉声明颜色、错误主题来源三个反例被拒绝。
完整方法、输入与产物哈希见[本批证据](../reviews/evidence/2026-09-30-source-chart-paints.json)。

后续将这些声明接到共享的填充/线条继承与场景准备阶段，覆盖图表自动样式、点覆盖、
绘制次序、描边与效果，再与标签、图例和绘图区布局合成。完整模板准入、Office/WPS
往返、性能及安装包体积仍分别验收。
