# 原生表格单元格文字计算

2026-09-29，接续[表格样式](table-styles.md)，将真实单元格的声明级联、字体、颜色和段落计算接入共享文字引擎。当前是 Rust 库能力；完整表格页面尚未启用，Musterwork 继续使用[独立接入工作区](product-worktree.md)中的上一验证材料。

## 作用域与职责

[TableTextResolver](../../crates/mo-presentation-source/src/source/text/cascade/table_text.rs)对原始对象、合并拓扑和显式样式进行一次绑定，之后按物理单元格解析。使用已有借用式文字根及段落区间，不复制对象或将单元格伪装为形状。结果保留文稿摘要、对象、物理行列和原始段落起点；计算数组使用格内索引，字体诊断与段落计算结果使用对象的原始段落索引。被合并覆盖的文字仍可独立查询、编辑，绘制端以后只计算需要绘制的合并原点。

[TableTextCompiler](../../crates/mo-presentation-compile/src/source_text/table.rs)沿同一作用域调用普通文字编译器，复用 Unicode 分段、脚本选择、显式字体 Manifest、字形整形及局部轮廓计算。内核不查系统字体，不获取文件或网络，不创建宿主任务、持久存储和交互页面。

拓扑构建沿用独立单元格、步骤和标识字节预算；每格文字级联和计算分别遵守步骤、段落、run、文本字节、计划字节、字体绑定及补充字体预算，并检查取消。每格的这些限额不等于整页累计限额；后续页面编译必须由页面预算汇总所有单元格，不能把逐格成功算作整页资源验收。没有本阶段性能/RSS测量或安装体积结论。

## 级联与原生来源

当前声明计算配置按以下顺序选取各属性，前者优先：run/endParaRPr，当前段落 pPr/defRPr，当前单元格 lstStyle 对应级别，已选表格文字样式，既有主题级别/链接母版 otherStyle/演示文稿默认文字样式，显式配置的最终默认值。表格样式只贡献实际声明的粗体、斜体、字体和颜色，不能替代段落属性。单元格不继承形状占位符的模板文字体。

表格区域优先级沿用上一阶段；区域成员、合并边缘、RTL、退化行列，以及上述全部继承组合仍需 Office/WPS 对照。共享配置名称仍明确为 draft，测试通过不代表已完成外部应用语义校准。

来源使用独立 `TableStyle` 身份，指向真实内联对象或共享目录的样式 ID、区域及物理元素序号。[声明访问器](../../crates/mo-presentation-source/src/source/text/cascade/table_text.rs)只返回该位置上的字体集合、字体引用或颜色，不在 SourceTextCatalog 中合成虚拟节点。直接格式仍指向原始文本节点。原有形状级联结果中的新增单元格字段在无值/零值时省略。

[字体选择](../../crates/mo-presentation-source/src/source/text/fonts/selection.rs)在主题集合与表格集合之间共用主字体/有序补充字体查找。集合字体保留脚本槽与补充项下标，字体引用沿所在绘图页面的主题选择解析。显式 `none`、缺失/重复补充字体、保留声明和无法识别的主题字体均产生可追溯结果，不猜测替代字体。[颜色解析](../../crates/mo-presentation-source/src/source/text/paint.rs)复用同一 DrawingML 颜色引擎，按需解析字体引用的 `phClr`；缺失且未被使用的字体引用颜色不妨碍明确 RGB 声明。

## 验证与尚未交付的范围

[原生来源测试](../../crates/mo-pptx/tests/table_text.rs)覆盖共享/内联样式、物理单元格与多段落范围、直接格式逐项覆盖、区域覆盖、补充字体、主题字体、占位色、缺失声明、来源绑定、取消和资源预算。[真实 HarfBuzz 测试](../../crates/mo-harfbuzz-sys/tests/table_text.rs)使用自有字体及实际 PPTX，比较表格与普通文本框相同文字的共享整形和局部轮廓结果，保留空段落、合并覆盖文字及原始诊断位置。

验证结果、命令、失败尝试、产物和源码摘要见[本阶段证据](../reviews/evidence/2026-09-29-table-text-verification.json)。跨端来源读写回归验证来源保留链路；新表格文字库尚未经公共请求完成 Native/WASM 计算对照，不能把来源回归计作表格像素一致性。
