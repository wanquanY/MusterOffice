# 原生填充声明与来源绑定

2026-09-24。本阶段接通真实 PPTX 中的填充读取，继续采用已确认的 Rust 核心、原生/WASM 同源和 TS 薄接入。它位于[原生路径编译](native-paths.md)与来源页面绘制之间，不代表完整画笔、原生页面或 Musterwork 替换已经验收。

后续状态：2026-09-25 已新增[填充继承与查询](fill-styles.md)；随后已接通[效果声明](source-effects.md)，共享读取器迁至内部 `source::paint`，已知效果不再作为不透明填充内容。以下描述保留本阶段封存时的范围与数字。

## 实现边界

`mo-pptx::source::fill` 统一读取六种原生声明：无填充、纯色、渐变、图案、图片填充、组合继承。声明用于以下位置：

- 形状、连接线、图片外框、组合形状及页面根组合的直接填充。
- 对象 `fillRef`，页面/版式/母版的 `bgPr` 和 `bgRef`。
- 主题及主题覆盖的普通填充、背景填充与线条样式。
- 图片的 `p:blipFill`。图片内容与 `spPr` 外框填充分开保留，不互相覆盖。
- 线条的无填充、纯色、渐变和图案，通过同一读取层解析。图片/组合填充仍不被接受为线条原生声明。

新增的 `SourceFill` 保留源节点、类型化声明和未解释节点序号。来源部件及 SHA-256 由外层索引绑定；MCE 投影使用原始物理节点序号。核心不打开文件路径、网络 URL、图片或系统字体。

## 原生值与结构

渐变保留停靠点原始顺序、重复位置和颜色变换，支持线性/路径阴影参数、填充矩形和平铺矩形。图案保留 54 个原生枚举及独立前景/背景色。图片填充保留嵌入/链接关系 ID、压缩提示、DPI、裁剪、平铺/拉伸、对齐、翻转及随形状旋转声明。背景额外保留黑白模式和 `shadeToTitle`。

缺省值没有在读取时补入。例如未声明的 `rotWithShape`、显式 `false`、缺少矩形、空矩形、矩形边距 `0` 都是不同的来源声明。整数与小数百分比保持词法精度；平铺位移支持整数 EMU 及 `mm/cm/in/pt/pc/pi` 的精确词法，不经过浮点舍入。

填充引用保留原始索引：0/1000、1–999、1001 以上分别属于不同选择规则。当前阶段不解析引用、不替换 `phClr`，也不把 `grpFill` 直接当成父组合的已求值画笔。下一阶段必须结合占位符、主题和上下文完成解析并保留来源。

原生顺序、互斥选项、已知取值范围和必需子项受验证。例如非空渐变停靠点列表至少两项；同一声明不能同时指定 `lin/path` 或 `tile/stretch`。ECMA-376 §20.1.10.45、§22.9.2.10 将正固定百分比限定为 0–100%；其 XSD 正则却会接受 `100.01%`。内核按正文拒绝该越界值，验证报告将其单独列为语义范围拒绝，不冒称 XSD 也拒绝了它。

## 未解释内容与资源边界

图片效果、背景效果、未知属性及扩展保留源绑定。它们不能注入正常填充字段，也不能被计作已支持的效果计算。图片颜色变换属于 blip 效果时保留整棵效果子树；普通填充颜色继续复用既有六种颜色模型和有序颜色变换读取。

所有投影填充根及子元素共享全包预算：默认 100 万个元素、32 MiB 属性值，覆盖对象、主题、背景及线条内的填充。保留子树也消耗这项预算。底层 XML/MCE/OPC 物理字节、节点、深度和取消限制同时生效；未选择分支仍受底层预算约束。

`pptx-inspect` 和 WASM `inspect_pptx` 直接返回新声明，没有新增一套平行查询协议。来源文本编辑仍只修改授权文本，并重读候选包；填充 XML、扩展、原编码和未改动部件保持原有来源策略。尚未开放填充属性/树修改。

## 开发契约变化

只更新 57 份运行期 Schema 中的 `pptx-source-response` 及对应生成 TS，其余 56 份保持原内容。对象新增 `fill/fillReference/pictureFill`，表面新增 `background/rootGroupFill`，主题条目新增 `fill`；这些字段缺省时省略。线条原来的 `retained + nativeKind` 渐变/图案记录升级为类型化声明。已有无填充、纯色及线条解析结果的表示不变。

这是开发阶段来源查询契约演进，接入方应重新生成/使用同版本类型。完整画笔计算尚未实现，既有线条解析对渐变和图案继续返回未支持画笔诊断。新增结构不能被当成绘制已经支持。

重复线条颜色仍返回 `INPUT_INVALID`，诊断文字由 `multiple line colors` 变为共享的 `duplicate or out of order fill property`。旧语料中两条重复执行记录涉及这项变化；验证逐项重建旧响应摘要，同时核对当前完整错误响应，没有忽略错误码或输入差异。

生成的来源响应 TS 为 1451 行，低于 2000 行限制。后续扩展应在生成器层拆分引用模块，不能手改生成产物。本阶段未增加外部依赖，Cargo/pnpm 锁文件不变。
