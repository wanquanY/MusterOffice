# Musterwork 原生导出准备与最终存储验证

2026-09-27：接续[真实创建与编辑](product-native-mutations.md)，在产品内实现调用固定 SDK/worker 的导出准备器。这里的 `MW:` 是产品相对路径；私有产品源码仍留在产品仓库。本阶段产出经过验证的私有候选，正式 Artifact、Tool 成功与 Ledger 原子提交继续由原 Runtime 实施，尚未切换用户入口。

## 实际计算链路

`MW:apps/agent-runtime/crates/runtime/artifact/src/presentation_office_export.rs` 定义导出请求、计算读取集、收据及候选端口。请求绑定完整原生草稿、来源 Invocation、创建时间、实际 OperationRequest ContentRef 和精确的资源/字体输入。候选保存原草稿及其 Artifact 基准版本，不用内核版本摘要替代产品版本序号。

`MW:apps/agent-runtime/crates/infrastructure/musteroffice/src/export.rs` 从产品 Content Store 打开已授权、已完整校验的范围读取器。严格解析真实请求和模型，核对 Invocation UUID、文稿和修订、语义摘要元数据、页面顺序以及完整资源映射。原 SDK 继续负责真实语义恢复、绘制与文件检查。请求不能指定可执行文件、临时目录或未固定的渲染器；字体必须由宿主显式绑定。

资源和字体的操作别名必须与请求完全一致。资源映射匹配草稿的精确 ContentRef，而不只是相同字节摘要。读取器可复用，但操作别名、请求、模型、来源文件共同计入输入准入预算，不能借去重少算别名或给元数据另开额度。

## 产物与证据

准备器使用不透明的 `NativeExportCandidate` 构造 `presentation-artifact/4`。每个实际输出、public bundle、原导出收据、最终检查报告和产品清单，都有按 Invocation、用途、MIME、内容摘要确定的不可变 ContentRef；相同请求得到相同引用。候选 ID 还绑定产品清单摘要，来源或 Artifact 版本变化不会复用错误候选身份。

所有资产角色、预览采样模式以及五类质量声明逐项显式转换，原样保留状态、依据、原因和证据引用。不能把结构通过升级成排版、原生编辑、播放或 Office/WPS 应用验证通过。公共版本元组继续保存在实际 bundle 中。

完整输出计划，包括收据、检查报告和产品清单，在第一笔产品写入前完成容量及引用验证。资产通过有界流写入原 Content Store；准备器再打开最终实际存储文件，调用共享 `delivery::inspect` 核对模型、资源、PPTX 包与预览像素。最终检查报告必须与原候选检查完全一致，之后才保存元数据并返回产品候选。存储返回的引用本身不能替代实际字节验证。

## 取消与资源所有权

创建/编辑和导出共用宿主注入的计算名额，不新增队列。通用取消、诊断和不可变 JSON 写入已抽取共用实现。异步请求退出会通知仍在执行的阻塞工作。

导出的计算名额随真实候选及所有排队的文件读取共同保留。即使等待者被取消，也要等实际读取、文件句柄关闭和私有目录清理完成才释放名额；清理在阻塞执行器上进行。成功路径等待显式清理结束后返回。

这仍不是完整的 Invocation 生命周期：进程崩溃后的 worker 暂存发现、预写内容的持久保留和回收、全任务磁盘/RSS/句柄配额仍待接入原 Runtime。取消可能留下已写入的私有产品内容；不能盲删确定性 ContentId，因为它可能被重试或其他合法引用使用。生产工具路由继续关闭。

## 验证与范围

真实 worker 测试从自有两页样本创建产品草稿，调用实际准备器并回读 SQLite 文件。12 份交付文件、内核收据及最终检查报告与历史冻结基准一致；产品层只增加自身身份和证据绑定。另验证重复请求、来源 PPTX 区分、候选元数据替换、请求/修订/渲染器/资源/租户错误、关闭草稿、完整写入预算、输入别名与元数据共享预算，以及损坏落盘、错误返回引用、元数据写入失败和取消。

取消专项占满唯一阻塞线程，再让真实输出读取进入队列，取消整个准备 Future：名额和目录仍被读取任务保留；释放阻塞线程后实际读取及清理完成，名额才恢复。这证明的是进程内所有权，不代替进程崩溃恢复。

最终测试、源码摘要、实际文件与限制记录在[阶段证据](../reviews/evidence/2026-09-27-product-native-export-verification.json)。早期编译错误和测试误用小写诊断代码的失败记录保留；真实协议代码仍按原大写形式传递，没有为通过测试修改协议。

最终 5 项新增真实导出测试、11 项原生草稿回归、82 项相关库测试和一项原桥接真实导出回归通过。三个相关生产库的严格 `--no-deps` Clippy 与全工作区 all-targets 编译通过；编译保留既有测试未使用导入警告。扩大到依赖库的 Clippy 在未修改的 capability/browser 条件写法处失败，源码与产品 HEAD 字节相同，保留失败日志而不计为全库 lint 通过。没有运行完整产品测试套件。

固定 SDK、worker 及产品 Cargo.lock 与创建/编辑阶段相同，没有新增外部组件。仅测试显式启用既有 Tokio 的 time 功能。没有发布新 SDK、修改旧 checkpoint 或改变默认路由；完整发行许可、跨平台与性能验收未在本阶段完成。
