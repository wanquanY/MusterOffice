# 渐变坐标精度与刚性变换

本阶段修复[来源变换编辑](source-transform-edit.md)暴露的共享绘制问题：同一渐变随对象平移、翻转或旋转 90 度后，少量像素因浮点坐标计算路径不同而改变。PPTX 的对象声明和编辑结果不需要补偿，修复位于原生/WASM 共用的 C++ 画笔。

## 计算边界

旧画笔由 `SkMatrix` 展开 float32 逆矩阵，再在向量管线中计算局部坐标。针对四个平移差异位置，实际 Skia 的 seed、inverse、callback 管线复现了不同的坐标位模式；并非只依据自写的标量模拟判断。

新 `PreparedCoordinates` 接收编码后的六个 binary32 平面参数和设备采样点，先减原点，再求逆、平铺和焦点坐标。对线性/矩形场，返回正确舍入的平铺坐标；对椭圆场，完整计算 `(2 × tiled(u) − 1) × scale` 后才舍入为 binary32，避免中间坐标量化在中心附近放大相对误差。

普通计算使用向外包围的 binary64 区间；只有两端舍入到同一 binary32 值时才返回快速结果。对角和交换轴矩阵共用相同语义的轴向实现，保留单一分母，在分子中完成平铺和中心化；一般矩阵的行列式被证明为点区间时，也复用这条分子计算路径。点区间除法用保守的 binary64 误差包围验证最终舍入；不确定时继续走区间或精确计算，不依赖经验 epsilon 判相等。

精确回退使用固定 768 位无符号整数及符号位，将有限 binary32 输入表示为整数乘 `2^-149`，完成有理数逆变换、带符号平铺和中点比较，以 ties-to-even 决定最终浮点值。没有新第三方依赖、堆分配、系统字体或宿主 I/O。输入绝对值仍受 32768 限制，固定整数容量与溢出检查配合使用。

共享组件取消画笔平面的 Skia local matrix；路径实例的局部放置与反向画笔平移仍由原有画布链路抵消。既有线性、矩形和椭圆场均调用新映射器；椭圆首次交点算法、覆盖率和颜色插值实现没有改写。

这是对**已编码平面和设备采样值**的正确舍入保证。它不扩展为来源 EMU/Q32 到平面的量化证明，不证明任意角度旋转的覆盖率恒等，也不关闭 Office/WPS 兼容和统一颜色误差门槛。

## 有界工作

每次组件绘制最多允许 65,536 个采样点进入精确坐标回退。超过后沿用数值工作失败状态，整帧不返回像素；后续独立调用可以继续使用组件。已有椭圆采样和求根工作上限继续生效。这个限制单独约束昂贵坐标计算，并不限制普通快速采样只能绘制 65,536 个像素。

## 验证与性能

独立 Python `Fraction` 对平面求逆、平铺、缩放和最终中点舍入作精确参考，覆盖一般矩阵、两种轴向矩阵、负基向量、极小数、边界和非法输入。实际 Native/WASM 和 ASan/UBSan 使用相同输入并逐字节核对。完整源页面验证另行执行编辑、来源读取、原生宿主和 WASM 绘制，再以整数像素置换构造刚性变换参考，要求零差异。

最终验证包括 7,513 个数值输入（7,466 个有效、47 个预期非法）、32 对精确刚性坐标、637 组组件三端检查、355 对公共入口调用、636 项 Rust 测试和 83 份 Schema/TS 检查。两份 PPTX 的 8 个编辑后页面与独立参考共核对 960,000 个像素，全部相等；此前 4 个偏心渐变失败样例关闭。独立颜色参考核对 1,848,597 个像素，沿用原量化界。

旧渲染器的像素不是修复后的正确性参考。回归同时保留旧像素差异、跨端一致性、未变化的源帧，以及独立线性有理数和原生 XML 派生的矩形/椭圆颜色参考。颜色参考沿用原来的最多 1 个 RGBA8 量化级标准；这没有放宽坐标舍入或刚性变换的零误差要求。

最初通用区间实现使普通中心渐变页面的局部 WASM 中位耗时约从 5 ms 增至 12 ms，轴向实现及点除法验证随后用于减少这项开销。最终构建、实际页面测量和剩余开销以[本阶段证据](../reviews/evidence/2026-09-26-gradient-coordinate-verification.json)为准。测量包含同步 Rust WASM 的 PPTX 解析、页面准备、C++ 绘制及像素返回，使用 400×300 渐变页面、空显式字体清单、预热模块；不等于浏览器播放、原生产品、冷启动、RSS 或安装包测量。

最终在 Apple M4 Max、arm64 macOS（Darwin 25.2.0）、Node 23.5.0 上，每项预热 3 次、采样 25 次，前后顺序执行，中位值如下。测试期间未并行运行本任务的构建/回归，其他系统负载不受控。

## 复现与后续

`gradient-coordinate-checks.py` 验证数值核；`gradient-coordinate-trace.py` 复现旧 Skia 管线差异；固定 `build-skia.py` 分别构建 Native、WASM 和 sanitizer 组件；`gradient-coordinate-workspace.py` 重连原生宿主并检查 Rust/TS 合同；`gradient-coordinate-render.mjs`、`gradient-coordinate-components.mjs`、`gradient-coordinate-replay.mjs` 检查实际页面及既有组件；`gradient-coordinate-reference.py` 核对独立参考；`gradient-coordinate-benchmark.mjs` 对比前后公共入口。产物位于 `.codex-work/gradient-coordinates`，尝试过程与最终构建分开，旧封存阶段不覆盖。

Rust WASM 复用已验证的 `.codex-work/transform-edit/wasm-node`，原生宿主链接新的 C++ 组件。原始源码、构建配置、输入、输出及报告摘要由证据文件绑定。没有新增 Office/WPS 实机验收；固定方向渐变的系统权限问题仍保持原状。

本阶段只关闭已复现的坐标路径问题。后续继续按交付计划推进高级对象、时间线和通用宿主的纵向样本，以及结构编辑、多表示同步和实际 Musterwork 适配；不能以此代替完整一期或替换验收。
