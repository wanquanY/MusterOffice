## 计算边界

`mo-pptx::source::fill::resolve` 在不可变来源索引上工作，支持对象填充、线条填充、图片内容填充、页面根组合和背景五种查询目标。图片 `p:blipFill` 与图片外框的 `spPr` 填充保持独立；普通图形框不被假装成形状。图片占位符允许匹配版式中的普通形状，后者没有图片内容声明时继续查找，不把外框填充错误地转换为图片内容。

解析按直接声明、局部样式引用和占位符父链逐层补全。每层只合并同类填充；线性/路径渐变和平铺/拉伸的分支也保持类型边界。已经完整的纯色或无填充不继续读取无关的坏引用。渐变停靠点作为整体选择，保留原顺序、重复位置及精确词法，不排序或去重。

显式 profile 为 `ms-oi29500-fills-2024-draft-v1`，依据 [Microsoft 对 DrawingML 填充继承与默认值的说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/c0c046ec-a61d-405d-88fe-74d8487a37d7)。默认值包括空纯色的 `bg1`、空渐变的黑白停靠点和线性阴影、图案 `pct5`、图片平铺参数。没有把这些默认值写回源声明。本解释尚无新 Office/WPS 对照证据，不能称为目标应用认证 profile。

矩形按该 profile 的属性族分别处理：`srcRect`、`fillToRect` 逐边继承；未填补的边分别使用 0、50%。`tileRect` 和拉伸 `fillRect` 的已选节点使用 Schema 默认边值 0，不从低优先级节点补边。因此空路径渐变矩形与空平铺矩形有不同结果。相关行为由具体输入验证，仍需目标应用校对。

填充索引 0/1000 表示无填充，1–999 选择 `fillStyleLst`，1001 以上选择 `bgFillStyleLst`；越界返回类型化诊断。线条目标通过自己的 `lnRef` 和线条样式目录解析填充，不误用 `fillRef`。

`grpFill` 转向声明对象的实际父组合，允许继续到页面根组合；跳转保留来源并有环检测及独立上限。形状 `useBgFill` 已从原生属性读取为 `useBackgroundFill`，真值转向查询页面的背景。背景选择页面、版式、母版中最近的完整声明，显式无填充会阻断后续背景。

## 来源、颜色与图片

每个有效属性区分直接声明、经引用选择的主题节点、Schema 默认值和 profile 默认值。主题来源额外记录消费者、引用物理节点及样式索引。所有源节点使用 MCE 投影前的物理序号，源包摘要仍是查询前置条件。

颜色保持模型与有序变换，附 `contextOwner`。后续颜色求值只有真正遇到 `phClr` 时，才应读取该上下文的原生引用色；不能提前采样或截断颜色，也不能因为无关占位色未解决而拒绝普通 RGB。当前接口尚未执行这一步，不能把 `resolved` 理解为颜色已经可绘制。

图片嵌入/链接 ID 各自记录声明部件。例如图片来源可以在主题，链接来源可以在版式；将它们统一按页面关系解析会取错资源。当前保留关系表达式，不打开 URL、文件路径、不解码图片。两种 ID 都为空时返回 `missingImage`，不悄悄变成透明填充。

## 未完成能力与失败边界

未知属性、图片效果及其他保留内容会返回 `retainedContent`。背景效果目前仍属于保留内容，**包括空 `effectLst`**；需要后续独立效果声明与求值层处理，当前普通含此节点的背景查询也会未解决。不能删除效果节点来伪造成功。`shadeToTitle=true` 明确未支持，黑白输出模式还未求值。

缺失主题、样式索引越界、占位符不匹配等是逐目标诊断；摘要冲突、结构绑定损坏、循环、预算和取消导致整批失败。目标顺序和重复查询保留。所有目标共享默认 100 万步、262144 个值、4 MiB 词法数据预算，最多 256 个目标和 256 次组合/背景跳转。OPC/XML/来源读取自身预算同时生效。

既有完整线条查询仍对渐变/图案返回未支持画笔；本接口只解析填充属性，并未把完整线条绘制标记为支持。尚无来源填充修改 API、完整图片/效果画笔或导入页面绘制。

## 接口与契约

原生范围读取入口为 `mo_kernel_api::resolve_pptx_fills`，接受来源限制、解析限制和宿主取消函数；薄入口如下：

```sh
target/release/mo-cli pptx-fills request.json source.pptx
```

WASM 对应 `resolve_pptx_fills(requestJson, sourceBytes)`。请求包含 `expectedSourceSha256`、`surface`、`targets` 和显式 `profile`；目标使用 `object/line/picture + nativeId`，或 `rootGroup/background`。响应为 `evaluated + styles` 或整批 `error`，每个目标有 `resolved/unresolved`。此处 `evaluated` 表示查询执行完成，不表示全部目标已经解决。

新增 `pptx-fill-query`、`pptx-fill-response` 两份 Schema；来源响应增加可省略的 `useBackgroundFill`。原 57 份 Schema 中仅来源响应变化，其余 56 份保持字节不变，总数 59。对应 TS 由 Rust Schema 生成，填充响应为 773 行。没有新增外部依赖或修改 Cargo/pnpm 锁文件。
