# Musterwork Invocation 预写额度与写入授权

2026-09-27：接续[原生候选与 Artifact 提交](product-native-commit.md)，在原 Runtime 内容端口和 SQLite owner 中实现预写资源账户。本阶段完成存储能力；原生创建、编辑、导出准备器尚未改为强制使用该端口，完整资源生命周期仍在实施。下文 `MW:` 表示产品仓库相对路径，私有源码保留在产品仓库。

## 账户与执行权

`MW:apps/agent-runtime/crates/runtime/content/src/invocation.rs` 定义 `InvocationContentStore` 和不可变 `InvocationContentLimits`。普通 `ContentStore` 不隐式获得 Invocation 权限。宿主绑定原 Tenant、Attempt、Invocation 和额度，准备器须在写入前一次预留完整输出集合；媒体类型、长度、摘要和 ContentId 都属于精确身份。

SQLite v186 新增 `invocation_content_budgets` 与 `invocation_content_outputs`，外键连接原 Tool 的 tenant/run/invocation 三元组和已就绪内容。没有新的任务状态、队列或任务数据库。额度按 Invocation 累计，已预留但未落盘的资源也占额度；相同身份重试不重复计费，改额度、身份冲突、超限都使整批预留回滚。存储重开不会释放额度，失败写入也不会重置预算。

每次预留、文件写入前、文件写入后都复用原 `lock_live_attempt`：要求 Device writer 有效、Attempt 租约有效、Run 未取消、Tool 正在由该 Attempt 执行且未过截止时间。文件 I/O 期间释放 SQLite 写事务；末次校验成功后，内容元数据与预留的就绪标记在同一事务中提交。文件已经写完并不授予已取消或过期的执行者登记权限。

这是 private Device 路径。预留/写入检查还明确要求非共享作用域及 private execution kind；不会以本地绑定替代共享 Home 的独立授权协议。

## 身份隔离与预算边界

预留不能收编已有普通内容。普通按内容去重写入会跳过 Invocation 管理的 ContentId，并使用独立身份；底层仍可复用相同摘要的实际文件。普通 `put_at`/流式写入不能覆盖或接管已预留身份。这避免未来清理预写资源时，误把其他用途的普通内容一并视为临时产物。

额度统计逻辑内容长度与身份数量，同字节的不同输出身份分别计入；它不是磁盘去重后的物理用量。单项沿用共享内容上限，账户数量上限为 65,536，实际数量/字节额度由宿主显式配置且持久固定。该上限是登记容量约束，不是完整文稿档案、进程 RSS、worker 暂存、打开文件数或设备总容量的承诺。

已有内容删除仍代表显式撤销，不能通过重试复活。预留账户目前不会因 Tool 结束自动删除，不能把本阶段称为失败产物回收完成。后续必须以原 Runtime 的终态及正式内容引用证明可回收，覆盖重试、历史版本和别名；仅凭确定性 ContentId、Attempt 过期或文件年龄不足以删除。

## 验证与后续

新增专项使用原调度器实际领取 Attempt、原 journal 启动 Tool，然后执行实际 SQLite 文件写入。覆盖整批超额回滚、并发争用同一额度、精确身份重复、内容校验失败后重试、普通身份隔离、落盘后登记故障整体回滚，以及数据库重新打开后的额度保留和旧 writer 拒绝。

写入中撤销通过可暂停的实际 ContentSource 复现：在文件读取期间分别注入 Run 取消、租约过期、Tool 不再执行和截止时间到期，最终内容元数据均不提交。负例的 SQL 故障注入不用于授予或延长正例执行权。v186 的迁移测试使用最小历史关系签名，检验历史行、外键、不可变身份与末尾故障整体回滚；不代表用户数据库升级验收。
