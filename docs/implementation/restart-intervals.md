# 重复激活与父级活动区间

2026-09-27。接续[开始条件列表](start-conditions.md)，将一次激活调度改为共享的活动区间调度。本阶段仍不代表完整主序列、WPS 回存投影或 Musterwork 替换已验收。

## 实现语义

行为和容器新增 `restart: never | always | whenNotActive`。作者模型省略字段仍表示 never，并省略默认值的序列化，保留已有 JSON 和导出声明。Rust 草案结构体调用方需补充字段，TS/JSON 调用方可继续省略。Writer 写明确原生值；Reader 读取明确值，不将来源文件中缺失的 restart 偷换成作者默认值。

never 限制同一次父级激活中的再次开始；always 允许用新开始中止当前区间；whenNotActive 忽略活动中的重启请求。父容器重新激活会创建新的子节点活动周期，包括重新允许 never 子节点开始。每次区间保留其具体父区间身份，旧子节点的完成值、冻结状态和延迟动作不能进入新父区间。

调度区分实际事件与延迟执行。点击按完整宿主日志的时间和序号进入同一队列；引用开始/结束事件通过编译后的监听索引分发。在事件发生时，先根据节点状态决定是否接收开始，再决定是否接收同一事件的结束，最后添加延迟。一个点击用于开关时，whenNotActive 忽略活动中的开始并接收结束；always 接收新的开始并忽略该事件的结束，即使开始有延迟。不会因延迟执行时已经空闲而重新接收之前忽略的点击。

重新激活后的区间身份使旧结束计时器失效；父活动周期变化使其所有旧排队项失效；同一节点重启清除旧事件产生的延迟开始，静态声明的后续时间候选仍存在。祖先结束先关闭子树，再传播实际开始过的节点的结束事件；外部依赖可以响应这些结束，已关闭子树不能借此重新打开。

实际事件还具有调度内的发生序号。重置记录已发生事件的边界，避免时间戳和宿主序号都相同的旧外部事件被新子区间重新使用；新父区间在重置后发出的开始事件仍可触发其子节点。这个边界不依赖浮点时间差或人为延迟。

自动容器按每个当前子区间完成情况求结束。子节点在其他子节点仍活动时再次开始，会撤回其已完成计数，重新计算自动结束；显式结束上限仍独立存在。行为内部 repeat 时钟继续使用原有精确计算，不把循环次数展开成重新激活实例。

属性覆盖先比较完整激活时刻（有理时间及宿主事件序号），相同激活时刻再按作者结构顺序取值。因此同一时间戳内后一次事件激活的行为不会被作者顺序较后的旧行为覆盖。采样选择区间索引并借用区间数据，不逐帧复制全部精确有理数。

## 有界计算与缓存

`TimelineLimits.max_intervals` 默认 65,536，包含等待条目和已生成的活动区间；工作量另受 `max_schedule_steps` 限制。事件监听按目标和引用索引分发，不为一个事件遍历所有节点。区间、排队工作、精确算术、节点/条件、历史输入各自受预算和取消约束。

含重启的计划只传播到请求采样时刻，避免正时间反馈向无限未来展开。返回当前区间已经知道的自然/祖先结束上限及可确定的未来首次开始，不会通过预测未来反馈或未提交的点击生成事件。未来开始受已知祖先终止上限约束。完整主序列导航、一般循环图以及全部来源默认值仍需后续实现。

保留式 sampler 对重启计划以 `session/revision/generation + 完整事件前缀 + 采样时刻` 判断复用；时刻或前缀变化重新建立有界区间。普通 never 计划保留原来的同前缀跨时刻复用。此阶段未实现重启计划跨时刻的增量推进优化；不得把它宣称为每帧常数开销。失败或取消不发布部分帧、不替换已有缓存或计数。

## 原生范围与后续工作

支持平面行为、并行容器中的重启，以及外层序列容器重启后重新运行其 never 子项。直接序列子项的独立重启会涉及顺序位置、并发和 next/previous 行为，目前明确拒绝，等待导航事件模型；不悄悄按并行播放。原生 tmRoot/mainSeq/preset 包装的缺省值及真实 WPS 回存中的导航、缺失 tn 目标仍未开放。

结束条件继续遵守现有的显式诊断规则：如果全部已解析的结束条件都早于激活，不自行丢弃该区间并寻找下一个区间。负时间、容器重复/变速、一般循环约束以及完整 SMIL 区间选择算法不在本阶段已验收范围内，完整一期目标仍保留这些待实现语义。

生命周期及事件敏感性参考 [W3C SMIL timing](https://www.w3.org/TR/SMIL2/smil-timing.html)。这是计算设计依据，不把 SMIL 与 PresentationML 或 WPS 实现视为完全等价。Microsoft 记录 PowerPoint 对缺失 restart 使用 always；这与作者草案默认值不同，也不能直接证明 WPS 的行为。[Microsoft cTn 实现说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/02b2312e-9700-42e0-8a19-b2af1ba83a20)
