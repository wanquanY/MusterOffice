# 原生交付的视觉复核绑定

2026-09-28，继续在用户指定的 Musterwork 独立 worktree 实现。本阶段补齐原生复核材料与共用证据校验；尚未接通原生复核子任务和完整 `native_verify`。

## 实现

`office_template_inspect` 在公共 SDK 验证完整交付后，从同一交付的有序预览描述和已验证输入引用生成 `review_material`。它包含实际图片引用、页面 ID、宽高、生产结果引用和固定字体/编译档案；没有第二次渲染，也不改变 SDK 的质量声明。

产品新增 `presentation-native-review-subject/1`。其独立摘要域绑定实际复核报告、生产结果、全部有序图片、档案、创建 Invocation 和稳定时间。文稿、版本、语义、设置和完整 bundle 由所绑定报告及生产结果覆盖。原生复核不要求伪造旧引擎的 scene、object-map 或 HTML 文稿。解码检查规范编码和摘要；构造/解码成功仅表示元数据一致，不能替代 SDK 验证、生产 Tool 证明或发布权限。

旧候选与原生对象共享页面覆盖、模型请求/输出校验和物理调用 ID 计算。原生对象只接受现行、由 Runtime 绑定的复核输入与输出合同，拒绝旧的模型回显摘要协议。旧候选编码和摘要、历史请求构造器保持原意；共用校验器通过明确目标类型区分两者。

复核属于 Musterwork 的产品工作流。MusterOffice 本轮没有新增模型、权限、存储、任务或页面，也没有更新 SDK、worker 或依赖。通用计算传输继续只保存实际计算产物；复核对象应由最终验证阶段在检查生产证明后构造。

## 验证范围

19 项相关测试及五个相关生产库的严格 Clippy 通过，见[阶段证据](../reviews/evidence/2026-09-28-product-native-review-binding-verification.json)。其中实际交付专项覆盖 9 份文稿、18 页和 72 个文字框，原有 1 处横向溢出保留。每份交付使用实际图片引用，经原规范请求编码器和内容证据校验器验证；换报告后套用旧请求、漏页、乱序、自我复核、调换图片、旧输出协议和序列化摘要变造均被拒绝。

新增专项的模型结果是确定性的协议夹具，不是在线模型视觉判断。另有 6 项既有模型循环/SQLite 复核回归、1 项历史请求校验、10 项领域规则及 1 项 Python/Rust 历史摘要与快照对照。未将测试耗时当作性能数据；本轮没有重新生成 PPTX、测量发行体积或执行 Office/WPS。
