## 同一计算核心与原生上下文

`mo-pptx::source::fill::colors::query` 先取得不可变的填充表达式，再通过已有 `source::color::Session` 计算颜色。纯色、渐变和图案没有各自复制一套颜色公式。工作通道和采样统一由 `color::ColorSample` 产生；旧 Rust 名称 `line::colors::LineColorSample` 保留为别名，旧线条响应的实际 JSON 不变。

颜色表达式里的 `contextOwner` 定位声明/继承时的原生上下文。只有实际求值遇到 `phClr`，包括通过主题色间接遇到时，才查找该 owner 的 `fillRef`、`lnRef` 或 `bgRef`。直接 RGB 不会因为未使用引用的未知属性、缺失系统色或循环而失败。请求表面的有效映射与颜色方案仍控制颜色求值，源 owner 则控制原生占位引用。

每个图案颜色、渐变停靠点独立携带 owner。例如前景色来自页面、背景色来自版式时，不能把两者都代入页面的同一个引用色。组合或背景跳转后的颜色也按解析结果的 owner 查找。图片内容和根组合没有自己的上述样式引用，不挪用图片外框或其他对象的引用。

本 draft 明确采用 owner 的局部原生引用；未声明引用色时使用请求中显式的 `context.placeholder`。原生引用表达式自身再次遇到 `phClr`，也使用这个显式宿主值。没有所需值时返回 `missingPlaceholder`，不猜测黑色。引用或引用颜色有未知保留属性时，只有真正需要该上下文才返回 `retainedPlaceholderContext`，附部件和物理节点。

原生引用的概念依据 [Microsoft FillReference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.fillreference?view=openxml-3.0.1)；填充继承继续遵循既有显式 draft。这里的局部上下文解释与数值规则仍需实际 Office/WPS 对照，不能视为目标应用认证。

## 精度、依赖与诊断

样式引用边界不会量化为 RGBA8，也不会先转成 RGB 再重建 HSL。继承、主题引用和外层变换共享完整工作状态：

- 红通道 1/255 在引用内外各调制 50%，最终为 0.25/255，而不是经过中间采样后得到错误的码值。
- 蓝色色相、零饱和度的 HSL 引用，外层恢复饱和度后仍能恢复蓝色，不因中间灰色 RGB 丢失色相。
- 超出显示色域的工作通道保持原值；只有诊断采样执行裁剪和量化。

返回的 `srgb`、`linear` 为非预乘四通道；`rgba8/rgba16` 是诊断采样，不应再作为另一条原生表达式的输入。非有限结果返回数值范围诊断。

每个颜色结果包括实际触发的主题/系统/占位依赖、提示，以及真正读取过的原生引用节点与颜色节点。未使用引用没有伪造来源。主题循环检测贯穿占位表达式，不能在引用边界清空活动栈。

渐变颜色结果与原生停靠点严格一一对应，保留原顺序、重复位置与精确位置词法。某个颜色缺少上下文时保留其逐项诊断，其余颜色仍可用于检查；这不是一个已经可绘制的完整渐变。不会对停靠点排序、去重或擅自选择空间插值规则。

## 接口与预算

范围读取 API 为 `mo_kernel_api::resolve_pptx_fill_colors`，复用一次来源检查并接受宿主取消函数。开发入口：

```sh
target/release/mo-cli pptx-fill-colors request.json source.pptx
```

WASM 为 `resolve_pptx_fill_colors(requestJson, sourceBytes)`。请求包含 `expectedSourceSha256`、`surface`、`targets`、`fillProfile`、`colorProfile` 和 `context`。两个 profile 必须显式指定现有的 `ms-oi29500-fills-2024-draft-v1` / `ecma376-2016-draft-v1`。

每个目标保留原 `style`，另有 `colors`：

| colors.kind | 含义 |
| --- | --- |
| none | 原生无填充，不执行无关颜色计算 |
| unresolvedStyle | 填充选择未解决，原因保留在 style |
| imageResourcesRequired | 已有图片关系表达式，仍需资源和图片计算；不是透明颜色 |
| solid | 一个颜色结果 |
| gradient | 与原生停靠点同序、同数量的颜色结果 |
| pattern | 独立前景和背景颜色结果 |

同一批次共享填充继承、颜色步骤和百分比词法预算。默认填充最多 256 个目标；颜色最多 65536 个待求值位置（渐变的每个停靠点单独计数）、65536 步和 64 KiB 百分比数据。颜色位置预算同时约束重复目标，不是每个对象重置。所需表面的原生对象查找表按需建立并复用，每个查找/扫描步骤计入同一颜色预算；100 个停靠点不会各自扫描整个对象列表。

取消、源摘要冲突、来源绑定损坏和预算超限使整批失败，不发布已算出的半批结果。核心不加载文件路径、系统字体、网络或隐式系统色。

新增两份 Schema：`pptx-fill-color-query`、`pptx-fill-color-response`，总计 61 份。旧 59 份中只有主题色响应、线条颜色响应因共享颜色采样类型和新增诊断而更新，其余 57 份保持原字节。生成的新响应 TS 为 923 行；没有新增外部依赖或锁文件变化。
