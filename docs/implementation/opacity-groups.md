后续进展：[原生淡入淡出](fade-native.md)已接通时间图、页面与产品固定材料。本文保留透明合成基础阶段的验证范围；背景快照的跨组语义与完整性能验收仍待实施。

## 合同与计算

`PathRasterRequest.opacityGroups` 和 `DrawScene.opacityGroups` 描述绘制区间，按前序排列。每项包含 `firstDraw`、排他的 `endDraw` 和 `opacity`（0–65535）。区间只能嵌套或相邻，禁止交叉、倒序、空区间与越界。Draw IR 的区间引用 instance，几何降低保持绘制顺序与数量。

组内先在透明表面完成原有填充、描边、文字轮廓、图片、渐变和裁剪，再对完成的整组施加一次透明度，最后按 SourceOver 合成到父级。对每个填充分别乘透明度会改变重叠区，不能用于实现此语义。每个通道先按 `round(channel × opacity / 65535)` 得到预乘值，再按 `source + round(destination × (255 − sourceAlpha) / 255)` 合成。此版本使用现有 sRGB 预乘 RGBA8 输出，不是线性光混合档案。

快照属于捕获位置的最内层组；引用不得跨组。进入和离开组时恢复原画布裁剪状态，下一绘制重新应用完整的显式裁剪链。组没有权限、持久化、人的页面或系统资源获取能力。

空组列表省略序列化并沿用原帧版本。非空列表使用 V13 帧及 `mo_skia_opacity_groups_abi() == 1`。Rust 元数据档案和 TS 同步／分步入口识别该扩展；旧组件收到新组格式明确拒绝。

## 资源与执行

- 最多 4096 组、64 层嵌套；所有结构在后端分配前检查。
- 中间表面按最大嵌套深度复用，同层相邻组不逐对象重新分配。当前表面仍使用完整 viewport，保持既有全局坐标和扫描舍入。
- 中间像素与保留快照共用 64 MiB 上限，不包括最终输出、输入图片、字体和其他计算内存；不能将它当作进程 RSS 上限。
- 清屏和合成总工作不超过 268435456 像素；每个明确的像素工作单元最多处理 65536 像素。分配、Skia 内部准备和实际扫描的墙钟耗时需分别测量，不能据此宣称整个调用的延迟上限。
- 中途取消只释放私有计算状态；完整组与完整最终帧才可交付。继续复用现有扫描 continuation，不把整组藏进一次不可分步的 `saveLayer/restore`。

完整 viewport 在复杂文稿中仍有成本。后续需让已证明视觉边界的区域表面在保持扫描精度后参与优化，并测量真实动画工作负载；本阶段不宣称已达到最终性能和体积目标。

## 验证

[验证记录](../reviews/evidence/2026-09-28-opacity-groups-verification.json)固定了源码、组件、测试脚本和输出摘要：

- 154 项相关 Rust 库测试通过，其中新增 5 项结构、预算、快照范围及取消测试；严格 Clippy、Schema/TS 生成与类型检查通过。
- 12 项自有渲染场景覆盖重叠、嵌套、相邻组复用、透明端点、半透明抗锯齿、裁剪恢复、组内快照和 Source 清除；5 项非法 JSON 请求在进入后端前被拒绝，5 项非法二进制帧由独立组件拒绝。Native/WASM 的公开路径输出和元数据一致，适用场景也通过 Draw IR 路径。
- 另有 8 项既有椭圆／矩形／Office／映射渐变、图片、快照及裁剪输入：用此前固定组件在透明背景上的实际像素，独立计算整组透明合成期望值，逐像素一致。旧组件对新格式的同步、分步拒绝分别验证。
- 新组用例原生分步执行 204 次、WASM 分步执行 75 次；WASM 66 次计算句柄均释放。ASan/UBSan 执行 200 次，实际触发 68 次中途取消与重开，没有报告越界、悬空引用或未定义行为。ASan 未启用 leak detector，不宣称测得零泄漏。
- 554 个原有组件案例的状态与全部像素保持。以上是标准帧与资源生命周期证据，不是 Office/WPS 动画观感验收或终端产品性能报告。

首次新测试脚本误在消费式 `take_pixels(self)` 后再次调用 `free()`，绑定层明确报错。修正测试所有权用法后重新运行，未修改内核以绕过该错误。
