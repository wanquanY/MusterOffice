# 作者播放计划中的有界局部轮廓复用

2026-09-27。继续[组合导出与曲线一致性](group-export.md)暴露的局部性能回退，保留已经对齐的原生精度、完整像素和文件能力。完整一期与 Musterwork 替换验收仍开放。

## 状态归属与失效规则

`PlaybackPagePlan` 已持有不可变作者文稿、指定页面和时间计划。本阶段把不随播放位置改变的局部轮廓移入该计划：按文稿摘要、页面和稳定对象遍历位置绑定，尺寸、局部锚点或细分级别变化时重新计算。每个对象只保留一个精度版本；不持有过去的设备帧，不缓存时间求值、绘制结果或完成回执。

每次采样仍重新选择曲线细分级别，计算当前属性、组合矩阵、画笔、路径与矩阵误差、描边尖角误差，并执行最终设备精度检查。复用的是同样的局部路径与误差数据，不降低细分、不扩大容限，也不跳过每帧的正确性检查。普通静态页面仍使用临时轮廓；来源 PPTX 继续使用已有的来源计划，本阶段只调整作者播放路径。

取消在命中、构建前后检查；失败或取消的替换不会发布半成品。已经完整计算的轮廓不具有帧成功语义，可被后续合法采样复用。播放代次前进时清理时间状态、保留同一不可变文稿的局部几何；旧代次的结果仍由原有绑定检查拒绝。已准备的帧独立拥有编译场景，不借用轮廓表，释放与跨实例完成规则保持。

## 容量与宿主边界

每个播放计划最多保留 1024 个对象条目，核算载荷最多 1 MiB。载荷按路径 `Vec` 的分配容量及条目/键结构计算，而非只计有效命令长度。BTreeMap 索引和分配器额外开销由条目数量约束，**1 MiB 不代表整个表或进程 RSS 的硬上限**。

新轮廓超过剩余额度时仍以完整质量临时计算；不循环逐出先前已经准入的对象，因此大页面不会每帧把整个表反复换一遍。更高精度的单对象轮廓超过额度时也使用临时值，保留旧值供未来相符的采样使用。整个状态随播放计划销毁，不增加文件、数据库、全局缓存、权限或 UI。

## 实现与验证入口

实现位于 `mo-presentation-compile` 的私有 `page_geometry` 模块，由现有 `page` 编译与 `PlaybackPagePlan` 共用。没有改变公共接口、生成合同、TS 客户端、依赖或组件版本。

单元测试检查文稿/页面身份隔离、尺寸/锚点/精度替换、条目/字节双重容量、超额完整计算，以及取消/失败不发布半成品。集成测试跨三个播放代次覆盖正向、倒退、重复采样及实际细分级别变化；复用实例的完整编译结果与每次新建实例一致，作者文稿不变。

像素基线固定为上一阶段已经通过精度检查的真实原生 Worker 输出。除原有 64 帧作者/来源语料外，增加 1100 个旋转、翻转、不同颜色椭圆的页面，旧实现生成三次采样作为独立基线。新实现必须匹配全部像素和元数据，不用新实现重新生成期望值。

## 相同质量下的局部成本

Apple M4 Max、arm64、macOS Darwin 25.2.0、36 GiB、Node 23.5.0。三个自有 320×240 作者页面，无字体或外部资源。每个页面、每个版本使用独立的真实打包 Node Worker，分别记录首帧，再预热 10 次；两个嵌套页面各交替采样 200 次/版本，1100 对象页面采样 40 次/版本。全部像素与元数据按同一旧原生基线验证，检查位于计时之外。两版依赖、绘制与字体组件完全相同。

下表为 Worker 内部同步采样耗时，包含页面编译、绘制和结果校验，不含线程往返；括号为 P95，单位 ms。

| 页面 | 原完整精度实现 | 保留局部轮廓 | 中位数降低 |
| --- | ---: | ---: | ---: |
| 嵌套组合 | 2.054（2.477） | 1.327（1.529） | 35.4% |
| 嵌套组合及子对象描边 | 2.036（2.255） | 1.298（1.460） | 36.3% |
| 1100 个椭圆、超过保留容量 | 428.568（444.020） | 402.406（414.966） | 6.1% |

包含 IPC/结果传输的中位数分别从 2.141→1.414 ms、2.118→1.376 ms、428.694→402.544 ms。嵌套案例的局部成本显著下降，较上一阶段测得的曲线精度对齐成本有补偿，但两次运行的系统状态不同，不能据此认定所有工作负载消除了性能回退。

首帧不计入暖态分布，原始值、所有样本、最大值和内存快照保留在记录。系统负载、GC 和缓存未完全控制：优化后嵌套页面曾出现 59.373 ms 的线程往返最大值，1100 对象页面的内部最大值为 468.443 ms，后者大于旧版 448.034 ms。该大页面中位仍超过 400 ms，页面编译等长临界区仍需继续拆解；不能以平均改善宣称流畅播放、取消时限或整体性能已经达标。

## 内存观察的含义

每组在初始化、预热和多轮采样后直接读取该实例实际 Rust WASM 线性内存。两个嵌套案例预热后分别为 2,359,296 / 2,293,760 字节，1100 对象案例为 13,893,632 字节；直到最后一次采样均未继续扩张。相对旧版高水位分别增加 65,536 / 0 / 458,752 字节。

这些值包含内核其他分配，属于 WASM 分配器高水位，不是当前存活轮廓的字节数。实例 dispose 之后线性内存长度不缩小，不能用它判断物理回收。同步记录的 JS heap 和整个 Node 进程 RSS 受到两个 Worker、传输缓冲及 GC 影响，出现明显波动；本阶段没有给出全进程 RSS 上限或无泄漏结论。保留容量的逻辑约束由实现与边界测试证明，总资源验收仍需按设计档案执行。

完整动画语法、转场、音视频、SmartArt、公式、目标应用兼容及产品链路验收继续推进；本阶段不改变一期目标，也不表示可以直接替换 Musterwork。
