# 视频采样与编译合同

2026-10-06 · 开发中；本页描述已实现的纯计算语义，不是媒体渲染或产品验收报告。

## 1. 职责和入口

`mo-video-compile` 接收一个 `VideoDocument`，完整验证后计算内容摘要、各序列时长、可见轨道集合和轨道区间索引。`CompiledDocument` 不读取文件、网络、系统字体或设备；不持有业务任务或工程 head。调用方可共享不可变实例，旧实例不会因编辑候选或查询失败而变化。

当前实现编译全量工程，成本包括线性验证/摘要以及各轨道的排序建树。还没有按事务失效集增量重编译，不能把单次索引查询复杂度当成整个工程编辑延迟。

| 入口 | 结果 | 用途 |
| --- | --- | --- |
| `frame(n)` | `VideoFramePlan` | 第 n 个绝对输出帧的分组合成与源采样计划 |
| `visual_at(sample)` | 视觉节点树 | 精确 seek/边界分析，包括左侧极限 |
| `audio_sample(k)` | `AudioSamplePlan` | 第 k 个工程音频样本的语义检查/参考结果 |
| `audio_at(sample)` | 分层音频节点树 | 检查嵌套变速、反向策略和增益 |
| `PresentationIndex::select` | sample / gap / outsideWindow | 根据实际呈现区间选择 VFR 源帧 |

音频点查询不是生产 PCM 回调接口。实际音频执行必须将时间映射编译成连续处理区间，批量混音、重采样/时伸并补偿延迟；不能每秒运行 48,000 次完整工程查询。

## 2. 精确时间和左右侧极限

作者保存的时间仍为 `RationalTime`。计算中间值使用 `ExactRatio { numerator: decimal-string, denominator: decimal-string }`，JSON 输出约分，输入拒绝非规范十进制整数、重复字段、未知字段、非正分母和超过 4096 bit 的值。每个计算配置继续施加更小的 bit budget（默认 256）。不会为通过 `timescale <= 1e9` 而提前舍入嵌套时间。

源时间采样为 `TimeSample { time, side }`：

| side | 范围 `[a,b)` 对该采样的覆盖条件 | 含义 |
| --- | --- | --- |
| `after` | `a <= t < b` | 时间 t 的右侧；普通正向播放 |
| `before` | `a < t <= b` | 时间 t 的左侧；在倒放边界选择前一个源区间 |

`TimeMap::sample` 同时返回源采样和当前段精确导数。正速度保留 side，负速度翻转 side，定格返回固定源点的 after。分段锚点处，after 取下一段，before 取上一段。倒放从源结束位置开始时使用 `sourceEnd/before`，不减 epsilon，也不请求半开范围外的 `sourceEnd/after`。双重倒放翻转两次，恢复正确侧。

编辑用的 `map_boundary` 可以返回末端锚点，不能代替采样接口。两个接口均执行算术预算检查。

帧时间为 `n × frameRate.denominator / frameRate.numerator`；音频样本时间为 `k / audioSampleRate`。帧数和样本数分别为工程时长乘对应速率后取 ceil，含义是只包含起点早于工程结束的样本。负索引、空工程的第零帧和结束之后的索引返回 Outside；工程内空隙返回空节点树。最终容器的音频 padding/视频最后一帧时长由媒体输出合同处理，点采样计划不隐含容器策略。

## 3. 轨道、分组和效果

- 序列 tracks 顺序为从下到上的合成顺序；同轨重叠图形或音频按原 clips 顺序输出，时间索引不改变绘制/混音次序。当前视频轨仍遵守模型的非重叠约束。
- mute 从该序列的执行集合去除轨道，但不缩短工程时长。solo 分视觉与音频两个通道计算；已 mute 的 solo 轨不使其他轨无声。锁定只限制编辑，不影响播放。
- 嵌套 sequence 在视频轨实例中只投影视觉，在音频轨实例中只投影音频。需要复合片段两种内容时，宿主创建使用同一来源/映射的关联实例；不在视频轨背后隐式播放另一份音轨。
- 嵌套视觉保留 Group。先合成子节点，再按顺序施加组变换/透明度，禁止把组透明度直接分发给每一层；半透明叠层在这两种运算下结果不同。
- 嵌套音频保留每一级 time mapping、rate/pitch policy、增益/淡化。即使两级倒放的净速度为正，某一级明确 `reverse: mute` 仍必须静音；不能把所有 DSP 阶段粗暴合成单一倍速。
- Fade 按 clip-local 的显式 envelope 计算线性因子，使用精确比例。剪开/裁切后的相位不重启。范围之外为零；零长度淡入/淡出仍使用左右侧极限处理边界。
- 文字保留文本和显式字体资源摘要/face index；没有系统字体回退。当前节点不是已排版的 glyph run，真正排版仍待字体组件接入。

`VideoFramePlan`、`AudioSamplePlan`、`PresentationWindow` 的 JSON Schema 从同一 Rust 类型生成，保存在 `contracts/generated/`。这些合同未作为正式产品 SDK 发行。

## 4. VFR 源呈现索引

索引接收宿主从 demux/解码元数据得到的有限窗口：resource digest、stream、coverage 和呈现区间。样本 ID 是窗口内由宿主分配的身份，不根据平均帧率猜测帧号。

构造时检查 coverage、样本正时长、覆盖边界、呈现次序、重叠、身份唯一、数量和取消。出现重复/倒序区间时明确拒绝，不能通过静默排序或丢帧掩盖坏元数据。相邻区间允许不同长度和间隙；合法负源时间保留。

查询时验证资源摘要、流、视频类型及可用范围。修改素材不能复用旧摘要的索引。`gap` 表示已知窗口中的空隙；`outsideWindow` 表示需要宿主获取另一窗口，不能当作黑帧或末帧延长。源分辨率和名义帧率不参与帧身份推断。

该索引只描述呈现区间，不包含 DTS、关键帧或解码依赖。真正 B-frame seek、edit list、时间戳修复策略和解码器预热仍由后续媒体 I/O 合同与真实测试验证。

## 5. 有界查询与一致性

轨道索引是平衡区间树，每个节点保存子树最大结束位置；查询剪枝并恢复原 clip 次序。稀疏 10 万区间测试四个位置均访问少于 64 个节点；这证明没有线性遍历该轨道，不是 4K 播放、UI 延迟或完整工程编译的性能成绩。

查询限制包括 visits、选中的 clip 实例数、嵌套深度、输出字节和计算 bit budget。clip 实例数包含随后被显式音频策略静音的实例；大规模重叠不可绕开预算。复制节点/效果/文字前扣除保守扩展预算，最终再次检查序列化大小，所以可能在最终 JSON 达到字节上限之前拒绝。超预算/取消返回整体错误，不返回可误当成完整画面的部分结果。

测试包括：

- 2,048 组随机区间查询与独立线性扫描对照，覆盖负位置、空隙、重叠和两侧边界。
- 倒放嵌套末端、双重倒放、分组透明度、剪后 fade 相位、音频独奏、逐级保调策略、静音/定格，以及每个观察到的取消检查点。
- 分数帧率与音频绝对边界、超过作者时基范围的精确计算比例、非规范/过大 JSON 数值。
- Native 与 WASM 运行同一 15 查询合成元数据 fixture；11 次成功、4 次明确拒绝，完整结果及统计一致。单独断言关键边界、源身份、组层级和拒绝位置，不能以“两端同错”替代预期结果。

复现入口：`tools/verification/video-projection-parity.mjs`；已加入 `tools/verification/current.py` 的 wasm 组。它与原 25 步编辑事务对照共同执行，不能只比较预录结果。
