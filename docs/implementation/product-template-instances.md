# 原生模板参数实例的实际计算与交付

2026-09-28，Musterwork 独立 worktree 在原 `NativePresentationEngine` 端口加入 `office_template_instantiate`。它消费固定的原生模板包，通过已安装 SDK 进行原子参数绑定，再使用来源预览的同一渲染路径生成实例 PPTX、文稿快照、逐页预览和真实交付回执。这是原生压力验证所需的计算能力；`native_stress` 的覆盖计划、维护工具与完成证明尚未接通。

## 计算与资源边界

显式原生档案 `presentation.office-template@1` 的实例参数为：

| 字段 | 责任 |
| --- | --- |
| `template_ref`、`template_digest` | 实际模板包内容引用，以及 SDK 定义摘要 |
| `document_id` | 新实例的文稿身份 |
| `settings_digest` | 已冻结的设置、渲染器和实际字体组合 |
| `bindings` | 公共 SDK 的类型化参数值，由原子实例操作校验 |
| `source_resources` | 原模板资源在当前产品内容库中的精确引用 |
| `resources` | 实例所需的显式替换资源引用；没有替换时明确为空 |

来源预览和实例交付共用有界渲染实现、OfficeHost 计算额度、取消状态和 native worker。绑定计算使用公共 SDK 的 `InstantiateTemplate`，不另建产品文稿模型或渲染算法。实际输入、输出和资源别名仍计入原有预算，未引用的材料和未知资源 ID 被拒绝。设置变化不会静默产生新的渲染基线。

跨阶段重新写入内容库可能产生不同的 `content_id`。`source_resources` 允许调用方显式绑定新的内容引用，但资源 ID 集合、SHA-256、字节数和媒体类型必须与不可变模板包完全一致，实际字节也必须校验通过。此过程不修改模板包或原始 PPTX。消费模板的旧入口仍拒绝多余资源；新增实例入口将来源和替换输入分别完整消费。

结果保留 SDK 的实例化回执、来源/实例作用域映射、实际快照和交付资产。输入授权、文件存储和任务状态继续由 Musterwork 拥有；本次没有给 MusterOffice 增加权限、存储、页面或任务系统。

## 已验证范围

本轮 16 项相关测试通过，包括模板库、计算端口合同、实际引擎及原维护 Agent 定义回归；接入库全部 target 与 Artifact 库严格 Clippy 通过。每次验证记录源码清单和执行前后摘要。证据和失败记录见[验证报告](../reviews/evidence/2026-09-28-product-template-instances-verification.json)。

真实引擎专项在自有两页模板上分别绑定 1 和 100 个字符，两次执行各自结果一致。独立 Python ZIP/XML 检查确认：

- 两份实例各有 21 个部件，只改变目标 XML 的指定文字叶节点，其余 20 个压缩部件逐字节保持；原始 PPTX 作为来源继续完整保留。
- 实际验证每份实例的 12 项 SDK 资产。修改页的预览发生变化，未修改页 PNG 逐字节保持。
- 模板包仍使用原内容引用，实例使用不同的来源内容 ID；摘要、长度和媒体类型一致，重新绑定后计算成功。
- 实际拒绝短于/长于参数范围、错误模板摘要、来源身份变化、缺少来源、未知替换资源和缺字等七组输入。库级检查另覆盖媒体类型、长度、资源集合和字节篡改。

测试字体为项目自有的有限合成字体，成功用例选择其中已有的 `A` 和空格。首次使用 `W` 暴露了明确的 `UnresolvedFont` 诊断；该失败保留，并成为实际拒绝用例。当前成功样本验证的是字符数边界与真实文件计算，不能代表多语言字体覆盖或版面质量。没有添加隐式系统字体回退。

SDK 交付的有限结构检查为 `passed`；布局、原生编辑往返、播放及目标应用仍为 `not_proven`。即使 100 字符实例成功生成，也没有据此宣称其版面合格。本轮没有执行 Office/WPS 打开编辑验收，也没有测量发行体积或完整产品性能。

## 后续接入

下一步将固定模板与实例计算接入原 `native_stress` 阶段：由明确覆盖计划选定必需样本，沿原工具日志逐项计算，并在提交时独立验证覆盖和实际结果。多语言、资源、几何、主题及参数组合的覆盖、真实质量判定、修复后重新计算仍需完成，不能用这两份字符数样本替代。

自动上传协调器、原任务阶段推进、`native_verify`、原目录版本事务、Cloud/Web 路由与完整 PPT 替换继续实施。SDK/worker、候选 `device.v54 / author@7 / Skill v10` 与默认 stable 选择未变化；本轮没有启用生产替换。
