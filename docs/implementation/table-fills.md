# 原生表格填充计算

本阶段把真实表格单元格、表格背景及样式区域接入已有的填充、主题矩阵和工作精度颜色引擎。它是整页表格绘制的来源计算部分；边框、单元格画框与页面合成仍须继续接通。

## 实现与边界

`FillTarget` 新增 `tableCell`、`tableBackground`、`tableStyleFill`。单元格使用物理行列地址，覆盖单元格仍可查询，绘制器应只绘制合并区域的起点。`tableStyleFill` 用于查询真实样式区域及记录该区域的 `fillRef` 上下文；`region: null` 指向 `tblBg`，不表示整张幻灯片背景。原有对象、线条、图片及页面背景目标保持。

每批查询只为每个涉及的表格构建一次有效网格与样式绑定。网格的最坏遍历步数、临时条目和标识字节计入整批填充预算，后续查询共用预算与取消检查。颜色阶段缓存实际表格样式引用；一个渐变的多个色标不重复绑定同一原生引用。未来页面计算还需与[单元格框](table-frame.md)共用网格，并汇总填充、边框、文字、路径和保留资源预算。

单元格直接声明优先，其后按已有的十三个原生区域顺序解析，复用填充类型选择及逐项继承。区域顺序依据 [MS-OI29500 2.1.1265](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/90de4085-5fbf-47a7-bc37-d59509481d0a)。`noFill` 是显式无填充，不能被背景颜色代替。表格背景来自 `tblPr`／`tblBg`，独立于单元格背景；渐变和图片仍需在对应的原生区域中布局。

来源保留真实部件、XML 位置、表格身份和样式区域。共享样式直接声明使用 `FillOrigin::TableStyle`；主题矩阵填充使用原主题位置，并保留触发引用的表格样式目标。`phClr` 仅在颜色计算需要时读取对应引用，保留其变换至工作精度阶段。共享引用的 `sourcePart` 指向实际 `tableStyles.xml`。完整 sRGB 直接声明不会因为未使用的样式矩阵索引或颜色上下文而进行无关查找。

本阶段复用纯填充、纯色、渐变、图案和图片声明的解析计算。图片结果仍明确要求资源解析和原生区域布局；现有独立对象图片布局入口拒绝没有绑定表格区域的目标，不能拿整个 GraphicFrame 的矩形冒充单元格。非空背景效果保留显式待计算诊断。缺失内置样式定义、无效网格、未理解的选中声明、摘要冲突、取消和超出预算均保留对应结果。

这些规则属于现有 DrawingML 草案计算协议的扩展。直接格式与不完整区域填充的继承、合并单元格和 RTL 的最终表现，仍需实际 Office/WPS 校准；来源计算成功不代表整页视觉兼容。

## 验证与后续

源码用例见 [table_fills.rs](../../crates/mo-pptx/tests/table_fills.rs)，公共跨端与独立 XML 验证见 [Native/WASM 核对器](../../tools/verification/native-table-fill-parity.mjs)、[XML 来源核对器](../../tools/verification/native-table-fill-readback.py)。最终命令、结果和源码摘要记录在[本阶段证据](../reviews/evidence/2026-09-29-table-fills-verification.json)。证据只覆盖已运行的项目，不包括表格像素、Office/WPS 回存、安装包体积或性能结论。

431 项相关 Rust 回归通过，最终颜色上下文缓存与内存布局调整后，45 项填充回归再次通过；严格 Clippy、工作区全部目标、合同生成、TS 和原生／WASM 构建通过。6 份自有 PPTX 经公共接口完成 17 次跨端比较，涉及 68 个查询目标；独立核对 259 个来源位置、31 个实际使用的引用、40 个 XML 部件和 34 次 JSON Schema。另重放 572 个历史填充案例，共 1,144 次原生／WASM 比较，与冻结返回字节相同。来源部件与保留 payload 的渲染质量仍应在整页路径完成后另行验收。

下一步完成原生边框、共享边缘和合并冲突规则，再将背景、单元格填充、边框、文字和动画目标接入同一静态／保留式页面管线。完整表格通过实际公共运行时和应用验证后，统一更新独立 Musterwork worktree 的 SDK、导出 Worker 和播放材料；产品主工作区不参与这些操作。完整一期目标和替换门禁保持开放。
