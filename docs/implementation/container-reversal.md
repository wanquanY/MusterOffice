# 有限同步子树的容器反向时钟

2026-09-29：负速度已进入容器自身的精确时间计算，当前支持同时开始、同一有限时刻结束的子树，包含不同重复周期、嵌套方向、缓动、祖先截断、重新激活和范围跳转。一般错峰／不同长度子树、容器自动往返及完整替换验收继续实施。WPS 的负速度实测存在差异，本阶段不计作传统应用兼容通过。

## 计算与边界

容器反向不能只交换叶子动画端点。一般情况下还需选择反向激活区间，改变子项开始顺序，并处理填充和事件。当前准入要求每层子项都从局部 0 开始、没有内部结束条件或导航、有效跨度相同；多子项顺序容器不满足条件。每个后代只有一个已知区间，反射 `[0, D]` 后物理激活区间仍是 `[0, D]`，因此当前调度器可保持实际开始／结束通知和因果次序。准入不满足时返回诊断，不生成伪造的反向画面。

调度使用速度的绝对值计算物理耗时，容器以自己的有限跨度反射局部时间，再应用自己的缓动。层级逐层组合，不复制或改写叶子时长与变换。父时钟方向与叶子自身方向共同决定重复边界取值：反向进入时取终点，反向经过内部重复边界时取零；两次反向恢复正向，最终保持也恢复正向终点。计算使用精确分数及既有预算／取消机制，覆盖完整有符号速度范围，包括 `i32::MIN`。

祖先截断使用原始反向起点，不把截断位置当作新的反向终点。重新激活和 Previous 使用新的激活身份；Next seek 推进对应子树的物理时钟，不改变宿主时间。文稿、原生 `cTn.spd` 及各自层级原样保留。

时间模型依据 [SMIL 时间变换与负容器速度](https://www.w3.org/TR/SMIL3/smil-timemanip.html)；PresentationML 的速度属性见 [CommonTimeNode](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.commontimenode?view=openxml-3.0.1)。这些规范依据不等于 Office／WPS 的实际实现验收。

## 实际验证

543 项相关 Rust 测试、严格 Clippy 通过，其中新增 6 项覆盖重复边界和外部结束通知、两次反向与非对称缓动、截断、重新激活、倒退采样、Next／Previous、完整负速度范围、精确算术预算和未支持域的拒绝。此前“所有负容器速度都拒绝”的旧测试已改为验证错峰反向仍被拒绝。

四份完整自有 PPTX 覆盖反向重复、双重反向／缓动、截断和非对称缓动。72 帧由独立 Python Fraction 闭式公式核对，69 个可表示为原生整数角度的状态另与去除动画后的静态几何逐像素比较；20 个 PresentationML 根部件通过独立 XSD 校验。其余分数角度不舍入制造静态参考。

相同 72 帧分别通过实际打包 WASM Worker 的同步和分步执行。原有正向变速 72 帧、旋转组合 72 帧、包含文字／图片的缓动 40 帧在新包下保持既有结果。验证材料和源码身份见[本轮证据](../reviews/evidence/2026-09-29-container-reversal-verification.json)。

初次测试夹具缺少显式重新激活策略、预期分数没有约分，独立 Python 参考在整数截止处意外使用浮点数；均修正夹具并保留失败日志，没有修改生产计算以迁就错误期望。

## WPS 兼容差异

WPS 12.1.22553 实际打开同一份自有六矩形文件。六行分别是正向对照、容器负速度、容器 autoRev、叶子负速度、叶子 autoRev、容器与叶子双重负速度。对象原角度 20°，原生动画偏移为 0→80°，每个单程 6 秒。

中间截图六行都约为 34°；两次播放的最终截图方向分别约为 100°、100°、20°、100°、20°、100°。本样本中 WPS 将容器和叶子的负速度都按正向处理，autoRev 则回到初始角度。最终方向测量误差小于 0.2°，仅是对象方向观察；动态截图没有精确同步时钟，不能用来证明逐帧时序一致或 FPS。相邻旋转矩形的端部有重叠，因此方向测量使用中部条带的中心线，避免整体协方差被遮挡部分偏置。

这是一项公开保留的兼容缺口，没有据此让内核忽略负速度，也没有宣称 PowerPoint 行为相同。传统工具中的负速度可编辑互操作、容器自动往返和一般反向区间调度仍需分别补齐与验证。校准文件 SHA-256 未改变，结束后回到原 WPS 文稿，未改变用户前台应用。
