# 原生效果声明与来源绑定

2026-09-25。继续原方案，在填充、线条和颜色的来源模型之上接通原生效果声明。Rust 核心、Native/WASM 和生成 TS 共用一份实现。当前解决读取、结构约束、来源定位和保留式文本编辑；效果的继承、图连接及像素计算仍需实现。

后续状态：同日已接通[填充颜色](fill-colors.md)及按需上下文；以下范围与数字保留为本阶段封存记录。

## 共享读取层与平坦目录

`mo-pptx::source::effects` 定义 30 种 DrawingML 效果节点，覆盖标准 `EG_Effect`：容器、引用、透明度、混合、模糊、颜色替换、双色调、填充叠加、发光、阴影、反射、柔化边缘、色相/亮度、偏移和变换等。对象、图片外框、组合、页面根组合、背景、主题效果样式和图片 blip 接入同一声明层。blip 只允许自身的 17 种效果，不把完整效果集合放宽到所有位置。

填充与效果可以互相包含，例如 `fillOverlay → blipFill → blip → fillOverlay`。为避免 Rust 类型递归、来源 JSON 深度随嵌套增加，以及重复复制效果树，读取器统一在内部 `source::paint` 中维护显式栈；每个来源部件用 `effectNodes` 存储平坦目录，边保存原始物理节点序号。公开的填充、效果领域类型仍分别放在 `fill` 和 `effects` 中，线条读取器复用同一填充读取层。

这不是绘制图。容器的子节点 ID 已有物理来源；`effect ref` 的名称保持声明，还没有解析名称作用域、前向引用、循环或执行顺序。部件身份由目录外层的路径和源摘要绑定，不以节点序号跨部件寻址。

来源属性区分以下情况：

- 没有 `effectLst/effectDag`：没有本地效果声明。
- 显式空 `effectLst`：已知的空效果列表；不能与缺省合并为同一种状态。
- `effectDag`：独立容器声明，即使没有子节点也不擅自当作恒等操作。
- 未解释属性或扩展：保留在所属节点的 `retainedOrdinals`；不能因效果已类型化而丢弃。

效果内的颜色复用六种模型和有序颜色变换。相同 XML 名称由所在结构决定语义，例如颜色里的 `alphaMod val=...` 是颜色变换，效果里的 `alphaMod` 必须有容器。`effectRef` 保留索引和颜色声明，尚未套用任何填充索引规则。

主题 `effectStyle` 必须包含效果属性；后续的 `scene3d/sp3d` 暂时保留独立来源节点。这不是 3D 效果支持。

## 原生约束与资源边界

读取器检查效果列表顺序及唯一性、DAG 子节点集合、颜色/填充/容器必需项、互斥选择、20 种预设阴影、5 种混合模式和数值范围。属性缺省保持缺省，不提前写入默认值；百分比与通用坐标保持词法精度，整数 EMU 保持精确整数。

正坐标半径等字段只接受原生整数范围；支持通用坐标的位移等字段才允许 `mm/cm/in/pt/pc/pi`。固定角度为开区间，正固定角度和百分比使用各自范围。XSD 接受 `100.01%` 而规范正文限制最大 100% 的情况，继续单列为正文范围拒绝，不能冒称 XSD 已拒绝。

填充和效果共享全包 `max_paint_elements`、`max_paint_attribute_bytes` 预算，默认 100 万个元素及 32 MiB 属性值，取代之前仅名为 `max_fill_*` 的预算。底层 XML/MCE/OPC 字节、节点、深度和取消限制仍独立生效。未选中的兼容分支不进入活动目录，保留扩展中的同名原生节点也不能注入活动效果。

核心不加载外部图片、字体、网络或任意路径。未知内容仍依附源包保存；来源文本修改后会重新读取实际候选包，验证效果、填充与其他来源信息没有被改写。

## 填充查询的修正

背景中明确为空、没有未知属性的 `effectLst` 不再阻止背景填充解析。非空列表或 DAG 返回 `effectEvaluationRequired`；未知内容仍返回 `retainedContent`。图片中已识别的效果也有专门的待求值诊断。已知效果和未知扩展同时存在时，剩余未知扩展仍能阻止查询被误判为成功。

普通形状的填充查询仍只描述基础填充，不表示该对象的完整效果已经绘制。颜色表达式、图片关系及完整效果画笔没有因返回填充表达式而完成。

效果列表的实际绘制需要标准规定的默认效果图，不能直接把 XML 子项顺序当作逐项图像过滤器；例如阴影的输入包含哪些先前效果，需要按规则连接。依据为 [EffectList 的标准语义说明](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.effectlist?view=openxml-3.0.1) 与 [EffectDag 的结构说明](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.effectdag?view=openxml-3.0.1)。这些语义将在求值阶段独立实现和验证。
