# 产品云端原生宿主与执行路由

2026-09-28，Musterwork 独立 worktree 已为原云端维护执行器接入固定的 MusterOffice SDK/worker，并让执行路由区分原生模板与旧 HTML 引擎。真实计算、路由及旧数据升级在本机通过验证。自动上传前的环境发现、完整产品会话和替换验收仍未完成。

## 已实现的产品组合

Device 与 Cloud 共用产品适配层的 `OfficeRuntimeConfig`。宿主在启动时校验 worker、设置和字体文件的精确摘要，使用 SDK 自身的 `DeliverySettings`，不另造设置语法。文件在加载后成为明确的进程材料；Agent 请求不能指定宿主路径或替换可执行程序。

Cloud 的可选配置包括闭合的原生组件 JSON、私有暂存根目录和 1–64 个计算名额，默认一个。全部省略时保留原配置；部分填写或校验失败会拒绝启动。输入和输出分别限制为最多 1024 个资源、单资源 128 MiB、总量 512 MiB，单次 worker 超时 120 秒。这些是材料与并发边界，不是进程内存占用的硬上限。

原云端维护 Agent 与产品计算路由共用同一个 `OfficeHost`。启动和既有内容维护循环负责有界暂存恢复，沿用取消及存活租约机制。新增宿主逻辑独立于原组合文件；不新增任务队列、数据库平台或用户页面。本阶段的宿主配置、路由和维护均属于 Musterwork，MusterOffice 的纯计算边界未改变。

## 路由与升级

Runtime 迁移 `0206_presentation_route_compiler.sql` 为原执行记录增加不可变的编译档案。旧记录默认保留 `presentation.html-ooxml@1`，原任务策略、修订、取消和私有请求信息不变。

`presentation.office-template@1` 只允许在已配置的原生执行器上运行。旧浏览器引擎的在线状态不能使其取得原生执行资格；当产品策略要求 `client_only` 时，当前没有合格原生客户端路由，因此明确拒绝。已经选择的策略和档案保持固定；原生失败不改走 HTML 引擎。旧 HTML 流程原有的显式浏览器失联接管继续可用。

以上接通的是云端执行能力；稳定发布档案未切换，未新增公开的原生 Cloud Tool，也未将上传入口直接切成原生策略 /3。

## 验证范围

[验证证据](../reviews/evidence/2026-09-28-product-native-cloud-verification.json)记录最终源码、命令、日志和实际文件摘要。31 项不同测试通过：云端配置与真实计算 3 项、Device 启动维护 3 项、共享适配器 19 项、真实 PostgreSQL 路由及升级 6 项。四个相关库通过严格 Clippy 检查。

- 通过正式 Cloud 配置打开宿主，使用固定 SDK/worker 导入、渲染和导出自有两页文稿。12 个逻辑资源通过摘要和长度校验，两张实际 PNG 为 640×360；原始与导出 PPTX 字节相同，ZIP CRC 和 20 个 XML 部件解析通过。
- PostgreSQL 验证并发选择、档案与策略固定、跨用户/租户隔离、取消、拒绝错误执行位置，以及从实际旧路由表升级后保留全部原字段。测试使用隔离容器，不连接产品数据库。
- Device 继续验证原有配置兼容、启动恢复和私有目录检查。共享适配器覆盖固定文件、取消期间名额持有、来源字节和压力计划边界。
- 首次严格检查发现四处既有 PostgreSQL 语法告警，已作等价整理；没有屏蔽告警。首次测试的一处字段断言错误已改为读取实际检查报告，未改变生产校验。

这里使用 macOS ARM64 Debug worker。它既不代表 Linux 云部署，也不代表桌面发行包大小。路由和配置宿主分别进行了真实测试；完整后端、云 API、父子维护任务和外部模型尚未在本阶段联机验收。实际交付仍仅声明结构检查通过，视觉保真、外部编辑往返、播放和目标应用声明均保持未证明。
