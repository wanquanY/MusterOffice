# 原生缩放动画

2026-09-27。对应 F06.03/F06.08 的增量实现，完整动画和一期替换验收保持开放。当前实现是显式起止值的二维缩放，不代表已覆盖全部 PowerPoint 动画语法。

后续[原生缩放输入与 WPS 校准](scale-inputs.md)已扩大 by/to-only 输入范围，并实测发现当前直接时间树导出不能让 WPS 正确播放。以下测试及数字是本阶段历史证据，不代表目标应用互操作通过。

## 计算与接入

`mo-timeline::Effect::Scale` 持有目标及 `from/to: {x, y}`，单位为千分之一百分比，100000 表示原始尺寸。范围为 0..2147483625。时间树、事件历史、重复、结束条件、速度、自动反转和缓动仍由同一时间求值器计算；缩放与旋转具有独立的替换优先级，同一属性按开始时间和树中顺序确定结果。

`FrameState.scales` 保留精确有理数。在共享坐标边界才转为向外包围的 Q96 区间，随后携带 Q32 误差界进入已有绘制链路。缩放改变对象的可视空间，中心保持不变，原始尺寸、组合子坐标、文字排版、图片裁切和原始声明保持不变。组合及子对象复用统一的坐标计算，不让宿主拼接另一套 CSS 变换。

创建的文稿与导入的原生文稿都使用 `SampledTransform`；已准备的图片和文字资源在采样时继续复用。SDK/WASM/原生 Worker 接收已有的创建、时间修改、播放接口及生成的类型合同，不增加 UI、网络或持久化。拥有缩放行为的时间图输出 `musteroffice.transform-frame/0.1-draft`，对应页面输出使用 transform profile；既有纯旋转输入保持原有 profile 和序列化。空 `scales` 字段不写出，但等待事件的缩放时间图仍能通过 profile 辨认。

Rust SDK 的帧响应校验调用核心的 profile 选择规则，来源页也使用核心计算的 profile；不会在接入层维持只接受旋转的旧白名单。旧的已编译 SDK 不理解新增 Scale 枚举，接入方需使用配套的新 SDK，不能把旧类型库与新 worker 当作已兼容。

对于严格证明某一局部轴为零的对象，填充面积为零，不需要求图片或渐变画笔逆矩阵。判断同时检查名义值与误差界，没有面积阈值，也不会把微小非零尺寸当成零。声明、资源及内容仍先完成验证，绑定和文字遍历保留；后续采样恢复时继续使用原有资源。

## PPTX 映射

导出为原生 `p:animScale`，写入 `ScaleX/ScaleY` 和明确的 `p:from/p:to`，与旋转共用 `cBhvr`、目标、条件和时间树写入逻辑。没有将对象或播放帧转换成图片。导入的原始 OPC 由来源层持有；不支持的语法返回诊断，不悄悄丢弃动画。

当前来源计算只接收显式 from/to、repl、none、pt 及已有已实现的时间条件。`by`、仅 to、`zoomContents`、属性累加、额外属性名和更广的原生默认规则尚待逐项接通；超出整数千分之一百分比表示范围的词法不会舍入接收。上述限制不是缩减一期设计目标。

依据：[微软 animScale 实现说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/358c6de3-2cd7-459b-8eb9-b90f3721fd12)说明属性名、组合方式及仅 to/by 的起点；[微软 from 范围说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/b4e7ea1e-7bb9-454d-96a3-61c6fcd0ea9a)约束对象尺寸百分比。仅凭文档和内部一致性测试，不能确认目标应用的非均匀组合缩放或动画叠加行为已一致。

## 验证边界

测试覆盖独立属性、精确分数帧、同属性替换/恢复、点击和结束条件、缓动、自动反转、组合中心、图片资源复用、零尺寸、取消、来源不变，以及原生 XML 时间树回读。使用独立静态尺寸改写作为组合空间对照，不能把它当作 Office/WPS 对照。

最终 21 步门禁通过，含 958 项 Rust 测试、119 份合同及生成的 TS、21 项 TS 播放客户端测试与四项实际 native 播放测试。常规 Rust 测试另有 25 项默认忽略，显式执行的组件/worker 测试另列于证据，不把所有忽略项算为通过。

新语料包含作者组合缩放及来源文字图片、组合图片、圆形渐变共 24 帧；原生单次 Worker、从独立源码包编译的 Rust SDK consumer、Node Worker 的分步 WASM SDK 和隔离 Chrome 153 均核对完整像素与对应元数据。三个零尺寸帧与独立移除对象的原生文件得到相同像素。原生 SDK 和 Node WASM 另回放原有 71 帧；旧像素及元数据不变。四份原生文件共 28 个 PML 部件通过固定 ECMA-376 XSD，包含六个缩放行为。

当前开发用 WASM 播放包为 60 个文件，未压缩 14,495,206 字节（不含 manifest），压缩归档 4,166,180 字节；比上阶段分别增加 70,697 和 16,476 字节，主要为 Rust WASM 增加 69,780 字节及生成的声明类型。两次构建归档一致。Rust SDK 继续包含 25 个同源库、54 个 registry 依赖，两个源码归档一致。本阶段没有新增依赖、字体/图形组件或产品代码，没有测量新的吞吐、RSS 或完整桌面安装包体积。

完整记录、源文件摘要、失败和修正见[本阶段证据](../reviews/evidence/2026-09-27-scale-animation-verification.json)。完整动画/转场、媒体、SmartArt、公式、跨应用保真、持续性能预算与 Musterwork 替换验收仍需继续推进。
