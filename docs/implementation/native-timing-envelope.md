# 原生演示效果组织与平面时间图

2026-09-27。[缩放输入与 WPS 校准](scale-inputs.md)之后的实现增量。目标仍为完整演示文稿内核；本阶段修复平面变换动画的原生组织，不代表完整主序列、任意时间树或 Office/WPS 验收完成。

## 原因与设计

此前直接把行为写在 tmRoot 下，虽然 XML 和内核回读合法，WPS 不识别动画。新的成对实验保留相同主序列、容器、目标和行为，仅为六个效果加入 presetID、presetClass、presetSubtype：没有元数据时放映保持原尺寸；加入后六个矩形均放大。该自动播放实验没有 prev/next 条件，seq 明确关闭 concurrent，nextAc/prevAc 为 none。因此导航并非这个场景的必要条件，不能为解决识别问题而先忽略导航语义。

对 `Timeline.tree == None` 的已有变换图，Writer 增加明确的原生组织：

```text
tmRoot
  mainSeq（唯一子节点、无导航条件）
    parallel（开始 0、无限时长）
      parallel（开始 0、无限时长）
        effect（每行为一个，开始 0、无限时长）
          原始 animScale 或 animRot
```

所有新增容器均 restart=never、fill=hold，没有结束条件、重复或变速；单子节点序列不引入顺序等待，零开始、无限父区间不改变行为时钟和截止。每个效果只拥有一个目标行为，避免此前把六个目标合并成一个效果而只播放第一个对象的问题。第五层效果拥有带有效目标的子行为，对齐[微软 tnLst 结构要求](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/55167345-00ff-4d39-b4a8-6ca61d86227a)。

`TransformPreset` 统一 Reader/Writer 使用的缩放和旋转编辑身份；具体起止值仍在行为中，不由 preset 替代。缩放使用 emph/6，旋转使用 emph/8，子类型 0。WPS 自有实验是本阶段的应用依据；微软[旋转时序示例](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-ppt/13b03cf8-e193-4d7c-bece-efee91ea40bd)也记录了 emphasis Spin 的效果编号 8，但该页属于二进制格式说明，不据此声称所有 OOXML/应用版本均已通过验证。

行为 cTn ID 继续为 2..N+1；新增 ID 在行为之后分配，最大 ID 用 checked 算术验证。原有 onBegin/onEnd 引用、目标、延迟、结束条件、重复、fill 和时间变换原样写入。普通无动画文稿及显式分层树仍走既有路径；任意分层图的原生演示组织尚待单独实现，不能宣称该路径已解决。

## 来源投影与边界

Reader 只提升可证明时序中性的上述结构。无须私有标记或特定 ID 排列；原始 OPC 继续保存完整编辑信息。提升后仍是既有平面计算图，保留全部行为和对象绑定。

每层的属性、子节点顺序、开始条件、无限时长、fill/restart、效果和行为匹配均严格检查。容器 ID 与根、其他容器、行为不能重复；引用被提升掉的容器会报缺失依赖，不改绑到另一个节点。任何未知属性、扩展、额外效果行为、非零开始、有限父时长、容器结束/重复/变速、导航或并发均不会被静默丢弃。

计算节点限额继续按投影后的语义节点计算。XML 捕获上限为 32×max_nodes+32，包含固定主序列与每效果的组织开销，保留独立 XML 字节、深度与元素限制；行为、条件及计划仍分别执行已有预算和取消检查。

本阶段没有加入播放器界面、权限、存储或后台计时。宿主只提供时刻和输入事件；结构、语义及诊断属于内核。

## 验证结果与范围

18 步门禁通过：972 项全仓 Rust 测试、119 份合同和生成类型、严格 Clippy、显式原生集成、WASM 构建与公开入口对照。常规测试另有 25 项默认忽略，显式集成单列，不把所有忽略项算作通过。新增四项测试覆盖完整平面图和事件时钟、非中性容器拒绝、身份冲突/容器引用、语义节点及 XML 捕获预算；已有 17 项时序与缩放测试继续通过。

两份六对象文稿经生产 CLI 导出；Native/WASM 导出字节完全一致，12 个相关 PML/DML 部件通过固定 ECMA XSD。与上一版 Writer 相比，只改变 slide1 的时序结构，12 个行为子树、其他幻灯片内容及其他包部件保持不变；PPTX 分别从 5,939/6,032 字节变为 6,064/6,161 字节，增加 125/129 字节。成对元数据控制文件另验证了两份 slide XML，且仅六个效果的 18 个 preset 属性不同。

24 组作者/导出来源帧涵盖起点、分数时刻、结束、回看、延迟依赖、remove/hold、旋转及往返重复，完整像素、属性值和节点状态相同。48 个新帧加 139 个冻结旧帧，在独立 Native SDK consumer、打包后的 Node WASM 分步播放及 Chrome 153 隔离 Worker 上分别核对 187 帧、25 个 owner。这里证明跨端与投影一致性，不把共同使用内核的结果当作 Office 参考。四份来源查询也得到相同 Native/WASM 结果：两份实际导出和有元数据控制成功，无元数据控制明确拒绝。

WPS 12.1.22553 / macOS 26.2 arm64 实际打开并放映内核直接导出的两份自有文稿，动画预览可用。保存的 3840×2100 最终画面测得：

开发用 WASM 播放包仍为 60 个文件，未压缩 14,521,676 字节（不含 manifest）、压缩归档 4,174,438 字节；比上一阶段增加 10,343/2,823 字节。只有 Rust WASM 改变，TS、合同、Skia、HarfBuzz 和依赖清单不变。未测量本阶段吞吐、RSS、取消尾延迟或完整桌面安装包；未重新生成 Rust SDK 源码归档，既有独立 consumer 配合新 worker 验证稳定协议。
