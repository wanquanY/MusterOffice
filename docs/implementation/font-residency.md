# 计算作用域内复用已验证字体

2026-09-30。状态：内核实现与局部验收完成；本节证据形成时尚未激活到产品。

真实 Agent V6 的三页、21 个文本框文稿在第二页触发 `native frame component work`。
其草稿语义摘要与本地回放逐字相同，旧 Worker 同样失败。根因是原生页面的 1 GiB 字体
输入预算按每次塑形、度量、轮廓调用重复计算完整字体；窄中文文本框需要在真实行上下文
中尝试多个断点，WASM 适配器也确实每批重新分配并复制字体。不能通过改成单调宽度假设、
缩减文稿或提高预算来解决。

现在 `PreparedManifest::font_session` 创建单页/单框计算作用域，只对已验证且仍被不可变
借用的字体分配组件句柄。句柄仅绑定该组件实例，结束、错误或取消时释放；不跨请求持久化。
Native 组件持有一次有界不可变副本，WASM 组件在自己的内存中只复制一次，后续塑形、度量、
轮廓共用。没有新增 C/C++ ABI、网络、字体发现、磁盘缓存或依赖。

组件最多同时保留 32 份、合计 128 MiB 字体；句柄不回收复用，失效句柄被拒绝。失败组件
按原规则隔离。不能注册的历史自定义后端继续走原批接口并承担真实完整输入计量；不会
获得缓存后的低计量。非目录内的字节视图同样不享有句柄复用。Rust 不保存可悬空指针，
只在不可变借用仍有效时比较字节地址与长度；Native 句柄持有 `Arc<[u8]>`。

原有 1 GiB 字体预算、4096 次组件调用、请求字数、字形/路径与换行候选预算全部保持。
`fontUploadBytes` 记录当前作用域真实交付给组件的字体字节；调用数与请求字数仍逐批累计。
标准 Native 与 WASM 的预算及观测保持一致。行上下文、fallback、双向文字、断点搜索、字形
验证、Q32 计算和绘制算法未改。私有 WASM 适配器增加五个字体句柄方法，必须与对应 Rust
WASM 一同按摘要交付；旧适配器不能冒充新固定包。

## 证据

- 102 项文字单元测试、91 项页面编译单元测试、3 项原生组件单元测试和 24 项实际原生
  frame/page/capacity/table/resource 测试通过；严格 scoped Clippy、TS 检查通过。
- 自有多框页面在仅允许一次字体输入的预算下成功；旧批接口和复用接口的像素与除字体
  传输计数外的全部页面元数据相同，组件调用次数也相同。作用域释放与下一次重新注册可观察。
- 真实 C++ WASM 组件九次塑形/度量/轮廓回复与原接口完全相同，仅分配一次字体；调用方
  修改原数组不影响已注册内容，释放、失效句柄、数量预算及空输入检查通过。
- 失败文稿保留完全相同的模型、语义摘要、字体及字号后，默认预算内导出成功。三页分别
  调用 9/93/98 批，每页输入字体 17,772,300 字节。单次本机导出观测 2.119 秒，仅是该次
  局部观测；没有旧成功基线，也不是产品性能或 P95 结论。
- 原始版面仍报告 9 个容量/字形范围问题。公开计算接口只改对应框的尺寸，保留文字、
  字号及其余模型字段，再次导出后容量问题与相交候选均为零。该操作是确定性回放，**不是
  模型自主修复证明**；没有把诊断清零等同于视觉验收。
- 修复前后各三页共六页，完整交付检查、页面元数据、测量与 RGBA 在 Native/WASM 一致。
  另对此前 V5 的已验证文稿复验，三个 PNG 文件与 PPTX 文件均逐字节不变。
- 本次固定 macOS arm64 Worker 为 12,472,128 字节，比此前 c0a7100e… 的 12,466,976 字节
  增加 5,152 字节。字体包未变；不是整个桌面安装包大小，也不推断其他平台体积。
