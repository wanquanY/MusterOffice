# Musterwork 独立接入工作区

当前工作位置更新（2026-09-30）：独立接入已合并；用户明确要求后续实现和验收直接在
MusterOffice 与 Musterwork 两个主工作区推进。内核保持 `main`，产品保持用户选定的
`codex/shared-project-acceptance-20260916`，不另建 worktree。以下保留先前隔离阶段的历史记录。

2026-09-27，用户要求新建 Musterwork worktree 持续完成对接，将原主工作区留给其他产品开发。此授权只改变 Musterwork 的工作位置；MusterOffice 继续使用原主工作区，完整一期、内核边界和替换验收目标不变。

## 隔离与迁移

- 接入分支：`codex/musteroffice-integration`，基于当时产品 HEAD `8280b9837b7ed7fae5a502e97d6967b128772c11`。
- 迁入 1,073 个未提交文件：53 个已有文件的改动、1,020 个新增文件。其中 904 个文件是两版固定 SDK 的源码副本，169 个是产品代码、配置和验证材料。
- 迁移前保存完整二进制差异、全部文件字节、权限与 SHA-256。新 worktree 逐文件一致、Git 差异一致后，逐项移走原主工作区中对应的改动。迁移期间有变化的文件应留在原地；本次未发现此类冲突。
- 原先被组件 `.gitignore` 隐藏的 874 个 SDK/worker 开发文件一并保留、迁入和备份。没有迁移账号配置、运行数据库或用户文稿。
- 迁移完成时，原主工作区 `git status --porcelain` 为空。该状态是迁移时的检查，不约束用户此后的开发。
- 新 worktree 的准备脚本已实际验证固定 SDK 清单和 macOS ARM64 worker 的摘要。备份及机器路径保存在忽略的 `.codex-work/musterwork-isolation-20260927/`，不进入公开资料。

这是工作位置迁移，不是合并、公开发布或产品替换完成。已有未验证实现也原样迁移，历史通过记录不能自动覆盖当前工作区。

## 后续执行边界

所有 Musterwork 源码修改、准备命令、编译、测试和产品侧诊断均显式指定新 worktree。不得继续写入原主工作区，也不得利用其运行数据进行接入测试。用户在原主分支的新提交以后通过明确的分支同步处理，不覆盖其未提交内容。

接下来按产品链路收敛：

1. 补齐已有 SQLite v188 实现的历史升级、失败回滚、不可变引用及实际写入测试，恢复当前工作区的可验证状态。此步骤不继续扩大为全产品存储治理，不启用业务终态回收。
2. 升级产品固定材料，消费当前公共计算 SDK，检查其依赖不包含旧业务宿主；接通真实 Agent 工具入口和既有 Invocation、Artifact 提交。
3. 对接产品自己的读取、查看与播放入口，并完成失败、取消、重启、历史内容和资源生命周期验证。
4. 完整功能、Office/WPS 可编辑往返、Native/WASM、性能、体积及 E0–E3 分别验收。未通过前不宣称已替代原 PPT，也不以接口存在或局部示例通过计为完成。

完整需求不会因工作区隔离而缩减。当前高级内容和主序列兼容缺口仍在内核侧实施，见[总进展](progress.md)和[边界合同](../design/implementation/kernel-host-boundary.md)。
