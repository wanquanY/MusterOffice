# 原生复核接入现有产品任务

2026-09-28，继续在用户指定的 `codex/musteroffice-integration` 独立 worktree 实施。原生复核已接入 Musterwork 的快照、准入、任务循环、完成记录及协调器；最终模板验证阶段尚未发起这条链路，不能据此宣称完整替换完成。

## 实现与职责

在[原生交付复核绑定](product-native-review-binding.md)之上，产品增加明确的 `NativeVisualReview` 用途，以原生对象摘要和页面 ID 标识复核。它必须绑定父任务和原生编译档案；不填造旧 HTML 草稿和候选 ID。既有复核工作对象使用封闭的旧候选/原生对象联合类型，共用原 Agent Loop、任务查询、内容库、使用量日志和取消机制。

后端独立检查原生 JSON 的规范字节、摘要、图片顺序和引用；只有策略 /3 的整份 `native_verify` 父任务可以申请这类复核。生产结果与全部图片必须位于父任务已授权的精确输入范围内。原有用户、任务状态、代际、取消、模型路线和准入冻结检查继续适用。每次子调用只复核一页最终图片；原生来源目前没有外部应用参考图片，因此不虚构逐页来源图。

协调器恢复已完成的子任务，验证对应快照、实际模型请求/响应、图片与输出合同后汇总结果；缺少父输入、错用其他对象的子快照、换报告套用旧结论均不能通过。原生对象不接受历史模型回显摘要输出。`needs_revision` 是完成的复核结论，不是质量通过。

本次协议增加了 Protobuf oneof tag 17，同时更新 Python/TypeScript 生成代码和兼容性锁。跨语言测试发现 Prost 按 oneof 最小声明 tag 定位，而 Python 确定性编码按实际选中 tag 排序，导致新快照的签名摘要不同。协议编码器明确按字段编号编码新增分支，保持原 5/6 分支的全部历史字节；没有放宽规范字节、摘要或恢复校验。

这些都是接入产品的工作流职责。MusterOffice 未新增模型、权限、存储、任务或人机页面，公共 SDK 与 worker 固定材料未改变。

## 验证

48 项相关测试通过，见[阶段证据](../reviews/evidence/2026-09-28-product-native-review-run-verification.json)：34 项后端新旧准入与材料检查、2 项 Python/Rust 独立规范字节对照、10 项实际 Loop/SQLite 新旧复核测试、2 项新旧父任务取消测试。六个相关生产库通过严格 Clippy。

另外，正式协议检查完成生成代码一致性、持久化协议兼容性锁、12 项协议测试、1 项真实 Rust Tonic/Python 客户端调用测试、TypeScript 类型检查及 Python 导入检查。本阶段共 61 项测试，不与历史阶段累计。

原生测试实际运行原 Agent Loop 与 SQLite，检查逐页图片、格式纠正、完成记录、使用量及协调器重复查询。进程中断位置使用持久化的 staged completion 模拟，恢复时成功输出不重新调用模型，格式错误只执行纠正调用。父任务停止传递到子任务心跳，停止后的新子任务被拒绝；已准入记录重复提交仍保持幂等。测试不是进程强杀或外部模型网络故障验收。

模型使用确定性 Provider，像素输入为自有协议夹具；本轮证明任务与证据机制，不证明视觉判断质量。实际 SDK 交付图片的检查属于上一阶段记录，本轮没有重新渲染、进行 Office/WPS 操作或测量发行包大小。测试耗时不作为性能结果。后端测试保留既有 Pydantic 弃用等告警，不将它们隐藏为零告警。

## 继续实施

`native_verify` 仍需从原 `native_define`、`native_stress` 的不可变检查点逐项导出来源及全部压力案例，执行 SDK 检查、证明对应 Tool 生产结果、创建复核对象并调用本阶段链路；最终阶段完成证明和原目录提交尚未接通。自动上传选择、历史迁移、完整高级内容及替换门禁继续实施。已检出的宽文字溢出不能被确定性通过结论、缩短文本或静默缩小字体掩盖。

工作区隔离继续遵守[接入工作区记录](product-worktree.md)，不回写用户的 Musterwork 主工作区。
