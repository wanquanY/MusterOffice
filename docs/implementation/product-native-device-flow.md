# 同次上传至桌面文稿版本的连续链路

2026-09-28，在独立 `codex/musteroffice-integration` worktree 中，将[上传至模板入库](product-native-catalog-flow.md)继续接到实际桌面 Runtime 准入和原生文稿工具。Musterwork 主工作区没有参与写入、构建或测试。此阶段完成一条连续验证链路，完整一期替换仍未完成。

## 实际产品路径

同一次自有两页 PPTX 上传，仍经过原导入器、冻结策略、签名、真实 gRPC/PostgreSQL、维护 Agent Loop、固定 SDK/worker、18 个独立审查子任务、9 次父任务等待恢复、最终检查和不可变目录版本提交。没有借用此前完成的任务记录。

后端为新创建的测试设备签发当前 v8 执行许可和设备凭据。桌面侧通过原产品应用创建会话、签名准入、构建和封存 Runtime Snapshot，再由原调度器领取任务。使用当前编译目录构造测试账户能力范围；这是显式测试输入，不是新的生产权限实现。

正式 `tool_catalog_activate` 启用 author@7 后，原 `MusterworkToolExecutor` 执行模板查询、实例化、环境发现和导出。模板来源通过原 `BackendPresentationTemplateSource` 调用还在运行的后端接口，权属、固定版本、摘要和资源验证均保留。

联调最初直接调用处理器，触发 `RuntimeSnapshotInvalid`；原因是跳过了执行器中的参数级策略。最终测试改用完整执行器，保留 `supervised` 准入和保守的初始审批状态，由原参数策略根据不可变当前任务记录进行判断。没有手动修改授权材料、降低权限检查或伪造审批记录。

## 新文稿、版本与恢复

模板绑定文字 `A A A` 后产生独立文稿，模板版本不会成为它的文稿父版本。原 SQLite 事务和 Tool 日志提交实际导出版本 1。随后弃用草稿、重新打开数据库，从已发布版本恢复新草稿，编辑标题，再为同一 Artifact 导出版本 2。

版本 2 的实际 PPTX 再通过 `begin/import` 导入为另一份文稿。输入权限来自之前 Tool 结果日志中的精确输出引用，没有补造附件。导入后实际查询读回两页内容和新标题。

两个导出版本各保留 PPTX、产品 manifest、回执及完整资产集合，包含页面预览、可编辑模型、来源、环境与质量报告。独立 ZIP/XML 检查确认两个文件都有两页和绑定文字；第二版标题正确，两个版本只有 `docProps/core.xml` 的未压缩内容改变，其他部件保持一致。

## 实际验证

103 项不同功能测试通过：1 项完整跨进程 Device 消费链路、26 项原生工具回归、2 项上传定义/压力回归，以及 74 项 Python 回归。全部显式环境用例实际运行，没有跳过。独立核对 227 个留存文件条目的摘要和长度，其中 197 个来自上传及定义/压力流程，30 个来自桌面端两个导出版本；另记录模板描述、重导入查询、结果与命令日志摘要。详见[可复核证据](../reviews/evidence/2026-09-28-product-native-device-flow-verification.json)。这些是文件条目数，包含不同阶段重复保留的内容，不是唯一资产数。

扩大回归时发现历史原始导出请求仍固定旧 worker 摘要，以及引擎和模板测试都使用 `-source` 输出目录。旧输入和失败日志保留；新输入副本仅将 renderer 固定到实际已核对的当前 worker，文稿、资源和字体不变；模板输出目录独立命名后，26 项回归全部通过。错误 renderer 的拒绝测试仍保留并通过。

Python 静态检查、相关 Rust 格式检查和 Git 差异检查通过。整个历史 `sqlite_agent_loop` 目标严格 Clippy 仍报告 994 项既存诊断，新增 cloud consumer 文件没有诊断，没有关闭 lint。Python 回归有 294 项已有弃用警告。命令耗时只作诊断，不作为性能测量。

## 验证边界

测试使用真实签名准入、数据库、调度、曝光状态、参数策略、工具执行器、SDK、提交事务和模板 RPC；维护任务的模型工具选择与视觉判定仍是确定性输入。桌面下游工具调用也由测试驱动，尚未执行完整模型会话或桌面 UI 会话。

结构检查通过不能替代视觉质量、播放、Office/WPS 编辑往返或应用验收。两版回执继续明确标记这些项目为 `not_proven`。SDK/worker 字节未变，也没有新的性能或发行体积测量。stable 保持原版本，候选仍为 `device.v54 / author@7 / Skill v10`。

账户、授权、任务、目录和存储均属于 Musterwork；MusterOffice 仍只承担文稿计算和薄接入。下一步将下游工具序列接入完整 Device Agent Loop，并通过实际版本查询接到产品 Viewer/Player；继续历史内容、高级演示能力和各项替换门禁。
