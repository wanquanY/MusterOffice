## 宿主持久状态与调度

`StorageBusy` 只对应 SQLite `DatabaseBusy`／`DatabaseLocked`，不把损坏、权限或 I/O 故障归为可恢复竞争。每个 worker 退避从 25 ms 增长到 1 s 上限；数据库单次调用仍使用 5 s busy timeout。全部 worker 忙时，健康检查和能力发现报告暂不可执行；不自动重放已领取的计算或候选提交。已领取工作的租约、fence、原子 publication 仍由持久状态控制；无法续租或完成的工作按原有过期语义终结。

schema 6 新增 `job_bindings`，保存任务、文档、请求摘要及基础 revision 的不可变绑定。操作名与 requestId 复用已有列。迁移逐条验证旧请求与回执，在同一事务创建绑定；任一损坏使迁移整体回滚。原请求、revision 与历史回执不改写。新请求在 admission、执行加载和最终 publication 校验完整内容；轻量控制查询对照绑定和状态不变量，不重新解析文档。

数据库当前 schema 的连接建立不再预留迁移写锁。queued、未过期 running 和 terminal 状态读取只读；检测到过期时才获取写事务并重读，避免覆盖并发续租或提交。真正取消 running／queued 的状态写入仍需要写锁。`claim` 的写事务只改变领取状态，完整请求和 snapshot 在事务释放后读取。

跨连接持久取消的轮询间隔为 `clamp(lease_ms / 10, 1, 100)` ms，同时依据宿主时钟和单调时钟，避免固定宿主时钟导致永不轮询。此数值是下一个协作 checkpoint 发起检查的调度预算，**不是**数据库阻塞、原生函数或线程调度下的端到端取消延迟保证。原地取消 token 每次调用，最终提交始终执行强校验。

回归覆盖：写锁解除后自动恢复且 revision 仅提交一次；持写锁时从新连接查询 queued／running／terminal；过期与旧 fence；绑定损坏；正文损坏在执行时拒绝；v5→v6 成功和原子回滚；密集 checkpoint 的 SQL trace 计数；固定宿主时钟下另一连接取消。

兼容性：新增 wire 错误码需更新生成的 JSON Schema／TS 类型。schema 6 不能由旧版宿主直接打开；回滚部署前应使用升级前数据库备份，不可只手工降低 `user_version`。

## 文档级预览

`PreviewRenderer::render_pages` 是一次文档计算；所有输入遵循 `ReaderAt` 的不可变资源约定。已准备对象持有包、来源索引和字体清单；字体内容与清单均以文档为单位绑定一次，逐页输入不再复制清单。每页核对来源身份并使用显式编译配置，不跨请求复用页面派生结果；兼容单页适配器仍校验请求的字体身份。图片解码／页面布局仍是逐页工作，此轮不声称建立了跨页图片缓存。

原生适配器的文件批次使用 `--preview-document`，作者批次使用 `--preview-author-document`，版本化来源批次使用 `--preview-retained-document`；每批一次进程、一次文档/图片与字体输入传输。输出通过有界队列返回调用线程，由宿主逐页保存；不积攒全稿像素。输出回调失败、取消、超时、帧缺失／多余或异常退出时回收子进程；已收到页面仍是私有候选，只有完整批次成功和宿主最终提交才能发布。内嵌 export worker 同样复用已准备对象，通过拥有所有权的页面结果回调传递像素，不再为传输 envelope 额外复制整页像素。

`NativePreviewRenderer` 的 timeout 现在约束**整个文档批次**，包括传输和输出消费；不再按每页重新计时。Rust trait 实现者需实现批量方法，现有单页 `render` 是校验序号和数量的适配器。公共操作请求、单页 worker 模式和现有渲染 profile 保持可用。单批最多 256 页；输入及像素预算保留。协议 JSON 在写入时限制总字节；256 页加 1 MiB 字体清单的编码回归验证清单不会随页数放大。

回归以真实 worker 对照旧单页入口：两页的像素和完整响应元数据相等；计数 ReaderAt 确認来源和字体各传入一次；交付只发起一个批次。进程数由一次 `exchange_events` 调用的单进程结构保证，包／索引／字体准备由批次循环外的单次 prepare 保证；测试未伪称对这些内部次数做了独立运行时探针。取消、超时、消费者失败及部分输出后退出由传输与宿主真实 worker 回归覆盖。这些结果不是发行性能基准。

## 诊断所有权

`mo-presentation-edit::EditError::diagnostic` 负责领域错误分类和上下文；kernel API 与 operation service 只映射自己的错误 envelope。operation service 的 `detail` 保存该结构，kernel API 的 error 保存同构字段。测试将同一非法文档／冲突事务送入两个入口，比较结构化结果；不让 Agent 解析自然语言找字段路径。

## F2 统一语义与来源版本闭环

作者正常交付为 `Document → AuthorPlan → 共享资源页面编译 → 像素`；来源交付为 `Document + 原始资源 → SourcePlan → 同一资源页面编译 → 像素`。writer 消费同一不可变计划的格式投影；实际 PPTX 回读保留为独立文件验证。编译器不依赖 writer，来源语义与有界保留逻辑位于 `mo-presentation-source`。依赖方向和作者对照口径见[语义计划整改](presentation-plan.md)。

版本化导入将对象放入同一领域注册表，使用稳定的领域 ID、不可变来源地址/约束、原始资源摘要；普通文本和直接变换进入原有事务、revision、ChangeSet、幂等与 CAS。宿主/MCP 导入经过资源授权；CLI 与 WASM 使用同一纯计算入口。没有新增平行的来源业务版本系统。

来源计划从真实原包重建绑定并验证允许的字段差异，直接构造编译声明覆盖层；无需先写 XML 再解析来适配语义。未知内容、未改部件和关系保持保留，文字与变换的格式写回共享一次索引、每部件一次重写和一次封装。输出之后再独立核对读取结果。逻辑 `planSha256` 与实际 `pptxSha256` 分开，交付接收端重建计划验证。

这关闭 F2 指出的双业务状态及格式往返架构分叉，不宣称所有原生字段已提升为可编辑作者语义。当前来源编辑支持普通 run 的 `SpliceText` 与完整直接坐标的 `SetTransform`；继承坐标缺失、动态字段、签名或保留冲突等明确拒绝，结构增删和换样式等操作整笔失败。未知/未提升语义留在原始包中，不用假定值或绘图路径替代。详见[来源文档范围与兼容性](source-backed-document.md)。

回归覆盖作者/来源共享编译语义、真实 worker 像素与元数据对照、混合事务、锚点、稳定 ID、局部失效、无修改字节保留、未知扩展、伪造绑定、受保护字段、取消、过期 revision，以及实际宿主上传/导入、权限、幂等和重启。Native/WASM 以同一真实包比较导入模型、身份及事务结果。最终运行结果另附，不用编译通过替代这些行为验证。

## 额外两项设计能力

标题等非视觉事务不再触发全量布局失效；静态作者页面按依赖失效并通过宿主持有的有界缓存复用计划，以全量编译作对照。来源绑定只将当前页面及继承链上的依赖纳入页面键，原始包身份仍保守影响全部页。当前缓存范围、验证和成本边界见[增量编译](incremental-layout.md)，不把库内静态缓存说成整个导出链路都已增量化。

原生渲染适配器使用共享的窄批次协议，已经解除对聚合 `mo-kernel-api` 的生产依赖。格式输入、计算和宿主进程生命周期的职责保持分离。
