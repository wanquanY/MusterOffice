# 原生水平文本框布局

2026-09-25。[来源字形编译](source-glyphs.md)之后，`mo-presentation-compile::source_frame` 已把来源文本框、段落属性和真实字形计算连接为一个完整对象的布局操作。输出保留形状局部坐标、原始样式和字形路径；文字画笔、页面变换与页面绘制尚未接通，Musterwork 替换门禁保持未完成。

## 接口与数据责任

`compile` 接受不可变 `SourceIndex`、预期来源摘要、对象引用、路径边界容差、调用者持有的 `PreparedManifest` / `TextBackend`、对象预算和取消回调。它只计算，不读取文件、网络或系统字体。返回的 `SourceFramePlan` 保存来源样式、各段输入、有效文本框、文字矩形来源、各段布局与路径、逐行平移、最终局部字形位置、几何边界和工作计数。

框内所有段落的来源语义与清单实例先完成预检，然后调用字体组件。任何阶段失败或取消都不返回部分框结果；字形覆盖等需要组件才能确定的问题仍可能在计算中发现。`IncompleteParagraph` 保留断行、几何和路径诊断，不只返回一个无解释的失败状态。源文件与索引始终不可变。

各段继续共享已验证字体资源。扁平字形列表只引用段落内原有字形和路径，附加位置；不复制一份完整轮廓。完整来源 run、样式及物理序号仍在结果中，几何样式合并不会丢失后续画笔需要的来源信息。

## 原生属性到计算

当前配置名为 `drawingml-horizontal-source-frame-q32-draft-v1`，尚未通过 Office/WPS 排版认证。

| 属性 | 当前实现 |
| --- | --- |
| 文字矩形 | 使用已求值的原生几何 `rect`；未声明时使用形状范围，分别保留声明或范围来源 |
| 内边距 | 精确解析原生 EMU 与单位小数，应用左、上、右、下内边距后转 Q32 |
| 段落行宽 | 左右边距作用于全部行；首行缩进只改变第一行可用宽度，RTL 段落从右侧缩进 |
| 换行 | 首行/后续行分别使用精确 Q32 行宽，复用已有字簇安全候选搜索；显式换行后不重新应用首行缩进 |
| 水平定位 | 支持左、中、右；中/右对齐使用未取整的视觉笔位范围 |
| 垂直定位 | 支持顶、中、底；先累积各段精确高度，再计算整框偏移 |
| 行距 | 支持缺省自然度量及正数 `spcPts` 固定行距；显式 100% 暂沿用已有自然度量配置 |
| 段前/段后 | 支持非负 `spcPts` 及零百分比；按 `spcFirstLastPara` 决定第一段前/最后一段后的间距是否生效 |
| 空段落 | 保留段尾样式的 strut 高度，参与间距与垂直对齐，产生零个字形 |

无 `rect` 时使用形状范围的依据是 ECMA-376 Part 1 §20.1.9.22；原始几何查询继续忠实保留“未声明”，由文本框编译层应用此语义。文本框首尾间距和点值单位来自 DrawingML 文本定义。Office 对百分比词法的实现说明见[行距标准说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/4e043105-2ae4-4b85-baa8-4324ca7a6367)。已固定的标准输入摘要继续绑定在本阶段证据中。

自然行距、段尾 strut 对其他行的最低高度约束、相邻段落间距相加、RTL 缩进/对齐等仍是本配置中待目标应用核验的规则。显式 100% 并未证明等同于目标应用实际字体度量；其他非零百分比需要按来源行内字号制定策略，目前返回声明诊断，不能擅自套用分页文档的规则。

## 精度与共享排版层

`mo-text::flow::FlowInput` 借用段落和几何样式，接受 `LineWidths { first, rest }`。原有整数 EMU 请求只转换为相等的两个宽度，继续进入同一个搜索引擎，没有新增一套并行断行算法。已有公开操作和序列化字段保持不变。

`paragraph_geometry` 通过相同的几何计算保留 `PreciseGeometryLayout`，包含 Q32 的 top、baseline、bottom、height、advance、pen 范围；整数 EMU 响应仍按原有规则产生。框布局累加未取整的段落高度，再放置每个字形，避免逐段读取整数行高造成累积偏差。

内边距的十进制词法通过有界 BigInt 有理数处理；几何求值的 binary64 结果通过已有区间算术转换。`conversionErrorBound` 只认证该数值到 Q32 的转换，不认证上游公式、换行边界选择或最终像素。居中偏移另外记录半数取整界限。局部路径的边界容差与这些转换界限仍须在页面层合并传播，不能拿局部 Q32 精度代替全页面误差证明。

## 明确未完成的语义

目前只接受水平、单栏、方形换行、无自动适配、无文字旋转/WordArt、顶部/居中/底部锚点，以及水平/垂直 overflow 模式。多栏、竖排、autofit、clip/ellipsis、居中锚点扩展和兼容行距等返回明确属性诊断。`forceAA` 保留给后续绘制层。

段落两端/分散对齐、非基线字体对齐、项目符号和 tab 尚未接入；明确 `buNone` 时无效的 bullet 字体/颜色/大小声明只保留。需要东亚禁止断行或悬挂标点但当前算法尚未实现的内容返回诊断。先前来源字形层的字段、符号字体、字符间距、基线偏移等限制仍有效。这些都是当前未完成项，未从完整一期目标中删除。

字形路径没有颜色、下划线、删除线、效果、世界变换和页面裁剪。返回边界是局部几何范围，不是带画笔的墨迹范围。`source_page` 原有的文本拒绝检查仍有效；只有接通来源画笔、整页预检、变换和误差预算后，才能发布包含文字的来源页面。

## 资源与失败

默认每框最多 128 段、4096 次组件调用、1 GiB 逻辑字体上传、1600 万个请求字、262144 个字形和 524288 个路径命令。组件调用、上传字节和请求字在每次转发前计费；字形/路径总量在每段计算后检查，单段中间分配仍受既有文字层预算约束。这里没有宣称硬 RSS 上限、整页预算、性能提升倍数或完整安装体积。

取消或组件错误继续触发既有实例失效机制。Native 静态组件的失效状态属于整个进程，新建 Rust 包装对象不能恢复；测试宿主为每个破坏性案例启动独立进程，没有添加生产重置接口或绕过失败检查。生产实例池和 Musterwork 的任务取消/恢复仍须单独验收。

## 验证与复现

本阶段全仓 454 项 Rust 测试、严格 Clippy、格式检查、来源编译器 WASM 目标编译及 68 份 Schema 生成检查通过。新增 9 项测试，包括共享行宽/精确度量 2 项、真实 Native 文本框 7 项。后者覆盖原生属性、空段、小数高度、RTL 缩进、后段预检、组件预算/逐次失败、选定取消检查点及保留错误诊断。

独立验证宿主重新运行真实 Native 测试，读取 15 份原创 PPTX / 实际结果，通过 XML 物理序号和 Fraction 运算检查 22 个段落、23 行、28 个字形的 56 个位置坐标及 56 个局部/整体路径边界。语料包含 1 份小数文字区域及 3 行小数高度。合成字体只有简单 A 和空段落，证明计算接线与数值行为，不证明多语言排版、视觉质量或 Office/WPS 兼容。

当前 Native 工作进程重新执行 207 个受影响的既有普通文本请求，响应逐字节不变；历史专用组件故障注入脚本未因此全部重跑。没有新增运行时操作、Schema/TS 字段、外部依赖、WASM 执行批次或发行重建，11 个历史发行产物保持不变。
