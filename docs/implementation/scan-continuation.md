# 保留式填充扫描转换

状态：2026-09-27，实现及本阶段画质/生命周期检查通过；小对象计算开销回退和整体性能门禁仍开放。承接[有界像素准备](pixel-preparation.md)，不是完整 PPT 或 Musterwork 替换验收。

## 实现与生命周期

新增私有 C++20 [`RasterTask`](../../components/skia/mo_raster_task.h)，在同一个计算线程内持有嵌套 continuation。父任务保留路径、画笔、变换、绘图目标和 arena；子任务保留扫描边表、当前位置、裁剪包装器和累计抗锯齿覆盖率。宿主通过既有 `step` 推进，既有 `drop` 销毁整条状态链。

[`scan-continuation.patch`](../../components/skia/scan-continuation.patch)在固定 Skia 源码的绘图设备、路径准备、抗锯齿入口和解析扫描器之间传递这些状态。凸路径的扫描行、垂直边构成的矩形行，以及一般填充的扫描区间提供让出点。矩形着色逐行执行，边与覆盖率仍由原算法计算；没有重新裁剪路径或修改精度/抗锯齿容差。Skia 自身用于超宽/超高目标的既有 tiler 也在父任务内保留，其算法未替换。

`MoSkiaRasterTask` 保持 canvas 的变换和裁剪，直到当前绘制完成。最内层任务先销毁，再释放它借用的画笔、路径和 surface，最后才释放像素。Skia 的累计覆盖率析构器可能在销毁时刷新剩余的私有行/小 mask，因此此处不宣称 drop 为常数时间；中途数据不会通过 `take` 发布。数值预算失败在每次推进后立即返回，失败帧保持零输出所有权。

无参数的空任务正常完成；协程帧分配失败具有独立状态，嵌套失败不会被当成成功或继续恢复。组件将该失败转为分配失败并要求宿主丢弃实例。上游的同步 `void` 入口排空同一套任务，无法返回分配状态时遵循原有 abort/宿主隔离约定。

执行扩展 1、ABI 4、输入语法及 TS 签名未变。没有引入 Asyncify、JSPI、浏览器新特性、后台线程、全局任务服务、时钟或调度器。C++ 协程帧是进程内私有计算状态，不能序列化或跨实例恢复。当前实现仍只在 macOS Native 与 WASM 上构建验证，不据此声称全部桌面平台组件已验收。

## 验证

[阶段证据](../reviews/evidence/2026-09-27-scan-continuation-verification.json)绑定最终源码、产物、输入和观察。初步构建之后完善了数值失败的立即传播；最终适配层已全部重编译，并在最终产物上重新执行下列检查。初步构建/比较不混入最终计数。

- 既有 625 组输入在 Native、WASM 各以 1/7/4096 工作单元执行，共各 1,875 次分步比较；状态和全部像素不变。WASM 另核对 625 次同步调用。
- 新增 8192×9、9×8192 图片，以及一千/一万个小对象这四份原创压力输入，连同一份既有控制输入，跨端分别再核对 15 次分步结果；WASM 另有 5 次同步比较。原生 sanitizer 对这五份输入另运行 20 次。
- 原生 ASan/UBSan 常规组 2,500 次比较、实际提前取消 1,816 次；在复杂梯度、继承组、图片及合成场景的步骤 12/17/31/64/127/199/250 再取消 28 次，均完整重绘并保持旧像素。压力组另外发生 18 次实际取消。`detect_leaks=0`，不宣称 LeakSanitizer 或物理 RSS 回收通过。
- WASM 对同样四类场景完成 28 次扫描中段取消后复用，句柄和 TS 输入分配释放。该计数不代表内部堆或进程 RSS。
- 独立 continuation 探针在 ASan/UBSan 下核对七个提前销毁点、移动所有权、两个交错 owner、同步排空和嵌套失败传播。失败使用与空协程分配相同的返回对象注入，不是实际耗尽系统内存的试验。
- 同源离线 SDK 在 Node 和 Chrome 各核对 71 帧的全部像素及元数据；Chrome `153.0.8010.53` 隔离上下文另通过 30 次步骤间取消。26 个独立 WASM Worker 的所有权、恢复与返回故障隔离检查通过。
- 15 步所选门禁通过，包含严格 Clippy/格式、119 份 Schema、TS 与现有原生绘制/播放/导出/CLI 集成。未执行全部 Rust/MCP 套件；保留忽略项与筛选范围。

## 耗时：一项回退仍待解决

Apple M4 Max、36 GiB、macOS 26.2；三份固定输入，旧/新组件各七次新进程、交替顺序、`workUnits=1`。两版使用同一份计时探针，逐字节结果相同。下表为最长 step 和累计 step 时间分别取中位数，单位 ms：

| 输入 | 旧最长 step | 新最长 step | 旧累计 step | 新累计 step |
| --- | ---: | ---: | ---: | ---: |
| 高精度坐标回退渐变 `exact-below-budget` | 176.060 | 0.796 | 176.128 | 173.017 |
| 继承组渐变 | 0.741 | 0.055 | 1.297 | 1.267 |
| 一万个小矩形 | 0.064 | 0.068 | 3.858 | 6.040 |

复杂渐变的让出间隔明显缩短；一万个小对象的累计 step 时间增加约 57%，**不能算性能验收通过**。嵌套状态帧的分配和更频繁的调用是下一步需要分离测量、优化的成本，尚未把其中任何一项认定为全部根因。不得靠降低画质、放宽参考值或减小对象数量消除这项回退。

该诊断无字体，进程内缓存为空，系统页缓存和整机负载未控制；测量时本阶段其他检查已完成。step 计时不含 begin 验证、输入复制、结果取出、销毁、IPC 和步骤间时钟间隙，另保留包含启动/IPC 的进程时间。它不是整页 P95、端到端取消或物理回收验收。
