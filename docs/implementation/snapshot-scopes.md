# 透明组中的背景快照

2026-09-28：快照已具备明确的捕获画布，来源页面中的幻灯片背景填充因此能够在淡入淡出和嵌套透明组中使用。独立 Musterwork worktree 已升级 SDK、原生导出 Worker 和播放包，并用两份来源 PPTX 完成实际交付／播放检查。完整一期和产品替换验收继续进行。

## 问题与语义

此前快照只记录“在第几个绘制之前捕获”。引入透明组后，同一位置可能同时存在主输出、外层组和新建的内层组。背景窗口需要读取主输出中已完成的背景；把捕获位置等同于当前画布，可能得到空的组画布，或因为跨组限制而拒绝绘制。

`Brush::Snapshot` 现在明确区分：

| `scope` | 捕获来源与使用范围 |
| --- | --- |
| 省略或 `{ "kind": "current" }` | 保留旧语义，捕获该位置最内层组；使用也须位于同一组 |
| `{ "kind": "output" }` | 主输出画布，不包含尚未合入的活动组 |
| `{ "kind": "group", "index": 0 }` | 指定透明组，索引从零开始；捕获时该组必须仍处于活动区间 |

捕获发生在该绘制位置的关闭／开启组操作完成之后、执行该绘制之前。显式捕获会冻结像素；之后可以跨组使用，即使来源组已经关闭。尚未开始、已经关闭或不存在的来源组在分配像素前拒绝。相同位置和相同画布共享一次捕获；不同画布不能仅按位置合并。

来源页面的 `useBgFill` 现在明确请求 `output`。对象依然使用自身几何、裁剪和整体透明度，没有静态化动画、逐画笔乘透明度或回退浏览器绘制。页面展示、播放控件、文件获取和权限仍由接入产品拥有。

## 合同、资源与兼容

V14 维持 V13 的头部与透明组格式，每条快照改为两个 word：绘制位置和画布编号。编号零表示输出，正数为透明组索引加一。新增 `mo_skia_snapshot_scopes_abi() == 1`，Native／TS 同步与分步入口均校验；旧组件明确拒绝新功能。

没有透明组的 `output` 快照降低为原有帧格式；旧 `current` 请求的字节和局部范围限制保持。最多 64 次不同捕获、4096 组、64 层嵌套；快照和组中间表面继续共用 64 MiB 像素上限。V14 的最大帧长度仅增加 64 个 word，不改变现有像素和工作预算。

捕获复制继续分步执行，已有资源所有权和取消释放路径保持。当前仍使用完整 viewport 表面，这些上限不是进程 RSS 或单步墙钟延迟保证。

## 验证证据

[验证记录](../reviews/evidence/2026-09-28-snapshot-scopes-verification.json)固定了构建输入、源码、组件、测试材料和产品锁：

- 208 项相关 Rust 测试通过，其中新增 3 项覆盖捕获身份、结束后的使用、旧格式、预算和来源背景窗口。严格 Clippy、格式、Schema／TS 生成及类型检查通过。
- 7 项独立像素场景通过 Native、WASM 和 Draw IR，包括同位置不同画布、组开启／关闭边界、来源关闭后的使用及大表面复制。6 项非法 JSON 输入和 4 项非法二进制帧被拒绝。
- 原生分步执行 132 次、WASM 分步执行 33 次；WASM 27 个计算句柄全部释放。ASan／UBSan 执行 88 次，实际触发 9 次中途取消与重新开始，未报告错误；未启用 leak detector。
- 554 个既有组件案例及 24 个既有透明组案例保持原结果。过去用“未知版本 14”构造的一项负例因 V14 现已实现而失效，旧失败记录保留，新负例明确使用版本 15，没有把它算作旧输入不变。
- 3 组自有 PPTX 覆盖背景窗口作为首对象、前面已有对象及嵌套透明组；24 个原生采样与公共 WASM 包的同步／分步 Worker 路径一致。动态画面逐像素对照两个静态控制和独立整数合成计算；9 份幻灯片 XML 通过 XSD。另有前阶段 57 帧淡入淡出材料在两种 WASM 执行方式中保持结果。
- 两份来源 PPTX 经公共导入、独立 SDK 消费者和真实导出 Worker 形成交付，生成 12 个原生参考帧。Musterwork 实际播放 Worker 完成 26 帧对照，159 项产品测试、Vue 类型检查和完整桌面前端构建通过。

产品测试此前将所有页面 ID 写死为作者样例的 `slide:1`。来源文稿使用其导入后的页面身份；测试现改为与独立原生交付准备结果核对，产品的身份处理代码没有改动。其他初次命令路径、模块模式、测试数据和旧验证程序的失败均保留在记录中。
