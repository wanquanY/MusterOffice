# 持久资源、分块传输与原生导出资源绑定

状态：P02/P07 本阶段资源底座已实现并验证，见[阶段证据](../reviews/evidence/2026-09-26-resource-host-verification.json)。继承[文档操作宿主](operation-host.md)的同一标准宿主与数据库所有者；完整 v0.4 目标、Agent 接入和 Musterwork 替换条件保持不变。

## 为什么需要这一层

文档中的资源引用只包含逻辑身份、摘要和媒体声明，不能证明某个宿主有权访问对应字节，也不能让进程重启后自动找回素材。已有 PPTX Writer 支持 `Resources` 与 `ReaderAt`；本阶段将其连接到持久、按 scope 授权的实际字节，替代仅适合开发桥接的整块内存素材输入。

`mo-operation-service` 增加独立资源合同，仍没有数据库、路径或网络。`mo-standard-host` 负责接收、存储、摘要验证和权限，所有入口共用它的状态机。Musterwork EmbeddedHost 以后应将产品 ContentRef 映射到等价能力，保持自己的唯一提交 owner，不必运行本 SQLite 存储。

## 接收与封存

`beginUpload` 输入固定的 requestId 和 `{sha256, byteLength, mediaType}`。幂等范围为 scope、principal、requestId；同键同声明返回原上传，同键不同内容失败。返回上传 ID、状态、已接收长度、分块大小和过期时间，不提前返回可读取资源。

数据通过独立二进制通道传输。每块最多且通常恰为 256 KiB，最后一块可以更短；空资源不需要分块。分块 offset 必须按块对齐并连续。相同 offset 重发相同字节不增加存储或续期，重发不同字节、跳块、越界和非末尾短块明确失败。新块及已接收长度在一个短事务中持久提交，网络等待不占数据库写锁。

`sealUpload` 先持久冻结上传，禁止继续修改；随后在写事务之外逐块读取实际已保存字节，检查块摘要并计算完整 SHA-256。摘要及长度一致、尚未取消且租约有效，才在单个事务中写入 AssetInfo 和 sealed 回执。两个并发封存者不能同时执行；提交失败不留下公开资源引用。这里的“公开”指对获授权的同一 scope 可读取，不指公开到互联网。

上传失败或取消会删除临时分块、释放声明字节预留，并保留幂等终态回执。sealed 资源不可被取消或覆盖；当前没有删除已封存资源的入口，后续必须结合文档版本、Artifact、播放会话引用及保留策略实现释放。

## 身份、类型与预算

WriteAssets 控制接收、查询上传和取消；ReadAssets 控制打开已封存资源。上传只允许所属 principal/scope 查询；封存后，明确获授同一 scope 读取权限的成员可以共享资源。资源 ID 和摘要都不是 bearer credential。纯 JSON 合同不接受文件路径、principal、scope、权限或内联二进制。

`mediaType` 是长度和基本形式受限的声明。`verification=bytesSha256` 只表示实际字节与声明摘要一致，不意味着图片能解码、字体许可通过、媒体可播放或嵌入文件安全。用途与格式校验由图片/字体/媒体/OPC 等消费者继续执行，不将字节完整性升级为内容质量。

默认单资源上限 1 GiB、单 scope 声明字节预留 4 GiB、上传回执数量 10,000、活动上传租约 15 分钟，操作者可以指定有效限制。接收前原子预留完整声明长度，pending/verifying/sealed 均计入，取消/失败释放；同一作用域两个并发接收者不会超额预留。未自动跨上传去重，所有独立资源按实际预留计量。

这不是完整磁盘空间预算：SQLite 页面、索引、WAL、回执元数据及已删除页面的可复用空间另计。清理分块不会承诺数据库文件立即缩小；全存储字节预算、空间维护与大型工作负载 RSS/吞吐测量仍需完成。不要将当前限额当作运行时资源验收通过。

## 恢复与取消

追加成功后进程退出，另一个进程可以从持久收到的偏移继续；已完成回执的读取不受系统时钟回拨影响。活动上传的时钟回退和期限溢出明确失败。实际新分块与开始验证更新期限，重复旧分块不无限延长租约。

验证进程崩溃留下 verifying 状态和有限期限。查询/受控清理发现过期则将它终结为 RESOURCE_EXPIRED，删除暂存分块，并拒绝后来结果；不会猜测原验证已经成功。取消可与验证并发，最终事务再次确认冻结状态，取消先提交则不能发布 AssetInfo。租约失效不证明原进程内存已经释放，worker 强终止与完整调度仍属于后续工作。

`reap_uploads` 每次最多处理同 scope 的 128 个过期项，可以重复调用；接收新资源前也运行一批有界清理。数量配额仍包括历史回执。`getUpload` 成功表示查询成功，返回的 upload.state 和 error 才说明上传结果；failed/cancelled 的查询不会出现可用 asset。

## 范围读取和文档绑定

`AssetReader` 借用已授权宿主连接，每次最多载入一个分块，检查持久分块摘要再复制所需范围；跨块精确读取由已有 ReaderAt 合同完成。不拼装整份素材，也不常驻缓存所有媒体。已封存资产没有修改 API，因此活跃读取不会被上传取消删除。获得 reader 是当前一次授权，长会话和新下载请求仍由宿主重新核对权限。

`bind_resources` 接受完整的 `{resourceId, assetId}` 映射，拒绝缺失、重复、额外资源以及与文档声明不符的摘要/媒体类型。返回的 `BoundResources` 实现既有 PPTX `Resources`；Writer 使用这些范围读取器，并继续执行原有签名、摘要和实际 OPC 重读检查。

这里已经有原生 Writer 消费真实持久资源的代码与测试，但尚未把 export 作为统一任务或公共 bundle 交付。Writer 输出仍是其既有有界 Vec；下一步需要可回读输出暂存、实际候选验证以及与任务 fence 一起提交，不能因素材输入分块就宣称输出全程流式。

## CLI 与数据库升级

本地元数据通过 NDJSON 的 beginUpload/getUpload/sealUpload/cancelUpload/readAsset 传递。二进制使用操作者配置的 `mo-host <db> <principal> <scope> append <upload-id> <offset>` 从 stdin 接收一块；`read-asset <asset-id> <offset> <length>` 将指定范围写到 stdout。命令不接受资源文件路径，数据库与身份仍由安装者配置。二进制读取失败以非零退出和 stderr 报告，接收方必须丢弃部分输出并校验完整下载摘要。

数据库版本从 1 升到 2，只增加上传、分块及封存资源表和索引；旧 jobs/revisions/heads 的内容不改写。整个升级处于事务中；未知版本/应用 ID 仍拒绝。该迁移经过上一阶段真实数据库副本核对，原始封存数据库保持不变。
