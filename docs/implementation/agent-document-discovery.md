# Agent 文稿创建示例与发现成本

2026-09-30 实现检查点。此项改进公开 Schema 的指导信息，保持原生文档模型、操作语法、
资源边界及校验规则。它不是模板服务，也不增加模型调用、网络、文件路径或业务存储。

## 实际触发

在 Musterwork 已激活的原生环境中，真实模型使用作者 @7 创建三页中文 PPT，先完成了
超过 50 次 `describe` 查询。模型逐层探索主题、母版、资源等当前任务并不需要的类型。
两次并发查询返回 `RESOURCE_BUSY`，后续首次创建又因把不完整文档编码成字符串而被
工具参数校验拒绝。固定工具循环通过不能证明这条真实模型制作链路已通过。

这些是不同问题：例子和指导不足导致发现成本高；产品解析槽位的竞争属于宿主调度；
模型产生无效参数仍须原样拒绝，不能接受省略号、补造资源或关闭校验。本检查点仅处理
第一项，后两项以及完整制作结果分别记录，不以改动 Schema 宣称真实制作已恢复。

## 已实现

`Document` 的公开 JSON Schema 包含一份完整、可解析的 16:9 原生文本页示例。
示例采用明确 EMU 字符串、稳定对象/段落/文字 ID、原生 shape 和可编辑文本；不依赖
主题、母版、布局、图片或嵌入字体。空 maps 是模型合法输入；文字继承调用方提供的
交付默认字体，没有隐式发现系统字体。说明给出每磅 12700 EMU 以及复制页面时的 ID
要求，调用方仍须提供真实字体和交付配置。

Agent 在原有 `/$defs/Document` 查询中即可看到示例，或按 JSON Pointer 读取
`/$defs/Document/examples/0`。单个例子为 1398 个 UTF-8 字节；包含属性定义及指导的
整个 Document 子树为 3891 字节，低于 8000 字节的发现预算。此处测量是序列化大小，
不是端到端延迟、模型成本或质量提升的实测结论。

Schema 示例是项目自有固定教学内容，不承诺某种视觉风格或代替用户内容。程序测试从
实际生成 Schema 取出示例，通过模型校验、序列化回读和摘要一致性，再以真实 PPTX
writer 导出两次修改后的文稿并从实际 ZIP/XML 读取，确认仍是含文字的原生 `p:sp`，
没有全页图片或虚构外部资源。

TS 更新文档注释；模型字段和文档摘要规则保持不变。
