# XML 与 OPC 文件层实现

2026-09-24 · P02/P03 部分实现。此处描述当前代码的实际合同，不将 ZIP/XML 合法等同于 PresentationML 完整或 Office/WPS 可编辑。

## 读取与宿主边界

`mo-opc::Package::open` 接受不可变 `ReaderAt`、声明长度、预算及取消回调。核心不接受文件路径、不访问网络；CLI 测试宿主才负责打开显式路径。宿主必须保证资源在读取/重写期间不可变，生产资源需使用已封存的授权句柄。

ZIP 中央目录、局部记录、名称、压缩方法、尺寸、CRC 和可选数据描述符相互核对，已占用范围包括描述符，不能重叠或越入中央目录。支持 STORE/DEFLATE、32 位和 ZIP64 尺寸；拒绝加密 ZIP、非普通项、重复/等价名称和越界路径。加密 Office 文稿的封套尚未实现，不能用 ZIP 加密当作替代。

ContentTypes 与包级/部件级关系使用命名空间和结构解析，检查类型覆盖、源/目标存在、重复关系 ID、URI 解析和部件前缀冲突。外部关系保留原 URI，不自动获取。普通 XML 部件同样检查格式和预算；未知合法 XML 与二进制内容保留在包图中。

二进制媒体按 64 KiB 解压块验证，不为建立图而保留全部媒体。XML 受字节上限后缓冲解析；这不是全 XML 流式语义树。原包和每个部件记录真实 SHA-256，OPC 检查结果可由原生/WASM 输出同一份 JSON。当前 WASM 入口接收完整 `Uint8Array`，宿主分块桥、Worker 和大文件峰值测量尚未完成。

## XML 来源覆盖

`mo-xml` 支持 UTF-8、UTF-16LE/BE、BOM、XML 1.0 字符/换行/属性归一化、命名空间绑定和预定义/数值字符引用。禁用 DTD/外部实体，限制字节、深度、元素、属性和文本。UTF-16 解码在分配增长期间检查预算与取消。

`rewrite_text` 是格式适配器的内部叶文本覆盖工具。输入包括固定源 bytes、Start 事件序号、预期 expanded name、预期旧文本和新文本；它先结构解析与核对，随后只覆盖对应文本语法片段，实际输出再次解析。它不使用正则修改 XML，不建立第二套演示语义。

未修改属性/节点、注释/PI、命名空间词法形式、字符引用及原编码保持源字节；多个文本片段合并时保留其中注释/PI。空元素按原 QName 展开。无改动返回相同字节。含子元素的目标、重复目标、旧值不符、非法字符或超预算均失败，避免将复杂结构当纯文本抹掉。

这一原语尚不等于完整 SourceBinding：对象持久身份、属性/树编辑、AlternateContent 分支、未知扩展引用和修改影响闭包仍需领域适配器实现。当前只验证了原生执行，WASM 编辑入口与跨端编辑证据待接通。

## 写入与提交

`PackageBuilder` 以类型化部件/关系生成包；资源接受授权范围读取器、长度与预期摘要。XML 在写入前检查，资源摘要核对后才能成功完成。部件顺序和 ZIP 元数据确定，DEFLATE 当前固定 level 6。

`RewritePlan` 当前只替换已有非关系部件。未改动部件复制原压缩载荷，空计划复制并校验整包，签名包修改返回保留冲突。增删部件、关系重写和明确的移除/重签策略尚未实现；不允许将签名复制为“修改后仍有效”的证据。

`write_to` 写入宿主暂存 sink，任何中途失败都可能留下部分暂存数据，宿主必须丢弃，不得提交。返回写入收据不是完整交付批准：宿主 seal 后仍须通过实际句柄重新读取。小包 `to_bytes` 已自动重读 OPC 实际输出；后续 PPTX Writer 还必须重建文档语义并对照预期。当前没有 PresentationML 语义重读证据。

## 预算与验证范围

默认包大小/单部件上限 1 GiB、总解压 2 GiB、部件数 10,000、关系数 100,000、压缩比 2,000；XML 默认 32 MiB、深度 256、元素 1,000,000、单元素属性 256。来源文本编辑另限 10,000 个目标、100,000 个文本语法片段。这些是当前受控开发默认值，可由 Rust 宿主收紧，不是大文件性能验收结果。
