# 产品原生导出执行与恢复

2026-10-08。产品提交 `33e98a8f6409bd5cf745c9236967c8ba85165fdb`。接续[正式发布端口](video-product-export-publication.md)。Musterwork 将真实编码、原任务、内容保存与正式 Artifact 发布连接到同一执行器，并在原 Device 任务集合中装配常驻执行。Office 内核继续只提供计算能力，本增量没有修改 SDK、worker、PPT pins、稳定标签或对外发行。

## 完成的接线

整个导出保留独立任务名额直到保存、提交或实际清理结束；编码名额与整体名额分别管理。原任务固定工程版本、意图和新尝试，原发布事务独占 Completed 的写入权。

进度观察每 250 ms 合并一次更新，与实际操作并发轮询，避免等待 SQLite writer 的观察者阻塞持有 writer 的保存任务。用户取消会等待物理工作结束；Runtime 停止保存 Interrupted，异常丢弃执行 future 时由原启动恢复退休旧尝试，均不提前伪造完成或取消。

恢复沿用原规范验证记录，并用固定 SDK 重编译冻结工程的精确导出计划核对配置、计数和检查结果；随后仍验证当前来源和实际文件 hash。完整旧候选不会被后续空失败尝试遮蔽，也不会因恢复而改写 ContentId 或来源 attempt。

预检失败作为同一个原任务的失败验证尝试原子保存，原 writer、版本、竞争与取消检查都保留。失败任务等待显式重试，避免缺失素材或不可用目标不断自动执行。

Schema 204 只增加原候选和当前用户待处理 Product 任务的两个部分索引；新常驻执行器每次至多取 16 项，整体一个任务名额，原进程退出负责等待。Tool 工作仍须由原 Invocation/journal/liveness 接入，不能借用该手动执行器。

## 实际证据

9 项真实媒体测试通过，包括一次真实执行中创建目标会话、硬件编码、保存、原子 Artifact 发布和重放；发布阶段仍保持总配额、晚取消、退出中断、异常丢弃和原启动恢复、持久预检失败。恢复测试把编码名额设为零，仍能提交完全相同的旧候选。

SQLite 测试覆盖原发布/内容/任务、schema 201–204 迁移、当前用户待处理检索、旧候选检索、验证拒绝的并发和事务回滚。本轮 88 个不同测试通过：58 项内容、8 项任务、8 项发布、5 项迁移、9 项真实媒体；3 个特殊 fixture 直接 ignored 未计通过。生产库 strict Clippy 与 Device 编译检查通过。数量及源码/日志 SHA-256 在产品 `.codex-work/video-export-execution-report.json` 登记，不重复累计同名测试。

独立 FFmpeg 对正式发布输出做全片解码、时间网格及音频比较：75 帧、128×96、3 秒、48 kHz 双声道、144000 authored samples；解码包含 AAC padding 的 144384 帧另列。不同编码尝试的文件 hash 可以不同，候选与正式发布产物分别检查，不能借用另一次编码的证据。
