# 原生文稿模板的参数绑定与独立实例

2026-09-28，在 [Musterwork Agent 原生文稿打开](product-native-open-agent.md)之后，补齐接入所需的首段模板计算。`mo-presentation-template` 提供固定来源版本的参数描述、校验和整份文稿实例化，由嵌入 SDK、开发 CLI 和 WASM 共用。模板目录、选择、材料授权、任务和持久保存由接入产品实现。

这不是完整模板功能验收。当前没有向已有文稿插入模板页面，没有建立模板业务平台，也没有将普通 PPTX 导入标记为已完成参数化。本记录对应阶段未更新 Musterwork 的固定 SDK、worker 和候选工具。后续[模板共享协议与产品计算来源](template-protocol.md)已升级固定材料并验证原提交端口；产品选择模板的 Agent 调用链继续接入。

## 固定来源与原子参数计算

`TemplateDefinition` 同时固定来源文档 ID、revision 和语义摘要；模板摘要覆盖定义及全部参数。实例化必须提供该模板摘要和新的文档 ID。同一输入可重复计算相同快照和收据，但核心不持久去重 request ID，也不保证宿主唯一分配文档 ID。宿主完成目录版本选择、并发提交和持久幂等。

当前参数有四类：

| 参数 | 计算范围 | 约束 |
| --- | --- | --- |
| TextRun | 替换一个完整文字 run，保留段落、样式及身份 | Unicode scalar 长度；字段、换行及受保护来源仍服从原编辑器 |
| Resource | 替换同一资源身份的内容声明，所有引用共同生效 | 类型与 ID 不变，MIME 在显式集合内，来源 PPTX 不可替换 |
| ThemeColor | 替换指定主题色槽 | 同一主题的多个槽共同形成一次主题变更 |
| Transform | 替换对象的显式二维变换 | 原编辑器的几何、对象类型和来源约束保持 |

声明时通过真实原子编辑器验证所有参数目标，包括当前值的无变化探测。当前值必须满足声明的约束；查询返回真实例值，不推断占位内容。重复目标、缺失必填参数、未知参数及值类型不符整体拒绝。实例化复用同一编辑器，避免产生第二套参数修改语义。

绑定计算只在私有文档副本上执行。收据中的 `bindingTransaction` 描述针对固定来源的纯参数计算，不是提交到来源文稿的记录，也不能作为新实例上的下一条事务。新实例拥有独立 genesis revision；继续编辑应使用实例快照中的 revision。每个实例的后续修改不影响模板或其他实例。

## 整份文稿身份与原生来源

整份复制采用 `(原文档 ID, 局部 ID) → (新文档 ID, 同一局部 ID)` 的作用域映射。对象、段落、run、动画目标、连接线、布局和资源的内部引用保持原样。它不适用于向已有文稿复制部分页面；后者必须实现跨文稿的引用闭包、冲突重映射与原生包组装。

导入对象 ID 原先由原文档 ID 和来源包摘要共同派生。新实例如果只替换文档 ID，来源写回器将无法验证对象。模型现在以可选 `SourceBindings.identityScope` 保留不可变的派生命名空间；首次实例化固定来源作用域，后续嵌套实例沿用。旧文稿省略该字段，旧序列化与摘要不变。

写回器仍根据实际来源包重新投影，检查摘要、全部绑定、受保护字段及完整文档等价；没有放宽来源验证。修改该作用域而不匹配真实投影会被拒绝。此字段是来源信息，不是权限身份。输出后重新导入的 PPTX 按新输入重新形成身份，不能据旧局部 ID 推断匹配。

## 同源接口与输入边界

- Rust：`Presentation::prepare_template` 与 `Presentation::instantiate_template`，直接返回调用方持有的计算值；无需数据库。
- JSON：`musteroffice.template-computation/1-draft` 的 `describe` 和 `instantiate`，来源是显式 `SnapshotRecord`。权限、文件路径、业务任务等额外字段拒绝。
- 开发 CLI：`mo-cli template <request.json>`，结果写标准输出。JSON 计算错误通过 `status: error` 返回，传输/文件错误使用非零退出；调用方必须检查计算状态。
- WASM：`compute_template(requestJson)`，使用同一 Rust crate。同步调用中不能接收新的取消事件；浏览器宿主仍须在 Worker 中运行并负责终止策略。
- Schema：`template-definition`、`template-request`、`template-response` 可通过既有计算 Schema 入口查询；TS 类型由 Rust Schema 生成。

默认最多 4096 个参数、每标签 4096 UTF-8 字节和 32 MiB 序列化输入/结果，并叠加文档与原子编辑器限制。流式 JSON 计数避免为测量额度再分配一份 JSON；克隆前检查来源额度。原生取消回调贯穿参数、编辑和序列化边界，但完整 JSON 解码、文档验证等步骤仍有同步段，尚不构成实时延迟承诺。

资源参数只改变声明，不读取文件、不下载字节。实际编译、渲染和导出仍须通过原资源端口验证内容摘要及依赖。文字长度符合约束也不等于字体覆盖、排版容量或视觉质量已通过。

## 验证及下一步

测试覆盖独立实例、来源版本冲突、参数类型/长度/资源限制、同主题多色绑定、引用保留、取消、输入/输出预算和来源完整性。自有真实 PPTX 包含专用未知扩展；实例写回后核对未修改部件的完整字节和所有关系，再重新导入核对原生文字。嵌套实例与来源作用域篡改分别验证。SDK 调用后的普通编辑及恢复保持来源不变。

九个选定 crate 的 367 项 Rust 测试通过，16 项属于新增模板 crate；SDK 新实例测试及共用序列化额度测试另在对应 crate 中计数。相关九个开发包的 all-targets 严格 Clippy、生成 Schema 与 TS 检查通过。扩大回归时修正了旧条件测试将已映射 `onNext` 当成未知事件的预期，并新增方向/延迟保留断言；未知事件和无效目标仍拒绝。一次新断言错误地比较不同的有理数编码，已按原生毫秒编码校正。原始失败记录保留；367 项回归后仅折叠一处测试 helper 的等价嵌套条件以通过 Clippy，生产源码未再变化。

原生 CLI 与 WASM 的 15 组自有请求完整 JSON 响应逐字节一致，并与 Rust 测试断言得到的结果比较。两份输出 PPTX 各有 21 个 ZIP 部件、20 个 XML/关系文件，CRC 与 XML 均通过；只有 `ppt/slides/slide1.xml` 改变。

本地 SDK 归档包含 26 个生产库与 54 个既有 registry 依赖；没有引入新的 registry 包。独立 Cargo 项目只引用归档 SDK，离线编译并对 3 份作者/原生输入完成实例化、全快照与收据对比、来源不变检查；实际文件清单与固定摘要验证通过。该归档尚未替换 Musterwork 当前固定材料，也未公开发布。

具体命令、源码摘要和产物见[阶段证据](../reviews/evidence/2026-09-28-template-computation-verification.json)。这是计算及原生结构验证，不代表 Office/WPS、视觉/字体/性能/体积或产品完整模板流程通过。
