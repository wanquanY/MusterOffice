# 原生文字容量测量与产品传递

2026-09-28，内核已将实际排版产生的文字容量测量随渲染结果输出；Musterwork 独立接入 worktree 已更新固定 SDK/worker，并通过原维护 Agent 的实际模板任务。此阶段提供最终模板质量验证需要的计算事实，`native_verify` 和完整替换仍未完成。

## 计算来源与边界

此前 `SourceFramePlan` 已含真实行布局、内边距、段落尺寸和字形边界，但栅格结果只保留工作量，产品无法从生成成功判断文字是否装得下。新增 [`source_frame::capacity`](../../crates/mo-presentation-compile/src/source_frame/capacity.rs) 从同一份已完成排版提取测量，不重新选择字体、塑形、断行或截断文字。

`drawingml-text-capacity-q32-v1-draft` 按绘制顺序覆盖所有文字框，包括空文字框。每项绑定实际来源部件和原生对象 ID，并保留：

- 已应用内边距的局部矩形、实际内容高度、超出可用高度的量。
- 实际行数、横向溢出行数、紧急断行数、左右最大超出量。
- 首个溢出位置，其中 `paragraph` 是来源段落的 XML ordinal，`line` 是该段内从零开始的行号。
- 未应用画笔效果的字形墨迹边界；它不等价于描边、阴影、剪裁或对象重叠检查。

长度采用 Q32 EMU，坐标位于对象自身空间、先于页面/组/动画变换；行宽使用相应段落首行或后续行的缩进和边距。垂直超出量在顶部、居中或底部锚定之前计算。仅有墨迹超出或紧急断行也不自动成为质量失败。

静态文字页、资源页及保留的播放帧共享测量。播放准备只计算一次紧凑记录，取样沿用局部测量，不逐帧重排文字。这里没有测量完整视觉质量，也没有更改自动缩放、裁剪、字体回退策略。

## 传输与历史文件

栅格 metadata 增加可选 `textCapacity`；生成的 JSON Schema 和 TS 类型同步。当前生产者总是输出记录，零文字页返回空 `frames`。历史文件缺失此字段仍可读取，缺失表示未测量。

交付生产和接收边界检查档案版本、覆盖数、对象重复、非负尺寸/超出量、行数和高度算术，以及取消；不把结构自洽当作测量真实性或质量通过。逐页证据继续绑定实际来源/渲染计划、PPTX、页面和 PNG。整体结构、布局、原生编辑、播放、目标应用声明保持原有语义。

## 实际验证

证据见[本阶段记录](../reviews/evidence/2026-09-28-text-capacity-verification.json)。相关 Rust 测试去重计 109 项：83 项库测试、7 项已有来源文字框回归、3 项新增容量测试、14 项真实原生渲染/导出/播放测试、2 项产品维护任务。相关严格 Clippy、生成 schema 和 TS 检查通过。

6 份专用自有文字样本分别通过文字页和资源页入口，共 12 组 Native/WASM 对照；实际测量与像素全部一致。样本包含长词超宽、单字超宽、紧急断行后超高及三种垂直锚定。该专用语料只保留目标文字框并明确隐藏母版对象，混合图片/母版仍由原生导出和产品完整样本覆盖。

独立工作区的真实来源与 8 类参数压力实例共 9 次计算、18 页、72 个文字框全部输出测量。独立 ZIP/XML/文件验证确认所有实际 PPTX、PNG 与更新前保持字节一致；更新 renderer 身份、设置及逐页测量会改变证据资产摘要，质量声明内容没有升级。已有来源和实例链路仍验证参数绑定、完整页序、压缩部件保留及产物引用。

`text-maximum-latin-wide` 的 16 个 `W` 在第二页 `/ppt/slides/slide2.xml`、原生对象 `2` 检出 1 行横向溢出；本次产品样本没有垂直溢出。原文完整保留，不缩短压力输入、缩字或修改样本以得到通过。所用字体为自有合成字形，仅证明计算及传递，不证明多语言排版质量。

## 产品接入与后续

Musterwork 固定 SDK 更新为 `1cf36a1a8808c2efa28f5413b96cdba4656ae594d9cf38e94317d7a3a3a2c4c9`，ARM64 开发 worker 更新为 `52bdebdbebd0ef7feca35e4f66213ba237e7ef48a3f6b248d0ac168c71dfcc50`。依赖版本未新增，产品沿现有资产传递路径接收这些计算事实，没有实现第二套排版器。worker 大小 42,750,912 字节是当前 debug 产物，不能作为正式发行体积或桌面安装包估算。

接下来由原 `native_verify` 消费精确来源/实例证据，明确区分容量失败、测量缺失和其他未证明的质量维度，再完成原目录事务、自动上传环境选择和真实产品流程。不得用这项容量测量直接宣布完整布局或 Office/WPS 兼容通过。完整高级能力、历史迁移、性能/体积与 E0–E3 仍分别推进，见[总进展](progress.md)。

产品修改、构建和诊断只发生在[独立接入工作区](product-worktree.md)。Musterwork 主工作区留给用户，未进行正式切换、部署或合并。
