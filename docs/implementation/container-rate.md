# 容器正向变速与激活时钟

2026-09-29：正向容器变速已进入共享时间调度和采样。不同长度的子项、开始延迟、顺序与并行组、事件依赖、重新激活和范围跳转共用同一时钟转换，不再因为容器速度不是 100% 而拒绝。反向／自动反向及一般非线性容器时钟继续实施，完整一期与替换验收尚未完成。

## 语义与职责

[SMIL 的级联时间模型](https://www.w3.org/TR/SMIL3/smil-timemanip.html)规定容器变速影响整个子树，开始和结束条件的偏移在接收节点的父时钟中解释。原生 PresentationML 的容器 `cTn.spd` 属性由[Open XML 定义](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.commontimenode.speed?view=openxml-3.0.1)确认。本阶段实现这一计算模型及原生读写；没有新增实际 Office／WPS 播放结论。

例：容器在宿主时间 2 秒开始，以 200% 速度播放；子项相对它延迟 1 秒、持续 6 秒。实际子项在 2.5 秒开始，正常于 5.5 秒结束。如果容器自身声明的固定持续时间为 4 秒，则容器于宿主时间 4 秒截断，子项保持在 50%。容器自己的开始／结束条件不再额外乘一次自己的速度；跨分支事件则使用接收节点父时钟的速度解释延迟。

每个激活记录保留自己的父激活身份和输出速度。子时钟以父激活的原点为锚进行仿射变换；开始延迟、自然截止、显式结束、事件依赖与帧采样使用互为正逆的映射。重新激活及 Previous 创建新的记录，旧起点和旧跳转不会进入新子树。

下一步跳转仍只推进对应子树。跳转及同一宿主时刻内的事件顺序使用未缩放的时间距离，再经各接收时钟转换；不同速度分支不能直接比较各自局部时间单位。没有生成新的宿主事件，也没有把速度复制到每个叶子或改写文稿中的时长。

没有变速或跳转的图保留原快速路径。有变速的映射按受限祖先深度组合精确分数，并沿用算术位数、区间数、调度工作预算和取消检查。此次没有性能基准，不将正确性通过表述为吞吐提升。

## 与缓动的组合

正向速度适用于现有调度器支持的不同长度、错峰、事件与导航子树。它不要求所有子项同时结束，也不要求容器预先有有限时长。

非线性缓动仍由容器自身持有：先转换到该容器的局部时间，再施加缓动，最后级联给后代。在此前已验证的同步有限子树中，现已支持同时存在正向速度与嵌套缓动，包括没有缓动但有变速的中间容器。编译器比较的是变速后在父时钟中的跨度。

不同时长／错峰子项与非线性缓动的任意组合仍需逆截止投影；负速度、自动反向和反向期间的事件语义也尚未接通。本阶段保留明确诊断，没有用舍入、复制叶子属性或静态画面替代这些能力。

## 验证

537 项相关 Rust 测试和严格 Clippy 通过。新增 7 项测试涵盖嵌套不同速度、开始／结束条件的时钟归属、固定时长截断、外部事件、重新激活、倒退采样、导航跳转与无关分支、缓动级联、精确算术预算和原生 XML 所属节点。原生 Writer 保留容器速度与子项原始时长，Reader 还原同一计算结果。

四份完整自有 PPTX 分别覆盖并行错峰、顺序延迟、嵌套速度和速度／缓动组合。72 帧由独立 Python Fraction 公式验证，59 个可表示为整数角度的状态另与无动画静态几何逐像素比较；其余分数状态不为制造对照而舍入。20 个 PresentationML 根部件通过独立 XSD 校验。

同样 72 帧分别通过实际打包 WASM Worker 的同步及分步执行。此前旋转的 72 帧、包含组合／文字／图片的容器缓动 40 帧在新分步播放包下保持既有结果。

独立产品 worktree 已同步升级固定 SDK、导出 Worker 与播放包。四份完整文稿经独立 SDK 导出，保留原始全部字节及每份 13 个 OPC 部件；48 帧原生参考、76 帧实际产品 Worker 对照、161 项产品测试、类型检查和完整前端构建通过。[验证证据](../reviews/evidence/2026-09-29-container-rate-verification.json)绑定本轮源码、输入、命令、材料和先前失败。

首次产品采样仍沿用旧导航测试的 0–2.2 秒时间窗，未覆盖新样本的完整变化，触发了至少三个不同画面的检查。原失败留存；重试使用 0–21 秒的 12 个显式时刻，不降低检查要求。完整前端构建仍有既有的大分块提示，未据此宣称性能验收通过。
