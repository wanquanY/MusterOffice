# 保留式时间区间复用

状态：本阶段实现与验证完成。属于 P06 的播放计算优化，不代表完整播放能力、外部应用验收或 Musterwork 替换通过。延续[容器生命周期](container-lifecycle.md)的同一因果调度语义。

## 原因与实现边界

作者和导入 PPTX 的播放会话此前已经持有文档计划、来源索引以及局部图片／文字资源，但每次采样仍完整执行时间事件议程。即使期间没有点击，节点开始、自然结束、显式结束和父级截断都重新求解。

`mo-timeline::TimelineSampler` 现在独占一个不可变 `TimelinePlan`，保留最近一份已验证事件前缀对应的区间。无状态 `TimelinePlan::evaluate` 与保留式入口共用事件验证、调度和帧求值实现。没有第二套近似算法、全局缓存、隐式系统时钟或宿主侧补偿。

缓存键包含 session、revision、generation，以及采样时刻之前（含该时刻）已消费事件的精确时间和目标。序号由从 1 开始的连续位置唯一确定。比较有理数时刻而非浮点值，不使用可能碰撞的摘要替代事件相等。只保存规范化的唯一消费事件；不保存完整原始历史、未来点击或已输出帧。调度结果仍可包含由已知条件推导出的未来开始／结束，这是确定性计算结果。

每次命中之前仍完整验证宿主历史：覆盖范围、绑定、原始条数预算、事件代次、非负时间、连续序号、时间顺序及重复冲突。允许的重复仅为相邻、逐字段相同的记录；两条同序号记录即使时间数值相等但编码不同，仍按原合同视为冲突。独立请求中的等值时间编码可以命中同一缓存。

一个 sampler 只保留一份区间和消费前缀；节点、事件及精确整数长度受原有 `TimelineLimits` 限制。重建期间旧条目与新计算临时共存，峰值不能按一份常驻数据估算。不同前缀的后退跳转会重新计算；相同前缀的任意时间采样会复用区间。采样始终重新计算精确进度、属性和实际画面，不缓存旧帧冒充新帧。

## 生命周期与失败语义

计算、帧求值、事件键构造和末尾取消检查全部成功，才替换区间并递增计数。输入不合法、时间计算失败或时间阶段取消，均保持上一个条目和计数。有效区间无法确定无限倒放的终点时，帧求值仍必须报错，不因命中而忽略诊断。

作者和来源计划改为显式可变采样，调用者必须持有独占借用。来源 `SourcePlaybackSample` 借用期间不能再次修改 sampler。没有为保持旧 `&self` 签名引入隐藏内部可变状态。

`advance_generation` 验证旧绑定和严格增长成功后释放缓存，保留不可变文档计划及累计计数；失败或调用前取消不清空。dispose／drop 释放所有缓存。新会话不能获得旧会话缓存。

时间求值之后的放置、绘图或组件失败，允许保留已经成功的时间计算；其计数不意味着有画面提交。宿主仍负责取消、输出代次隔离和提交，WASM 宿主仍负责 worker 终止；本阶段未增加从 JS 中途打断同步 WASM 的能力。

## 诊断合同

作者与来源的请求合同都增加 `inspectTiming`，要求当前完整 `binding`；未 prepare、旧绑定、已 dispose 的错误与其它会话操作一致。响应状态为 `timingInspected`，不需要图片、字体或 raster 组件。

`info.binding` 为当前 owner，`info.sampler` 包含时间图摘要、可空的缓存绑定、`schedulesBuilt`、`schedulesReused`、`retainedIntervals`、`retainedEvents`。全部计数使用可验证的规范 uint64 字符串，跨 JS 安全整数边界仍精确且不回绕。累计计数只在成功时间求值后更新；到达上限时明确诊断。读取诊断不构建区间或递增计数。

原 `inspect`、prepare、采样、advance、dispose 成功输出不新增字段。生成的 Rust → JSON Schema → TS 合同保持同源；没有将这项局部诊断冒充正式 OperationService 或 Agent 产品接口。

## 验证与性能

738 项 Rust 测试、严格 Clippy、格式、Native 与 WASM 构建及 96 份 Schema／TS 合同通过。新增测试覆盖完整历史验证、规范化时间、目标／绑定变化、不同前缀跳转、命中／重建每个取消点、语义失败及代次失效。作者页面取消测试分别从冷缓存和已命中状态执行，验证下一次可恢复。

10 个实际 Native／WASM owner 执行 654 次配对调用，其中 228 次有效工作量读取，76 个作者保留帧和 108 个来源保留帧。含对照共 358 次实际绘图；逐字节比较元数据、绘图命令和 RGBA。来源保留帧不再次解码、排字、上传字体或汇集资源。读取诊断不调用绘图组件；无效未来事件保持上一个条目。

此前 4,856 次静态／作者／来源／分层／变速／重复／结束／容器配对调用，以及 246 次时间查询重放通过，已记录请求、响应、绘图命令、像素和既有导出文件保持字节一致。结果、代码与产物由[阶段证据](../reviews/evidence/2026-09-26-retained-timing-verification.json)绑定。

在 Apple M4 Max、arm64 macOS Darwin 25.2.0、Node 23.5.0 上，旧／新 release WASM 在同一进程交错测量。每项预热 3 次、21 轮，小项每轮 5 次，大项 2 次，前缀变化项 4 次；完整样本、p95 和输入／产物摘要保留在证据中，不删除异常值。页面为 320 × 240、3 个作者对象；100／1,000 是时间节点数，不是同数量完整页面对象。没有字体／媒体依赖，render 项使用同一真实 C++ raster 组件。

测量包含 JSON、完整事件验证、精确时间采样、放置、页面准备、序列化和结果断言；render 还包含实际 raster 与像素复制／比较。排除 prepare、Native IPC、导入来源成本、实际字体／媒体、冷启动、RSS 和显示合成。命中时实际计数仅构建一次；变化前缀按预期重建。小图绘制和重建场景没有测得收益，不把局部改善外推为整机播放 FPS 或产品性能通过。

Rust WASM 为 7,822,561 bytes，比上一阶段增加 19,585 bytes；C++ WASM 仍为 2,370,691 bytes。没有新依赖，锁文件不变。这是未压缩模块，未包含完整字体、媒体、运行时和安装包闭包。

初次编译检查因来源测试仍同时保留旧采样借用和再次可变采样而失败；按显式独占 API 调整测试操作顺序后，定向测试和完整工作区通过。初次日志保留，未放宽生产借用或取消语义。
