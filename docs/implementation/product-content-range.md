# Musterwork 有界验证范围读取

2026-09-27：在[流式内容存储](product-content-stream.md)和[持久回收](product-content-retirement.md)之后，为原生计算提供可保留的随机读取材料。以下 `MW:` 路径属于产品仓库；计算核心没有取得产品路径、租户权限或结果提交权。

## 同一内容端口

`MW:apps/agent-runtime/crates/runtime/content/src/range.rs` 定义同步的 `ContentRangeSource` 和 `VerifiedContentReader`；`ContentStore::open_verified()` 是异步准入入口。没有实现该能力的存储直接返回不可用，不通过旧整块 `Vec` 读取模拟范围读取。`RecordingContentStore` 只在完整成功且返回身份精确匹配后记录原始 ContentRef，用于后续产品提交事务的权限复查。

读取器建立时，以最多 64 KiB 的请求分段读取完整内容，验证声明长度、真实 EOF 和整体 SHA-256，并保留各块的 SHA-256。读取器不暴露底层源、可写句柄或存储定位符。后续每次范围读取先完整读取对应块并核对其摘要，再把所需字节复制给调用者；跨块读取重复这一过程。源后来变化，只能返回已绑定的字节或完整性错误。任何多块读取失败时，调用者必须放弃整个目标缓冲区。

块摘要来自已通过整体摘要检查的那次完整读取，不是生产者另行声明的可信信息，也不引入新的公开文件格式。每个内容保留 `32 × ceil(byte_length / 65536)` 字节的摘要信息；单次块验证使用最多 64 KiB 临时缓冲。测试中的 8 MiB 加 17 字节源使用 129 个摘要。调用者目标缓冲、并发读取、文件句柄和其他运行时对象另计；这些数字不是进程 RSS 或全局内存上限。每次范围读取包含块读取与摘要计算，尚无整体速度收益结论。

## SQLite 真实文件适配

`MW:apps/agent-runtime/crates/infrastructure/sqlite/src/content/range.rs` 使用现有租户和精确 ContentRef 授权，在完整文件扫描后重新检查元数据。扫描与既有读取共用八个并发名额；实际阻塞任务持有名额，接收 Future 取消不会提前释放。取消标记在块读取边界检查，未返回的文件句柄随任务/结果释放。测试只观察生产任务的实际提交，不替代文件读取。

顺序与范围读取复用 `stream_file::open_std()`，核对普通文件并禁止跟随末端符号链接/重解析点。范围材料持有已打开的只读文件，互斥保护定位读取，后续路径替换不会把它重定向到新文件。原文件内容原地变化会被对应块的验证发现。内置产品材料仍走原有精确身份检查，并使用同一范围读取合同。

保留材料与已经返回的字节缓冲一样，不是新的授权凭据。墓碑提交后不能重新打开该内容；已经获得的私有材料仍可能由计算持有，底层文件空间也可能直到句柄关闭才释放。作业取消、材料释放和最终权限检查仍属于原 Runtime；不能用一个读取器绕过 Artifact/Invocation 提交授权。

同步范围计算应在原生阻塞执行器运行，不能在 UI 或异步控制循环中执行文件扫描。这里没有新增任务 owner、数据库表、调度器、MusterOffice SDK 依赖或权限代理。

## 验证与后续

最终共享内容库 26 项测试、SQLite 内容/准入/迁移/维护筛选 55 项测试通过，两者生产库严格 Clippy 和所改 Rust 文件格式检查通过。验证覆盖短读、长度/EOF/摘要错误、超限输入、跨块与逆序范围、底层内容变化、内置内容、符号链接、精确租户/身份、取消及扫描期间撤销权限。取消测试占住唯一阻塞线程，观察实际扫描提交后取消接收方，确认名额直到任务退出才释放。八类已有写入/回收进程强制终止场景在本次最终回归中重新通过；未重跑上一阶段的外部 v183 二进制升级实验，三个 ignored 条目仍是专用验证入口。

初次构建的缺失括号、lint 和测试未使用导入已修正；第一次 SQLite 回归为 54 项通过、1 项失败，原因是新增测试把既有 `IdentityConflict` 错误误期望为 `Invariant`。按原内容合同修正断言后，最终 55 项重新通过；产品错误分类没有被改成迎合测试。各次日志保留，不把中间结果计为最终源码通过。

同一组两页交付分别经过产品顺序流式读取和新范围读取，后者以逆序 4 KiB 片段重建文件。两条路径各得到 12 个资产和 bundle，共 13 个实际内容文件，全部与上一阶段封存字节一致。固定摘要的共享内核 CLI 对范围读取结果重新执行交付检查，报告保持一致。这验证实际存储材料和文件，不代表 SDK `ReaderAt` 桥接或原生生产者已经接通。

共享内容库另通过 `x86_64-pc-windows-msvc` 目标编译检查。最初按项目固定工具链检查时缺少该工具链的目标标准库，随后使用同为 Rust 1.92.0、且已有该目标的 `stable` 完成检查；没有据此声明 SQLite 文件层、整个产品、Windows 运行或文件系统验收。当前工作不修改内核 Native/WASM、worker 或 SDK 字节，没有新增依赖版本、数据库迁移或安装包测量。
