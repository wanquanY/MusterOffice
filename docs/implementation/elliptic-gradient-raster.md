# 椭圆渐变实际绘制组件

2026-09-25。在[有界标量求解](elliptic-gradient-scalar.md)之上，椭圆场已进入真实 Skia CPU 绘制组件和 TypeScript 薄适配层。Native、WASM、ASan/UBSan 输出实际 RGBA 像素。**Rust 场合同和 PPTX 来源页面尚未生成这种画笔**；本阶段不是源页面渲染、目标应用兼容或 Musterwork 接入验收。

## 组件格式与计算

基础 ABI 4 不变，新增可选查询 `mo_skia_elliptic_gradients_abi() == 1` 和 V12 帧。V12 保留 V11 的 14 字帧头、8 字绘制记录和既有画笔，最多 2,895,950 个 u32。TypeScript 必须检查新能力；旧组件明确拒绝 V12，不降低到其他画笔。

渐变几何 kind 4 的头为 19 字：

| 字段 | 数量 | 语义 |
| --- | ---: | --- |
| 通用头 | 5 | kind、标量平铺、颜色插值、alpha 策略、色标数量 |
| 仿射基 | 6 | 与既有二维渐变平面相同 |
| 平面轴平铺 | 2 | Clamp / Repeat / Mirror |
| planeScale | 2 | `qx=(2u-1)*scaleX`，`qy=(2v-1)*scaleY`，每项 `(0,1]` |
| innerCenter | 2 | 外圆中心零、半径一时的内椭圆中心 |
| innerRadii | 2 | 同一归一化空间中的非负半轴 |

上述数值为显式 binary32 位模式，范围继承标量核。颜色坡道独立，沿用现有 sRGB、线性 sRGB、Office 插值、alpha 及合成逻辑。场不预烘焙成图片、不创建临时纹理，也不改变原生文稿对象。

`PreparedField` 在画笔建立时选择同心圆专用计算：预先确定半径平方和分母区间，每个采样点直接求距离。binary32 平方在 binary64 中精确，后续和、平方根、减法和除法使用向外界；不确定分类仍交给同一个通用核。返回值保持此前的标量误差合同，没有以放宽误差换取速度。

其他椭圆继续使用有界首次交点求解。Skia 固定阶段按当前 CPU 批次传递坐标，使用栈数组，没有逐像素堆分配；当前求解本身尚未完成 SIMD 优化。尾部不足整批的像素从管线自己的 tail 指针读取，只计算有效通道。管线建立与复制都按 Skia 自有方式绑定 tail，不从外部暴露其私有接口。

## 错误与计算预算

每个同步绘制请求持有独立状态，所有椭圆画笔共用计数器：最多 16,777,216 个采样点、67,108,864 个根隔离节点，每个采样点仍最多 512 节点。计数包括实际有效通道，内部原子计数不会跨请求共享。

数值精度耗尽或预算耗尽返回组件状态 3；每次普通绘制和 miter-clip 绘制完成后检查状态。失败时释放整个候选像素缓冲区，输出指针和长度保持零。有效输入的数值失败不隔离整个实例，后续健康请求仍可成功。实际验证分别触发了精度、采样预算和节点预算失败，并验证失败后恢复。

这只是低层状态。Rust/PPTX 接入时仍需定义参数转换误差、可定位来源诊断及宿主取消，不得把状态 3 静默转成默认颜色、位图替代或成功结果。

## 验证结果

- 2,646 个预计算求解用例：2,638 成功、1 精度诊断、5 非法输入、2 预算诊断；成功结果使用独立精确有理数/Sturm 参考核对，Native/WASM/检查构建逐字节一致。
- 23 个实际画笔场景包含 20 个成功图像和 3 个数值/预算失败；覆盖点、同心圆、非等轴、偏心、外部焦点、点/线退化、外扩、平铺、斜切、翻转、尾部通道和 Office 坡道。
- 总计 551 组三端组件对照一致，含 19 个非法帧/截断用例、490 个历史通用帧、18 个历史来源页面帧及失败恢复。历史帧保持原像素。
- 90 位 Decimal 同心圆参考和精确 Sturm 拓扑参考核对 48,233 个像素，最大灰度差约 0.49970。32 个像素的边界方程有三个根，实际绘制选中第一个。一般椭圆按每四个像素取样；同心圆完整图像核对。Office 色彩坡道本阶段没有独立新像素参考，仅三端和已有坡道回归。
- 用新静态库重新运行 611 项 Rust 测试、严格 Clippy、格式、82 份 Schema 和 TypeScript 检查，全部通过。Rust 主体、82 份生成合同和第三方依赖未改变。

第一次组件构建发现 tail 访问属于 Skia 私有接口，已改为管线原生注册位置并完成三端重建；构建补丁格式错误也已修正。没有放宽编译器、验证器或权限来绕过失败。当前最终构建和测试结果见[阶段证据](../reviews/evidence/2026-09-25-elliptic-render-verification.json)。

## 实际绘制耗时与体积

Apple M4 Max、arm64、Darwin 25.2.0、约 36 GiB 内存，Apple Clang 17.0.0，固定 Emscripten 6.0.10，Node 23.5.0。每项三次预热、25 次测量，以下为中位数；每次重新校验、建立路径/画笔、分配和绘制像素。Native 计时覆盖 C ABI 调用；WASM 还包含 TS 输入分配/复制和输出复制。没有字体、图片、Rust、PPTX 排版或启动成本；未控制其他系统负载，不能视为产品性能验收。

| 场景 | 尺寸 | Native | WASM＋TS |
| --- | --- | ---: | ---: |
| 既有 Skia 径向画笔对照 | 1024×1024 | 2.81 ms | 18.56 ms |
| 新中心点场 | 1024×1024 | 14.04 ms | 44.33 ms |
| 新同心圆场 | 1024×1024 | 13.40 ms | 43.08 ms |
| 偏移点 | 512×256 | 52.37 ms | 75.85 ms |
| 中心非等轴椭圆 | 512×256 | 142.42 ms | 203.63 ms |
| 非嵌套椭圆 | 512×256 | 233.62 ms | 324.17 ms |

中心点与既有径向画笔的像素差不超过一个色阶。通用椭圆仍明显偏慢；同心圆也比既有专用画笔慢。这些差距保持为未完成项，后续要做参数预计算、经条件验证的专用算法和批量向量化，同时保留首根和诊断语义。

当前绘制 WASM 为 **2,343,781 字节**，相对 V11 的 2,327,852 字节增加 **15,929 字节**。Rust WASM 主模块保持 6,398,266 字节。数字是独立未压缩模块，不包含字体/媒体/宿主，不代表 Musterwork 安装包增量。
