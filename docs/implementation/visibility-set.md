# 固定可见性属性与保留资源播放

2026-09-28，演示文稿时间图增加通用 `setVisibility` 行为，覆盖创建、原生 PPTX 读写、时间计算和作者／来源页播放。Musterwork 对接继续使用独立 `codex/musteroffice-integration` worktree；本阶段先验证内核，没有切换产品固定组件或默认引擎。

## 语义与接口

`Effect::SetVisibility { target, value }` 的值只能是 `visible` 或 `hidden`。行为在活动或保持期间固定替换可见性；尚未触发、被移除、祖先结束或重新开始时，由下层动画或文稿基础状态决定显示。时间、重复、结束条件、重启和导航仍使用同一个时间计算器；离散值不进行插值。

多个行为采用已有的激活时间与结构顺序规则，后来的可见性赋值不会覆盖旋转或缩放通道。隐藏组会抑制整个子树，子对象的可见赋值不穿透隐藏祖先。文稿、来源 XML 和原始几何保持不可变，采样只产生当前帧的组合结果。

原生映射是 `p:set`、明确的 `style.visibility` 属性及 `p:to/p:strVal`。未知属性、缺少属性名、未知值和未实现预设仍返回结构化拒绝，原始来源包保留。普通 Set **不等于**“出现”或“消失”预设：通用“设为可见”没有动画开始前自动隐藏的含义。本阶段没有接受或生成 entrance/exit 预设来伪装这一差异；预设基础状态和原生隐式事件仍需继续实现与外部验证。

含可见性行为的结果使用 `musteroffice.property-frame/0.1-draft`；作者、来源页分别使用 `property-playback-author-page-q96-v1-draft` 和 `source-property-resource-page-q96-v1-draft`。旧旋转／变换 profile 不变，空的可见性通道不输出，以保留旧响应和摘要。Rust 生成 JSON Schema 与 TypeScript 声明。CLI 通过与生产者共享的 profile 选择函数检查作者结果，通过来源帧自身的 profile 方法检查来源结果；不再固定只接受早期旋转结果。

## 资源与边界

保留播放在初始化时准备基础可见内容，以及时间图可能显示的隐藏内容。准备阶段仍检查所有可能进入画面的内容；资源无效时拒绝创建播放状态。始终隐藏且没有可见赋值的资源不会因此被加载。

图片缓存绑定改为稳定的来源部件与对象身份。隐藏前面的对象后，后续绘制序号变化，不会被当成资源身份变化。每帧核对当前可见资源的覆盖，文字也按可见对象核对绘制集合，返回对应文字工作量和容量信息。它不是通过关闭“遗漏内容”检查来容许隐藏。字体与图片在后续帧中复用，不重新调用排版或解码组件；原有容量限制和取消校验继续生效。

内核不引入按钮、页面、权限、文件存储或后台任务。Agent 通过既有文稿／时间图接口设置属性，接入产品仍拥有用户交互与播放时钟。

## 验证范围

时间单测验证精确触发与移除边界、保持值的恢复、多个行为的顺序、重复／反向时钟、父级结束、点击历史、重新采样和非法离散值。PPTX 测试覆盖平面和层级图导出后重新读取，并拒绝把未实现的出现预设投影成普通 Set。编译测试比较独立静态来源页，检查组继承、隐藏资源准备、图片顺序改变和反向采样。

真实原生 Worker 使用自有字体、图片和文稿，覆盖文字、不同图片的顺序变化、隐藏文字／图片的显示，以及含文字和图片的组。五个场景各采样九次，共 45 次与独立静态 PPTX 的像素、文字覆盖及容量信息对照。另有九帧作者文稿通过公共 CLI 验证隐藏、移除恢复和倒退采样。

547 项 Rust 测试与严格 Clippy 检查通过；普通运行的九项显式组件测试保持 ignored，其中本阶段新增的一项随后用固定真实 Worker 单独运行并通过。新 54 个采样通过公共 WASM SDK 的同步和分步两种方式核对，449 个旧冻结帧回归通过。六份自有 PPTX 的 45 个 PresentationML 部件通过 XSD，另有七组 CLI 像素检查覆盖新行为和原有缩放。JSON Schema 与 TypeScript 再生成检查、复现工具静态检查通过。

[最终验证记录](../reviews/evidence/2026-09-28-visibility-set-verification.json)核对 4,081 个源码和材料文件。WASM 开发包清单摘要为 `520895755070722f2b18e1c2289b1e44b370d667bf398972fdd7b0e05df57704`；它是本阶段独立验证材料，尚未替换 Musterwork 的固定组件。原生及 WASM 使用同一个 Rust 计算实现，跨端一致性不能代替外部办公软件验收。

首次原生检查因自有测试字体没有字符 B 而被正确拒绝；样本改用该字体实际具有的字符，未放宽字体检查。首次 CLI 作者采样暴露早期 profile 检查的缺陷，修复消费者后重新执行。失败记录和初始材料保留。

这些检查不代表 Office/WPS 的出现／消失预设互操作验收，也不代表完整动画、转场、媒体、SmartArt、公式、完整 Electron 链路、性能／安装包或 Musterwork 整体替换完成。完整一期目标继续实施。
