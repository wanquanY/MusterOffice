# 原生路径空间与椭圆弧编译

2026-09-24：在[几何求值](geometry-evaluation.md)之上实现原生路径编译，将求值后的自定义几何转换为形状局部空间的 Q32 EMU 路径。计算位于 `mo-presentation-compile::native_paths`，源文件读取、原始声明和公式解释仍由 `mo-pptx` 负责。CLI、Native 范围读取 API 和 WASM 使用同一实现。[封存证据](../reviews/evidence/2026-09-24-native-path-verification.json)绑定本阶段源码、实际产物和验证结果。

2026-09-25 更新：187 种预设及显式文档/定义来源已接通本编译器，见[预设展开](preset-expansion.md)；以下验证数字保留为此前阶段记录。

这是来源页面绘制的计算环节，尚未接通来源页面完整画笔、对象变换、文字或图片。本节早期验证时预设声明仍需展开；验证中把标准示例包装成真实自定义几何，并不表示已实现原生预设形状。路径计算不会改变原 PPTX 的可编辑声明。

## 输入、输出与来源

CLI 为 `pptx-paths <query.json> <source.pptx>`，WASM 为 `compile_pptx_paths(request, source)`。请求中的 `geometry` 是已有摘要绑定的 `SourceGeometryQuery`，`options` 显式指定 `drawingml-polar-arcs-q96-hermite-v1-draft` 和正数 `coordinateTolerance`。容差是形状局部 EMU 的 Q32 整数字符串；例如 `4294967296` 表示每轴 1 EMU。

响应保留来源摘要、表面、几何解释配置、路径配置、容差及请求对象顺序。逐对象结果区分公式/声明未解析、路径未解析、成功编译。成功结果含尺寸及其声明来源、路径的填充/描边/挤出原始修饰项、命令及来源映射。一个原生弧可生成多个三次曲线；无长度弧也保留命令数为零的映射。没有把样式省略提前解释成无填充或默认画笔。

`NativePathCompiler` 实例共享预算，重复对象、失败对象和整个查询批次不能刷新预算。默认最多 4096 个路径、262144 条输出命令、262144 个弧片段、4000000 个工作步骤和单弧 128 圈。取消与预算耗尽中止整批，语义未解析定位到原生节点。核心不读取任意路径、网络或系统字体。

## 坐标和轮廓

路径声明 `w/h` 时，分别按形状尺寸除以路径尺寸缩放。未声明的轴沿用 EMU；零路径尺寸保持明确未解析，不与省略合并。该解释仍是 draft，需目标应用核对。坐标系依据 ECMA-376 Part 1 §20.1.9.15、Annex L.4.9.2.3。

直线、二次和三次 Bézier 曲线直接转换控制点。初始笔位置为局部原点；`close` 回到当前子路径起点，之后继续绘制时生成显式 `move`，满足通用 Draw IR 的轮廓顺序。新增 `move` 也属于引发它的来源命令。每个原生路径保持独立，不合并其画笔修饰。

## 椭圆弧和误差

`arcTo` 的起始角锁定到当前笔位置，圆心由当前点与该角的椭圆交点推导；不会添加一条到猜测起点的连接线。角度单位为 1/60000 度。非圆椭圆必须区分从中心射线测量的角与参数角：参数点为 `(rx cos φ, ry sin φ)`，参数角取决于 `atan2(rx sin θ, ry cos θ)`，并保留象限和圈数。[微软 ArcTo 说明](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.arcto?view=openxml-3.0.1)及 [Apache POI 角度转换实现](https://raw.githubusercontent.com/apache/poi/trunk/poi/src/main/java/org/apache/poi/sl/draw/geom/ArcToCommand.java)用于交叉核对含义，没有复制其代码。

当前配置保留有符号扫角和多圈路径。零扫角不生成曲线；两个半径同时为零时，椭圆退化为当前点，也不生成曲线，支持标准圆角示例中的零圆角。负半径与仅一条半径为零分别保留诊断；后者的目标应用行为仍需核对，不能直接填零或删去整个对象。

公式输出 binary64 在进入本阶段时按位解码为二进制有理数，向外包围到 Q96；不经本机浮点乘法转换坐标。区间除法和整数平方根向外取整，π 复用已有独立验证的 Q96 包围。正弦/余弦用象限归约和有余项界的级数；正切反函数用半角归约及级数，极坐标到参数角的映射利用单调性包围端点。不调用平台超越函数。

弧采用三次 Hermite 插值。参数跨度为 h、缩放后半径为 r 时，每轴连续曲线近似误差不超过 `r·h⁴/384`。按 2 的幂增加片段数，直到解析近似上界不超过所请求容差的四分之一。Q96 计算与 Q32 控制点量化误差另行包围；合计超出容差就返回诊断，不能悄悄放松容差。

输出分别报告 `numericErrorBound`、`curveErrorBound` 和两者之和 `coordinateErrorBound`，均为每轴局部 Q32 EMU。**这些界只相对于求值阶段输出的确切 binary64 值成立**，不证明来源公式的数学误差、世界变换、像素转换、抗锯齿覆盖率或 Office/WPS 视觉差异。后续页面编译必须继续传播各层误差；不能把局部 1 EMU 直接写成整页像素保证。

## 验证与复现

自有边界语料包含四种椭圆比例、各象限、分数角、负角、零扫角、正反多圈、单轴缩放、零尺寸、退化半径和闭合后继续绘制；同时复用此前 602 份真实公式/PPTX 输入。独立 Python 验证以 80 位 Decimal 计算极坐标交点、控制点和插值余项，并采样输出曲线与解析椭圆的误差。输入公式值用确切 binary64 有理数重建，与本阶段合同一致。

- 全仓 302 项 Rust 测试、严格 Clippy、rustfmt、TS 和 57 份 Schema 检查通过；新增 10 项测试及 2 份合同，此前 55 份 Schema/生成 TS 字节不变。
- 808 份 PPTX 中 762 份编译成功，46 份保留诊断。包括 602 份既有输入与 206 份自有新输入；6 个额外非法请求也分别验证摘要、数量和请求合同。
- 新增 814 批路径查询和 206 批导引查询的真实 Native/WASM 字节比较；其余 602 批导引查询属于重跑，不重复增加累计数。旧 5216 批在新产物上重跑且结果不变，累计 6236 批主内核逻辑检查。
- 独立检查 1112 条路径、121927 个控制点、38429 个弧片段和 115287 个椭圆采样点；最大控制坐标差约 1.16416×10⁻¹⁰ 局部 EMU。此差值相对于精确插值控制点，不是连续曲线误差或应用视觉差异；曲线余项另受返回的界约束。
- 新输入的 1236 个表面部件通过官方 XSD。46 份未解析包含 42 份此前公式/声明诊断、一个单零半径弧、一个负半径弧及两个显式零路径尺寸；不以成功比例替代能力验收。

本轮没有新增外部运行依赖版本，只增加内部依赖边。CLI 增加 74096 字节、Rust WASM 增加 73012 字节；全部产物的实际大小见封存证据，不代表完整内核或安装包。原生工作进程已重建并通过回归；六个 C++ WASM/薄层产物字节不变，197 批 Skia 组件/sanitizer 和 61445 个参考像素的既有证据按摘要复用，本轮没有重跑组件测试。
