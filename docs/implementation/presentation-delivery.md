# 演示文稿私有交付计算

状态：完整私有候选计算已实现并通过本阶段验证，源码、产物和失败记录由[阶段证据](../reviews/evidence/2026-09-26-delivery-verification.json)绑定。公开导出作业、宿主资产原子提交、完整一期和 Musterwork 替换仍未完成。“完整候选”指当前开发配置要求的全部交付文件，不表示完整演示文稿能力或质量已经验收。

## 计算与宿主职责

`mo-presentation-delivery` 接收已验证快照、显式导出/预览设置、范围可读的素材/字体、输出存储能力和预览计算能力。核心不持有文件路径、数据库、进程、网络、系统字体或产品业务。它复用既有 `mo_pptx::export_to`，而非重新实现一套格式生成器。

一次计算生成原生 PPTX、可编辑 SnapshotRecord、文档素材副本、字体上下文、交付配置、逐页 PNG、每页渲染证据及质量报告。隐藏页仍有编辑态预览。清单绑定文档版本、引擎/规则/字体/配置摘要及全部资产；最终检查页序、资产引用、五类声明和证据引用的闭合关系。素材身份由文档声明及实际字节共同验证；每个输出封存后重新读实际存储字节，与写入长度及 SHA-256 核对。

`featureRegistrySha256` 绑定本次保存的交付组件登记快照，列出 pipeline 和页面预览的命名空间、原生 profile、参数合同、语义版本、能力 ID、目标及语料。它明确标记 `scope=delivery-composition`、`completeNativeCatalogue=false`、能力部分实现且尚未验收，不替代设计要求的完整原生格式枚举注册表或用于协商完整能力。完整交付目前仅有 Native 集成；可移植计算核心的 WASM 编译与预览器的双端执行分别登记。具体 renderer 实现摘要保存在交付上下文并参与设置摘要，避免将部署二进制身份误当成能力登记。早期诊断候选把交付配置摘要写入该字段，后续候选已修正；早期文件和失败记录保留。

PPTX 通过实际 OPC/ZIP/XML 图检查后，预览器直接读取同一封存包。字体同样从本次封存的字体包读取。每页响应检查包摘要、部件、可见性、尺寸、场景/像素配置及实际像素摘要。预览失败、中途取消、存储字节不一致或文件缺失均不能返回 `DeliveryCandidate`。候选类型不能由 JSON 反序列化伪造。

`OutputStore` 创建的是私有输出；返回候选不提交文档、不发布资产、不修改任务成功状态。标准宿主与嵌入宿主还必须将其绑定到接受的请求、执行器、租约/fence、输入内容及取消状态，在既有任务 owner 的事务中提交全体资产和回执，不能嵌套第二个任务 owner。

## 原生隔离预览与 PNG

`mo-native-render` 实现原生预览能力。可信操作员配置 worker 路径及预期 SHA-256，每次调用前核对实现摘要；路径不进入核心或 Agent 参数。导出设置摘要同时绑定 worker 实现和渲染配置。它调用既有 `--pptx-resource-page` 入口，透传真实诊断。

`mo-native-worker` 将同步 pipe I/O 放在传输线程中。输入提供者在调用线程从范围读取器分块取数，单块最多 64 KiB，通道容量为一，避免为了线程约束复制整个 SQLite 资源。所有者检查取消与时限，错误时结束并回收直接子进程；CLI 的既有一次性 worker 通信复用此实现。协议为先完整请求、再完整响应，不能当作通用双向流协议。

worker 内部仍可能分配整包输入、字体和页面像素；元数据也在显式预算内收集。此处没有常量总 RSS 或整个系统资源上限声明。输入提供者和可信操作员路径属于宿主边界，前置摘要检查不解决同一用户恶意并发替换可执行文件的 TOCTOU 问题。

`mo-image::png` 将预乘 sRGB RGBA8 转成 PNG 非预乘通道，写入 sRGB 声明、Sub 行过滤和 64 KiB IDAT 块，保持确定性输出。验证有效预乘通道后才开始写出；输出预算、短写、取消、flush 错误及摘要按实际写入处理。PNG 依据 [W3C PNG 第三版](https://www.w3.org/TR/png-3/)，没有新增图像处理运行时。使用已有 `flate2 1.1.9` 与 `crc32fast 1.5.2`；后者由传递依赖提升为显式直接依赖，版本及许可未改变。

## 真实链路发现的默认文字样式缺陷

第一次实际交付未能渲染母版文字：Writer 将全局、母版和文本框默认样式写在 `defPPr` 中；已实现的来源级联遵照 Office 行为忽略该节点，因此缺失字体。Microsoft [defPPr 说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/18292376-7677-4792-8422-8024b97ec52f)确认 Office 不使用此节点来决定段落属性。

修复位于 Writer：当前作者段落为原生零级，默认样式改写至对应的 `lvl1pPr`，保留文本框、段落、run 与母版之间的逐属性覆盖。没有改变 Reader、替换字体或删除文稿内容来获得成功。新增往返测试核对所有八段文字的字号、三类脚本字体声明及继承来源，并验证母版→文本框→段落→run 覆盖。

新建 PPTX 字节因此有意改变。原始两页语料由 10,952 变为 10,962 字节，独立解包确认仅四个 XML 部件中的上述节点名称改变；其余部件和素材不变。旧记录与旧文件保留原样，新的冻结摘要不能解释为历史版本也正确。此前“缺少文字画笔”的负例现在从合法全局默认项继承颜色，因此负例显式移除该默认项，继续验证真正缺少画笔时在组件调用前拒绝；生产级联没有放宽。

## 质量与验证范围

五类声明分别为结构、排版、原生可编辑性、播放、目标应用。当前结构声明的通过范围仅为 `opc-zip-xml-graph-digest-v1-draft`，不声称生产过程执行完整 PresentationML XSD。其他四类均为 `not_proven` 并说明原因；成功生成每页预览不能自动证明视觉保真或动画/媒体播放。

真实候选语料见[自有测试输入](../../fixtures/presentations/delivery/README.md)。它有两页、15 个对象、母版/版式、图片及明确自有字体；八段文字为 `A A`。字体的 A 轮廓本来就是三角形，这不是商业排版质量样例。

- PNG 测试覆盖全部有效透明度/单通道整数组合、独立解码、跨 IDAT、短写、无效像素、取消及失败传播。
- 传输测试真实运行子进程，检查非 Send 提供者、有限提前读取、阻塞输入取消/超时、尾随响应和非零退出。
- 两项显式原生集成测试使用已构建并按摘要固定的 worker，覆盖实际两页/隐藏页、四类渲染响应篡改、第二页存储失败、封存字节变化、最后封存时取消、提前预算拒绝和实际字体摘要错误。普通 workspace 测试将这两项列为忽略；阶段验证另行显式执行，不能将忽略当作通过。
- 独立 Python 检查实际文件摘要、全部引用、模型内容/版本、字体和素材、PNG 解码与像素摘要、原生对象及官方 XSD。它不使用外部应用，不代表 Office/WPS 已验收。

新增三份生成合同：交付设置、候选清单和渲染实现身份，TS 类型由同一 Rust Schema 生成。它们是库级候选接口，不新增已可调用的公开 `presentations.export` 作业。

全仓 819 项 Rust 测试通过，另显式执行上述两项真实 worker 集成测试。严格 Clippy、Native 构建、107 份 Schema/TS 检查及纯交付核心 WASM 编译通过；此前 104 份合同不变。72 次文件/编辑双端调用通过，12 份来源编辑结果、12 份来源检查响应及 22 份文档编辑响应保持历史结果。7 份新建文件分别与冻结旧 WASM 生成结果解包对照，仅默认样式节点变化，70 个相关 XML 部件通过 XSD。

最终磁盘候选包含 12 个文件；两页实际 PPTX 经 Native 与新构建 WASM 的相同预览入口执行，元数据及全部像素一致，PNG 独立解码后的预乘像素摘要匹配。完整候选计算本阶段只在 Native 执行，不能以纯核心 WASM 编译代表完整 WASM 交付运行。全仓回归启动后调整了注册表元数据，随后重建 Native、显式集成测试与独立文件检查覆盖最终实现。独立脚本首次因注册表循环变量覆盖摘要函数失败；仅修正脚本并从新目录重跑实际交付，失败日志及此前候选保留。

## 复现与下一步

全仓检查使用 `python3 tools/verification/delivery-workspace.py`，输出位于 `.codex-work/delivery-pipeline/`。显式集成测试先构建 `mo-raster-worker`，设置其绝对路径 `MO_DELIVERY_WORKER` 和真实摘要 `MO_DELIVERY_WORKER_SHA256`，运行 `cargo test -p mo-native-render --test delivery -- --ignored`。

`mo-native-render` 的 `delivery` 例程参数为：新诊断目录、输入 JSON、图片 bundle、字体 bundle、worker 路径、worker SHA-256。它只导出验证用诊断文件，不伪装成正式任务提交。`delivery-reference.py` 读取这些真实文件独立检查；`delivery-parity.mjs` 执行原生/WASM 文件及页面对照。

后续必须接通真正的导出动作、持久资源绑定、取消/版本/fence 检查和完整交付原子提交，再实现 Agent 与 Musterwork 产品适配。完整动态/媒体/SmartArt/公式、复杂文字/效果、目标应用兼容、跨平台发行与整机性能预算仍按既定目标实施。
