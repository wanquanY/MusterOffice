# 任务私有输出与同库生命周期

状态：标准宿主的导出结果所有权底座。完整公开 export 作业、交付清单、预览/质量证明和 Musterwork 接入仍需继续实现；本阶段不把候选文件登记成成功导出。

## 实现与边界

`mo-standard-host` 提供 `create_result`、`open_result`、`SqlResultSink` 与 `SqlResultReader`。既有 `mo_pptx::export_to` 直接使用这个 sink，无需先在内存生成完整文件、上传到公共资源区，再复制进最终存储。CLI 继续使用文件 spool；Musterwork 嵌入模式仍由产品自己的内容存储和任务事务提供能力，不嵌套标准宿主数据库。

新输出的身份绑定作用域、执行主体、任务、fence、请求摘要、执行器摘要和输出名称。`WorkLease` 由宿主产生，不从 Agent 参数反序列化。每次流访问检查持久任务的运行状态、租约与取消标志；创建/重新打开还核对原始操作权限。逐块检查只解码有界任务元数据，不反复解码完整文稿。输出名在一次任务中不能重用，放弃后保留墓碑。

状态依次为 Writing、Sealing、Sealed；失败、取消、过期或无输出的文档操作提交后转为 Discarded。Sealed 仅意味着实际存储字节已冻结并完成摘要计算，`VerifiedPackage` 仍须由 OPC 回读路径产生。当前没有 Published 状态、公开资产映射、导出成功回执或 public bundle。

## 写入与验证

- 写入最多持有一个 256 KiB 尾块。`flush` 会持久化部分尾块；后续只能在 Writing 状态扩展该尾块。写入失败保持失败状态，不能再封存截断结果。
- 每块写入在独立事务中重新检查任务和已保存长度。时钟回调、格式计算、整文件摘要计算均不占用写事务。
- 封存先核对 SQL 中实际块数、长度和索引范围，冻结写入；然后逐块读取持久字节，检查块摘要并计算完整摘要，最后再次检查执行状态才保存 Sealed。
- 读取的任务检查、候选元数据和实际块处于同一短读事务。读取不保留块缓存；已有句柄在取消/过期后也不能继续读取。后续校验使用同一批私有字节。
- 读写能力支持同时借用标准宿主，允许资源读取和输出流共用连接；所有内部事务在返回前结束，不跨调用持有锁。

取消与当前文档操作的终态提交在同一数据库事务中删除未发布输出块并释放预留。若删除失败，任务状态也回滚。正常 Drop 尽力清理未封存输出；进程强杀或清理失败由任务租约及后续维护回收。封存的候选由任务持有，读取句柄释放不会提前删除它。

## 预算和迁移

输入上传预留与任务输出预留共用 `max_scope_bytes`。输出在开始计算前声明容量，封存后按实际长度收缩；单输出沿用 `max_asset_bytes`，另有任务/作用域输出记录数限制。输入和输出的两类接纳均在同一写事务内计算共享额度，不能并发超额。墓碑计入记录上限。

接纳前按作用域清理最多 128 条过期输出，不暴露其他主体的元数据。租约续期同步更新输出过期时间。当前没有独立后台清理服务：没有新接纳或任务查询时，过期记录不会自动消失。清理事务可能删除多个数据块，本阶段不宣称其最坏延迟已经满足生产门禁。

数据库版本从 2 升到 3，增加 `result_spools`、`result_chunks` 和到原任务的外键。既有六张表的内容不重写，v1 数据库仍顺序升级。没有新增第三方依赖、核心/WASM 依赖或公共 wire 合同。

这些是逻辑字节预留，不是数据库文件、WAL、空闲页、索引、RSS 或全机磁盘的硬上限。SQLite 物理空间回收、全机预算、公平调度和运行时强终止仍需后续验收。没有本阶段吞吐、内存或安装包体积收益声明。

## 验证范围

专项测试覆盖：部分块刷新与继续追加、重开后的同字节读取、读取权限隔离、名称重用拒绝、摘要损坏/缺块、共享配额与多连接竞争、取消撤销旧句柄、续期和过期、时钟回退、执行器/请求/fence 变化、终态事务回滚、文档操作成功时回收候选、封存过程中取消及最终保存故障。父测试实际启动并强杀 Writing 与 Sealing 两种阶段的子进程，重开后验证租约回收。

真实 PPTX 测试通过持久化素材 `BoundResources` 写入 `SqlResultSink`，由核心回读验证，并与原内存导出路径逐字节比较。`job_output` 例程用于独立检查重开后的实际数据库字节，其诊断文件不是产品发布。例程使用真实创建任务的租约验证底层所有权，不宣称公开导出操作已经实现。

全仓 810 项 Rust 测试（新增 14 项）、严格 Clippy、104 份不变 Schema/TS 合同通过。两份真实 v2 数据库副本升级后保留全部原有行；3 次 release 进程调用验证私有 PPTX、任务过期回收及跨块读取。两页 PPTX 的实际存储块与此前导出文件逐字节一致，独立检查 20 个 XML 部件和媒体字节。

当前 debug CLI 的二进制摘要与父阶段不同，未将它计为未改动产物；另行运行 17 次作者导出、33 次来源读取/编辑和 22 次文档编辑双端调用，与冻结 WASM 一致。release CLI 和 Rust WASM 的摘要保持不变。最初独立脚本误取失败响应字段，保留失败记录后按原有 Failed 信封修正，并从新数据库副本完整重跑；未修改生产响应合同。

这些检查和源码摘要由[验证记录](../reviews/evidence/2026-09-26-job-results-verification.json)绑定。不增加整页像素或 Office/WPS 应用验收；完整动画/媒体/SmartArt/公式以及 E0–E3 门禁仍保持未完成。

## 后续交付链路

在同一操作 owner 中加入真实导出请求、输入版本与资源/字体绑定，完成模型、PPTX、逐页预览和质量声明组成的交付物。最终提交必须再次验证任务 fence、取消状态及完整交付证据，原子写入资产引用、回执和成功状态。不得只把这个私有 PPTX 候选包装成完整导出成功，也不得把标准宿主当作 Musterwork 的第二个任务所有者。
