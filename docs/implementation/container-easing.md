## 计算边界

`TimingContainer.timeTransform` 是可选字段，旧输入省略它时保持原有序列化。容器先变换自己的简单时间，再把结果传给后代；嵌套容器按祖先到子孙顺序组合，叶子的重复、反向和自身缓动继续消费这个时间。没有把容器属性复制到各个叶子，也没有改写来源树。

这符合[级联时间变换模型](https://www.w3.org/TR/SMIL3/smil-timemanip.html)：容器时钟影响整个子树，而不是各个行为独立重置缓动。原生 `cTn` 的位置及属性由[原生节点定义](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.linq.p.ctn?view=openxml-3.0.1)确认。

当前编译器证明子树满足以下条件后才启用非线性容器缓动：

- 容器有有限、正的跨度；后代均相对父级零延迟开始，所有后代的活动终点相同。
- 容器为并行组，或只有一个子项的序列；内部没有导航或独立结束条件。单一零偏移开始条件没有第二次激活，因而可以保留原生 restart 声明。
- 容器自身为正常速度、不自动反向。叶子可以有自己的速度、反向、重复和缓动，只要其活动跨度满足上述证明。

缓动保持首尾端点。在这个定义域内，既有开始／结束事件顺序、祖先截断、父级重新激活和范围内跳转仍然成立；采样使用原始容器跨度，提前结束不会重新缩放缓动曲线。编译为每个实际过滤器保留一个容器时钟，按现有精确算术和深度预算执行，未新增依赖。

不同时长、错峰子项、内部事件和容器变速／自动反向仍需继续实现。它们涉及非线性截止时刻向父时钟投影，逆变换可能产生无理数，不能用毫秒舍入或复制叶子缓动代替。当前明确拒绝这个定义域以外的输入；完整一期目标未缩减。

## WPS 对照结论

上一阶段的六方向自动启动样本可以播放，但动画列表为空。本次用相同公共作者接口只改为单击触发，WPS 动画列表正常显示自定义路径。因此问题已缩小到自动启动组的导出／编辑识别，尚未证明具体修复办法；未凭这次成功改动全部自动组的语义。

WPS 12.1.22553 将该单击样本的持续时间从 2 秒改成 3 秒并保存。原生 `animMotion` 保留，`dur` 变成 `3000`，明确的 `additive="repl"` 也被保留。新内核读回 3000/1000 秒，经独立 SDK 再导出，实际产品播放 Worker 完成采样。两份产品输入共有 11 个 PresentationML 根部件通过 XSD；未通过截图替代文件回读。

之前在 WPS 直接绘制的对照文件仍未通过：其效果容器缓动已可识别，但它省略了 `cBhvr.additive`，当前诊断为该行为尚不支持。[Microsoft 的默认值说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/6988ac0e-8227-47dd-a67b-1bbb925cd0af)给出 `base`，不能擅自当成 `repl`。该原文件与旧失败记录均保留，不声称任意 WPS 路径动画已兼容。
