# 本地薄 MCP 与共享文件计算

2026-09-27 · 接续[直接 SDK/CLI](direct-computation.md)，按 [ADR 0007](../decisions/0007-kernel-only-integration-boundary.md)实施。当前默认 `mo-mcp` 不再依赖业务宿主或数据库；完整一期及产品替换仍在推进。

## 计算与产品责任

`mo-native-compute` 从 CLI 提取已有文件桥接，和默认 MCP 共用 `mo-embedded-sdk::execute`。输入为调用方打开的文件、资源解析器、明确输出位置、临时空间、可选固定 exporter 和取消回调；请求、快照及资源的格式语义仍由原计算库实现。SDK 的普通内存/读取器用法不依赖这个文件适配库。

本地 MCP 的安装配置只有输入目录、输出目录、临时目录、并发槽及可选 worker。目录和祖先由调用方创建、保护并保持稳定；运行中的输出不能由外部程序改名或修改。工具参数只接收便携文件叶名称，拒绝路径跳转、绝对路径、符号链接/reparse point 和设备名称。资源清单中的文件也经同一桥接打开，不能借清单取得额外路径访问权。这是宿主明确提供的本地文件通道，不是新的业务权限系统，也不宣称对控制这些目录的恶意进程提供沙箱隔离。

MCP 不创建内容库或上传服务。输入、实际结果文件和保留策略均归调用方；临时执行目录仅用于有界计算和随机回读。客户端若没有可用文件/附件桥接，这个本地档案不能单独满足它；远程 Streamable HTTP 及网关附件通道继续实施。

## 协议投影

三个工具分别提供实际能力/限额、六份同源计算 Schema，以及创建/导入/原子编辑/导出。计算工具从调用方的调用 JSON 和资源清单读取大输入，避免把整份文稿或 PPTX 编码到模型工具参数。输出包含请求关联、结果摘要与标准资源链接，`productCommitted` 始终为 false；结果文件仍需产品按自己的规则接收、保存或发布。

标准 Resources 读取调用方输出，最多返回 256 KiB；大文件可通过显式范围 URI 分块读取或原生文件通道消费。返回块的偏移、长度、当前总长度和实际块摘要；接收方仍应核对完整文件与计算清单的摘要，块摘要不代替整体校验。没有内部文稿索引、持久任务查询或重启任务恢复。

配置、调用示例、预算和平台限制见[适配器说明](../../tools/mo-mcp/README.md)。Tools 的结构化结果/资源链接遵循[标准工具合同](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)；不存在资源的错误码分别按 [2025 资源合同](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)和 [2026 资源合同](https://modelcontextprotocol.io/specification/2026-07-28/server/resources)处理。两种协议均由真实独立客户端分别检查，不将一个版本的通过当作另一版本通过。

## 取消、并发与释放

协议取消传到实际计算、输入封存和最终输出写入。异步 handler 被丢弃时也会发出取消信号；阻塞任务持有并发槽和请求身份直到完成清理。正常失败清理本次未完成的输出，不覆盖旧结果。进程强制终止或响应丢失可能留下调用方文件，不能据此推断业务已提交。

真实并发测试发现，多个已准入导出会竞争同一个物理 registry；原即时 `WouldBlock` 不应直接变成随机计算失败。底层保留非阻塞维护 API，并为活跃计算增加有界、可取消的取得锁接口；暂存所有者及导出候选在成功、错误或取消离开作用域时有界释放。正常释放等待仍占用执行槽，耗尽释放额度的孤儿保持可恢复；这不是业务任务重试，也不是延迟等待来掩盖验证失败。

真实 EOF 测试还发现原协议层会等 5 秒宽限期后才中止 handler。新入口从传输直接观察断线，在等待协议结束前通知实际计算停止；默认入口不再等待该宽限期才开始取消。旧兼容宿主仍按原持久任务语义运行。操作系统文件 I/O 和磁盘错误没有被宣称为硬实时可取消。

## 旧实现与交付依赖

旧 `HostRequest`、业务身份、SQLite、Jobs、上传等源码和测试保留在显式 `legacy-host` feature 与 `mo-mcp-legacy` 二进制中，配置见[兼容说明](../../tools/mo-mcp/LEGACY.md)。旧配置不会被默认入口重新解释；本轮不迁移、不删除任何旧数据库。

默认 MCP 的生产依赖图不含 `mo-standard-host`、`mo-operation-service`、SQLite 或旧 `mo-native-render` 适配器。Tokio/rmcp 留在 MCP 层；独立 SDK 仍为 23 个自有库、54 个 registry 包，不带 MCP、数据库或新的文件桥接。源码包及依赖数量不是安装包体积或运行性能结果。

## 验证与未完成范围

当前专项已通过两代协议的创建、编辑、两版真实导出、重新导入、资源字节与 Schema 对照、1 MiB 分块读取、路径/符号链接负例、重启读取调用方文件及 8 次并发真实导出。另以阻塞的测试 worker 验证真实取消、EOF、执行槽保持与暂存释放；正常渲染由真实 worker 单独验证，不用假 worker 证明效果质量。

30 步整体回归已通过，生产源码在完整运行中未变化。当前工作区 930 项 Rust 测试通过、20 项忽略：14 项真实 worker 测试由专项明确执行，6 项进程帮助入口由父测试调用。原生 render 4 项、旧宿主 export 9 项、worker 12 项、CLI 1 项分别记录，其中 worker 与工作区有重叠；MCP 默认 17 项、显式兼容 18 项的共同 17 项也不重复计数。两代旧协议、传输、生命周期及取消回归通过。27 组 Native/WASM 文稿结果与 6 份计算 Schema 一致，不代表完整渲染一致。

独立打包 SDK、CLI 和两代 MCP 的导出收据及 12 份资产逐字节一致。独立文件检查核对 10 个 XML 部件的官方 XSD、15 个原生对象、8 处文本和两页 PNG 像素；与上一阶段相比，PPTX、两份预览和其他 7 份资产不变，另 2 份元数据只因当前 worker 摘要及引用更新而改变。所有布局、原生编辑、播放、目标应用质量声明仍为 `not_proven`；不得以结构与字节一致推导 Office/WPS 验收。

独立 SDK 严格检查与实际消费通过；Native I/O/export/文件桥接的 Linux aarch64、Windows x64 仅有严格交叉编译证据。本机生命周期证据为 macOS。完整[阶段证据](../reviews/evidence/2026-09-27-thin-mcp-verification.json)绑定源码、锁定 SDK、二进制、组件和实际结果。初次并发失败、协议版本 ping 差异导致的检查器失败、EOF 宽限期观测和证据记录文件名冲突均保留，修正后重新执行对应检查。

本阶段不改动 Musterwork。Streamable HTTP、宿主附件桥接、Skill/Plugin 发行包装、其余高层接口、完整高级内容、Windows 原生生命周期、Office/WPS、完整性能/体积与 I01–I20/MW 验收继续开放。当前默认本地 MCP 可消费已实现计算能力，不等于完整替换条件已经满足。
