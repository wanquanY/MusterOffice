# 流式 PPTX 与封存结果回读

状态：P02/P07 导出底座实现；本阶段实现和验证见[封存证据](../reviews/evidence/2026-09-26-sealed-export-verification.json)。完整 v0.4、公共 export 作业、预览/质量交付和 Musterwork 替换目标保持不变。

## 原因与职责

[资源宿主](resource-host.md)已经提供有界素材读取，但此前 `mo_pptx::export`、开发桥和 CLI 仍收集完整输出，并在输出后反复打开同一内容。大文件输入/输出的整块内存与重复解压不应成为 Writer 的固有要求。

现在 `mo_pptx::export_to` 将同一份文稿规划写入注入的 `mo_opc::ResultSink`。原有 `export` 选择内存 sink，保持兼容。作者包和 `RewritePlan` 共用 `write_sealed` 完成路径；不存在第二套简化 PPTX 格式生成器。

`mo-native-io` 是 CLI、标准宿主与未来嵌入宿主共享的原生 I/O 模块，使用已锁定的 OPC/rawzip 依赖，没有新增第三方版本。文件路径、时钟和文件系统只存在于宿主模块，Rust/WASM 计算核心不依赖它。SQLite 不因本次改动进入开发 CLI 或 WASM。`PackageReport::from_package` 从已有校验结果生成同一报告，避免为了打印结果再次解压整包。

## 写出、封存与证据

1. Writer 按有界资源读取生成 ZIP，记录实际写入长度与 SHA-256；写入收据不表示存储成功。
2. 宿主 flush 后 seal，冻结写能力并报告实测存储长度，交出不可变 `ReaderAt`。
3. 核心打开同一封存资源，验证 ZIP/CRC、XML、OPC 图，并计算存储字节摘要。
4. 长度和摘要都与 Writer 一致、取消未生效，才返回私有字段构造的 `VerifiedPackage`。

`VerifiedPackage` 证明当前 OPC 校验范围。它不证明完整 PresentationML XSD、排版、可编辑往返、播放或目标应用兼容。类型提供只读 package/reader 与回执，也可转交同一 reader 的所有权，不要求复制全部字节。宿主必须保持资源不可变，并在实际提交时检查版本、输入资源、executor/fence、取消和质量证据。

输入 `ResourceProvider` 和输出 `ResultSink` 分工独立。输出摘要/长度在写出后得到，不伪装成预先知道摘要的输入上传。

## 原生暂存与 CLI

`FileSpool` 接受可信操作员提供的目录，创建独占子目录和文件。Unix 子目录/文件权限为 0700/0600；其他系统依赖宿主配置的 ACL。64 KiB 写缓冲与逐次逻辑输出限额限制暂存写入；写入/flush 出错后实例永久失效。放弃时不再隐式 flush 缓冲。

seal flush、同步文件并验证长度，关闭写句柄后重新打开只读文件。`SealedFile` 不提供文件路径或可写句柄。Drop 尽力清理自己创建的文件和空目录，显式 `discard` 返回清理错误；不递归删除未知文件。

CLI `pptx-export` 通过范围读取访问既有资源 bundle，并直接导出到文件 sink。接口仍采用原来的 128 MiB 开发输入上限，输出沿用包预算；没有提高预算来掩盖问题。校验完成后以 hard link 原子建立新的输出路径，禁止覆盖，也不在跨文件系统失败时回退为未经校验的复制。发布的文件就是回读过的同一文件。既有文本/变换编辑及其他 CLI 输出共用该暂存实现；这些其他操作的计算入口仍可能返回内存字节，本阶段不声称它们全部流式。

## 当前边界

- XML 部件、计划和 OPC 元数据仍在受限内存中；这不是常量总内存或完整 RSS 预算验收。
- 每个 spool 的逻辑字节限额不包含文件系统分配、其他并发任务、数据库/WAL 或输入素材。完整 owner 的预算预留、记录和回收仍需接入。
- 进程正常失败/退出清理已有测试；强杀可能留下私有暂存目录。没有恢复日志、自动 orphan 回收或掉电持久性声明。
- 原生模块实现了本地候选存储；WASM 的既有二进制返回入口仍使用内存 sink。浏览器持久资源适配尚未完成。
- CLI 本地新文件发布不等于产品 Artifact/Resource/Ledger/成功回执事务。标准宿主 export job、公共 bundle、预览及五类质量声明仍需继续完成。
- 本阶段不增加 Office/WPS 互操作、完整高级内容、播放或产品替换通过声明。

## 验证

专项测试覆盖实际短写/范围读取、写入和 flush/seal/read 故障、合法但与写入收据不同的包、写入/封存/回读期间取消、输出限额、真实文件损坏、并发 hard link 只允许一方成功，以及旧文件不被覆盖。另有无需整块素材内存的生成式资源测试、两页原生 PPTX 回读与标准宿主持久素材绑定。

全仓 796 项 Rust 测试、严格 Clippy、格式、104 份未改变的 Schema/TS 合同、Native/release/WASM 构建通过。17 个作者导出、33 个来源读取/编辑、22 个文档编辑双端用例通过；7 份作者候选、12 份来源候选与上一阶段 WASM 输出逐字节一致，12 个来源检查与 22 个文档编辑响应保持一致。

独立 lxml/python-pptx 检查 7 份实际文件、70 个官方 XSD 部件、原生对象和资源字节；12 份来源编辑结果另核对 255 个未修改压缩条目。共享 CLI 暂存路径还用一个冻结的绘制 worker 执行两次发布调用，像素/元数据保持不变且第二次不能覆盖；这不是新渲染能力验收。

历史来源测试中两项预期已经过时：未绑定兼容前缀、错误 AlternateContent 顺序/数量均被上一阶段和当前内核以 `INPUT_INVALID` 拒绝。本阶段单独派生测试清单并核对冻结父版本响应，不改旧输入、旧验证程序或生产诊断。两次失败记录保留；独立报告汇总脚本最初把部件列表误当计数，修正为列表长度后重新运行，记录同样保留。

## 局部内存与耗时

Apple M4 Max、36 GiB 内存、macOS 26.2 arm64、Rust 1.92 debug CLI。上一阶段二进制在改动前按摘要留存；两版各预热一次，再交替执行三次，表中为中位数。操作系统缓存未清空，测量时不并行构建；`/usr/bin/time -lp` 包括进程启动、写出、回读和本地发布。仅引用 fixture 中显式字体名，没有加载字体、排版或绘制。

| 输入 | 上一阶段峰值 RSS | 流式峰值 RSS | 上一阶段耗时 | 流式耗时 |
| --- | ---: | ---: | ---: | ---: |
| 原始两页小样本 | 13,647,872 bytes | 13,647,872 bytes | 0.03 s | 0.02 s |
| 两页，单张 2048×2048 RGBA PNG，素材 16,780,612 bytes | 48,922,624 bytes | 14,008,320 bytes | 5.84 s | 3.89 s |

大素材样本峰值 RSS 降低约 71.4%，耗时降低约 33.4%；两版文件摘要完全一致。小样本没有测得内存下降，其毫秒级时间差不作稳定吞吐结论。这是两种本地 debug 工作负载的证据，不是 release 性能、持续任务内存、完整内核或 Musterwork 收益验收。

当前 release 开发 CLI 为 10,201,936 bytes，标准文档/资源宿主为 4,865,392 bytes，核心 Rust WASM 为 7,791,918 bytes。C++ WASM 仍使用此前 2,370,691 bytes 产物；这些组件不构成完整字体、媒体、worker 和产品运行时闭包，不能相加推断桌面安装包。
