# 嵌入式宿主的无状态原生导出

本阶段为 Musterwork 现有 Runtime 提供独立的计算入口，源码为 [mo-native-export](../../crates/mo-native-export/src/lib.rs) 与 [mo-export-worker](../../tools/mo-export-worker/src/main.rs)。它不创建数据库、持久任务或产品成功记录；当前仍是接入准备，尚未修改 Musterwork 的产品入口、Artifact 合同或提交事务。

## 所有权与调用

宿主先在自身权限和历史版本规则下取得不可变 SnapshotRecord、OperationRequest 与 ExportAssets；随后在已有任务内调用 NativeExporter::prepare。导出进程的路径、摘要、超时与受保护暂存根目录来自可信运行配置，文稿和工具 JSON 不接受这些值。可执行文件在构造与每次执行前读取真实摘要，工作进程也计算自身摘要并核对请求中的 renderer 身份；宿主须保证可执行文件和其目录不可被非可信主体替换，这不是操作系统代码签名或远程证明。

父进程以固定上限的分块传递元数据、图片和显式字体；一个子进程只处理一次请求。工作进程复用纯 compute_export、已有 PPTX Writer、页面准备与 Skia/HarfBuzz 组件，整个原生计算位于隔离进程中，不为每页启动第二个绘图进程，也不查找系统字体。

成功响应携带绑定请求摘要的 ExportReceipt 和二进制交付文件。父进程先保留实际收到的文件，确认完整协议结束和子进程成功退出，再用共享交付接收器核对文稿版本、语义摘要、设置、renderer、实际资产摘要、文件结构及逐页像素证据。只有通过后才返回不可反序列化构造的 NativeExportCandidate；候选仅持有私有文件和验证结果。

宿主可以范围读取候选资源，写入自己的 Content Store；随后必须在既有事务内重查 Invocation、fence、generation、文稿 pin 和取消状态，再提交 Artifact、资源和 Tool receipt。此适配器不代替上述事务，不宣称只计算一次或只提交一次。Standalone 的 SQLite owner 不进入该接入路径。

## 生命周期与预算

内部一次性帧使用 u32 小端长度和严格 JSON，元数据上限 65 MiB，序列化过程即检查上限，不先分配无限 JSON 再检查。拒绝重复键、未知字段、未绑定/重复资源、错误版本和 renderer；元数据不包含文件内容。二进制输入每块至多 64 KiB，工作进程全部接收完输入后才发送计算失败或输出，避免发送/接收背压环。

当前输入总量至多 512 MiB、单资产 128 MiB、显式字体 32 MiB；输出复用 DeliveryLimits，最多 1024 份资产、合计 512 MiB。父进程为实际接收结果再保留一份独立文件。最坏逻辑暂存数据为输入、子进程输出、父进程接收输出合计 1.5 GiB；文件系统开销、元数据和渲染/字体内存另计。该上限不是内存或整机配额，生产宿主仍须预留磁盘并控制全局并发。

父进程拥有每次执行的独占目录。超时、取消、协议失败或崩溃先终止并回收子进程、等待传输线程结束，再清理本次目录，包含被杀进程遗留的未封存输出。正常候选保留到使用者释放或显式 discard；读句柄先关闭再删除目录。显式删除成功后放弃路径，避免 Drop 再删除后来复用该路径的目录。

宿主自身崩溃的恢复登记和清理尚待产品 owner 接入。Drop 的删除为尽力执行，显式 discard 可报告存储失败；不能把 RAII 宣称为磁盘故障或断电后必定回收。宿主资源读取回调必须有界，任意阻塞回调不能由普通 Rust 线程强制中断。

## 诊断与验证状态

字体及页面失败复用 kernel-api 的现有结构化诊断转换，不另建错误分类；进程/传输中断与内容绘制失败分开。这里没有更改已有公共 JSON Schema 或 WASM 操作合同。

真实原生集成已验证两页文稿、全部 12 个交付文件、重复导出一致、保留文件生命周期、损坏输入、错误版本、取消和结构化字体失败。额外故障进程覆盖终止/回收、超时、可执行文件改变、伪造回执、损坏/截断/多余字节和失败退出。故障脚本仅用于拒绝测试，成功页面由真实原生组件产生。首次短时限故障测试曾因启动时序未取得 PID 失败；修正为读取完整 PID 的握手并给予明确启动余量，失败日志保留。

873 项全仓 Rust 测试、严格 Clippy、格式检查和 111 份 Schema/TS 检查通过。固定摘要的 release worker 又通过全部 8 项进程集成；实际输出的 12 份文件由独立 Python 读取器核对，十个相关 XML 部件通过锁定的官方 XSD，包含 15 个原生对象和八段文字。PPTX 完整字节、两页实际 PNG 像素与既有同输入基准一致。成功样本使用自有合成字体，不能证明完整内容、商业视觉效果或 Office/WPS 外部编辑。

新构建 WASM 与旧模块同为 9,843,551 字节、gzip-9 为 2,693,291 字节；实际二进制仅两处 panic 源码行号改变，共两个字节。验证器解析数据段定位到上述两个新增诊断转换所在文件，Code、导入导出及所有其他区段完全相同，JS glue 和公共合同字节不变。另重跑 36 组交付接收及 72 组文件/编辑 Native/WASM 调用，结果保持基准；没有重新声称完整播放或浏览器导出已验收。

macOS arm64 / Rust 1.92.0 的 release 工作进程为 10,027,936 字节，gzip-9 为 4,233,513 字节，包含本次所需的 Skia/HarfBuzz 静态组件，仅动态链接系统 libc++/libSystem。它没有捆绑字体或媒体；该数字不包含产品父进程、全部高级能力或安装包装。逐页准备仍包含重复包/字体检查，尚未建立 40/80 页性能、峰值 RSS 或完整磁盘预算通过的结论。
