# 原生缩放输入与 WPS 时序校准

2026-09-27。[显式缩放](scale-animation.md)之后的增量。扩大原生输入计算范围，同时记录实际发现的导出兼容性缺陷；尚未达到 Office/WPS 动画验收或 Musterwork 替换条件。

## 已实现的输入语义

来源 Reader 将以下声明无损投影为计算所需的显式端点。原始 OPC 和声明继续由来源层保留，不因投影而改写。

| 原生声明 | 计算起点 | 计算终点 |
| --- | --- | --- |
| from + to | from | to |
| by + from + to | from | to，按 Office 规则忽略 by 的数值作用 |
| to-only 或 by + to | (0, 0) | to |
| by-only | (100000, 100000) | by |

单位为千分之一百分比。整数和能精确表示的百分比字符串共用已有的 `NativePercentage` 解析，不新增浮点舍入规则。范围仍为 0..2147483625；超出精度、缺少坐标、重复或乱序声明、未知属性及子节点均返回诊断。即使 by 在计算中被忽略，其语法仍需合法。

`from + by` 尚未支持。本阶段曾提出相对终点的候选解释，随后 WPS 对照没有证实它，已从实现和成功用例中移除；不能把未经目标应用校准的公式写成已支持能力。`zoomContents`、属性累加及更广的时间树默认值也保持未完成状态。

依据为[微软 animScale 实现说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/358c6de3-2cd7-459b-8eb9-b90f3721fd12)及[原生尺寸范围](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/b4e7ea1e-7bb9-454d-96a3-61c6fcd0ea9a)。这里的规范依据与下面的 WPS 观察分别记录，不互相替代。

## WPS 实际观察

在 macOS 的 WPS 12.1.22553 上，用本仓库自有的六色矩形文稿进行编辑和放映。每个原始矩形为 400000 × 300000 EMU，文稿为 8000000 × 4500000 EMU。用户授权了短暂前台校准及仅校准目录的访问；操作结束后关闭校准标签并恢复原应用。没有编辑用户已有文稿。

| 对照文件 | 时序结构 | 观察 |
| --- | --- | --- |
| 原生直接行为 | tmRoot 下直接放 animScale | 文件可打开，动画面板为空，放映保持原尺寸 |
| WPS 自有编辑控制 | 在校准文稿中原生创建“出现”并保存 | 获得 mainSeq、点击组、效果组、行为及 prev/next 条件的真实结构 |
| 单效果组实验 | 所有六个目标放入同一个效果组 | WPS 识别动画，但只改变第一个对象；不能据此采用该结构 |
| 分离效果组实验 | 保留 mainSeq 层级，每个目标独立效果组 | from/to、by-only、to-only、带忽略 by 的 from/to 最终约为 2 倍；两组 from/by 最终不可见 |
| 仅效果组实验 | 删除 mainSeq 和中间组，六个目标统一显式 from/to | 动画面板为空，放映仍为原尺寸 |

五份实验文件的幻灯片 XML 均通过固定 ECMA-376 XSD。**文件能打开、XML 合法、内核自行回读通过，都不足以证明动画能在目标应用中编辑和播放。**

分离效果组的最终放映画面为 3840 × 2100 像素。六色区域单独测得：四个可见对象约 373–374 × 279–280 像素；仅效果组对照约 186–187 × 140 像素。蓝色、青色两个 from/by 对象在前者没有检出对应色区。测量针对 JPEG 最终帧，容许边界抗锯齿/压缩的 1 像素差异；不是精确中间帧、叠加、反转或点击轨迹验收。

实验改变了层级和元数据，尚未独立证明每个属性的必要性。`presetID=6` 等实验值也不能直接变成通用 Writer 决定。from/by 不可见是当前实验条件下的事实，不能推广为所有 WPS/PowerPoint 的语义结论。

## 已定位的根本缺口与后续实现约束

当前 Writer 直接映射计算时间树，缺少目标应用可识别的演示效果与主序列组织。来源 Reader 也尚未实现 mainSeq 的导航/并发语义，因此继续明确拒绝该结构；不通过忽略这些字段宣称已成功导入。

下一步需要实现独立的原生时序投影，边界如下：

1. 区分演示效果身份与底层属性行为。同一效果可能包含多个行为，但跨对象的六个行为不能未经定义地合并成一个编辑效果。
2. 分开保存计算节点身份、效果身份及原生 cTn ID。增加原生容器后重映射全部开始/结束引用，保持原目标与对象分组。
3. 类型化表示主序列、点击组、with/after/click 效果及 prev/next 导航；明确 concurrent/seek、重复、结束和保持如何改变事件轨迹。包装容器的时钟和 fill 不能改变原图结果。
4. Reader 和 Writer 共用可检验的投影规则。只对语义已实现、可证明等价的输入生成该 profile；其余保留来源与精确诊断，不扁平化、不烘焙图片、不在宿主补做动画。
5. 独立验证规范结构、原生/WASM 计算等价、WPS/Office 编辑和放映轨迹。至少覆盖初始态、分数中间帧、结束保持、多对象、嵌套组、连续点击、前后导航、重复/反转和重新保存。

[微软 tnLst 实现约束](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/55167345-00ff-4d39-b4a8-6ca61d86227a)也说明 PowerPoint 对根节点及特定深度的行为目标另有限制。完整投影需结合这些规则和实机验证，不能仅加一层 XML 包装。

以上属于已批准的完整 PPT 功能实现；不改变 Rust 主体、TS 薄接入和 Agent 内核边界。主序列与事件由内核计算，鼠标、按钮、计时和可视界面仍由接入产品负责。

## 验证记录

最终 18 步门禁通过，含 968 项 Rust 测试、119 份合同及生成类型、原生组件/Worker 集成和实际 WASM 构建。常规测试另有 25 项默认忽略，显式组件测试单列于证据，未把所有忽略项计为通过。五个缩放 Reader 测试覆盖既有端点、时间树、四类新声明、精确百分比、无效顺序/精度及 from/by 明确拒绝。

新增 72 个来源帧覆盖图片文字、组合图片及圆形渐变；逐帧与显式端点控制比较完整像素、精确状态和除来源摘要之外的全部响应。加上冻结的既有 67 帧，独立原生 SDK consumer、打包后的 Node WASM 分步播放及 Chrome 153 分步 Worker 各通过 139 帧、21 个播放 owner。控制输入与原输入共享内核，证明投影和跨端一致性，不是 Office 视觉参考。

公开来源时间查询另执行 29 组 Native/WASM 对照：24 份新输入/显式控制成功投影，五份 WPS 实验文稿均得到一致的 `MAPPING_NOT_IMPLEMENTED`，未被误报为完整播放支持。新语料 24 份 PPTX 的 168 个相关原生 XML 部件通过 XSD。原始内容、资源与输入文件摘要保持不变。

开发用 WASM 播放包仍为 60 个文件，未压缩 14,511,333 字节（不含 manifest）、压缩归档 4,171,615 字节；比[上一阶段](playback-geometry.md)分别增加 2,118 和 872 字节。仅 Rust WASM 改变，TS、Skia、HarfBuzz 与合同未变。没有测量本阶段的吞吐、RSS、取消时延或完整桌面安装包；未重新生成 Rust SDK 源码包，稳定协议由既有独立 consumer 配合新 worker 验证。

本阶段记录见[源码、校准和回归证据](../reviews/evidence/2026-09-27-scale-inputs-verification.json)。WPS 失败观察和中间测试保留，不能用最终内部测试通过覆盖实际互操作缺陷。

首轮全仓检查暴露旧宿主测试目录仅用时间戳命名而重名。两个测试入口已复用既有的“进程 ID + 原子序号 + 独占创建”分配器；没有改动宿主生产逻辑或将测试改为串行以规避失败。

本阶段没有新增组件/运行依赖，没有改动 Musterwork，没有将校准应用操作或授权逻辑加入内核。完整功能、跨应用保真、性能/资源预算与产品替换门禁继续开放。
