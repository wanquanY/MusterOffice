# 原生圆形渐变接入页面

状态：开发实现与阶段验证，2026-09-26。遵循原有 Rust 核心、TS 薄适配与精选 C++ 组件方案。完整一期、目标应用互操作和 Musterwork 替换门槛尚未完成。

## 实际链路

PPTX 来源索引 → 填充/颜色继承 → 原生路径编译 → 路径边界与 V2 焦点布局 → 世界坐标渐变平面 → Rust V12 批次 → Native/WASM 绘制 → 公共 API/CLI 文件提交。

本阶段把此前独立的[焦点布局](radial-gradient-calibration.md)和[椭圆绘制组件](elliptic-gradient-raster.md)接入实际页面。通用路径/场景、来源页面和来源资源页面共用同一画笔；没有新增浏览器渲染或图片替代。来源索引和原始 DrawingML 声明保持不变。这是读取和绘制链路的进展，不代表高级内容的编辑、导出、播放全部完成。

## 路径与坐标职责

圆形渐变读取接收对象实际路径的紧边界，包括不填充但有轨迹的子路径。仅移动、不产生轨迹的子路径不影响边界，也不提交到绘制器。路径仍经过原生编译及共享预算，来源声明保留。

`NativePathCompiler` 增加同一预算内的更精细编译入口。页面只在圆形渐变依赖路径边界时提前编译，布局使用锚点重定位之前的路径；后续绘制复用该结果，不再次解析或编译对象。已有线性/矩形/图片/纯色路径保留原有编译顺序。

圆形接收对象使用普通局部容差的 1/16，为边界、半径和归一化传播保留余量；普通局部容差已从设备容差中分配 1/4。最终仍按原始设备误差预算验证。此分配不保证任意病态参数均可接受；不满足预算时明确拒绝。

沿用 V2 开发策略：tileRect 作用于实际路径边界，外圆包围该矩形；焦点位置使用锚定矩形，焦点尺寸使用外圆半径。背景直接使用页面矩形，背景窗口复用页面背景，不按窗口尺寸重算。

设 tile 宽高为 `w,h`、外圆中心为 `C`、半径为 `R`：

- 平面映射整个 tile；分别反射平铺两个单位坐标。
- `tileScale = (w/(2R), h/(2R))`。
- `innerCenter = (Cinner - C)/R`，`innerRadii` 复用布局的精确比例，避免将相关半径误差重复除算。
- 原生仿射变换和误差应用于平面；旋转、翻转、分组变换不会改用另一个对象的尺寸。

固定页面方向的对象渐变仍明确拒绝；shape 路径渐变尚未实现。

## 误差合同

新增 `GradientField::Elliptic` 携带两轴 tile 比例、内中心、内半径及可选六参数不确定度。全部参数使用 Q32，编码为 binary32；可选不确定度使用独立存储，避免扩大所有常见画笔的内存布局。

`RasterWork.ellipticGradients` 仅在使用此场时出现，分别返回：

1. 六个参数的上游误差与 binary32 转换误差。
2. 对应椭圆族边界点的设备几何位移界，包含平面/参数交叉项与全视口平铺相位预算。
3. 成功求根区间的最大宽度 `2^-23`，仅针对已编码的 binary32 场。

几何界比较同一 `t`、同一椭圆角度的点。单位平面内中心为 `(1+c/scale)/2`，半径为 `r/(2*scale)`；两端点的位移界覆盖线性插值族，随后映射到设备空间。比例的不确定区间不能跨零。

非嵌套椭圆可能多次穿越，微小参数变化可能改变首次交点分支。因此参数误差没有加到 `gradientValueErrorBound` 冒充统一标量误差。上述数据不约束像素颜色、覆盖率或着色器逆矩阵计算误差；有硬色标时尤其不能据此保证色差。数值核仍使用首次闭集进入语义、切触检查及整帧失败。

## 版本与宿主

Rust 新增 V12 profile、最大批次字数和 Native 可选 ABI 查询。此前 V4–V11 输出不因新能力而升级。TS 继续检查 V12 组件能力，旧组件不被当作支持新场。

实际 CLI 验证发现：渲染已成功，但宿主独立维护的 profile 白名单漏掉 V12，导致文件提交失败。现在由 `mo-raster` 的同一版本注册表负责输出 profile 和宿主资源模式检查；未知版本及模式不匹配继续拒绝。此注册表不替代组件 ABI 检查。

## 验证范围

阶段产物位于 `.codex-work/elliptic-source`；旧阶段目录和证据保持冻结。最终数字及摘要见[阶段证据](../reviews/evidence/2026-09-26-elliptic-source-verification.json)。

- 实际 PPTX 样例覆盖背景、背景窗口、继承、分组变换、椭圆、预设路径、二/三次曲线、多路径、点/线/区域焦点、外扩、平铺、透明度和硬色标。另有可见多路径三角形，验证非空且包含变化的渐变颜色。
- 原生索引读取前后相等；XML 使用已有官方 XSD 检查。文件结构通过不代表目标应用视觉验收。
- 来源公共 API 的 Native/WASM 元数据、批次与像素对照；CLI 成功发布、拒绝覆盖、错误不产生输出。
- 旧来源中一个原本拒绝圆形渐变的输入现可绘制，作为明确能力增量记录；其余旧来源结果保持不变。
- 独立参考从原始 XML 计算轴对齐矩形场景，使用 Decimal100 几何、独立有理数 Sturm 根计数以及原始色标。按 16 像素步长采样，覆盖 Office 插值和透明度；曲线/旋转覆盖率未纳入该像素参考。
- 独立精确有理数比较六参数不确定度的全部 64 个角点、两个矩阵扰动方向、三个时刻和八个圆周方向，共 24,576 个几何样本；这是位移界检查，不是统一颜色界证明。
- Rust 生成的新批次再经过 Native/WASM/ASan/UBSan 组件执行，并验证资源预算失败不泄露部分像素。

## 性能和替换状态

本阶段不修改 C++ 着色核或解码依赖，C++ WASM 模块仍为 2,343,781 字节。Rust 模块、生成类型和 Native 宿主因新能力改变，最终实测字节数单独记录于阶段证据；不能把这些裸模块相加当作 Musterwork 安装包大小。

通用椭圆的实际绘制性能缺口仍见前阶段基准，本阶段没有宣称其已优化，也没有新的桌面安装包、RSS、冷启动或完整产品性能结论。
