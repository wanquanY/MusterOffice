# 视频区间编辑与变速合同

2026-10-06 · 开发中的纯计算合同；未发行、未接入真实产品媒体执行。对应 [技术方案](../design/video-editing/technical-spec.md) 第 3、4 节；整体状态见[实施记录](video-editing-progress.md)。

## 保存语义

`Overwrite`、`DeleteRange`、`Retime` 与已有单片段操作共用 `mo-video-edit::prepare`。没有另一份模拟算法，也没有内部业务版本提交。整个批次的中间修改只存在于候选，最后统一检查工程、计算摘要和生成有条件逆操作。

轨道和片段都使用稳定 ID。区间属于其序列的时间坐标；同一波纹范围不能混入另一个序列的轨道。联动组的成员也必须属于同一序列。移到另一个序列是显式的目标轨道操作，不把跨序列的裸时间解释为共同播放时钟。

## Overwrite 与 DeleteRange

所有区间是半开 `[start,end)`。覆盖操作仅替换目标轨道对应区间；用户要同时替换关联音轨，可在同一事务中组合跨轨区间删除与素材插入。`linkedPolicy` 明确是要求完整关联范围，还是只编辑指定实例、保留独立声音/轨道。

`DeleteRange` 接受显式轨道集合、区间和 `ripple`。不启用波纹时保留空隙和区间外的工程时间。启用波纹时，所选轨道中区间后的内容整体前移区间长度，包括空隙所占时间；不通过反复修剪逐个片段来累计位移。

| 原片段相对区间的位置 | 结果 |
| --- | --- |
| 完全在左侧 | 保持不变 |
| 完全在右侧 | 非波纹保持；波纹整体前移一次 |
| 完全在区间内 | 删除片段，资源留给宿主管理 |
| 只保留左端 | 保留原 ID，准确截取原时间映射 |
| 只保留右端 | 保留原 ID，截取来源后再按波纹规则定位 |
| 左右两端都保留 | 左端保留原 ID；右端使用调用方显式提供的新 ID |

`remainders` 必须恰好覆盖跨越两端的原片段；多余、缺失、重复和已经存在的新 ID 均拒绝。覆盖片段不能复用任何被分配给右侧残片的 ID。不会凭随机数或数组下标替调用方创建对象。

来源范围与分段 TimeMap 均按原曲线截取，保留反向/定格段；淡入淡出相位随片段局部原点移动。不会在每个切口重新开始效果，也不会将不能精确保存的时间悄悄四舍五入。

### 关联组

`requireAll` 要求受影响组的所有成员轨道进入明确作用域。确实被分成左右两组时，分别保存仍有两个及以上成员的一侧；原组 ID 优先保留给左侧，否则用于仍成组的右侧。如果两侧都需要组，调用方必须提供精确右侧成员及一个新的组 ID。单独幸存的片段不构造伪造的单成员组。

没有任何成员同时产生左右残片时，保留原组中所有幸存原 ID 的关联关系。`independent` 不自动关联新残片；被完全删除的成员从旧组清除，仍存在的其他成员素材不修改。

这些规则使对称音画切口与音频较晚开始的非对称切口都具有确定结果。保存后的组及片段关系进入逆操作条件；之后新增关联或修改幸存成员，不能被恢复旧组的撤销操作覆盖。

## Retime

变速的唯一保存真相仍是 `(local,source)` 时间锚点。`Retime` 显式给出目标片段、新 TimeMap、音频策略、效果时间策略和可选波纹轨道。新时长由最后一个局部锚点决定，不另存一个可以与映射分离的速度值。

- 正向、反向、定格及线性分段均沿用同一时间映射校验。
- 新的源范围、局部顺序、时长、目标重叠及素材余量不成立时，整批拒绝。
- 多个片段共同触发波纹时，必须具有相同原结束边界与时长变化量；不能让后继素材被多次或相互矛盾地推移。
- `preserveClipTime` 保留效果原局部时间；`scaleToDuration` 按新旧时长的精确比例缩放效果时间。常量变换/增益没有时间参数；新增效果类型必须明确实现窗口与缩放语义。

### 音频策略是数据，不是已经实现的解码承诺

片段保存 `AudioTimePolicy`：

| 字段 | 取值 | 合同含义 |
| --- | --- | --- |
| rate | `resample` / `preservePitch` | 随速度改变音调 / 保调时伸 |
| reverse | `reverse` / `mute` | 对反向段反播音频 / 静音 |
| hold | `silence` | 定格段不无限重复一个 PCM 样本 |

普通导入片段的默认策略为保调、反向静音、定格静音；`RetimeTarget.audio` 必须显式提供。独立继续播放的配音应使用自己的音频片段和时间映射。视频轨不会因此隐式播放源文件的嵌入音频，音频轨才消费该策略。

当前只实现策略保存、编辑和校验。时伸、重采样、混音、设备播放和真实媒体输出仍待媒体内核执行与验收，不能以元数据已保存声称声音处理已完成。

## 验证范围

新增专项包括两端残片、完整删除、区间空隙、半开边界、关联组完整/缺失/非对称、独立声音保留、锁轨、每个观察到的取消点、逆操作后继依赖、跨序列拒绝、分数时间、不能表达的效果缩放、反向和定格，以及真正使用 `TrackKind::Audio`/音频流描述的联动编辑。

固定种子长序列已纳入 overwrite、区间删除和 retime，仍运行 100,000 次。Native/WASM 相同 fixture 扩展至 25 步；每一步明确断言预期成功或拒绝，再比较完整结果，不能以两端都意外拒绝当作通过。

这仍是计算语义证据，不能关闭真实音画同步、音频质量、浏览器媒体、产品保存恢复或整个最终功能矩阵。
