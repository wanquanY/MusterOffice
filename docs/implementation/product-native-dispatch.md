# 原生任务的环境派发与恢复

2026-09-28，Musterwork 独立 worktree 将已固定的原生计算环境接到原有 Cloud Run 派发器。此阶段属于产品接入；MusterOffice 仍只交付计算能力，没有增加权限、任务、存储或用户界面。

## 同一环境身份贯穿原流程

上传策略 /3 已固定 SDK 产生的字体和设置摘要，见[上传环境描述](product-native-upload.md)。设置摘要包含 SDK 设置、字体和渲染器身份；其中渲染器绑定实际 worker 字节。

原签名 Snapshot 授权精确的输入清单 ContentRef。准入读取该清单并验证长度、字节摘要、任务和阶段身份、编译档案、字体及设置摘要。准入与文稿计算共用同一环境解析规则，未增加可由请求自由指定的执行环境字段，也未改变既有签名编码。

新增 Runtime 迁移 `0207_presentation_execution_environment.sql` 保存原请求的不可变派发投影，和原 Run、请求、Ledger、审计在同一事务提交。清单读取在写事务之外完成；重放复用同一 Snapshot 对应的已验证投影，不重新读取部署配置或重新选择环境。无效清单不产生部分任务。

Cloud Worker 从工具执行器共用的已加载 `OfficeHost` 取得实际环境。原调度器在候选数量限制之前过滤不匹配任务，并在领取事务取得 Run/Lease 锁后再次检查。直接调用 Ledger 领取及幂等领取回执也检查环境。没有 OfficeHost 的节点只能领取不需要原生计算环境的任务。

Define、Stress、Verify 整份原生模板阶段使用同一约束。独立视觉复核子任务只消费已生成的证据，不要求安装计算内核。普通任务和旧 HTML 流程沿用原调度器。

## 恢复、取消与历史任务

失效租约及主动交还的原生任务只由环境匹配的节点恢复，保持原有 Attempt 与 fencing 递增。已进入取消状态的任务走原取消恢复通道，不要求匹配计算环境；不能因匹配节点离线而阻塞清理。

迁移不改写历史请求、签名 Snapshot 或 Ledger。旧任务尚无派发投影时不能执行计算。启动组合按最多 128 条一批，从待执行历史任务的原 Snapshot 和实际清单补建投影；中断后重启可继续。取消中的任务不依赖补建。无法核实的历史材料导致明确失败，不能把它默认为旧引擎或任意环境。

投影补建是产品已有事实的派生索引，不执行 SQL schema 迁移。Schema 仍由专用迁移流程管理。首次部署应排空旧版 worker、应用迁移、更新 API 与 worker，再开启候选流量。旧可执行程序没有新的派发谓词，**不能承诺与它们混跑时仍满足本次环境隔离约束**。新版节点之间可以使用不同环境，领取各自匹配的任务；描述文件不表示节点在线或资源预留。

## 验证与剩余范围

最终验证通过 32 项不同测试：原 PostgreSQL 调度/执行与准入 24 项、真实 SDK 维护 4 项、云宿主 3 项、完整数据库结构 1 项。六个相关 Rust 库通过严格 Clippy，207 个迁移文件的不可变摘要检查通过。结构检查还发现并补齐了旧迁移 0192 已创建的两张表清单，以及上一阶段 0206 的遗漏摘要；未修改历史 SQL 或已有摘要。

最终命令、源码摘要、实际输出与计数记录在[本阶段验证证据](../reviews/evidence/2026-09-28-product-native-dispatch-verification.json)。调度测试使用独立 PostgreSQL，执行原准入、签名应用、派发、租约交还和取消接口；派发测试中的来源字节仅为专用任务材料，不声明它是可渲染文稿。实际 SDK 文稿计算另行验证。

本次工作不证明 Linux 云部署、完整外部模型会话、视觉质量、Office/WPS 往返、Native/WASM 一致性、性能或发行包体积。后续继续完成真实上传至模板目录的父子 Agent 链路，以及用户文稿创建、编辑、预览、播放和导出的产品替换验收。完整目标保持进行中。
