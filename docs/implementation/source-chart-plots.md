# 来源图表的系列、数据点样式与实际绘图

本阶段把源圆形图表的缓存、几何、颜色和描边连接为共享 Draw IR，调用者不再自行拼接
数据点配色。它是图表绘图区的计算原语，尚不等于标题、标签、图例齐全的图表，也没有
解除来源页面对完整 graphicFrame 的准入约束。Musterwork 人工验收候选保持固定。

## 输入、输出与复用

Rust 入口是 `mo_kernel_api::compile_pptx_chart_plot`，JSON/WASM 入口为
`compile_pptx_chart_plot_json` / `compile_pptx_chart_plot`，CLI 为：

```sh
mo-cli compile-pptx-chart-plot request.json source.pptx
```

请求显式选择 `source-circular-declared-solid-plot-v1-draft`，包含此前
[圆形源几何请求](source-circular-geometry.md)和颜色上下文。几何请求绑定文件摘要、
原生对象、绘图序号、已计算的中心与半径、容差和负数策略。自动绘图区布局仍需后续
计算；不能把 graphicFrame 外框直接当作绘图区。

输出包含真实源文件、图表部件、系列、缓存点与样式的物理序号，以及可由现有场景
渲染器使用的 `DrawScene`。每个非零点共用一条几何路径，按源顺序产生填充和描边实例；
显式 noFill 不产生相应实例。零值点保留身份和样式，路径为 null，不添加退化描边。
完整圆环沿用内外反向轮廓，避免凭空增加径向线。

几何计算复用此次解析出的同一图表对象，不再为它重新查询来源图表。填充和描边
语法、类型约束、颜色上下文、曲线生成、Draw IR 和原生/WASM 光栅化均沿用已有实现。
形状、表格与图表的描边准入转换抽到一个共享模块，原有拒绝条件保持一致。

## 声明继承与尚未解决的自动样式

本 draft 按数据点、系列的顺序补齐直接声明。填充节点按类型合并；选中 solidFill
后，较低层的 noFill 不替换它，较低层的 solidFill 可以补齐缺失颜色。线宽、端点、
连接及虚线通过已有逐属性解析器继承。来源记录新增真实 chart 部件与物理序号，
不将图表伪装成具有幻灯片 native ID 的普通形状。

空 effectLst 是明确清除效果，阻止继续继承系列效果；缺失效果仍是缺失。类型合并、
空列表阻断和基本线条缺省值依据
[微软 DrawingML 说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/c0c046ec-a61d-405d-88fe-74d8487a37d7)。
点到系列的具体应用及跨应用行为仍是待 Office/WPS 校准的 draft，不将共享属性规则
等同于已证明完整图表样式兼容。

ECMA-376 Part 1 §21.2.3.46 的表格定义了图表自动样式，不能用普通形状默认值替代
整套图表样式。当前要求填充与线条填充都能够从明确声明中完整获得；若线条有颜色，
还必须有显式可继承线宽。只有已取得声明线宽后的 cap、compound、alignment、dash、
join 和端点等基本属性才使用共享 DrawingML profile 的缺省值。仍缺少自动填充、
线宽或效果时返回带源位置的未解析错误，不自动补颜色或认定无效果。

本绘图区准入为无填充或纯色、普通居中实线、round/bevel 连接、无箭头和明确空效果。
渐变/图案/图像、阴影等效果、双线、内侧描边、虚线、miter、标记、pictureOptions、
负数颜色反转等尚未接入的语义都不会被删除后继续渲染。系列与点的未知属性、扩展及
未识别内容同样返回诊断。数据标签是明确分离的后续组件，不在本原语中伪造空标签。

这些边界描述当前实现，不缩小一期完整目标。后续须完成自动图表样式及其他绘制
语义、标签/图例、布局、图表原生编辑、工作簿同步与全页合成。

## 资源与精度

解析、颜色求值沿用[来源配色阶段](source-chart-paints.md)的共享预算。样式准备阶段
一次绑定全部声明、颜色、系列和点，避免每点扫描整个图表；全部点共享填充和线条
步骤、值数量、词法/来源字节预算。默认最多 4096 次点样式计算、8192 个绘制实例，
调用方可进一步降低限制；取消、预算或语义错误都不返回部分场景。

输出坐标误差为 Q32 EMU，包含来源角度/半径与曲线误差。渲染调用方须将它按视口
比例换算，叠加场景变换及设备坐标量化界后检验总容差。描边宽度量化另由现有
光栅元数据报告；这里不将控制点误差冒充描边外缘、像素覆盖或抗锯齿误差证明。
数据仍明确来自缓存快照，没有隐式工作簿刷新、网络、文件路径或系统字体依赖。

## 验证与继续验收

自有语料覆盖逐属性覆盖、空纯色继承、noFill、透明色、线宽与描边颜色独立继承、
空效果覆盖、零值和完整圆环、主题映射以及未实现语义的拒绝。API 检查来源摘要、
未知请求字段、请求体积和取消；共享形状/表格、线条/填充解析保持回归验证。
Native/WASM 验证直接比较 Rust 产生的完整场景及实际 Skia 输出；JS 不重新选择样式。
独立 Python 程序从原 ZIP/XML 重建所用属性、来源及绘图顺序，检查内部填充、外弧
描边、圆孔与外部透明像素。最终数字与哈希保存在
[本批证据](../reviews/evidence/2026-09-30-source-chart-plots.json)。

复现工具为
[`chart_plot.rs`](../../tools/test-support/chart_plot.rs)（自有语料）、
[`chart-plot-parity.mjs`](../../tools/verification/chart-plot-parity.mjs)、
[`chart-plot-oracle.py`](../../tools/verification/chart-plot-oracle.py)。
设置 `MO_CHART_PLOT_CASE_DIR` 为存在的空目录，再运行公开 API 的
`pptx_chart_plot` 测试，可保存全部自有源文件、请求与清单；工具禁止覆盖已有文件。
真实私有模板仅保留本地验证产物，公开证据不含模板文件或图像。

本批实际通过 6 项新绘图测试、7 项源几何测试、100 项编译器库测试、14 项形状/表格
编译回归、48 项既有填充/线条回归以及 3 项 API 测试。31 份 Native/WASM 完整响应
一致，其中 17 份成功、14 份预期失败；17 帧所有像素与元数据一致，包括两个真实
模板圆环图。独立原 XML 校验覆盖 51 点、85 个绘制实例、96 处填充/透明探针和
548 处描边像素，四类篡改反例均被拒绝。61 份旧源几何/配色接口结果在旧 WASM、
新 WASM 与新原生中保持一致；31 份请求和响应通过生成 Schema，严格 Clippy、
TypeScript、格式与链接检查通过。诊断图已查看，不据此宣称完整模板或目标应用保真。

整图外观、自动样式、多系列环形图顺序和抗锯齿相邻边界、Office/WPS 打开/编辑/
播放仍需分别验收。本批没有变更正式 Agent 能力声明、产品 SDK/worker 或桌面安装包；
不能据此宣布已完成模板适配或整个 PPT 替换。
