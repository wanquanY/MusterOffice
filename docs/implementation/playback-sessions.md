# 可复用页面播放采样会话

状态：已实现共享 Rust 会话、WASM 所有权对象及原生隔离 worker 的常驻命令流。它复用上一阶段作者页面的旋转计划，仍不是完整放映状态机、媒体同步器或保留式实时合成器，尚不能替换 Musterwork。

## 准备一次，显式采样

`PlaybackSession` 每个所有权对象至多持有一份 `PlaybackPagePlan`，后者持有不可变作者文稿、时间图和初始放置。`prepare` 验证快照摘要与 revision、文档、所选页面和时间图；成功后，`compile` / `render` 只接收绑定、目标时间和完整事件历史，不再逐帧提交文档或重做快照验证。

本阶段复用的是文稿、时间图与初始放置。动态放置、路径、误差认证、场景和设备降低仍在每次采样时计算；没有缓存最终像素，也没有用上一帧修改下一帧的文稿。准备成功表示计划已建立，不承诺所有时间点均可绘制；尚未实现的内容、动态精度或组件问题仍会使具体帧明确失败。

每次采样仍进入[同一共享页面管线](playback-rendering.md)。旧的逐请求接口保持原有响应；会话中的编译/绘制成功响应与旧接口同形、同值。会话错误单独归类；计算错误包含原有的时间或页面诊断，失败没有部分像素。

## 版本、跳转与生命周期

生命周期为 `Empty → Prepared → Disposed`。准备失败或取消不提交新计划；已准备对象拒绝再次准备。需要更换文档、页面、viewport 或默认画笔时创建新所有权对象，旧对象可以按宿主授权继续采样原快照。释放后禁止重新准备，避免相同句柄被悄悄指向新文稿。

所有采样、查询、generation 更新和释放都要求 `session + revision + generation` 完全匹配。`advance` 同时携带当前绑定和严格更大的 uint64 generation，原子更新绑定并复用原计划；禁止相等、倒退与整数回绕。generation 在 JSON 中仍为规范十进制字符串，不经过 JavaScript Number。

宿主在展示用 seek、导航或取消旧一轮播放时先提升 generation，再以新绑定采样；已发出的旧帧由宿主在实际提交到显示表面时再次核对并丢弃。核心拒绝旧请求，但不能撤回宿主已拿到的字节。普通离线 `sample` 可按任意时间顺序求值，不隐式读时钟或自动变成 seek。

事件历史不在会话内增长积累。交互采样要求宿主提供完整前缀和覆盖时间；提升 generation 不会暗中改写或沿用旧事件，宿主必须显式提供新绑定的历史。未来 checkpoint 和增量事件队列必须有独立预算与等价性验证。

`planId` 以当前 profile、revision、文档语义摘要、页面、viewport、画笔默认值及绘制 profile 计算；generation 和 owner session 不改变计划内容身份。它不是授权令牌、可跨版本恢复的内存布局或完整发行版本元组。

相同绑定的重复 `dispose` 幂等；错误绑定无法释放当前会话。Rust drop、WASM `free()` 或进程退出都会释放持有的计划。会话不持有组件或输出帧队列：组件由宿主按既有生命周期管理，结果缓冲交给调用方释放。组件调用后取消仍丢弃全部像素并使该组件失效；计算计划可保留，后续需用有效组件。

## 原生和 WASM 边界

合同 `playback-session-request` / `playback-session-response` 从 Rust 同源生成 Schema 与 TypeScript；不另行手写文档或动画解释器。

- Rust：`mo_kernel_api::PlaybackSession::default()`，然后 `dispatch` / `dispatch_json`；取消由显式回调控制。
- WASM：`new PlaybackSession()`、`command(request)`、`render(request, rasterComponent)`、`free()`。`command` 无绘制组件，误发 render 返回 `RASTER_REQUIRED`。对象只属于创建它的 WASM 实例，不能转发裸 Rust 指针。
- Native：`mo-raster-worker --playback-session` 每个隔离进程拥有一个会话。每条输入为 little-endian u32 JSON 长度及 UTF-8 JSON；每条输出为两个 u32 长度、JSON 元数据及 RGBA 字节。处理完一条后 flush，持续接受下一条；父进程负责超时、关闭、资源授权、背压和最终结果提交。

单条 JSON 输入沿用 32 MiB 预算，文档/时间图/事件/绘制沿用已有结构和计算预算；这不是实际总内存测量。帧、历史和输出不积存在会话内；进程数量、WASM owner 数量及宿主待显示队列仍须由产品宿主限制。原生协议遇到超限、截断或无效 UTF-8 会退出；普通结构或语义错误返回诊断，当前计划继续有效。

WASM 入口是同步计算，浏览器应放入专属 Worker；执行中的线程不能凭空收到 JS 取消回调，需要由宿主终止 Worker。原生父进程也负责强制超时和进程终止。本阶段没有宣称完成跨线程取消令牌、资源租约或完整宿主播放控制。

## 验证范围

本阶段新增测试覆盖快照所有权、旧接口等价、generation 超过 2^53、uint64 极值、旧绑定拒绝、准备/更新/释放的取消原子性、重复释放、准备失败后恢复、事件历史、格式/大小拒绝和组件后取消。公共验证工具在真实常驻 Native 进程与同一 WASM owner 上重放命令流，并对照上阶段冻结的动画元数据和真实像素。

性能工具使用同一个当前 WASM 模块、相同页面与相同像素，交替顺序对比逐请求准备和复用会话；一次准备单独记录。测量仍包含动态放置/路径计算和像素传递，不包含真实显示、完整文稿、字体媒体、冷启动或 RSS，不能外推安装包体积或实时播放门槛。

673 项 Rust 测试（新增 8 项）、92 份同源 Schema/TS、严格 Clippy 和 rustfmt 通过。真实命令流覆盖 9 个 owner、111 次 Native/WASM 成对调用，重放 74 次已准备页面的编译/绘制及 34 个成功帧；快照不匹配在准备阶段拒绝。355 次静态调用、246 次时间接口调用保持历史结果；组件失败恢复及原生截断/超限退出也通过。

局部测量环境为 Apple M4 Max、arm64、Darwin 25.2.0、Node 23.5.0；模块已加载，320×240 自有页面，10 次预热后 30 次采样，交替顺序比较两种路径。本任务没有同时构建/测试，其他系统负载未控制。以下是每次采样的中位数，准备和请求序列化不计入 retained 行：

| 样本 | 逐请求准备 | 复用会话 | 每帧请求字节 |
| --- | ---: | ---: | ---: |
| rigid-1 | 0.746 ms | 0.643 ms | 1952 → 207 |
| grouped-4 | 1.788 ms | 1.622 ms | 3284 → 207 |
| grouped-1 | 1.837 ms | 1.665 ms | 3284 → 207 |
| nested-2 | 1.398 ms | 1.191 ms | 4057 → 214 |

这些样本中采样耗时下降约 9%–15%，不能作为整个产品的加速比。当前 Rust WASM 为 7,284,988 字节，增加 114,668 字节；C++ WASM 保持 2,370,691 字节。这是原始模块，尚未测量完整分发包。

详细测试、输入、当前模块、历史回归与成本由[阶段证据](../reviews/evidence/2026-09-26-playback-session-verification.json)绑定。此前的精确几何和像素参考仍保留，当前命令流用相同结果核对；Office/WPS 实际播放与编辑没有新增验收结论。
