# 工程保调图、裁切上下文与派生 PCM

2026-10-06 · 工程计算和测试 Host 已实现；生产存储、后台调度、声音设备和工作台接入仍待完成。

## 处理顺序

`AudioMixer` 已调用真实保调处理结果。非原速片段不再一律拒绝，也不会为每次定位重新创建一个从可见窗口开始的 DSP。

```text
不可变媒体 / 子序列
  → 来源采样率与命名声道归一化、正向或反向读取
  → 连续同向的 StretchSchedule + StretchStream
  → RetimeMaterializer 的不可变 PCM 分块候选
  → Host 原子发表派生数据
  → CanonicalRetimedAudio 随机读取
  → 当前片段增益 / 淡入淡出
  → 所属序列混音
  → 上一级片段的速率处理
```

子序列先完成自身政策，然后处理父片段；不能只看相乘后的净速率。测试中，子片段 0.5× 保调后经父片段 2× 变调，440Hz 变成 880Hz；父片段改为 2× 保调后仍为 440Hz。

`AudioResources` 增加 `retime_profile` 和 `read_retimed` 能力。未提供的 Host 仍返回明确的 Unsupported；已绑定而数据缺失返回 `PendingDerived`，由 Host 准备依赖后重试。同步计算不运行在声卡/AudioWorklet 回调中。

## 连续调度

`RetimePlan` 从完整上下文提取连续同向、非零速率的 run。同向的 0.5× → 1× → 2× 使用一个 DSP；停帧和反向边界切开 run。纯 ±1× run 使用既有精确重采样，反向静音策略不创建派生任务。

所有时间运算先使用有界精确有理数。工程采样率为 `F`，上下文在序列中的起点为 `O`，某 run 的上下文起点为 `L`：

- 首个样本为 `N = ceil((O + L) × F)`，允许上下文起点位于可见片段之前。
- 在 `N/F - O` 采样原始映射，得到准确的 `input_zero`。
- 剩余源锚点转换成相对 `N` 的输出样本坐标，输入坐标按方向转换为严格递增的项目采样坐标。
- 锚点可以是分数样本；输入边界使用分段精确插值再下取整。每段限制为 `[1/64,64]`。
- DSP 量子最多 128 个输出帧，在中间锚点的上取整样本边界进一步切开。调度不由播放器的查询大小决定。
- 最后锚点后的尾部按最后斜率外推；声明源范围外补零。两侧延迟和输出裁切继续由 `StretchStream` 管理。

处理 profile 为 `musteroffice.audio.stretch-sequential-q128/2-draft`。它明确改变了分段调度合同；旧 profile 的缓存不能沿用新身份。

## 分割和裁切不能重置声音

工程片段新增可选 `audioContext`：完整原始 `timeMap` 和当前可见片段在其中的 `offset`。资源和流仍使用片段自己的绑定，不能在上下文中另指一个来源。

- 首次裁切/分割非原速保调片段保存完整上下文；继续裁切只移动 offset。
- 分割两侧共享同一个原始处理 run，通过各自窗口读取，保持样本一致。
- 再次拉长时从完整上下文恢复被隐藏的速率锚点。超出原上下文才按最外侧斜率扩展，并重新计算身份。
- 整数样本平移可复用相同派生 PCM；分数样本平移改变采样相位，需要新身份。
- Slip、替换来源和显式 Retime 清除旧上下文，开始新的处理定义；逆事务恢复原上下文。
- 验证同时检查可见映射和上下文映射的所有断点，证明整个可见范围一致。仅检查两个端点不足以排除隐藏的速度变化。检查支持取消，锚点计入文档已有总额度。

媒体上下文受声明媒体范围约束。嵌套序列的隐藏上下文可以超出后来裁短的子序列，这部分按序列外静音处理；可见映射仍必须在子序列有效范围内。否则裁掉一个已不可见的子序列尾部会无端阻止父工程编辑。

`audioContext` 是工程声音语义，必须随保存、撤销和跨端交换保留，不能当作可随时清理的性能缓存。缺省省略该字段，旧工程仍可读取。

## 内容身份与失效

`CompiledDocument::audio_sequence_digest` 按活动音轨及混音顺序计算音频依赖摘要：媒体摘要/流描述，子序列的音频摘要，时间范围/映射/上下文，音频政策和效果。轨道 mute/solo 的实际选择会影响输入。工程标题、画布、片段名称和视觉轨道不参与音频摘要。

派生请求身份包含：

| 内容 | 用途 |
| --- | --- |
| 媒体输入身份或子序列音频摘要 | 防止上游声音变化后读旧数据 |
| 精确 input_zero、方向、采样率、调度锚点 | 绑定取样相位和处理曲线 |
| 输出命名声道布局 | 不把不同声道解释混用 |
| Host 的数值 profile | 绑定解码 PCM、声道矩阵及实际 DSP 构建 |
| 重采样与伸缩 profile | 绑定算法和分块规则 |

片段 ID、整数位置及本片段的后置增益/淡变不参与其自身伸缩身份。修改自身音量无需重新伸缩；如果它位于另一个保调片段的子序列中，则会改变父层输入身份，父层必须重算。

`render_retime_input` 再验证当前工程中的资源/流或子序列摘要、采样率、声道和 Host profile；旧请求不能拿来读取新工程的内容。测试 Host 的固定 profile 只是测试约定，生产接入必须根据实际数值构建和能力绑定生成，不能硬编码这一个值。

## 候选发表与重试

`RetimeMaterializer` 将连续 DSP 结果交给既有 `PcmTileBuilder`。派生源有独立类型和内容身份，不能作为解码源交给 `normalize`。

1. `prepare_next` 最多推进一个可发表输出，保留该 PCM 和分块候选。
2. Builder 预算不足或取消时，已得到的 PCM 保留；重试不能重复推进 DSP。
3. Host 写入所有 immutable blob/ref，并原子公开引用后调用 `accept_published`。
4. 写入失败时再次 `prepare_next` 返回同一候选；空 tile 列表也可能是有效的 carry-only 候选，仍须接受。
5. 计算到有限长度结束返回 None。缺失子层派生资源时先准备子层，再重试当前输入。

`accept_published` 代表 Host 的发表断言，不提供虚构的落盘回执。进程断电仍会丢失 DSP 内部状态；生产 Host 应从连续起点重建并验证已发表的前缀，不能从任意 PCM tile 之后恢复相位声码器。

派生读取复用原 PCM reader 的范围、布局、有限样本、校验和、缺块错误和 LRU 预算。缺块不伪装成静音。

## 内存和执行边界

- 音频计划缓存默认 16 MiB、上限 128 MiB，使用保守准入计数、BTreeMap 索引及 LRU 淘汰；片段和 run 查询不扫描整个缓存。先扫描借用锚点，再淘汰旧计划，再分配新计划。纯原速映射只保留一个固定开销的否定结果，不因锚点多而占完整 DSP 计划额度。
- 扫描工作计入混音访问额度并支持取消。计划数、锚点、有理数位宽均受限。
- Host 保留的请求拥有独立生命周期和预算；它不能通过持有 Arc 阻止混音器 LRU 淘汰。Host 还需限制并行派生任务、磁盘总量、资源 pin 和过期请求。
- `RetimeMaterializer::retained_bytes` 统计 Rust scratch、carry、待发表 PCM 和 tile payload。计划元数据、DSP 组件、存储缓存、allocator 开销和进程 RSS 分开计量；不能把该数值当作总内存。
- 从上下文起点物化可能较慢，尤其裁切很长素材后首次定位。这里首先定义可重复的声音；后台增量准备、进度、取消、磁盘回收和冷定位性能仍属于后续产品验收。
